Local-first AI agent · Rust

Built for the context window you actually have.

luu orchestrates calls to models made for local inference — 7B–32B, with 8K–32K of context — and its whole job is deciding what earns a place in the prompt. It reaches a remote model when you name one, never as a fallback.

Install with one line

Linux and macOS. No root: one binary in ~/.local/bin. The script asks what to do — install, or update, reinstall and uninstall when it finds luu already there.

  • Install, update, reinstall or uninstall 
    curl -fsSL https://jgermade.github.io/luu/setup.sh | sh
  • Linux x86_64
  • Linux arm64
  • macOS Apple Silicon
  • macOS Intel

Read it before you pipe it: setup.sh. Downloads are checked against the release's sha256.

What it does

Context is the product

A small model with a small window does well when what reaches it is chosen, not accumulated. Everything else in luu exists to make that choice visible and safe.

Decide, then render

The prompt is chosen against a token budget, bucket by bucket, and rendered from that choice — so every token sent is attributable. History gives way in whole turns, and a finished task folds into a summary.

A prefix the cache can keep

System text and tool definitions stay byte-identical across calls, which is what a local server's prompt cache reuses. How much of it survived is reported every turn.

Plans you approve

A prompt becomes a plan that says what it will read, write and run — and is held until you approve it. The approved plan is the sandbox for its task, not a comment.

The kernel holds the child

The model never executes anything. Commands run under Landlock and seccomp on Linux, rlimits everywhere, or inside a container — and every verdict says what enforced it.

Any model you can reach

Ollama, anything OpenAI-compatible (llama-server, vLLM, LM Studio) and anything Anthropic-compatible. luu can also start llama-server, mlx-serve or Ollama for you.

Sessions you can replay

Sessions live in SQLite and survive a restart. Every run can be recorded and replayed in the web UI, which is how two context strategies get compared rather than recalled.

Quick start

First run

The first run asks where to keep its state — ~/.luu or ~/.config/luu — and LUU_HOME answers it without asking.

# one turn on the mock backend,
# no model needed
$ luu chat "hola"

# against a local Ollama
$ luu chat "hola" --backend ollama \
  --model qwen2.5-coder:7b \
  --context-limit 8192

# llama-server, vLLM or LM Studio
$ luu chat "hola" --backend openai \
  --openai-url http://localhost:8080/v1 \
  --model qwen2.5-coder-7b

# the web UI, on 127.0.0.1:7878
$ luu serve
See it without installing anything → The web UI replaying recorded sessions: the gate, the budget panel, and eviction under two policies.

setup.sh

Installer options

Pass them after sh -s --, for example sh -s -- install --dir ~/bin. The script never edits a shell profile: when the directory is not on your PATH, it prints the line to add.

install · reinstall · uninstall
With no command, the script asks which to do, offering reinstall and uninstall only when luu is already there. install does nothing when that version is already there. reinstall always downloads again.
--dir DIR
Where the binary goes. Default ~/.local/bin, or LUU_INSTALL_DIR.
--version TAG
A release such as v0.1.1. Default the latest, or LUU_VERSION.
--purge
With uninstall: also delete sessions, keys, config.toml, engines and models. Asks first.
-y, --yes
Do not ask before deleting — needed for --purge when there is no terminal.
LUU_DOWNLOAD_URL
A directory with luu-<target>.tar.gz and SHA256SUMS, used instead of GitHub: a mirror, or file:// for your own build.
