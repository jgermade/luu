# A probe for tool calls: four outcomes, scored off a recording

**Status:** WIP — a proposal and the code it plans. Roadmap item **4** of
[`ROADMAP/2026-09-09`](../ROADMAP/2026-09-09/README.md), the harness half of it:
*the instrument is writable without a model; only running it is section A's kind
of work.*

It is the instrument [`a-grammar-for-tool-calls`](2026-09-06.a-grammar-for-tool-calls.WIP.md)
named and did not build:

> **N prompts that each require exactly one call**, scored per reply on four
> outcomes — *parsed* / *drifted* (the fenced `write_file` case) / *no call* /
> ***continued past the fence*** — the fourth being the one the precision run
> found by accident and the one no existing probe counts.

Nothing about the grammar is decided here. This is the denominator the grammar
arm will be read against, and it is worth having before the arm exists: two of
the three failures it counts are already on disk, in runs nobody was scoring for
them.

## The problem, stated as a measurement

`parse_call` answers one question — *is there a call in this text* — and the
interesting failures are all in what it does **not** say:

```text
reply                                     parse_call     what actually happened
────────────────────────────────────────────────────────────────────────────────
"…" ```tool {…} ```                       Some(call)     the format held
"…" ```tool {…} ``` + 1 700 chars of      Some(call)     generation did not stop
      invented Rust                                      and was paid for
"…" ```write_file {"path": …} ```         None           a call was meant
"…" {"name": "read_file", …} no fence     Some(call)     the parse absorbed it
"the loop is in agent.rs"                 None           no call was attempted
```

Rows two and four are the ones this repository keeps meeting and cannot count.
Row two cost ~1 700 characters of invented `sandbox.execute_tool` in the
precision run; row four is `parse_call`'s own doc comment conceding that a 7B
*"drops the fence about a third of the time"* — a number nobody has ever
measured, because the function that would have measured it is the one hiding it.

## The proposal

### 1. Four outcomes, one of them with a sub-count

`CallShape`, beside `parse_call` because it is a claim about the same text:

| outcome | what it means |
| --- | --- |
| `Parsed` | a ```` ```tool ```` fence, a call inside it, and nothing after the closing fence |
| `Continued` | the same, and then generation kept going |
| `Drifted` | no ```` ```tool ```` call, but a call was attempted: a fence tagged with a tool's name, or a bare object the parse recovered |
| `NoCall` | nothing that looks like a call at all |

**A bare object is drift, not a parse, and it carries `recovered: true`.** This
is the one place the taxonomy argues with the code it sits next to. Counting it
as `Parsed` would report the text parse's generosity as the model's compliance —
and the whole question the grammar arm asks is *does the format hold*, which is
precisely the question `bare_object` exists to stop anyone having to ask. So it
is counted as the format failure it is, with a sub-count saying the run
survived it, because that sub-count is what says what removing the fallback
would cost.

### 2. It scores a recording, not a live turn

The probe reads `--record <file>.jsonl` and nothing else. Three reasons, in
order of how much they matter:

1. **Re-scorable.** A taxonomy is a guess about failure modes, and the fifth
   shape nobody has seen yet arrives as a re-run of the scorer over files
   already on disk — not as a box booked for a second afternoon.
2. **Backend-blind.** Ollama, an OpenAI-compatible server, the mock: they
   differ where the reply is produced and not where it is written down.
3. **Runnable here.** With `--mock-script` ([`a-mock-that-calls-a-tool`](2026-09-13.a-mock-that-calls-a-tool.completed.md))
   a recording can be made in which each of the four shapes was emitted *on
   purpose* — so the scorer is tested against calls that really went through the
   loop, on a machine with no model on it.

Only the **first reply of each turn** is scored. A turn that drifts never gets a
second call, so counting later steps would average a question about the first
call with a question about recovery, and the probe would answer neither.

### 3. The corpus, and a key

`scripts/tasks/tool-call-probe.txt`: ten prompts, each answerable only by making
exactly one call, over this repository's own tree.
`scripts/tasks/tool-call-probe.key`: the tool each one needs, one per line, in
the same order — the same shape as
[`map-order-probe.key`](../scripts/tasks/map-order-probe.key) and for the same
reason. **A `Parsed` reply that called the wrong tool is not a success**, and
without the key nothing would say so.

## What it costs

- **The classifier is a heuristic over text**, exactly like the parse it
  measures. `Drifted` needs to know the tool names to recognise a fence tagged
  with one, so it takes them as an argument; a model that invents a tool nobody
  defined scores `NoCall`, which is arguable and is written down here so the
  next reader can argue with it.
- **One session, not ten.** The corpus runs as one script against one history,
  so prompt 7 has seen prompts 1–6 answered. That is the shape every other run
  in this repository has and it is a bias: a model that has produced six fenced
  calls is likelier to produce a seventh. The alternative — ten sessions — costs
  the comparison with everything else measured here, so it is a caveat rather
  than a design.
- **A number for the mock is not a number for a model.** The scorer's test
  proves it counts what it saw; what a 7B does is unbought and stays unbought.

## What was rejected

- **Scoring inside the turn**, live. It would put a probe's taxonomy into the
  agent loop, where a change to the taxonomy becomes a change to the thing under
  test.
- **A test like `select_probe`.** Coverage is structural and needs no model;
  this needs replies, and the only replies available without a box are ones a
  mock was told to write. The test proves the scorer, not the format.
- **Counting a bare object as `Parsed`** — above; it is the number the grammar
  arm exists to move.
- **A fifth outcome for it.** `Drifted { recovered }` keeps the four the record
  of 2026-09-06 named, which is what makes the two files readable together.
- **Scoring every step of a turn.** Above: two questions, one number.

## Still open

- **The run.** Ten prompts against `qwen2.5-coder:7b` at temperature 0 is one
  afternoon on machine 1 or 4, and it is not bought here. This record claims the
  harness.
- **The grammar's first move is still one curl** — whether
  `/v1/chat/completions` takes a bare `grammar` field — and nothing here changes
  that it comes before item 5.
- **Whether ten prompts is enough** to separate two arms. The gate probe used
  fifteen and the map-order probe thirty-eight; ten is chosen to be written by
  hand from real files rather than to satisfy a power calculation nobody has
  done.
- **Nothing scores the *arguments*.** A call to `read_file` with an invented
  path is `Parsed` and correct by this key. The selector's probes measure paths;
  this one measures the shape of a call, and the seam between them is not
  covered by either.

## 2026-09-13, later: what the diff was

Built as proposed. Four pieces, and one thing the writing did not know.

**`CallShape` and `shape_of`, beside `parse_call`** — in `tools/mod.rs`, because
they are claims about the same text and a classifier that lived elsewhere would
drift from the parse it measures. `fenced` gained a sibling, `fenced_at`, that
also returns where the block ended: that index *is* the difference between
`Parsed` and `Continued`, and nothing in the tree had ever needed it, which is
why the outcome had never been counted. Seven tests, including the two that say
what is *not* drift — a ```` ```rust ```` fence (drift is recognised against the
tool set the run offered, which is why the names are an argument) and an
unclosed block (a call still being generated is an interruption, not a
deviation).

**`luu probe <recording> [--key]`** — `crates/luu/src/probe.rs`, over
`export::read_record`, which already existed for the static twin. It scores the
first reply of each turn: tokens are accumulated until the loop either calls
something or ends the turn, and the `ToolCall` at step 1 is what says which tool
actually ran. The report prints one line per prompt before the counts, because
a probe whose rows are not printed can only be argued with in aggregate.

**The corpus and the key** — ten prompts over this tree, and the tool each one
needs. Written so that no prompt has two right answers: *what is in this
directory* is `list_dir` and not `run_command ls`, even though the policy allows
`ls`.

**`scripts/mock/tool-call-shapes.txt`** — the fixture, and the piece that only
exists because [`a-mock-that-calls-a-tool`](2026-09-13.a-mock-that-calls-a-tool.completed.md)
landed this morning. Five turns, one per shape, eight blocks:

```text
turn 1  parsed                    a ```tool block, then the answer    2 blocks
turn 2  continued past the fence  a block, then an invented result    2 blocks
turn 3  drifted                   a ```write_file fence, no call      1 block
turn 4  drifted, recovered        a bare object, then the answer      2 blocks
turn 5  no call                   prose                               1 block
```

**The shapes do not cost the same number of model calls, and that is what the
cycle has to absorb.** It does: the cycle is over *calls*, so five turns of
2/2/1/2/1 is eight blocks that come back into phase every five turns, and a
corpus with a multiple of five prompts stays aligned. Ten prompts, two clean
passes — and a test asserts exactly that, because a drifted phase would score
every turn against the wrong prompt and still look like a table.

`cargo test -p luu --test tool_call_probe`: four tests over one recorded run of
the real binary — the shapes, the recovered sub-count, the key separating *the
format held* from *the right thing was called*, and the phase. 2 parsed, 2
continued, 4 drifted (2 recovered), 2 no call, 2 hits, 2 wrong tool.

### Still open, unchanged

**The run.** Ten prompts against a 7B at temperature 0, on machine 1 or 4. The
harness is on disk and tested; what a model does with the fenced format is
exactly as unmeasured as it was this morning, and no amount of scoring code
changes that. The number this instrument exists to produce does not exist yet.
