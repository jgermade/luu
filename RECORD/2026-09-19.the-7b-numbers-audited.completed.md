## The question, and why it was worth an hour

On 2026-09-15 the 14B's registry-vs-local comparison turned out to have held
three things variable at once — the file, the backend **and** the tool schema —
because `82229cc` ("`run_command`'s argv: one array instead of command+args",
2026-09-15 11:38:17 +0200) landed between the two runs being compared. The
conclusion survived a re-run; the evidence under it had not been clean.

The bullet that came out of that reads: *this project's 7B tool-call-format
numbers may carry the same confound — every 7B run in this record predates or
postdates `82229cc` in some mix that was not audited here; only the 14B pair
was checked.* It has sat unaudited for four days, as the roadmap's own row 8:
*cheap, unglamorous, and the kind of thing that quietly invalidates a table six
weeks later.*

It is cheap. It took two scripts and no model.

## The instrument: no run records its binary, but every transcript records its schema

**No run directory in this repository writes down the commit it was made
with.** `README.md` names the model, the machine, the backend and the flags;
`stats.json` names the verdicts. The binary is nowhere, which is the reason the
14B confound was found by hand and the reason this bullet stayed open.

It does not have to be. `82229cc` changed the *shape the model is asked to
emit*, and every committed transcript is full of what the model emitted:

```
pre-argv    {"command":"cargo","args":["test","-p","agent-core"],"cwd":".","timeout_ms":30000}
post-argv   {"argv":["cargo","test","-p","agent-core"],"cwd":".","timeout_ms":30000}
```

So the schema generation is readable out of the evidence itself, for every run
ever committed, without trusting a date or a memory.
[`audit.sh`](runs/2026-09-19.schema-generation-audit/audit.sh) does it in
fifteen lines.

**Fifteen runs classify and every one is unanimous** — 100% one shape, no run
mixed. That unanimity is what makes the instrument sound: it reads what the
model wrote, not what the schema said, and a run whose model ignored the schema
on every call would be misread. None does.

## The blast radius is three prompts in fifteen

`82229cc` changed `run_command`'s schema and **no other tool's**. Three of the
fifteen prompts in
[`scripts/tasks/tool-call-probe.txt`](../scripts/tasks/tool-call-probe.txt)
call `run_command` — 4 (`cargo fmt`), 9 (`cargo test`), 14 (`cargo clippy`).

So the most the confound can reach is **3 of 15 verdicts in any tally on either
side of the line**, and the twelve `read_file` and `list_dir` prompts are
comparable across it unconditionally. That is a bound read off the schema
rather than off the runs. The next section is the runs agreeing with it.

## The 7B pair, which is not one flag apart, and what the 14B pair says about it

**Two of the three prompts the fix could reach moved, and both moved off
`NoCall`** — the model attempted a call where before it produced none, the same
direction the 14B's prompt 9 moved. Prompts 4 and 14 are precisely the two
[`what-constrain-does`](2026-09-14.what-constrain-does.completed.md) recorded as
*a `` ```tool `` fence around `run_command`'s flat argument object, missing the
`{"name", "arguments"}` wrapper*. Prompt 9, the third, was `Drifted` on both
sides.

**And three prompts moved that the fix cannot explain at all** — 12, 13 and 15

What this supports is a **rule about quoting**: a 7B tally from 2026-09-14 and

## What the audit does to the claims already recorded

**Clean, and now known to be clean.** The whole of
[`the-drift-was-never-the-backend`](2026-09-15.the-drift-was-never-the-backend.completed.md)'s
triangulation — local GGUF over `llama-server` (6/15), the identical file over
Ollama (6/15, byte-identical), the registry blob (3/15) — is three post-argv
runs on one day. The registry-vs-local direction that record establishes, and
that its own §Still open leaves unexplained, is **not confounded by the
schema**, which is one of the two things the fifteenth update wondered about and
the cheaper one to close.

That record's own cross-day sentence — the registry blob's 3/15 *"reproduced
almost exactly, on different hardware, a different Ollama version, and eleven
days later"*, with the per-prompt difference put down to *"different days,
different machines, both true"* — was one cause short. The schema is the third,
and the 14B pair says it is worth about one verdict.

**Clean internally, dated externally.**
[`what-constrain-does`](2026-09-14.what-constrain-does.completed.md)'s table —
`off` 3 Parsed, `--constrain grammar` 7, `--constrain schema` 0/15 answered — is
three arms of one pre-argv run, one flag apart, scored by one scorer. The
comparison is sound and nothing here touches it. The *absolute* numbers are on a
schema that shipped out the next morning, and 3 of their 15 verdicts sit on the
tool that changed.

**A recorded cost whose mechanism no longer exists.** That record's *one new
cost, worth naming plainly: forcing the shape does not mean forcing the
content* — the grammar-constrained model emitting `{"name": "run_command",
"arguments": {"command": "cargo", "cwd": ".", "timeout_ms": 30000}}` with the
`args` field carrying `["fmt", "--all", "--check"]` *simply gone* — rests on
`args` being **optional** and sorting before `command`.
[`grammar.rs`](../crates/agent-core/src/grammar.rs) spells an optional property
`( … )?` at its own sorted position, so skipping it was a branch the grammar
offered. Today
[`command.rs`](../crates/agent-core/src/tools/command.rs) declares
`"required": ["argv"]` and the program and its arguments are one array. **The
branch the model took is not in the grammar any more.**

Said carefully, because it is easy to overclaim: this does not refute the cost.
A model can still write `{"argv": ["cargo"]}` and drop the flags inside a
required array, and *shape forced, content not* would be just as true. What is
gone is the specific mechanism the record demonstrated, and **nothing has
re-measured the claim under the schema that ships**. It is one example, one
model, one seed, on a schema that no longer exists — which is a stronger version
of the caveat that record's own §Still open already wrote for it.

**Item 7 is pre-argv and half of it is fine.** *Drift under a tool's own name*
rests on prompts 2 (`` ```list_dir ``) and 9 (`` ```run_command ``) drifting
identically in the `off` and `grammar` arms. Prompt 2's tool was not touched by
the fix. Prompt 9's was — and the 7B pair above shows prompt 9 `Drifted` on both
sides of it, which is the one piece of post-argv evidence that the trigger
survived the schema change. The row stands; it is now two prompts with one of
them independently re-observed rather than two prompts on a retired schema.

## Found while doing it, and it was not the thing being looked for

**The `off` arm of [`2026-09-14.constrain`](runs/2026-09-14.constrain/README.md)
is identical to [`2026-09-14.tool-call-probe`](runs/2026-09-14.tool-call-probe/README.md)
prompt for prompt** — all fifteen verdicts, not merely the 3/2/2/8 tally. One is
the registry blob over Ollama; the other is the same blob served by a standalone
`llama-server` on port 8090. Same machine, same day, two engines, fifteen
identical verdicts.

That is an independent replication of the engine-invariance result
`the-drift-was-never-the-backend` §The triangulation established with its run 2
— and it covers the case run 2 did not. Run 2 imported the **local** GGUF into
Ollama with a bare `FROM`, so both sides read the GGUF's own embedded Jinja
template; the proof was *same weights, same template, two engines*. This pair is
the **registry** blob, where Ollama uses its own hand-authored Go template and
`llama-server` uses the GGUF's: *same weights, two templates, two engines,
fifteen identical verdicts*. The record's own argument for why the template
should not matter — this project never sends the API's native `tools` field, so
both templates' `{{if .Tools}}` branches are dead code on every call `luu` makes
— now has a run under it rather than only a reading of the code.

It was sitting in two files committed on the same day and nobody had put them
side by side. Two runs were made to answer the question this replicates.

## What it cost

Two committed scripts, two JSON files and this record. No model, no machine, no
GPU-hours. The audit is worth writing down mostly because of how little it cost
relative to how long its bullet sat open, which is the same lesson
`ROADMAP/2026-09-17` §What actually blocks what wrote about item 9: *a row
blocked on an argument is blocked on an afternoon, and the cost of leaving it
ordered is measured in the days it sits.*

The one real cost is a **precedent**: `audit.sh` and `pair.py` are committed
where the tool-call probe's own scorers were scratch. The argument for
committing them is that the instrument is the finding — re-running `audit.sh`
after the next run lands re-answers the question for that run, where a scratch
script would have to be re-derived first. The argument against is that this
repository now carries two more files that can rot. They are pinned to a
mechanical fact about text in `RECORD/runs/`, which is append-only, so the rot
has a floor.

## Still open

- **Nothing makes a run record its own binary**, and this audit is a workaround
  for that rather than a fix. `record::FORMAT` has a header with the model, the
  posture and now the three window rules; the commit that produced the binary is
  not on it, and every confound of this shape costs an audit to find. **It is a
  one-field change and this record does not take it** — a header field is a
  format bump and the argument for which identifier (a commit, a `git describe`,
  a dirty flag) belongs there is a decision somebody makes, not a line to add.
  Worth its own row.
- **What the argv schema was worth to the *7B* is still not measured.** The 14B
  pair measures the 14B. The run that would answer for the 7B is small and
  specific — prompts 4, 9 and 14 only, one machine, one engine, one file, two
  binaries — and it needs a model, so it is Section A work. Three prompts is the
  cheapest thing on that list by an order of magnitude.
- **`what-constrain-does`'s dropped-`args` cost has not been re-measured under
  the schema that ships**, and the record it belongs to is `completed`, so a
  re-measurement is a new file and not an edit to that one.
- **The 7B pair's registry-vs-local direction is still unexplained** — the
  fifteenth update's other bullet. This audit closes only the half that asked
  whether the schema was underneath it. It was not.
- **Eleven run directories commit no `run_command` call** and cannot be
  classified by this instrument. None is a 7B tool-call-format run and the fix
  touched no other tool's schema, so none of them can carry this confound; the
  gap is in the instrument, not in the answer.
- **Three of this project's `read_file`/`list_dir` verdicts moved between two
  machines at temperature 0 with a fixed seed**, which is a number about
  reproducibility that nothing here was looking for and nothing here explains.
  It is the same size as the effect the pair was built to see, and it is the
  reason the 14B pair carries this record rather than the 7B one.
