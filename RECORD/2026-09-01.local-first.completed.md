# Local-first, not local-only

**The change, in four words.** `built for local inference` becomes `built for
local-first inference`. Decided today, by the person whose project it is, on the
grounds that the tool should be pointed wherever its user wants to point it.

It is a small edit to one sentence in two files and it moves the ground the whole
design stands on, so it gets a record rather than a commit message.

## What the old sentence was doing

"Built for local inference" read as a **constraint**, and a constraint argues for
you. If 8K is all there is, then deciding what earns its place in the prompt is
not a feature, it is the only way the thing works at all. The differentiator was
justified by arithmetic and needed no defence.

"Local-first" is a **default**, and a default has to earn its keep every time
someone asks why they should accept it. That is the real cost of the change and
it should be stated before the benefits: the project just took away its own best
argument.

## What it buys, which is more than permission

The user's inventory as of today: six machines — an M1 Pro, an M4 mini, an M4 Pro
with 48 GB, a Ryzen with a 5060 Ti, an i5 with a 1660 Super, a BC-250 — plus
BytePlus ModelArk and a build.nvidia.com free tier. Under "local inference" the
last two are a category error and five of the six are unusable, because their
natural serving path is `llama-server` or a hosted endpoint rather than Ollama.
Under "local-first" they are all *the same item*: an OpenAI-compatible backend,
which is already #1 on the surface track and #4 on the engine track and is blocked
by nothing.

The sentence did not create that work. It stopped the work from contradicting the
premise.

## What "local-first" obligates

Permission is the easy half. The term has content, and if the design is going to
use it then it should say what it is promising:

1. **It works with nothing configured and nothing reachable.** A default install
   talks to a model on this machine, and an offline machine is a working machine.
2. **Remote is named, never a fallback.** Nothing silently reaches the network
   because the local model was slow, missing or busy. A fallback is how local-first
   becomes cloud-with-extra-steps, and it is rejected here explicitly so that it
   has to be argued rather than added.
3. **Nothing leaves the machine without the destination having been typed.** This
   repository's own probes send file paths and source excerpts; that is fine when
   a person chose where they go and is not fine as a default.
4. **Every measurement carries its backend or it is not a measurement.** Already
   true in practice — the record header names backend and model — and now load
   bearing rather than incidental.

## The awkward question, stated rather than dodged

If the user may point this at a 256 K hosted window, does context management still
matter?

The honest answer is that the *argument* changes shape and the *work* does not.
Before: you have no choice, so choose well. Now: a smaller, better-chosen context
should beat a larger, worse-chosen one — cheaper, faster, and no worse in the
answer. That is a claim, it can be false, and the project now has to demonstrate
it instead of inheriting it from the hardware.

Which is a better position to be in, and today already produced the first instance
of the demonstration. [`2026-09-01.the-map-against-a-7b.completed.md`](2026-09-01.the-map-against-a-7b.completed.md)
is exactly that shape of claim: 939 tokens of outline moved a 7B from 0/6 to 6/6
on questions about files it had not been shown, and left the placebo group flat. A
larger window would not have produced that; a better-chosen one did.

## The debt it creates, which is concrete

**The backend is per-session in the data model.** `SessionView.backend` is a
`String` set once from `Hello`
([`api.rs:190`](../crates/agent-core/src/api.rs#L190),
[`:252`](../crates/agent-core/src/api.rs#L252)), and `SessionSummary` carries the
same single value. Freedom to choose implies freedom to *switch*, and a session
that switched cannot be described by this shape: every per-turn number —
prompt tokens, prefix reuse, the counter behind the budget — is backend-specific,
so a session with two backends and one label produces mixed numbers under a name
that says they are comparable.

Three options, none of them chosen here:

| | what it costs |
| --- | --- |
| Backend per turn in the record | the honest one; a schema change, so a protocol version |
| A switch closes the session and opens a new one | free, and makes "switch model mid-task" impossible, which is half the point of the freedom |
| Forbid switching mid-session | free, honest, and a smaller promise than "complete freedom" |

Naming it today is cheaper than discovering it the first time someone switches and
the reuse graph goes sideways. It belongs to the session store
([`ROADMAP/2026-08-31/session-store.md`](../ROADMAP/2026-08-31/session-store.md)),
which is where the shape of a persisted session gets decided, and it should be
settled before that lands rather than after.

## What does not change

**The sandbox and the gate.** An approved plan is a statement about what runs on
this machine — which files, which programs — and where the tokens were sent is a
different permission that composes with it rather than replacing it. That makes
three permissions the design now has in play and has never described together:
the sandbox's, the authenticated user's (named as open in
[`ROADMAP/2026-08-31/surface.md`](../ROADMAP/2026-08-31/surface.md)), and the
backend's destination. The first two already needed a record. This adds the third
to the same one.

Note the asymmetry, because it is the interesting part: an approved plan can grant
a model the right to read a file, and sending that file's contents to a remote
backend is not something the plan said anything about. A gate that guards `writes`
and says nothing about egress is guarding the smaller half.

## Still open

- Whether `luu.toml` grows provider profiles. It is `[sandbox]` and nothing else
  today, and "the user chooses" is not a real freedom if the choice is four flags
  retyped per run.
- Whether the destination is part of what a plan declares, per the asymmetry above.
- Whether a hosted model may be the **judge** while a local one closes tasks. The
  design says the judge is "the same model"
  ([`loude-design.md:130`](../loude-design.md#L130)); the reason it gives is about
  the judge's *input* — evidence, not narrative — which does not settle its
  identity. Under local-first that sentence is worth re-reading, and it is a
  separate decision from this one.
