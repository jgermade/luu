# Styles that stay in their component, and a shared layer that says it is one

Asked, looking at the page: *can the components' styles be scoped? I think
there are style conflicts.*

There were. Nine of the ten components were already scoped; the tenth was
`app.html`, and because it was the shell that mounts all the others, its
unscoped `<style>` had quietly become the page's shared stylesheet. This file
argues the split that fixes it, and records the three collisions that were live
on the page while it was being written.

## The problem: one component was doing two jobs

jq79 supports `<style scoped>` and rewrites every selector in such a block to
also match `[data-jq79="…"]`, the attribute its compiler stamps on the elements
*that file's* template built. Every component in `crates/luu/ui/` used it:

```
app.html                GLOBAL   <-- 480 lines, every selector page-wide
content-viewer.html     scoped
folder-picker.html      scoped
inspector-debug.html    scoped
inspector-files.html    scoped
inspector-git.html      scoped
session-starter.html    (no styles)
settings-general.html   scoped
settings-modal.html     scoped
settings-models.html    scoped
```

`app.html`'s block held two different kinds of rule and could not tell them
apart:

- **The shell's own**, which is what the file is for: `.app`'s grid, `.col-head`
  and `.col-foot`, the tab strip, the chat's `.name`, `.transcript`, `.gate`,
  the `.history` popover.
- **Everything a second component also needed**: `input`, `button`,
  `button.link`, `pre`, `.dim`, `.warn`, `.error`. Nine components were relying
  on these without ever saying so, which is why the block could not simply be
  scoped — every dialog on the page would have lost its buttons in the same
  commit.

The first kind leaked into the second's DOM, and that is where the collisions
came from. A name like `.name`, `.row`, `.status`, `.history` or `.code` is the
obvious word for what it labels, so more than one component reached for it — as
each was entitled to, being scoped.

## The three that were live

Measured by snapshotting `getComputedStyle` for every element in fifteen states
of the page (each inspector tab, each content tab, each modal, both themes,
both layouts — 2372 elements) before and after the change, and diffing.

**1. The budget bar's `history` bucket was wearing the session-history
popover.** `inspector-debug.html` draws one `<span>` per bucket with the
bucket's own name as its class, and one of the buckets is called `history`.
`app.html` styles the chat's session list with `.history { position: absolute;
top: calc(var(--chrome-h) - 2px); right: .4rem; z-index: 20; min-width: 18rem;
border: 1px solid var(--line); border-radius: 8px; padding: .3rem;
max-height: 60vh; box-shadow: …; }`. The segment was therefore taken out of flow
and parked over the chat column:

```
span.history   position  absolute -> static
               top       38px     -> auto
               z-index   20       -> auto
               border    1px      -> 0
               width     11.59px  -> 123.13px
```

The other seven segments were being sized against a bar that was missing its
largest one — every bucket in the chart was the wrong width, in both the bar
and the legend, in every session with folded history in it.

**2. The git panel's and the picker's `.name` was wearing the chat's rename
box.** `app.html` has `.name, .name-edit { flex: 1; min-width: 0; … }` and
`.name { font-weight: 600; padding: .2rem .35rem; border-radius: 6px;
cursor: text; }` for the editable session title.
`inspector-git.html`, `inspector-files.html`, `folder-picker.html`,
`settings-modal.html`, `settings-models.html` and `content-viewer.html` all
label something `.name` too. Thirty elements picked up a text cursor, semibold
weight, `flex: 1` and padding they never asked for — and the `flex: 1` is why
`.where` beside it had nowhere to go:

```
span.name       flex-grow    1      -> 0
                font-weight  600    -> 400
                cursor       text   -> pointer
                padding      3.2px  -> 0
span.where.dim  margin-left  0px    -> 203.58px
```

**3. Two `.refused` rules were racing on load order.** `app.css` styles the
modal refusal (a bordered box, `--dim`, 12px); `app.html` styles the chat's gate
refusal (a `--warn` left bar over `--warn-bg`, 13px). Same specificity, so the
sheet injected later won — and the component sheet is always injected after the
`<link>` in `<head>`. The session starter's refusal had been wearing the gate's
colours since the day the second rule was written.

## The change

**Everything a second component needs moved to `app.css`, and `app.html` became
scoped like its nine neighbours.** The moved layer is the controls (`input`,
`button`, `button.cancel`, `button.link`, `pre`) and the three words that carry
a volume (`.dim`/`.empty`, `.warn`, `.error`). `app.css` was already the page's
shared layer — the palette, the `dvh` height, `.ic`, the modal chrome, the
`.hl-*` captures — and each of those already carried a comment saying why it is
global. The new arrivals got the same treatment, so *why is this not in a
component* is answerable at the rule rather than by archaeology.

Nothing was rewritten on the way: the rules moved verbatim, and the snapshot
diff is the evidence. Every difference between the two runs is a leak
disappearing.

## Two things the move broke, and what they taught

**Scoping raises specificity, and `:disabled` was below the line.** jq79 rewrites
`.clip { cursor: pointer }` to `.clip[data-jq79="…"]`, which is two classes.
`button:disabled` is one element and one pseudo-class, so it lost — a disabled
button offered a pointer, and `.choice button` beat it for the same reason from
inside `app.css`. Disabled is a **state**, and a state has to outrank whatever
skinned the control it is on, so it is written as `button[disabled][disabled]`:
the attribute twice, which selects exactly what `:disabled` does and buys back
the two levels. This is the general shape of the hazard, not a one-off — any
element-plus-pseudo-class rule in the shared layer is below every scoped rule on
the page.

**A class that cannot be scoped needs a name that says so.** The file viewer's
rows are built by `rows.js` rather than by the compiler (93% of the viewer's
cost is building them — see
[`RECORD/2026-09-16.the-viewer-in-plain-js.completed.md`](2026-09-16.the-viewer-in-plain-js.completed.md)),
so they carry no `data-jq79` and their rules are global *by necessity*. They
were called `.code`. The git panel spells a two-letter status
`<span class="code">` and the budget bar spells its code bucket the same way,
and both were being handed a file's list box — `list-style: none`,
`counter-reset: line`, and `.5rem` of padding above and below a span two
characters wide. Renamed `.code-rows`, which is the id the element already had.

Scoping fixes a collision between two components. It cannot fix a collision
between a component and a rule that is global on purpose; only the name can.
That is the rule this change leaves behind: **a global class is named as though
the whole page could reach for it, because it can.**

## What it cost

`app.css` grew by the moved layer and its comments; `app.html` lost 60 lines and
gained the `scoped` attribute and the note saying what it is now for. No JS
changed. `tests/smoke/gate.spec.js` moved six locators from `.content .code li`
to `.content .code-rows li`; the seventh, `.inspector .changes .code`, is the git
panel's own class and stays.

## Rejected

**Shadow DOM per component.** It is the airtight version of this and it would
have taken the palette with it: `var(--accent)` crosses a shadow boundary but
`.ic`, `.hl-*` and the modal chrome do not, so every shared rule would need
`adoptedStyleSheets` plumbing that jq79 does not offer. The attribute rewrite
already gives the isolation the collisions needed.

**Prefixing every class per component** (`.git-name`, `.picker-name`). It is
what scoping does, done by hand and visible in the markup, and it would have to
be maintained by discipline in every new component. `scoped` is one word.

**Leaving `app.html` global and renaming the six colliding classes.** It treats
the symptom and keeps the cause: the next component to want a `.row` collides
again, and the shell keeps its accidental authority over the whole page.

## Still open

- **`session-starter.html` has no `<style>` at all.** It is legible now only
  because everything it uses is genuinely in the shared layer. That is true
  today by accident rather than by decision, and the first rule it needs of its
  own will need a `<style scoped>` block to go in.

- **`.small` is written twice**, identically, in `app.css` and in
  `content-viewer.html`'s scoped block. Harmless and redundant. Left alone: the
  scoped copy costs nothing and removing it is not this change.

- **The snapshot harness is not in the tree.** The before/after diff that proves
  this change was driven from `.tmp/`, against the page served from
  `crates/luu/ui/` with the store filled by hand, because the assembled static
  twin needs `cargo build --release` and a run of the agent. A committed version
  of it would be the thing that catches the *next* leak, and it is not written.
