# The panel keeps the turn

**Status:** a proposal, and the code it plans.

Item 3 of the reordered [`ROADMAP/2026-09-08`](../ROADMAP/2026-09-08/README.md),
asked for as *un panel de desarrollo para revisar la actividad* and argued in
[`the-surfaces-first`](2026-09-08.the-surfaces-first.completed.md).

## The problem

The inspector draws four things — the token budget, prefix reuse, the tool calls
with their verdict and who enforced them, and the exact prompt — and **resets all
four when the next turn starts**:

```js
case "turn_started": {
  …
  state.tools = []
  state.extraCalls = []
```

So a person can read what the model was sent only *while it is being sent*. Turn
3 is unreachable from a page watching turn 9, and turn 1 of a session resumed
this morning never existed as far as the page is concerned. That is not a
debugging surface; it is a live meter.

**It is also the cheapest thing on the roadmap, and the reason is worth writing
down.** Every number the live panel draws is already stored per turn and already
served: `GET /api/sessions/:id/turns/:n` answers with `prompt_sent`, `budget`,
`prefix`, `extra_calls`, `tools`, `dropped`, `pruned_by`, `cited` and both
timestamps, and `GET /api/sessions/live` — which the page *already fetches* on
every connect, to build the transcript — carries all of it for every turn. The
page read `prompt`, `text` and `usage` off each one and dropped the rest on the
floor.

## The proposal

**One shape, and history is a list of it.**

```js
{ turn, job, budget, prefix, tools, extraCalls, prompt, dropped, usage, reason }
```

- `state.history` holds one per turn, oldest first. It is filled from the API
  when a session is opened, switched or resumed — so a turn from before this page
  existed is in it — and appended to as each live turn ends (`keepTurn`), which is
  what makes a reload optional rather than required.
- `state.selectedTurn` is `null` for the live turn or a turn number.
- `panel()` returns the selected entry, or the live one **assembled out of the
  same fields the socket already fills**. The live turn is not a special case
  with its own bindings: that is the whole of why the panel can show turn 3, and
  the reason this is a small diff rather than a second inspector.
- The picker sits at the top of the inspector, and a turn that is being *read*
  says so once, at the top, rather than by every number in it looking current.

**Selecting a turn does not follow the conversation.** A person reading turn 3
while turn 9 runs keeps reading turn 3 — the view moves when they move it, and
"back to live" is one click. A panel that yanked itself to the newest turn would
be unusable for the thing it exists for.

## What it costs

- **The panel's bindings all move** from `state.budget` to `view.budget` and so
  on. Mechanical, and it is the diff: nothing else in the page changes.
- **`keepTurn` snapshots what the store holds**, so it is only as complete as the
  live stream was. A turn watched from the beginning and the same turn read back
  from the API are the same six fields; a turn the page joined halfway is not, and
  a reload fixes it because the server has the whole of it.
- **The history is unbounded.** A thousand-turn session keeps a thousand entries
  of a few hundred bytes each, and the transcript beside it already keeps every
  message. If it ever matters, the API pages (`?from=&limit=`) and the store does
  not — but paging a list nobody has complained about is the kind of work that
  looks like progress.

## What was rejected

- **Fetching each turn as it is selected.** One request per click, a spinner in a
  panel that is supposed to be instant, and a second code path for the live turn,
  which has no stored entry until it ends. The data already arrives in the
  request the page makes anyway.
- **Snapshotting the panel into the transcript entries.** The transcript is
  messages and the panel is turns, and a turn is two messages plus tool steps. A
  turn that produced no message would have had nowhere to live.
- **Keeping the reset and adding a second "history" pane.** Two inspectors that
  drift, and the live one keeps its special case forever.

## Still open

- **The compaction log** is item 4 and is not this: when a summary was written,
  what it replaced, what it saved. The fold is already an event and the summary
  is already in the stream, so it is the same kind of work as this was.
- **A prompt diff between two turns.** The panel can now show turn 3 and turn 4;
  it cannot show what changed between them, and `similar` on the server is the
  right tool for it (`luu-design.md` §Debug panels).
- **The trace channel has no consumer.** `/ws/trace` carries the agent's own
  lines — including the `pruned` ones rule B added — and nothing in the page reads
  them. An activity feed is the obvious home for it.
- **Nothing selects a turn from the transcript.** The picker is in the panel, and
  clicking a message to point the panel at its turn is the gesture a person will
  reach for first.
