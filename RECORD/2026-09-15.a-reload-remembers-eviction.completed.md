# A reload remembers eviction

**Status:** a proposal, and the code it plans, both here — small enough to
argue and build the same sitting. Found and deferred in
[`the-panel-reads-pruned`](2026-09-15.the-panel-reads-pruned.completed.md#still-open)
§Still open, while checking whether pruned messages should be marked the way
evicted ones are.

## The problem

The live `evicted` *protocol* case in `crates/luu/ui/store.js` marks messages
as it processes the event: `state.messages.map(m => gone.has(m.turn) ? {
...m, evicted: message.turn } : m)`. `refreshLiveSession` — the loader used
both for the live session on connect and for switching to or resuming a
stored one — builds the same messages from `GET /api/sessions/live`'s
`turns[]`, which already carries `evicted_by` per turn
(`TurnView::evicted_by` in `crates/agent-core/src/api.rs`, set the same way
`cited`/`pruned_by` are). It hardcoded `evicted: null` on both pushes instead
of reading it. A session watched live and evicted shows the strikethrough and
"· out of the window since turn N"; the same session reloaded shows neither —
the store had the fact and the page never asked for it.

## The proposal

Read it: `evicted: t.evicted_by ?? null` on both the user and assistant push
inside `refreshLiveSession`'s turn loop, in place of the hardcoded `null`.
`evicted_by` already *is* the turn whose selection dropped this one — the
same value the live case assigns — so no transform is needed, unlike
`dropped`/`cited` on the panel side, which gain the turn that made the cut
because the stored value only names what was taken.

## What it costs

Two words changed. `app.html` already renders `entry.message.evicted`
correctly — it was reading a field that was always `null` on load.

## Driven, not just tested

The real `refreshLiveSession()`, imported into Node with `fetch` stubbed to
return a two-turn `turns[]` shaped like the actual API (`evicted_by: 5` on
turn 1, `null` on turn 2): both of turn 1's messages come back `evicted: 5`
and both of turn 2's come back `evicted: null`. The stub matches the real
response shape rather than re-implementing the loader, so this exercises the
same code path a browser does.

## Still open

Nothing found while making this fix. The wider question it sits beside —
whether `cited`/`pruned_by` want the same per-message marking, rejected in
`the-panel-reads-pruned` as a second row — is still just that: a separate row,
not started here.
