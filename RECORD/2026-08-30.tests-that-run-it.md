# Tests that run the thing: a stub backend, a socket, and a page

**Status:** proposal, and the first code for the oldest open item in this
directory — *nothing in CI exercises the server or the page*, first written the
day PR #1 merged and repeated unchanged in
[`2026-08-30.state-of-play.md`](2026-08-30.state-of-play.md) and
[`2026-08-30.ready-for-the-m4-run.md`](2026-08-30.ready-for-the-m4-run.md).
Written after the fold-quote fix was verified on the M4, which is why the next
step is this rather than another measurement: what is left to measure now needs
the machine, and this does not.

## The problem, stated precisely

140 tests pass. Not one of them binds a socket, speaks HTTP, or opens the page.
Every bug this repository has had was found by running it — the four in the
walking-skeleton session, the tool call invisible to `prefix_reuse`, and
`num_ctx`, which silently invalidated every run against a real model.

`num_ctx` is the sharp case, because it is the one that *looks* covered. There
are five tests in `ollama.rs` about it today, and all five assert that a
`ChatRequest` value **serializes** the way we mean:

```rust
let body = serde_json::to_value(ChatRequest { … options: Some(Options { num_ctx: Some(8192), .. }) });
assert_eq!(body["options"]["num_ctx"], 8192);
```

The value under test is one the test constructed. Nothing asserts that
`Ollama::stream` builds that value from the `CompletionRequest` it was handed.
A regression that passes `options: None` there — which is exactly the bug that
existed until PR #6 — passes all five. The test that would have failed is the
one that reads the bytes off a socket.

## The proposal: three tests, cheapest first

### 1. The stub backend, asserting the request body

`crates/agent-core/tests/ollama_wire.rs`. A `tokio::net::TcpListener` on
127.0.0.1:0 speaking enough HTTP/1.1 to read a request with a `Content-Length`
body and write one NDJSON response. `Ollama::new(format!("http://{addr}"))`,
one `CompletionRequest` through `stream()`, then assertions on **what arrived**:
`model`, `messages`, `stream: true`, and `options.num_ctx` / `temperature` /
`seed`. Plus the negative: a request with no window and no sampling puts no
`options` key on the wire at all. And, because the response half is free once
the server exists, that the NDJSON comes back as `Text` chunks and a `Done`
carrying the usage.

No new dependency: the crate already has `tokio` and `reqwest`, and the stub is
about sixty lines because it never has to be a general HTTP server — it serves
exactly one request and knows what it will be.

### 2. The socket, asserting the message sequence

`crates/luu/tests/serve_ws.rs`. Bind an ephemeral port, connect to `/ws`, and
drive the gate end to end against the mock backend: `hello`, `prompt`,
`task_proposed`, `approve_task`, `task_approved`, `turn_started`, `token`…,
`ended`. Then read `/api/sessions`, `/api/sessions/live/turns` and
`.../turns/{n}/prompt` and assert they say the same thing the socket did —
which is the one property the read side has that nothing checks: it is folded
from the same events, so it *cannot* disagree, and no test has ever asked it.

This needs one change to `serve.rs`: `serve()` binds and then serves, so a test
cannot learn which port it got. Split it into `bind(options) -> Serving` with
`Serving::address()` and `Serving::run()`, and let `serve()` be the two of them
plus the line it prints. A test that binds a *fixed* port is a test that fails
whenever two jobs share a runner.

Cost: one dev-dependency on `tokio-tungstenite` for `luu`.

### 3. The page, failing on any console error

A Playwright smoke test over the `site/` directory CI already assembles — load
it, wait for the transcript to render from the exported fixtures, fail on any
console error or page error. It is separate from the two above because it is the
only one that wants node: `cargo build` must not require node, and this does not
change that — it runs in the `web` job, after the site is assembled, and never
in `cargo test`.

## What this costs

One dev-dependency, a fifteen-line refactor of `serve()`, and node in one CI job
that already exists. Test runtime is under a second for the two Rust tests: the
mock backend runs with a zero delay and the stub server answers immediately.

## What was rejected

- **Spawning `luu serve` as a subprocess and scraping the port from stdout.**
  It makes the test depend on a build profile's output path and on the exact
  text of a `println!`, and it can assert nothing about the server's own state
  when something goes wrong — a hung turn reads as a timeout with no evidence.
- **Hand-rolling a WebSocket client to avoid the dependency.** Masking and
  framing by hand is a hundred lines of protocol that exists only in this
  repository, and every bug in it would look like a bug in the server.
- **Asserting the request body by mocking `reqwest`.** The bug being guarded
  against is in the layer that builds the request; a fake that intercepts above
  it re-tests the same value the current tests already construct.
- **A fourth test that runs against a real Ollama in CI.** There is no model on
  a CI runner and there should not be. The stub is the part that can be checked
  everywhere; the real backend is what the M4 is for.

## What is still open after this

The three tests close the *class* of bug, not the class of question. They say
nothing about whether a context strategy works — that is still the grounded
pair against a real model, and still the M4's. And the reuse figure the server
reports is asserted here only for shape: that it is present and consistent
between the socket and the read side, not that it is right, because what "right"
means is a property of the model's tokenizer and not of our arithmetic.
