# A session picks its executor

**Status:** a proposal. `WIP` until the code it plans exists.

The other half of item 5 of the reordered
[`ROADMAP/2026-09-08`](../ROADMAP/2026-09-08/README.md). The Linux half closed
the same day — [`the-container-on-a-runner`](2026-09-08.the-container-on-a-runner.completed.md) —
and left this one, which the roadmap has been describing loosely enough that the
first job here is to say what is actually true.

## What is true today

**1. There is one live session per `serve`, not several.** Sessions are
*switched*, not run concurrently:
[`multi-session-in-serve`](2026-09-04.multi-session-in-serve.completed.md)
rejected per-socket virtual sessions precisely because "`Agency` / `Sandbox` and
worker container processes are currently single-tenant per session lifecycle".
So the sentence this record's own predecessor used — *every session shares that
worker* — is the wrong way round. There is only ever one session to share with.

**What is actually wrong is the lifetime.** The design says:

> The container's only process is the worker… So the container's lifetime *is*
> the worker's: no name to allocate, no `docker rm` to forget, and no way to
> leave one running after the session that owned it died.

In `serve` the worker is started **at boot**, from the policy file the process
was pointed at, and lives until the process exits. It outlives every session it
serves. That claim is kept by `luu chat`, where the process *is* the run, and it
is not kept by the surface a person actually uses.

**2. The `Agency` never moves.** `App` resolves tools, sandbox, limits and worker
once at startup. `create_session` swaps the **destination**, resets the stream and
writes a new header; it does not touch the agency. So a session can choose where
it sends and cannot choose where its tools run.

**3. The page can see it and cannot choose it.** The configuration modal renders
the resolved sandbox, worker line included. That is exactly where the provider
was before [`the-first-run-has-no-provider`](2026-09-07.the-first-run-has-no-provider.completed.md).

## The unit is the posture, not the runtime

`--sandbox luu.container.toml` does not choose an executor. It chooses
`commands`, `network`, `enforcement`, `limits`, **and** `[worker]` — runtime,
image, the toolchain paths that only resolve on the far side. They are one file
because they are one decision:
[`the-container-decided`](2026-09-01.the-container-decided.completed.md) put the
loosening and the seam in the same posture on purpose.

So "a session picks its executor" is a mis-statement of the thing worth building.
**A session picks its posture**, and the honest unit to name is the policy file:

```toml
[posture.host]
policy = "luu.toml"

[posture.container]
policy = "luu.container.toml"
```

in the state directory's `config.toml`, beside `[provider.<name>]` and for the
same reason. A session names a posture; the server resolves the file. **The
browser never types a path**, exactly as it never types a URL: what may be chosen
is bounded by what somebody wrote on this machine, and a name the file does not
carry is refused by name — the rule
[`configuring-from-the-browser`](2026-09-07.configuring-from-the-browser.completed.md)
established so that the rule has one implementation and the page never classifies
anything.

## The stream header has to say which one

`luu.container.toml` opens by saying it:

> **Probes run under this file are not comparable with probes run without it.**

That is the same sentence `context_limit`, `counter` and `eviction` are in
`RecordLine::Header` for — *two runs under different policies are not comparable,
and by the time anyone is comparing them nobody remembers which was which*. A
posture that a session chooses and the recording does not name is a corpus nobody
can read back, and this repository's entire measurement discipline is "one flag
apart".

So the header gains it, at **format 10**:

```rust
posture: Option<Posture>   // { name, runtime, enforcement, network }
```

Not a bare name. A name is a label, and the file behind it can be edited
tomorrow; `counter` is in the header as an id and not as "the counter I thought
was good", for the same reason. Four fields are enough to tell two recordings
apart without copying the policy into every stream.

## Lifetime: the container dies with the session

**Started at the first tool call of a session, killed when that session is
switched away, closed, or the process ends.** Not at the socket, because a
session that only ever asks questions should not pay for a container, and not at
boot, because that is what makes the design's claim false today.

This is cheaper than it looks, and the reason is a property the seam already
paid for: **a worker holds no state between calls.** That is what made killing a
wedged one and starting another sound
([`a-clock-at-the-seam`](2026-09-05.a-clock-at-the-seam.completed.md)), and it is
what makes a per-session lifetime introduce no new invariant. The machinery
exists too — `Executor::abandon`, the replacement path, the restart counter
`luu tools` prints.

## A posture is chosen when a session starts, and is not moved

The provider *can* move: `resume {provider, model}` carries a history to another
model and writes a second header
([`a-second-header`](2026-09-07.a-second-header.completed.md)). A posture must
not, and the difference is worth stating plainly: **a destination is where a
session sends; a posture is what it is allowed to do.** A job's sandbox is
narrowed from the session's, and an approval was given against a set of commands
and paths — moving the posture underneath a live job would widen or narrow a
grant a person already answered for, without them being asked again. The gate
exists to stop exactly that.

So: chosen at `POST /api/sessions`, refused on `resume`, and refused while a job
is open.

## What it costs

- **`Agency` behind an `RwLock<Arc<…>>`**, resolved where the destination is
  resolved, in the same handler, under the same "resolved before anything is
  reset" rule.
- **A container start on the first tool call** of a session that has one. Nobody
  has measured that number — the runner job is where it should come from, and
  [`the-container-on-a-runner`](2026-09-08.the-container-on-a-runner.completed.md)
  §Still open already asks for it.
- **Format 10**, and the two version constants moving together — free now that
  `crates/luu/tests/ui_versions.rs` exists, and the reason it exists.
- **A second list in the modal**, and first-run copy that says what a posture is
  without teaching sandbox theory. The provider table is the shape to copy.
- **`serve --sandbox` changes meaning**: from *the process's answer* to *the
  default for sessions that name no posture*. An old flag with a new meaning is
  the kind of thing that needs a line in `AGENTS.md` rather than a footnote.

## What was rejected

- **The browser naming a runtime and an image.** Unbounded, and the same mistake
  as letting it name a URL instead of a profile. A posture is a name in a file on
  this machine or it is not offered.
- **A container per job.** The design already rejected a start per command, and a
  job is nearer a command than a session.
- **Leaving the worker for the process's life and only *showing* it in the page.**
  That is today. It leaves the design's own claim about lifetimes false, and it
  makes "try it in the container" mean "restart the server with a flag".
- **Concurrent sessions in one process.** Still out of scope, and this proposal
  does not close the door on it: a per-session `Agency` is the first half of what
  concurrency would need, which is an argument for doing it this way rather than
  a reason to do it now.

## Still open

- **A session resumed under a different posture.** The store keeps jobs and their
  approved plans; it does not keep the posture they were approved under. After
  this, the *header* says which one a stream ran under, and nothing refuses a
  resume that changes it. The honest first step is that the header makes the
  mismatch visible; refusing it is a second decision and probably the right one.
- **Nothing measures what a container start costs**, so "on the first tool call"
  is chosen on the shape of the thing rather than on a number.
- **`luu chat` is unaffected** and keeps `--sandbox` as a flag: a one-shot has no
  session to hang a posture on, which is the same reason it has no gate.
- **Concurrency**, above, and with it the question of whether two sessions in one
  process may hold two containers at once.
