# Every dialog a sheet on a phone

**Status:** completed. It was decided and built the same day.

> Si, pásalas todas a hoja en móvil

This follows [`settings-as-a-sheet-on-a-phone`](2026-11-08.settings-as-a-sheet-on-a-phone.completed.md),
which made Settings a sheet and left the other dialogs as an open question.

## What there was

The page has three kinds of top-level dialog, and Settings used only the
first:

| Component | Used by |
| --- | --- |
| `components/modal.html` | Settings, the project picker, the diff, a turn's context, a snippet's preview, a host's form |
| `theme/default/components/modal.html` | the runtime dialog, and the theme's demo |
| `theme/default/components/tab-modal.html` | the sessions dialog and the permissions dialog |

Children (`SubModal`, and a `Modal` opened inside another) come out of
their parent's head. On a phone, that parent is now a sheet, so they are
left as they are.

## What was built

**Each of the three decides it by itself.** A dialog is a sheet when the
screen is a phone (`(max-width: 760px), (pointer: coarse) and (max-height:
760px)`, the same rule as `lib/phone.js` and the page's slides). Nothing at a
call site changes, and Settings no longer passes `:sheet`. On the page's
`Modal`, `sheet` is now `auto` by default, and `true` or `false` still say
it outright.

**One copy for the theme, one for `components/`.** The theme's rule and its
pull live in `theme/default/components/sheet.js`, which both theme dialogs
import (the theme imports only its own). `components/modal.html` keeps its
own copy of the same few lines, because nothing in `components/` imports
from outside it. Two copies of 40 lines was the price of keeping both
boundaries.

**A sheet is held by its bottom edge only (`inset: auto 0 0`).** A modal
`<dialog>` has both its top and bottom set to 0, and with both set an auto
height fills the window. The first project picker came out the full height,
with its content ending halfway down and white below it. Now a sheet is as
tall as what it holds, up to 2.5rem short of the top. Settings, a folio, is
that tall on purpose.

**Rules carried over:**

- A locked dialog, or one that cannot be dismissed, springs back from any
  pull: the first visit's folder picker, and "No way back" in the demo.
- A tab is not a handle: a finger on one chooses it.
- The theme dialogs' last part takes the bottom safe-area inset, so a foot's
  buttons clear a home indicator.

## A bug found on the way

`setPointerCapture` throws for a pointer the browser no longer tracks, and
the theme's pull called it before doing anything else. When it threw, the
handler stopped there and the gesture became a text selection. In the test
that was a synthetic pointer, but the same throw is possible on a real device
whenever a capture races the pointer's end. The capture is now in a `try` in
both copies. A drag that stays on the head does not need it.

## Checked

- **`gate.spec.js`, *dialogs on a phone* (390×844, touch):**
  - the first visit's project picker, the sessions dialog (`TabModal`) and a
    turn's context are each x 0, 390 wide, and end at 844;
  - pulling the head of the sessions dialog closes it, and pulling the
    context's closes it too.
- ***Settings on a phone*** waits on the sheet reaching the bottom edge
  instead of sleeping for 500 ms. That sleep failed it once in a full
  parallel run.
- **By eye, at 390×844:** the project picker, sessions, context,
  permissions, and the theme demo's small and large modals.
- **The live smoke suite**: 81 passed. The one failure, *the tab shows a
  changed file's diff in a modal*, fails the same way on `v0.1.13`.

## Still open

- **The runtime dialog** (the theme's `Modal`, `align="top"`) was not opened
  on a phone. It needs a terminal panel and a runtime. The CSS puts the sheet
  after `.top`, so the sheet's edge wins.
- **The diff and the snippet preview** are wide content in a 390px sheet.
  They scroll sideways inside it, and nothing more was done for them.
- **Not tried on a device**, the same as the two records before this one.
