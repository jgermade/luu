# The size sweep: does the map's 0/6 → 6/6 survive at 14b and 32b?

**Status:** run, on the machine [`machines.md`](../ROADMAP/2026-09-01/machines.md) named for
exactly this — a MacBook M4 Pro, 48 GB. That file's phase-one, item 1: *"Does the
map's 0/6 → 6/6 survive at 14b and 32b? Same quantisation, same sampler, same
corpus — the only local machine where the size sweep is one variable."* This is
that run.

## The question, restated

[`the-map-against-a-7b`](2026-09-01.the-map-against-a-7b.completed.md) found `--map-tokens 1024`
takes a 7B from naming zero of six group-A files to all six, with the placebo
group flat. A result on one model size is not yet a result about the map; it
might be a result about how small `qwen2.5-coder:7b` is. `map-probe.txt`, same
sampling, same command, model swapped for `:14b` and `:32b`.

```sh
for model in qwen2.5-coder:14b qwen2.5-coder:32b; do
  for m in 0 1024; do
    target/release/luu chat --script scripts/tasks/map-probe.txt \
      --backend ollama --model $model \
      --context-limit 8192 --reserve 512 \
      --tokenizer ~/models/qwen2.5-coder-7b/tokenizer.json \
      --temperature 0 --seed 7 --map-tokens $m \
      --sandbox luu.toml --record map-probe-$model-$m.jsonl
  done
done
```

`qwen2.5-coder:14b` was not pulled before this ran (9.0 GB, Q4); `:7b` and `:32b`
already were. The 7b halves are not rerun — sampling is pinned and the script is
unchanged, so the numbers in
[`the-map-against-a-7b`](2026-09-01.the-map-against-a-7b.completed.md) stand as this
sweep's third column.

## The headline result: it survives, and better than expected

| size | budget | group A (of 6) | group B (of 6) | group C declines (of 3) |
| --- | ---: | ---: | ---: | ---: |
| 7b | 0 | 0 | 0 | 0 |
| 7b | 1024 | **6** | 1† | 0 |
| 14b | 0 | 0‡ | 0‡ | 0‡ |
| 14b | 1024 | **6** | 0 | 0 |
| 32b | 0 | 3 | 0 | 0§ |
| 32b | 1024 | **6** | 4 | 2 |

† not genuine — the same naming-pattern hit
[`the-map-against-a-7b`](2026-09-01.the-map-against-a-7b.completed.md) already discounted.
‡ not a failure to answer correctly — a failure to answer at all; see below.
§ two of three are fabricated, cross-language boilerplate; see below.

**The 0/6 → 6/6 is not a 7b artifact.** Every size gets every group-A question
right at `--map-tokens 1024`, several down to the exact line
(`Backend` at `backend/mod.rs:133`, `AgentOutcome` at `agent.rs:36`,
`SessionView::from_record` at `api.rs:479` — all three checked against the tree
directly). That is the row [`machines.md`](../ROADMAP/2026-09-01/machines.md) asked
for, and it closes clean.

What no one asked for, and what turned out to be the more interesting result, is
that **the three sizes fail the *rest* of the corpus in three completely different
ways** — and one of those ways is a finding about this project's own open
questions, found by accident.

## 7b: fabricates from training, never touches a tool

Already on record. Confident, structurally plausible, wrong paths
(`src/backend.rs`, `src/landlock.rs`) for every question the map does not cover.
Zero tool calls in either run — a 7B free-associates rather than checks.

## 14b: reaches for the one tool this machine cannot give it

At `--map-tokens 0`, **every one of the fifteen questions ends with no file named
at all** — not a wrong guess, an absence. The model's first instinct is
`run_command` (`grep`, `find`, `ls -R`, `cargo search`), and every attempt is
refused, most of them with the same line:

> `denied · the kernel cannot hold this child (landlock and seccomp are Linux-only,
> and this is macos); grant it anyway with enforcement = "best-effort"`

Eight attempts, eight refusals, `[tool limit reached]`, no answer — for the first
two questions. The model then learns the pattern and stops calling tools, but
also stops answering: the remaining thirteen close with instructions telling the
*person* how to grep the codebase themselves, never a path.

This is the exact wall
[`the-container-decided`](2026-09-01.the-container-decided.WIP.md) named and
[`the-gate-probe`](2026-08-31.the-gate-probe.WIP.md) has been waiting to observe with a
model in the loop — `run_command` refusing categorically on macOS,
`sandbox-enforcement = kernel` doing exactly what it is specified to do. Nothing
here was arranged to demonstrate it; a 14B asked a locating question reached for
the tool on its own, and the sandbox answered honestly. The gate probe's own
prediction — *declaration rate low → grammar or function calling moves up the
list* — did not anticipate the model choosing to search instead of to answer, and
this is a second, cheaper way the same wall shows up before the probe itself ever
runs.

At `--map-tokens 1024` the wall never appears: **zero tool calls, zero evictions,
all fifteen answered in one short paragraph each.** The map does not just supply
group A's answers, it removes the *reason* to reach for a tool that cannot work
here — the plainest version of the map's case this sweep produced.

## 32b: the only size that can actually check its own answer, when the map lets it

32B's tool calls are `read_file` and `list_dir`, not `run_command` — in-process,
so the macOS wall does not apply to them. That makes 32B the only model in this
sweep that can *verify* rather than guess, and the map decides whether that
verification finds anything.

**With the map (1024 tokens):** group A answered directly, as the smaller models
did. For group B — files the map does not contain — 32B used the map's own
directory names as a starting point and **found four of six by actually reading
them**: `crates/luu/src/lib.rs` for the CLI's subcommands (confirmed via `clap`'s
`Cli`/`Command` definitions, read after tracing `loude.rs` → `luu.rs` → `lib.rs`
by hand), `crates/luu/src/export.rs`, `crates/agent-core/src/context.rs`, and
`crates/agent-core/src/sandbox/linux.rs` — all four read and quoted from real
lines. The two it missed (the HTTP router, the shared-prompt file) ran out of
budget still inside `crates/agent-core/`, having never gone looking in
`crates/luu/` for them despite having just found it for the CLI question.

Group C is where this size's honesty shows. Asked for the judge and the MCP
client — neither exists — 32B answered, in both cases, that the map does not
contain such a file and said so **without inventing one**:

> "The provided repository map does not include a file specifically named or
> described as defining a 'judge'... it might be in one of the files not shown."

Two genuine declines, the only ones this entire sweep produced (7b and 14b:
zero, every size, every budget).

**Without the map (0 tokens):** the same model, same size, same tools, collapses.
Group A drops to 3/6 — not because the questions got harder, but because 32B
now has to *find* `crates/agent-core/src/`'s contents by trial and error, and
spends read attempts on files that do not exist (`context_manager.rs`,
`backend.rs`, `session_manager.py` — the last one not even the right language).
Group B is 0/6. And once several turns evict — five real evictions in this run,
the most of any run in the sweep — **the model loses the repository entirely**
and starts answering as a generic assistant with no project in front of it:

> "The context window size and what gets dropped when it's full are managed by
> the system that handles the conversation... such as OpenAI's API settings."

Asked for the Landlock ruleset, it writes C. Asked for the SQLite store, it
writes Node.js (`module.exports = sessionStore`). Asked for the MCP client, more
Node.js. This is a new failure mode, not a bigger version of 7b's: 7b invents a
*plausible Rust file in this repository*; ungrounded 32B, post-eviction,
forgets **which repository, and which language**, it is even being asked about.

## Unplanned, and the one finding worth flagging above the others

During `32b`'s `--map-tokens 0` run, asked *"which file defines `AgentOutcome`?"* —
a locating question, nothing in the corpus ever asks for a change — the model
proposed **and executed** an `edit_file` call adding an unwanted field to the real
`AgentOutcome` struct in `crates/agent-core/src/agent.rs`, unprompted, mid-answer.
A second, similar edit against `backend/mock.rs` was drafted in the same turn but
only ever shown as prose, never sent as a tool call — this repository's actual
source carries one unwanted write from this sweep, not two, and it was reverted
(`git checkout`) before anything else here was written down.

Nothing about this required the container, the gate, or a plan: `luu chat` is
**ungated by design** — `luu.toml`'s policy grants write access to the crate tree
for local development, and a CLI session runs a proposed tool call the instant the
model emits it, with no approval step for anyone to catch that the question never
asked for a write at all. This is the gate's own justification, restated by an
accident rather than an argument: `the-gate-probe`'s protocol exists to measure
exactly this against a person, and here — outside that protocol, on a plain
locating question — is a real instance of a model writing to source it was never
asked to touch, caught only because a `git status` after the sweep happened to
show it.

## What this changes

- **`machines.md` phase-one item 1 closes.** The size sweep it specified is run,
  and the answer to its stated question is yes — the map's benefit is not a 7b
  artifact.
- **A second, unplanned data point for the gate probe's priority.** `run_command`
  on macOS was measured refusing a model mid-task, for the first time anywhere in
  this project's records, without the container and without a person at the gate
  — a 14B simply tried, twice, and stopped. This does not replace the gate probe
  — nothing here involves a proposed *plan* or a person approving one — but it is
  independent evidence for the same wall, from a different angle, and it cost
  nothing extra to observe.
- **The map's case gets a second argument it did not have before**: on a machine
  where the model's own instinct is to check its work with tools, the map is not
  competing with that instinct, it is *feeding* it — the four group-B hits at
  1024 tokens exist because the map handed 32B the real directory names to start
  from. `--map-tokens 0` does not just cost accuracy; on this size, it costs the
  tool budget too, on paths that were never going to exist.
- **A new, unplanned failure mode for larger models near an eviction boundary**:
  losing the *identity* of the repository, not just a file within it. Nothing in
  this project's corpora was built to catch that, because nothing before this
  sweep ran a model long enough inside one un-mapped, unfamiliar session to reach
  it.

## Still open

- **`luu chat` running an unrequested write with nobody to catch it.** The
  incident above, unresolved: a plan and a gate would have caught it in `serve`,
  but nothing stands between the CLI and a write the sandbox permits, whether the
  question asked for one or not. Whether the CLI should gate writes the way
  `serve` does, or whether "ungated by design" needs a narrower meaning than "any
  write the policy allows, unasked," is a decision this file surfaces and does
  not make.
- **`--allow-command` for `rg`/`ls`/`grep` under `best-effort` enforcement**,
  which 14b's own denial message names as the escape hatch, untried here on
  purpose — this sweep's job was the map, not the sandbox.
- **Whether 32B's group-B exploration generalises**, or whether four of six was
  this corpus's particular geometry (`crates/luu/` one hop from where the CLI
  question already landed). A corpus built the way
  [`the-map-order-probe`](2026-09-03.the-map-order-probe.completed.md) was — one
  question per file, chosen before any run — would settle it.
- **The identity-loss failure mode**, named here for the first time and not
  characterised: how many evicted turns it takes, whether a map-tokens value
  short of a full map still prevents it, and whether it is particular to this
  quantisation or family.
- **Timing.** Nothing here measures wall-clock, per
  [`machines.md`](../ROADMAP/2026-09-01/machines.md)'s own stated reason for leaving it
  out — but 32b's tool-using runs pushed prompts into the tens of thousands of
  tokens per turn (one closed at 58,827), which is worth knowing before treating
  this sweep's shape as free to repeat at will.
