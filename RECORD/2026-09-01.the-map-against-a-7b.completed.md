# The map against a 7B: what the grounded pair could not answer

**Status:** run, on a machine that is not the one the earlier model records used.
The numbers are real and the headline question is still open — not because the run
failed, but because the corpus it was run on cannot ask it. That is the finding,
and the second half of this file proposes the instrument that could.

[`2026-08-31.the-repo-map.completed.md`](2026-08-31.the-repo-map.completed.md) closed with a debt:

> What it has *not* answered is whether a 7B does better with it — that is the
> model run this file already describes, and it now has a number to beat: the map
> has to buy back the 870 tokens a turn it costs.

This is that run, and it does not settle the debt.

## The machine, because it is a new one

An Apple M1 Pro, 16 GB, macOS. Every earlier model record in this directory was
taken on an M4 Pro, on an unmerged branch, and says so. This is a smaller machine
and the numbers below are this tree's, taken today. `qwen2.5-coder:7b` at Q4 loads
as 5.0 GB, 100% GPU, and `ollama ps` reports `CONTEXT 8192`, so `num_ctx` reaches
the server — the check [`2026-08-30.ready-for-the-m4-run.completed.md`](2026-08-30.ready-for-the-m4-run.completed.md)
made non-negotiable after it turned out to be a bug.

```sh
for m in 0 1024; do
  ./target/release/luu chat --script scripts/tasks/grounded.txt \
    --backend ollama --model qwen2.5-coder:7b \
    --context-limit 8192 --reserve 512 \
    --tokenizer ~/models/qwen2.5-coder-7b/tokenizer.json \
    --temperature 0 --seed 7 --map-tokens $m \
    --sandbox luu.toml --record grounded-map$m.jsonl
done
```

Sampling pinned, one flag apart, same twenty prompts in the same order — verified
by diffing the prompts out of both transcripts rather than assumed.

## What it cost

| run | turns | total prompt | peak | mean/turn | `evicted` events |
| --- | ---: | ---: | ---: | ---: | ---: |
| `--map-tokens 0` | 20 | 36 880 | 2 797 | 1 844 | 0 |
| `--map-tokens 1024` | 20 | 52 586 | 3 445 | 2 629 | 0 |

**+15 706 tokens, +42.6%.** The mock measured +56% on the same script; the real
model's answers are a different length from the mock's fixed text, which is the
whole of the difference and is why the mock's totals were never a baseline for
this.

Two things in that table matter more than the percentage:

- **The mean grew by 785, and the map is 939 tokens.** It is not an accounting
  error: the two runs give different answers, so the history each turn carries
  differs, and the gap between 785 and 939 *is* that divergence. A per-turn delta
  that is not the map's size is the signature of a run that changed more than one
  thing, which this one did — deliberately, since the answer is what is under test.
- **Zero evictions, in both runs.** Twenty turns at 8 192 never filled the window,
  so the map was paid entirely out of slack. Its real cost — displacing history —
  did not occur here and remains unmeasured. A run that would show it needs a
  tighter `--context-limit` or a longer script, and until one exists, "+42.6%"
  is the cost of the map on a window that was not scarce.

## One answer changed, and it must not be read as the map working

Question 19, in the last group, where nothing is attached and the answer can only
come from what survived:

> **what does `enforcement = "kernel"` do when Landlock is missing?**

| run | answer |
| --- | --- |
| `--map-tokens 0` | "the policy falls back to `best-effort`… it will still attempt to enforce the rules as much as possible" |
| `--map-tokens 1024` | "`run_command` is denied, and it informs the user about what is missing" |

The second is right. The first is not merely wrong, it is **inverted**: it has the
sandbox degrading *open*, when `luu.toml` says the call is denied and that lowering
to `best-effort` is a deliberate, per-run act.

The temptation is to score that as the map buying something back. It cannot be,
and the reason is mechanical: at 1 024 tokens the map holds **four files, all of
them `.rs` under `crates/agent-core/`**. `luu.toml` is not in it. Neither is
`sandbox/`. There is no path by which the map's *content* could inform that answer,
so what changed is that the prompt changed — a different prefix is a different
forward pass, and temperature 0 makes each run deterministic without making the two
comparable. One question, n=1, no mechanism. It goes in this file as an
observation, not as a result.

The same run supplies the reason to be strict about it. Question 20 asks the model
which of its last four answers it filled in:

| run | what it flagged | was it actually invented? |
| --- | --- | --- |
| `--map-tokens 0` | the enforcement answer | yes |
| `--map-tokens 1024` | the enforcement answer | no — that one was right |

It flags the same slot either way. The self-report tracks the question, not its own
knowledge, so a first reading of the map-0 run — *the model's calibration caught its
only error* — does not survive the second run. Two runs killed it; one would have
published it.

## Why this corpus cannot answer the map's question

`grounded.txt` attaches the file every question is about. The map is a **locator**:
paths, line numbers and signatures, bodies elided, whose entire value is telling a
model where something it has not been shown lives. A corpus that hands over the
answer with the question cannot measure locating, in either direction.

This is the same failure as
[`2026-08-27.the-m4-pro-run.completed.md`](2026-08-27.the-m4-pro-run.completed.md) found in
`steady-state.txt` — a script written to measure eviction mechanics against a mock,
asked to answer a question about grounding it was never shaped for. `grounded.txt`
was the answer to that one. It is not the answer to this one, and the shape of the
mistake is worth naming because it has now happened twice: **the corpus is part of
the instrument, and reusing one across questions is how a run produces numbers that
cannot mean anything.**

## The map probe, which is what would settle it

Written here, run after — the order that worked for the fold and for the gate.

**The question:** does a path-ordered map at an affordable budget help a 7B name
the right file for a question about code it was not shown?

**The corpus:** nothing attached, ever. Fifteen questions, three groups, and the
groups are the design:

| group | targets | what it measures |
| --- | --- | --- |
| **A — inside the map** | `agent.rs`, `api.rs`, `backend/mock.rs`, `backend/mod.rs` — the four files a 1 024-token map holds | the map's ceiling: the best it can do is here |
| **B — outside it** | `serve.rs`, `lib.rs`, `export.rs`, `context.rs`, `sandbox/linux.rs` — none of which fit at any budget under the whole repository | **the placebo group** |
| **C — absent** | the judge that closes tasks; it does not exist | whether the map suppresses invention or the model invents regardless |

Group B is the part that makes it a measurement. If B improves along with A, the
map is not what caused the improvement and the run says so on its own, without
anyone having to argue it afterwards — which is exactly the argument this file had
to make by hand for question 19 above.

**Scoring**, per question and per run: names the right path / names a wrong path /
declines. Three outcomes, not two, because a model that says it does not know is
doing something different from one that invents `src/eviction.py`, and the M4 run
already showed a 7B will do the second.

**What each result would mean**, stated before the run:

- **A improves, B flat** → the map works, and the number is how much of the repo
  had to fit for it to. That is the case for ranking, since B is 25 of 29 files.
- **A and B both improve** → prompt perturbation, not information. The map's
  defence is then unmade and `--map-tokens 0` stays the default.
- **Neither improves** → a 7B cannot use an outline it was not asked to consult,
  and the next question is a tool that queries the map rather than a block that
  ships it.
- **C invents in both** → the map does not suppress invention, which is a claim
  nobody has made but everyone assumes.

## The path order, sharpened

The earlier record's table was counted approximately. With the real tokenizer:

| budget | files in the map | of |
| ---: | ---: | ---: |
| 1 024 | 4 | 29 |
| 8 192 | 28 | 29 |

At 1 024 the four are `agent.rs`, `api.rs`, `backend/mock.rs`, `backend/mod.rs` —
the alphabet, and nothing else. `crates/luu/` does not appear until the budget is
large enough to hold nearly the whole repository, which at 8 K is the whole window.
So the map, today, describes `agent-core`'s first four files to a model that may
be asked about the server.

## Secondary, and it points at the gate probe

The map-0 run has the model believing the sandbox degrades open. That belief is
about the *policy file*, which every planning call sees, and the gate probe asks a
model to declare what it will do under that policy. A model that thinks
`enforcement = "kernel"` softens when the kernel cannot help will write plans on a
wrong model of what it is being granted. Nothing here measures whether it does —
[`2026-08-31.the-gate-probe.completed.md`](2026-08-31.the-gate-probe.completed.md) is the run that
would, and it needs a person at the gate.

## Still open

- The map's cost under eviction, which this run did not reach.
- Whether the map should be a block in the prefix at all, rather than a tool the
  model calls when it needs to locate something. The block is paid every turn; the
  tool is paid when used and costs a round trip. Nothing has argued this either way.
- Whether `luu.toml` and other non-`.rs` files belong in the map. Question 19 was
  about a file the map structurally cannot hold.

# 2026-09-01, later the same day: the map probe, run

The corpus proposed above was written as
[`scripts/tasks/map-probe.txt`](../scripts/tasks/map-probe.txt) and run the same
way as the pair — same machine, same model, `--temperature 0 --seed 7`, one flag
apart. Fifteen questions, nothing attached, scored as *names the right path* /
*names a wrong path* / *declines*.

## The result

| group | targets | `--map-tokens 0` | `--map-tokens 1024` |
| --- | --- | ---: | ---: |
| **A** | inside the map | **0 / 6** | **6 / 6** |
| **B** | outside it — the placebo | 0 / 6 | 1 / 6 |
| **C** | absent from the tree | 0 declines | 0 declines |

**A goes from nothing to everything and B does not move.** That is the first of
the four outcomes this file named in advance, and it is the one that says the map
works — the improvement is confined to exactly the files the map contained, which
is what the placebo group exists to establish and what no amount of reading
transcripts could have established on its own.

Group B's single hit is not one. The answer was
`crates/agent-core/src/context.rs`, which is the right path, produced by a model
that answered *every* B question with `crates/agent-core/src/<topic>.rs`. It is
the naming pattern landing on a real file, and it is scored as a hit only because
scoring it any other way would mean deciding by hand which correct answers to
believe — which is the thing the group was built to avoid.

## How wrong it was without the map

Not "vague". Fabricated, in a shape that would pass review:

| question | `--map-tokens 0` answered | the tree says |
| --- | --- | --- |
| the Backend trait | `src/backend.rs`, line 10 | `crates/agent-core/src/backend/mod.rs:122` |
| the prefix-reuse struct | `PromptReuseReport`, `src/report.rs:25` | `PrefixReuse`, `crates/agent-core/src/api.rs:35` |
| the Landlock ruleset | `src/landlock.rs` | `crates/agent-core/src/sandbox/linux.rs:143` |

`src/` is not a directory in this workspace. `PromptReuseReport` is not a type
that exists. Asked how to script the mock backend, it wrote 374 tokens
implementing a `VecDeque` queue from scratch rather than naming `Mock::replies`,
which is one line away in a file the map holds. This is the M4 run's
`src/eviction.py` again, in Rust: **fluent, structurally plausible, and about a
repository that does not exist.**

With the map it answered `PrefixReuse`, `crates/agent-core/src/api.rs`, line 35 —
the exact line — and gave `backend/mod.rs` line 122, also exact.

## The finding nobody asked for, which is the useful one

**The map changed the failure mode of the questions it does not cover.** Group B,
same question, two runs:

> `--map-tokens 0`: "The file that builds the Landlock ruleset is `src/landlock.rs`."
>
> `--map-tokens 1024`: "Without knowing the exact structure of your project, I
> can't pinpoint the exact file, but it's usually located in a directory related
> to security or Landlock setup, such as `crates/agent-core/src/landlock.rs`…"

Two changes, and they point opposite ways:

- It **hedges**, where before it asserted. Every group B and group C answer in the
  map run opens by saying it does not know the project's structure.
- The invention **migrated into the namespace the map showed it**.
  `crates/agent-core/src/landlock.rs` is a far more convincing wrong answer than
  `src/landlock.rs` — it has the right crate, the right module depth, the right
  house style. The map taught it the prefix, and it extrapolated the leaf.

So the map does not suppress invention; group C confirms it, with zero declines in
either run and `crates/agent-core/src/judge.rs`, `…/session_store.rs` and
`…/mcp_client.rs` invented for three things this tree does not contain. **It
dresses invention better.** A partial map is a plausible-path generator for
everything it left out, and at 1 024 tokens it leaves out 25 of 29 files.

There is a smaller instance of the same thing inside group A. Asked where
`SessionView` is rebuilt from a recording, the map run named `from_record` in
`api.rs` — right function, right file — at **line 405**, which is `apply_trace`.
`from_record` is at 462. It did not invent a line: it took a neighbouring one out
of the map. Map-induced error, and the only kind this probe found.

## What it cost

| run | turns | total prompt | peak | mean/turn |
| --- | ---: | ---: | ---: | ---: |
| `--map-tokens 0` | 15 | 14 915 | 1 382 | 994 |
| `--map-tokens 1024` | 15 | 29 735 | 2 695 | 1 982 |

**+99.4%** — the prompt doubles. With no fragments and a short history the delta
is almost pure map (939 × 15 = 14 085 against a measured 14 820), which makes this
the cleanest reading of the map's price anywhere in this directory. The grounded
pair's +42.6% is the same map amortised over larger prompts.

Whether doubling the prompt to go 0/6 → 6/6 on a sixth of the questions is worth
it is not a question this probe answers, and it is the right question. What it
does establish is the shape of the trade: **the map's benefit is bounded by what
fits in it, and its cost is not.** The cost is paid on every turn for every
question; the benefit arrives only for questions about the four files the alphabet
happened to reach.

That is the argument for ranking, and it is no longer an argument. It is two
tables.

## What this changes

- **Relevance selection's success criterion is now concrete.** Not "beat path
  order on token count" — get group B's targets into the map without growing it,
  and B's score should move the way A's did. The corpus to measure that with
  exists as of today.
- **`--map-tokens 0` stays the default**, and now for a stated reason rather than
  caution: at any budget this window can pay, the map is a plausible-path
  generator for most of the repository, and a wrong path that looks right is worse
  for a *plan* than a wrong path that looks wrong. Which is the next item's
  problem —
- **The gate probe should be read with this in hand.** A plan whose `files` list
  says `crates/agent-core/src/landlock.rs` is well-formed, wrong, and grants
  nothing, and `Plan::narrow` will treat it as a read of a file that does not
  exist — the silent-skip half of the asymmetry that probe was built to exercise.
  If that shows up there, this is where it came from.

## Still open, updated

- The map's cost under eviction is still unmeasured; neither run here evicted
  either.
- **Whether a map that hedges is better or worse than one that asserts.** The
  hedging is honest and the guess underneath it is not, and this probe cannot say
  which a person acts on.
- Non-`.rs` files in the map, unchanged from above and now with a second reason:
  `luu.toml` is the file the gate's policy lives in.
