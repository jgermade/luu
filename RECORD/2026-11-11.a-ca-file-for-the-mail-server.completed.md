# A CA file for the mail server

Row 71 of [`ROADMAP/2026-11-08`](../ROADMAP/2026-11-08/README.md) is *a TLS
handshake that succeeds*. The run against Mailpit on 2026-11-04
([`an-owner-proved-by-email`](2026-11-03.an-owner-proved-by-email.WIP.md),
§*against Mailpit*) could not have one: luu trusts Mozilla's roots and nothing
else, and Mailpit's certificate chains to none of them. That record left a
decision — *whether luu should take a CA file, or the system's store* — that
nobody had asked for.

## Asked, and answered

> Para probar SMTP se puede usar mailpit

Put back as the question that record left, and answered: **a CA file**.

## The proposal

```toml
[auth.smtp]
url = "smtps://mail.internal:465"
from = "luu <luu@example.com>"
ca-file = "/etc/ssl/private-ca.pem"
```

```sh
luu config owner --smtp-url smtps://mail.internal:465 --smtp-ca-file ca.pem …
```

- **Added, not instead.** The PEM's certificates are trusted *beside*
  Mozilla's roots. A file that named the only roots would make a typo in it a
  server nobody can reach, and a public relay still has to work.
- **For the mail server only.** Providers, peers and release downloads keep
  the trust they have: this is one host, named by one URL.
- **Read on every send**, as a mounted password is, so a rotated CA is the
  next email's. Absolute, or under `~`.
- **Not a secret.** Its mode is not checked and it may sit under `/etc`: a
  certificate is public, and the rule that keeps a password out of the roots
  commands read does not apply to it.
- **It widens nothing else.** The name in the certificate is still checked
  against the URL's host, and `tls=required` is still required off this
  machine.
- **A file that does not load refuses the send**, naming the file — never a
  fall back to the public roots alone, which would turn a wrong path into
  `UnknownIssuer` about the server.

## What it costs

A fifth key in `[auth.smtp]` and a fifth flag. One more way for a deployment
to hold the trust of its mail: whoever can write that file can read every
code. It is the operator's file, like `config.toml`.

## Rejected

- **The system's store** (`rustls-native-certs`): trust that changes with the
  image luu runs in, and on a public server that is a base image somebody
  else updates. A file is named, and is in the record of the deployment.
- **`tls=insecure`, or skipping verification for this machine**: lettre has
  the switch, and it is the downgrade the 2026-11-04 run closed, by another
  door.
- **A CA in the URL**: the URL is one string a person types, and lettre reads
  it; a second reader of it is what `opportunistic` taught against.

## Still open

- **The setup page has no field for it.** A deployment with a private CA
  proves its mail with `luu config owner` on the server, or writes
  `[auth.smtp]` by hand. A path on the server typed into a browser by
  whoever holds the setup link is a file-existence question asked of the
  server, and wants its own argument.
- **A provider's key, a real account.** Row 71's other half — *a provider's
  own authentication* — still needs one.

## Appended 2026-11-11: built, and run against Mailpit

As proposed. `Mail::extra_roots` reads the file at `check` and at every
`send`; `Mail::tls_with` makes the transport's TLS again for the URL —
`Wrapper` for `smtps://`, `Required` for `tls=required` — with the
certificates added to lettre's own root store, which starts from
`webpki-roots`.

**The run** — Mailpit 1.33.0 as a plain binary, no container; a CA and a
certificate for `localhost` made by `openssl`; a password
(`--smtp-auth-file`); one instance on implicit TLS and one requiring
STARTTLS. Script and output:
[`runs/2026-11-11.mail-with-a-ca-file/`](runs/2026-11-11.mail-with-a-ca-file/).

| URL | `--smtp-ca-file` | What luu did |
| --- | --- | --- |
| `smtps://localhost:1465` | none | `invalid peer certificate: UnknownIssuer`; nothing saved — as on 2026-11-04 |
| `smtps://localhost:1465` | the CA | **the handshake succeeds**: the code arrived, the owner was made, `ca-file` is in `[auth.smtp]` |
| `smtp://localhost:1587?tls=required` | the CA | the same, by STARTTLS |
| `smtps://localhost:1465` | another CA | `UnknownIssuer`; nothing saved |
| `smtps://127.0.0.1:1465` | the CA | `certificate not valid for name "127.0.0.1"`; nothing saved |
| `smtps://localhost:1465` | a file that is not there | refused before connecting, naming the file |
| then `serve`, `POST /api/auth/code` for a user | (the saved one) | `202`; the code arrived; `/api/auth/login` `204` with the cookie |

**Verified:** the table above; `mail::tests` — a file that is missing,
relative, not PEM or broken PEM is refused by name at `check`, the key
round-trips through the table, and `/etc` is not refused for it;
`cargo test --workspace`, clippy, fmt.

**Not verified:** a certificate under a *public* root, and a provider's own
authentication. Row 71 keeps both.
