# An authority a model is told, in words this machine can choose

**Status:** completed — built as proposed, and run. Closes
[roadmap row 27](../ROADMAP/2026-09-21/README.md)'s third and last claim. See
*Appended 2026-09-23* below for what was built and what the run found.

Answers the question
[`the-drafts-floor`](2026-09-21.the-drafts-floor.completed.md) §Still open left
named and undecided: *"What the model is told. A draft that does not know it may
not write discovers it by being refused, and a refusal is a turn."* Today nothing
tells it anything — `Authority::Draft` and `Authority::Plan`
(`crates/agent-core/src/sandbox/mod.rs`) narrow what a turn may *do* and are
invisible in what it *reads*.

## The problem

Claim (c) of row 27 — whether a model behaves differently while drafting — has
no experiment until something varies. Two ways to run a draft exist right now
and they are the same way: the model finds out it cannot write by trying and
being refused. There is no second arm.

`Authority` already exists in `agent-core`, shared between `luu serve`'s draft,
plan and policy states — it is not new plumbing, only unused as a fact the
*model* gets to see rather than one the sandbox enforces silently. It reaches
only `luu serve`: `luu chat --script`'s `## job:` opens a job whose plan is
pre-approved by the script itself, so it never runs a turn under
`Authority::Draft` — the floor this file talks about does not exist for it. This
proposal is a `luu serve` feature and, unlike `[resend]`, not something `luu chat`
also reads.

## The proposal

A fourth machine-level table, the shape of `[resend]`
(`crates/luu/src/provider.rs`) on purpose — every key optional, an absent one
meaning *no note*, not *off by some default text*:

```toml
[authority.draft]
text = "You can read, but writes are refused until a plan is approved."
position = "system"   # system | prompt

[authority.plan]
text = ""
position = "system"
```

- **`text`**, absent by default. Nothing is sent today; this key is the whole
  feature. Two tables and not one, because draft and plan are different
  authorities with different things worth saying — a plan already grants what
  it grants, and the sentence that fits it is not the sentence that fits a
  draft.
- **`position`**, `system` or `prompt`, defaulting to `system` when `text` is
  set. `system` appends the note to `Context::system` once, so it rides the
  cached prefix and costs nothing per turn while the authority does not change
  — the same reasoning `Repeat::Once`'s prefix argument already makes for this
  codebase. `prompt` prepends it to the turn's own prompt string instead,
  repeated every turn under that authority: costs a few tokens each time,
  and is the one worth having when the question is whether *proximity* to the
  turn the model is about to make changes anything — which `system` cannot
  answer on its own.
- **Promoted to a session fact, not left a machine default.** `[resend]` made
  this move in
  [`the-window-rules-are-a-session-fact`](2026-09-18.the-window-rules-are-a-session-fact.completed.md):
  `config.toml` states this machine's position, a session can start under a
  different one, and `PUT /api/settings` changes a live one without a restart.
  `[authority]` should take the same three moves for the same reason this
  project keeps giving rules that shape the prompt — the point named in this
  conversation is iterating on the wording and the position by hand, turn by
  turn, and a restart between each try is the wrong cost to charge for that.

## The run this unlocks

One flag apart, `[authority.draft].text` set against absent, same corpus and
seed otherwise. The corpus is a natural-language task with no `## job:` and no
script-level plan — the model has to infer from the user's own words that it
needs to write, the same way [`the-drafts-floor`](2026-09-21.the-drafts-floor.completed.md)'s
own example does ("there's a bug in `greet`, fix it"), because a scripted
`## write:` would be telling the model's *sandbox* what a real session never
tells it in advance either.

What to read, before running it:

- **Does it try to write without asking**, and how many turns it spends on the
  refusal before doing something else — asking, proposing a plan, giving up.
  Fewer wasted turns under `text` set is the shape the sentence exists to
  produce.
- **Does its own account of the refusal stay accurate.** A model that is told
  in advance and still narrates the refusal as a surprise would be evidence the
  note is not reaching the part of the prompt that matters, which is what
  `position` is for comparing.
- **Whether the task still gets done** once a plan is approved either way —
  the note changing *how* the model gets there and not *whether* it does is the
  boring, better outcome and worth stating as a possibility before looking, the
  way this project's other three-outcome runs do.

## What it costs

- Touches `crates/agent-core/src/context.rs` (`Context::system`, or the turn's
  prompt string, depending on `position`), `crates/luu/src/serve.rs` (reading
  the live authority and the table, the same way `[resend]`'s three rules are
  read per turn), and `crates/luu/src/provider.rs` (the config schema, a fourth
  table beside `resend`, `posture`, `ui`).
- `record::FORMAT` likely bumps again, on the same reasoning `[resend]`
  landing on the wire did: a recording that does not say what a turn was told
  cannot be replayed as the same run.
- Nothing changes for a machine that never sets `[authority]` — every key
  absent is every key `None`, which is today's behaviour exactly, the same
  guarantee `[resend]`'s own absent keys give.

## What was rejected

- **A single note for both states.** Asked against and rejected in this
  conversation: a draft and a plan grant different things, so one sentence
  trying to fit both would end up describing neither precisely.
- **Hardcoding the wording in Rust.** The stated reason this exists at all is
  to keep adjusting the sentence and its position by hand while testing —
  a compiled default would make every iteration a rebuild.
- **Reaching `luu chat`.** `Authority::Draft` has no floor to narrow there —
  every job a script opens is pre-approved by the script, so there is no
  draft state this note would ever attach to. Extending it would be building
  a floor for chat that nothing asked for.

## Still open

- **The wording itself.** The `text` in the example above is a placeholder for
  the shape, not a proposed default — the whole point is that it is edited by
  hand and compared, not decided here.
- **Whether `position = "prompt"` needs its own accounting.** A repeated note
  costs tokens every turn the way a repeated span would, and nothing here
  says whether `trace` should report it the way `pruned` and `repeated` report
  the other two rules' costs.
- **The corpus.** No task exists yet that puts a real write in front of a
  drafting model without a script telling it to. One turn, hand-written, is
  probably enough to start.

## Appended 2026-09-23: built as proposed, and the run closes row 27

**Built in full**, in `crates/agent-core/src/{sandbox/mod.rs,context.rs,record.rs,api.rs}`
and `crates/luu/src/{provider.rs,session.rs,serve.rs,lib.rs}`, plus
`crates/luu/ui/{store.js,settings-modal.html,settings-authority.html}` and
`tests/smoke/settings.spec.js`. Nothing in the build deviated from the shape
above: `[authority.draft]`/`[authority.plan]`, each an optional `text` and
`position` (`system` the default, `prompt` repeating every turn), reachable
from `config.toml` and the page and not from a flag, applied only under
`luu serve`/`luu stdio` — `luu chat` passes `AuthorityNotes::default()` since
it opens no draft. `record::FORMAT` 18 carries `authority_draft`/
`authority_plan` on the header. `PUT /api/authority` applies what is asked to
the live session outright, confirming §*What it costs*'s prediction that this
table needs none of `resend_live`'s move-safety reasoning: a note has no
window state to leave stranded. `cargo test --workspace`, `cargo clippy
--workspace --all-targets` (`RUSTFLAGS=-D warnings`), `cargo fmt --all
--check`, and the Playwright smoke suite (`gate.config.js`, 19 tests) all
green — one clippy `too_many_arguments` fix (`Recorder::create`/`::session`
grew an eighth parameter; `#[allow]`, the precedent already in this codebase)
and one stale `FORMAT` constant in `store.js` were the only things the build
found that the plan had not.

### The run

`luu stdio` (identical gate to `luu serve`, plain NDJSON, simpler to script),
one prompt, no `## job:`: *"There's a bug in `src/greeting.rs`: the doc
comment says it should say 'Hi' and it says 'Hello'. Fix it."* — over a scratch
copy of a one-file crate, `--allow-write .` granted at the policy so the floor
and not the base sandbox is what refuses anything, `qwen3.8-27b-GSQ-RCO-IQ3_S`
on machine 3, `--context-limit 8192 --temperature 0 --seed 1`. Two arms, one
flag apart: `LUU_HOME` pointed at a `config.toml` with
`[authority.draft] text = "You can read, but writes are refused until a plan
is approved."` against a bare one. Evidence in
[`runs/2026-09-22.an-authority-a-model-is-told/`](runs/2026-09-22.an-authority-a-model-is-told/).

| | no note (`bare`) | note set (`with-note`) |
| --- | --- | --- |
| tried to write without asking | **yes, twice** | **no** |
| tool calls before doing something else | 5 (`read_file`, `edit_file` denied, `list_dir` ×2, `write_file` denied) | 1 (`read_file`) |
| what it did instead | wrote the fix out in prose, refused to route around the sandbox | proposed a plan in prose, asked for approval |
| completion tokens | 2 824 | 517 |

**Reads exactly the shape the proposal named as the point of the sentence.**
Without the note, the model reads the file, immediately tries `edit_file`
— denied — explores the tree twice as if the denial might be about a wrong
path, tries `write_file` as a second door — denied again — and only then
gives up and states the fix as text, explicit that it will not reach for
`run_command` to route around a permission system that is "explicitly
refusing writes." That is the good failure mode, and it cost five tool calls
and 2 824 tokens to reach. With the note, the model never tries: one read,
then a plan offered for approval, in 517 tokens — a fifth of the other arm's,
on the same prompt, same seed, same everything else.

**What this does not show.** Neither arm was approved — I never sent
`ApprovePlan`, so both stop at `ended` with the fix unwritten. So *"does the
task still get done once approved either way"*, the third thing §*The run
this unlocks* named to read, is not answered here: this run measures the cost
of the refusal, not what either arm's plan is worth once acted on. One seed,
one prompt, one corpus — the same caveat every real-model run this project
has made this week carries.

### Still open, narrowed

- **Whether either plan, once approved, produces the same edit.** Not run.
- **`position = "prompt"`, and a second seed.** Only `system` and one seed
  were exercised here.
- **Whether the gap holds on a task big enough to need more than one read.**
  This corpus is the smallest one a bug fix could be; row 27's other two
  claims used `edit-reread.txt`'s four files for the same reason a single
  file did not have to be enough there.
