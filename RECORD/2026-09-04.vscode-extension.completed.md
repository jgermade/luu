# Surface #3: The VSCode extension over stdio

**Status:** a proposal and the code it plans. It is item 1 of
[`ROADMAP/2026-09-04/README.md`](../ROADMAP/2026-09-04/README.md), continuing from
[`2026-09-01.how-a-surface-reaches-the-engine.completed.md`](2026-09-01.how-a-surface-reaches-the-engine.completed.md)
and [`2026-09-04.protocol-over-stdio.completed.md`](2026-09-04.protocol-over-stdio.completed.md).

## Problem

`luu` has had two surfaces:
1. The CLI (`luu chat`, `luu tools`, `luu map`), which links `agent-core` directly in-process.
2. The web debug UI (`luu serve`), which binds an HTTP/WebSocket port on loopback.

An editor cannot use the first because VSCode extensions run in Node.js / TypeScript,
and cannot safely default to the second because opening a local WebSocket without
authentication exposes `approve_job` (which grants filesystem writes and arbitrary command
execution) to any unprivileged local process. Off-loopback requires bearer tokens and
configuration overhead that collides across multiple windows.

[`2026-09-04.protocol-over-stdio.completed.md`](2026-09-04.protocol-over-stdio.completed.md)
implemented and verified `luu stdio`: line-delimited NDJSON over standard input/output.
The surface that drives it is now unblocked.

## Proposal

Implement Surface #3 as a standard VSCode extension in `editors/vscode`:
1. **Subprocess lifecycle**: On opening or activating the chat view, spawn `luu stdio`
   rooted in the workspace folder (`vscode.workspace.workspaceFolders[0]`).
   Stderr streams to an `OutputChannel` for diagnostics without polluting the protocol stream.
2. **Protocol bridge**:
   A typed `LuuClient` serializing [`ClientMessage`](../crates/agent-core/src/protocol.rs)
   to standard input and deserializing [`ServerMessage`](../crates/agent-core/src/protocol.rs)
   from standard output.
3. **Webview Chat & Gate UI**:
   - Sidebar chat view registered under `luu.chatView`.
   - Streaming assistant tokens (`ServerMessage::Token`).
   - Tool execution status and results (`ToolCall`, `ToolResult`).
   - **Job Gate approval card**: When `ServerMessage::JobProposed` arrives, present the
     objective, tasks checklist, read files, write files, network toggle, and closing command.
     Provide explicit actions for **Approve** (`ApproveJob`), **Amend** (edit files/commands/network),
     and **Reject** (`RejectJob`).
   - Eviction tombstones (`ServerMessage::Evicted`).
4. **Configuration**:
   - `luu.executablePath`: custom path to `luu` binary (defaults to searching `PATH` or `target/debug/luu`).
   - `luu.backend`: backend override (`ollama`, `openai`, `mock`).
   - `luu.model`: model name override.

## What it costs

- Adds TypeScript build tooling in `editors/vscode/` (`package.json`, `tsconfig.json`).
- Does not modify or add dependencies to the Rust workspace (`cargo build` remains isolated).

## What was rejected

- **Embedding a WebSocket client**: Rejected in `how-a-surface-reaches-the-engine` because sockets
  introduce port collisions across windows, token management, and local privilege escalation risks.
- **In-process WebAssembly**: Node extension host does not support POSIX `rlimits`, Landlock,
  or subprocess container orchestration.

## Still open

- File decoration/diff previews for proposed writes before approval.
- Terminal integration to run closing commands directly in the editor's integrated terminal.
