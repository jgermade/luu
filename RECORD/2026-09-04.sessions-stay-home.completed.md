# Sessions stay on the host that made them

**Status:** a decision, and the removal it caused. It supersedes half of
[`the-border-and-the-gate`](2026-09-04.the-border-and-the-gate.completed.md) —
transfer, the bundle and the border are withdrawn — and leaves the other half
standing, because the store keeping its own stream never depended on any of it.

That record is left exactly as it was written. It is what was believed at the
time, the argument it makes about *what a transfer would have to be* is still the
right argument, and rewriting it would erase the only evidence that this was
tried before it was decided against.

## The decision

**A session belongs to the host it was created on. It does not move, and there
is no portal.**

Not "moving is discouraged" and not "moving is an explicit act". The mechanism is
removed, so the tree says what the design doc says.

## Why

### The backend already reaches the other machine

This is the one that dissolves the use case rather than arguing with it. The
reason anybody wanted a session to move was that *the model they wanted was on
the bigger box* — 32b fits in 48 GB and not in 16. But the thing you need over
there is the model, and `--backend openai --openai-url http://other-box:8080/v1`
has reached it since
[`an-openai-compatible-backend`](2026-09-01.an-openai-compatible-backend.completed.md).
The session, its history, its approvals and its evidence stay where the person
is, and the GPU is a URL.

Moving the session was solving the half of the problem that was not the problem.

### Git already moves the part that matters

For an agent whose whole design reads the tree *at run time* — the repository map
rebuilt from the checkout, fragments read from disk on the turn they are
attached, plans that name paths and are re-resolved against the destination —
what is in the tree is most of what a session is about. `git push` and a fresh
session on the other machine is a real answer, it is what the person who owns
this repository actually does, and what it leaves behind is *what the
conversation decided and refused*. That may be worth moving. Nobody has shown
that it is, and the burden was on the feature.

### Evidence stops leaving the machine

A `tool_result` carries the bytes the model was given: file contents, command
output, denials.
[`the-portal-and-the-gate`](2026-08-31.the-portal-and-the-gate.completed.md)
named this as the single largest thing in the design pointing away from
local-first, and shipping the stream is exactly what made it real. A rule removes
it. A mitigation would only have managed it, forever.

### Two open questions close by construction

- **The fork.** A session on two hosts at once, with an append-only stream, is a
  fork; forbidding it was the smaller answer and this is that answer, arrived at
  from the other side.
- **Two rulers.** A history measured with one model's tokenizer and continued
  under another has a budget counted with two counters. It can no longer happen.

### What keeping it would have cost

Every mechanism has to be operated forever once it exists. The border is a second
gate — a second place where an approval is decided, with its own rules about what
crosses in which state — and a second gate is a thing to keep correct for as long
as the first one exists.

## What was removed

- `luu transfer` and `luu import`, and `luu::transfer`.
- `agent_core::transfer` — the manifest, the origin block, the resolved sandbox
  that travelled in it, and `regate`.
- `ServerMessage::Imported`, and with it **protocol 6 → 5 and record format
  8 → 7**. The bump is un-made rather than left standing: nothing outside this
  branch ever spoke 6, and a version number that exists to tell two peers what
  they can parse must not carry a variant that no longer exists.
- `SessionView::imported`, `JobView::approved_at_origin` and `JobView::unmet`.
- The gate panel's border block in the debug UI, and the crossing fixture.

## What was kept, and why each stands on its own

- **The stream in the store** (schema 2). The fold is a cache, and until this the
  thing it was a cache *of* existed only when somebody had passed `--record`.
  Keeping it makes `fold(stream(id)) == load(id)` checkable inside the file that
  holds both, and gives every stored session a replayable account without a flag.
  Transfer was the occasion for it, never the argument.
- **The gate on resume.** A proposal that outlived its server used to come back
  as a job sitting in `proposed` with nothing holding the gate, and the next
  prompt quietly proposed a second one beside it. `Pending.prompt` stays
  optional: the case that has no held prompt is now only this one, and it is a
  real one.
- **The session's own clock.** A resumed session's lines are timed from the
  session's start rather than the process's, which stopped being the same number
  the moment `serve` learned to switch sessions.

## What this decides about the roadmap

Items 7 and 8 of [`ROADMAP/2026-09-04/`](../ROADMAP/2026-09-04/README.md), and
stage 2 of [`federation.md`](../ROADMAP/2026-08-31/federation.md) — the registry,
the relay, the transfer service — are closed rather than pending. Stage 1's first
two items stay built and keep earning their place on their own: **the handshake**
is what lets any two `luu` builds refuse each other out loud rather than by
misparsing, and **signed approvals** answer *who approved* on a wire where a
bearer token only answers *who could reach the port*. Neither of those was about
moving a session.

**The transfer probe is not run, and that is a decision rather than a
measurement.** It is worth saying plainly, because this project's rule is that
context claims are measured and not argued: what the probe would have measured is
whether a moved session keeps its context, and that question is now moot, not
answered. The claim *a session moves between backends without loss* remains
untested and unmade.

## What would reopen it

One case is not answered by either the backend URL or by git: **a machine that
has no clone of the tree** and cannot get one — someone else's box, a support
copy of a session, a run whose evidence has to be read where it cannot be
re-produced. `luu export` already folds a recording into the static twin of the
read API for exactly that, and it moves a *recording* rather than a session
somebody can continue. If that stops being enough, this decision is what has to
be argued with.

## Still open

- **The cloud worker is unaffected**, and it is worth writing down so nobody
  reads this as a decision about level 3. What crosses that seam is the policy
  and one tool call; the session stays on the host either way. See
  [`the-worker-and-the-seam`](2026-09-02.the-worker-and-the-seam.completed.md).
- **Nothing signs a recording.** A signed approval can be re-verified out of the
  stream; a relay that dropped lines would not be detected. There is no relay now
  and the gap is smaller, but `luu export` still produces files that travel.
- **`luu chat` still has no gate**, unchanged by any of this.
