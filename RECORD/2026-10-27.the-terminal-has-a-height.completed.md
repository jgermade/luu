# The terminal has a height

Asked in two messages, with the Runtime dialog just built:

> *La modal de selección de Runtime, mejor alineada arriba, con el objetivo de
> que no cambien de posición las opciones debido a `.implications`.*
>
> *Sobre el arrastre para cambiar el tamaño entre el inspector, el editor y el
> chat, la línea en hover debería ser más ancha y usando el azul de acento del
> tema. Estaría bien también poder cambiar la altura del terminal.*

## The problem

**The Runtime dialog moved under the pointer.** `<dialog>` is centred, and
choosing a place adds the box that says what stays behind: the dialog grew by
its height, half of it upward, and the place just clicked slid up by half a box
— the next click landed on the one above it.

**An edge being dragged was a 2px line in the divider's grey**, the colour of
the borders between the columns: under the pointer it looked like the border
it already was.

**The terminal was 16rem whatever the window**, a fixed height in
`terminal.html`. A long build's output scrolled in a third of the column on a
tall screen, and covered most of the file on a short one.

## The proposal

**`Modal` takes `align="top"`**: hung from `min(10vh, 5rem)` below the window's
top instead of centred, its height capped against the rest, so what grows
grows downward. The Runtime dialog uses it; the others stay centred, which is
right for a dialog that does not change size while it is answered.

**Every edge is a 4px line in `--luu-accent`**, under the pointer, focused,
and while it is held (`:active`) — the columns' and the terminal's.

**The terminal's top edge is dragged as a column's side is**, the same module
(`resize.js`) and the same rules: an 8px strip over the border, the height a
custom property on `.app` (`--terminal-h`) that a drag writes without waking
anything reactive, kept in `localStorage` (`luu.height.terminal`) when the
pointer is let go, double click to forget it, ↑/↓ on the focused edge. The drag
stops at 96px and where the file above would keep less than 200px; the
stylesheet caps a kept height against the window (`100dvh - 14rem`), so a
height kept on a tall screen gives way on a short one without being forgotten.
xterm refits to it, as it does to a column's width, through the observer it
already had.

## Rejected

- **A fixed height for the Runtime dialog** — tall enough for the box from the
  start. The places would have stayed put, and a dialog with an empty band at
  its foot until something is chosen reads as unfinished.
- **The terminal's height as a fraction of the column.** A shell is read in
  lines; a height that changed whenever the window did would move the lines a
  person had sized it for.

## Built, the same day

As proposed. Tested: `workspace.spec.js` — the terminal's edge dragged 80px
up makes it taller and is kept, and a double click puts it back and forgets
it. Seen by hand: 256px dragged to 410px and kept across a reload; the line on
a column's edge under the pointer; the Runtime dialog's first place at the same
height before and after a place is chosen.
