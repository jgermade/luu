# The panel reads `pruned`

**Status:** a proposal, and the code it plans, both here — the change was small
enough to argue and build the same day. Item 6 of
[`ROADMAP/2026-09-09`](../ROADMAP/2026-09-09/README.md), open since
[`the-panel-keeps-the-turn`](2026-09-08.the-panel-keeps-the-turn.completed.md#still-open)
named it: *"The trace channel has no consumer. `/ws/trace` carries the agent's
own lines — including the `pruned` ones rule B added — and nothing in the page
reads them."*

## The problem

`onTrace` in `crates/luu/ui/store.js` had a branch for `prompt`,
`prefix_reuse`, `budget` and `step_call` — every `TraceMessage` variant except
`Pruned`, which rule B started emitting on 2026-09-08
([`prune-behind`](2026-09-08.prune-behind.completed.md)) and rule C extended to
tool results on 2026-09-09
([`what-a-result-costs`](2026-09-09.what-a-result-costs.completed.md)). The
read API already carried the same fact per turn — `TurnView::cited` and
`TurnView::pruned_by` in `crates/agent-core/src/api.rs`, built from the same
message — but `fromStored` in the page never read `cited` either. Both ends of
the same fact were unread: the live socket and the history the API serves.

The panel already draws the parallel case, eviction: `state.evicted`, filled
from the *protocol* channel's `evicted` message, rendered as a line under the
budget bars ("Turn N dropped turn(s) …, for good, under the X policy"). Pruning
is deliberately not eviction — a pruned turn is still asked, still answered,
still in the transcript; what left is its code — but it is the same shape one
level down: `{ turns, tokens, counter }` without eviction's `policy`. The panel
that exists to watch the window give way had no way to show the one rule that
makes it give way without losing a turn.

## The proposal

**The same three-field mirror `dropped`/`evicted` already has, named `cited`
on the read side to match `TurnView::cited`, and `pruned` on the live
`state` to match the trace message's own tag.**

- `state.pruned` — filled by a new `onTrace` branch on `"pruned"`, the same
  shape the other trace branches use.
- `panel()` and `keepTurn()` gain `cited: state.pruned`, beside `dropped:
  state.evicted`, so the live turn and a just-finished one both carry it.
- `fromStored(turn)` gains `cited: turn.cited ? { ...turn.cited, turn: turn.turn } : null`,
  the same treatment `dropped` gets — the stored `Pruned` names the turns that
  gave up spans, not the turn whose selection took them, which is the turn
  this is attached to.
- `reset()` clears `state.pruned`, so switching sessions does not leak the
  previous one's last prune into the new one's panel.
- `app.html` renders it right under the `dropped` line it sits beside: *"Turn N
  cited turn(s) …, instead of resending them — T tokens saved, still in the
  transcript."* Worded apart from `dropped`'s "for good" on purpose — the one
  claim this line must not make by accident is that the turns it names left
  the conversation.

## What it costs

Six small diffs, no format bump, no new wire message — `Pruned` has existed on
both channels since 2026-09-08/09; nothing read it. `crates/luu/ui/app.html`
and `crates/luu/ui/store.js` are the whole change.

## What was rejected

- **Marking individual messages in the transcript**, the way an evicted
  message gets `· out of the window since turn N`. Checked first: the
  live `evicted` *protocol* case does this by walking `state.messages`, but
  the *stored* path never sets it either — `fromStored`'s sibling message
  loader hardcodes `evicted: null` regardless of `t.evicted_by`, so a
  reloaded session shows no evicted messages as evicted today. That is a
  second, pre-existing gap in the same neighbourhood and not what item 6 asked
  for; fixing it here would have doubled the diff to close a row that was
  about the trace channel specifically. Left as found.
- **A dedicated activity feed for the trace channel**, floated as "the obvious
  home for it" in `the-panel-keeps-the-turn`. Rejected there already, for the
  same reason this record inherits: one line beside `dropped` is the shape the
  page already has, and a feed is a second inspector to keep in sync with the
  first.

## Driven, not just tested

No unit test in the tree exercises `crates/luu/ui/` — it is untyped JS with no
build step (`AGENTS.md`'s own note: `.tmp/` and `RECORD/` are the record,
`ui/` is driven, not type-checked, until `ts-rs` lands). Driven instead,
against a real recording:

```sh
target/debug/luu chat --script RECORD/runs/2026-09-14.prune-results/script.txt \
  --backend mock --mock-delay-ms 0 \
  --mock-reply 'looking
```tool
{"name": "read_file", "arguments": {"path": "crates/agent-core/src/context.rs"}}
```' --mock-reply 'Noted.' --mock-cycle \
  --context-limit 8192 --reserve 512 --sandbox luu.toml \
  --prune-behind --prune-results \
  --record run.jsonl
```

confirms the wire carries what the code assumes:

```json
{"channel":"trace","at_ms":21,"message":{"type":"pruned","turn":5,"turns":[1],"tokens":2047,"counter":{"kind":"approximate"}}}
```

Then the real `store.js` — imported into Node with `location` and
`requestAnimationFrame` shimmed, the two browser globals its module scope
touches — played the recording back through `playFixture()` against that file
served over a local static server. `state.pruned` and `panel().cited` both
landed on the run's last prune event (turn 20, citing turn 16), and
`state.history.find(t => t.turn === 5).cited` carried the same shape read back
through `fromStored`, matching turn 5's `pruned` line exactly (turn 1 cited,
2047 tokens, approximate counter). Live and stored paths both confirmed against
the actual reducer, not a re-implementation of it.

## Still open

- **Reloaded evicted messages don't show as evicted.** Found while rejecting
  the message-marking option above — `fromStored`'s message loader ignores
  `t.evicted_by` unconditionally. A pre-existing gap, not this record's to
  fix, but worth a row of its own before it is forgotten a second time.
- **Whether a person reading the panel understands "cited" without the doc
  comment behind it.** The wording leans on `dropped`'s "for good" contrast to
  carry the distinction; nobody has read it who did not already know rule B/C
  exists.
