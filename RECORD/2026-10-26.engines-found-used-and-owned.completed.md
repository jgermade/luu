# Engines: found, used, and owned

Asked from Settings → Engines, in four messages:

> *Cada motor debe mostrar si es copia local (`luu:`) o preexistente del
> sistema, dando la opción a instalar/desinstalar la copia local. Su output,
> mejor en una SubModal con la salida highlighted.*
>
> *Sobre los motores de inferencia preexistentes, los ya instalados, deberían
> aparecer directamente, sin la opción de quitar. Solo editar y arrancar, y
> estas acciones, mejor con iconos.*
>
> *De hecho, en lugar de quitar, podemos tener la opción: usar/no usar.*

And, asked back: *usar* writes the engine **and** a provider that starts it;
*no usar* keeps the table with `enabled = false`.

## The problem

**An engine exists only once somebody has written it.** The pane lists
`[engine.*]` and nothing else, so a `llama-server` Homebrew installed, or the
Ollama app, is invisible until a person opens *+ engine*, picks *found on this
machine* from a select, and saves. What the machine already has is the cheapest
engine there is, and it is the one the pane makes hardest to reach.

**Where a binary comes from is a word in a row.** *Binary: luu's own copy* or
*found on this machine* sits under the header, beside a path. The difference
decides what luu may do to it — it may delete its own copy, and never a
system's — and it is the least visible thing on the card.

**luu's own copy can be downloaded and not removed.** A release is 12–160 MB
per version and variant, and the only way to get the space back is `rm -r`
under the state directory.

**Remove is the only way to stop using one**, and it throws away the port, the
model and the arguments, which are the part somebody tuned. For an engine the
machine found, removing it is also a lie: it is still on the machine.

**The output is a 10rem box inside the card**, unhighlighted, so a load that
failed reads like a load that is printing progress.

## The proposal

**The pane lists what the machine has, not only what the file says.**
`/api/engines` gains `discovered`: every binary `engines::discover` finds for
each kind that no configured engine already resolves to (compared after
`canonicalize`, so Homebrew's symlink and its target are one). Each is drawn as
a card of its own, *not used*, under the kind's name.

**Each card says where its binary comes from**, as a badge in the header:
`luu:` for luu's own copy — the alias every path under the state directory is
written with — and `system` for one the machine had, each with the path as its
title; `path` for a binary the file names that is neither. The server decides
it (`origin` on `EngineView`): a managed binary, or one that resolves under
`engines::root()`, is `luu`; one `discover` finds, or an absent `binary`, is
`system`.

**Use and don't use, never remove.** A switch on every card:

- *on* for a found binary writes `[engine.<kind>]` with that `binary` path and
  `[provider.<kind>]` that starts it — what *+ engine* writes with its
  checkbox on — and the card becomes a configured one. A name already taken
  gets `-2`, `-3`.
- *off* for a configured one writes `enabled = false` into its table and stops
  it if luu started it. *on* writes the key away again. Nothing else in the
  table moves.

`enabled = false` means luu **does not start it**: `Supervisor::ensure`
refuses with *engine `<name>` is not in use: switch it on in Settings →
Engines*, so a session sent there says why instead of failing to connect; and
`start_engine` refuses the same. Its providers **leave the pickers** —
`ProvidersView` gains `idle`, the profiles whose engine is off, and the model
picker, its provider list and the sessions dialog leave them out — and stay in
Settings → Models, where a provider is edited. The key follows `ModelEntry`'s
`enabled`: absent is on, and only `false` is ever written.

**luu's own copy can be uninstalled.** `POST /api/engines/uninstall` with the
same `{kind, version, variant}` as install removes that copy's directory, and
is refused while an engine luu started runs from inside it. On a card whose
binary is `managed`, an install icon while the copy is missing and an
uninstall icon once it is there; the table is kept, so installing again brings
it back as it was. **A version or variant the page sends is checked as a name**
— letters, digits, `.`, `_`, `-`, `+`, not starting with `.` — for install as
well as uninstall: it is joined into a path under the state directory, and
install had been taking it as it came.

**Actions are icons**: start ▶ / stop ■, the output, edit ✎, install and
uninstall, each with its word as `title` and `aria-label`. *Remove* goes.

**The output opens in a `SubModal`**, over the Settings pane it belongs to,
with each line coloured by what it says — an error, a warning, a line luu
wrote (`[luu]`), and the rest — and kept to the bottom while it grows. The
card keeps no log box; the output icon shows how many lines there are.

## What it costs

- One more `discover` per kind on every poll of the pane — it already ran, for
  the form's *found* list. The comparison against configured engines is the new
  work, a `canonicalize` per binary.
- A key in `[engine.*]`. Additive and optional, so a file without it loads as
  before and an older luu refuses a file with it (`deny_unknown_fields`) —
  which is right: an older luu would start an engine somebody switched off.
- A configured engine can no longer be deleted from the page. That is the ask:
  *no usar* is the way out, and a table with `enabled = false` is a table
  somebody can switch on again. Deleting it is an edit of `config.toml`.

## Rejected

- **Writing found engines into the file on sight.** The pane would edit
  `config.toml` by being opened, and an Ollama app the person never meant luu
  to run would become an engine luu starts.
- **Deleting the table on *no usar*.** Asked and answered: the tuning is the
  part worth keeping.
- **Highlighting the log with the server's tree-sitter.** There is no grammar
  for a log, and the question a reader asks of one is which lines went wrong —
  a line's colour, not a token's.
- **An uninstall on a `system` card.** luu did not put it there.

## Still open

- Two found binaries of one kind, `/opt/homebrew/bin/llama-server` and
  `~/.local/bin/llama-server`, are two cards named `llama` until one is used:
  the second to be used becomes `llama-2`.
- A downloaded copy no engine names (an old version) has no card, so no
  uninstall; it shows in the pane's foot as a directory, as before.

## Built, the same day

As proposed, with these differences:

- **The output sheet is not kept to its end.** The `SubModal`'s body is the
  scroller, and a second `Scrollable` inside it, which is what *kept to the
  bottom* would have needed, nested two scrolling boxes in one sheet. The
  sheet opens at the top, on the command luu ran.
- **A found card has a start icon, disabled** until it is used, with *switch it
  on to start it* as its title — asked for as *editar y arrancar*, and a click
  that wrote a table and started a server in one would have been the one
  action on the pane that did two things.
- **The tables are written by one function** (`tableOf` in `lib/engines.js`),
  shared by the pane and the form. Both had their own, and neither knew
  `enabled`: saving any engine from the form would have switched every other
  one back on.

Tested: `engines::tests` — a tag is a name (`../../etc`, `..`, `.hidden`, and
an empty one refused), and an engine switched off is refused by `start` and by
`ensure` before anything is downloaded for it; `provider::tests` — the key
round-trips, written only when `false`. `settings.spec.js` — the added engine's
icons, its output in the sheet with the command line coloured, and *path* as
its origin; and, last in the file, a binary put on the server's `PATH` that
shows as *system*, is used (its table and provider in `config.toml`), switched
off (`enabled = false` once, the provider in `idle`), and a copy of luu's own
laid out under `engines/llama/b11236` that the card uninstalls while
`[engine.own]` stays.
