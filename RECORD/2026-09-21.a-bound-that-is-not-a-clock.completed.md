# A bound that is not a clock

Row 34 of [`ROADMAP/2026-09-21`](../ROADMAP/2026-09-21/), and it is the smallest
row in that file. It is first in its section anyway, for the reason the roadmap
gives: every other row in section C ends in *the workspace is green*, and a test
that fails under load and passes ten times after is what makes the next real
failure arguable.

## The test, and what it is actually for

`a_recording_that_spans_sessions_carries_a_header_for_each`
(`crates/luu/tests/serve_ws.rs`) drives item 23: a `--record` file that spans two
sessions carries a header for each, and **a header declares what the lines under
it are counted from**. The second half is the one at issue. `at_ms` is an offset
from the header above it (`record.rs`: *Unix milliseconds. Every later line is
relative to this*), so the test has to tell two worlds apart:

- **re-based** — a line under the second header reads `now - second.started_at`;
- **not re-based** — it reads `now - first.started_at`, which is the defect item
  23 closed.

The two differ by exactly the gap between the headers, which is why the run
sleeps before starting the second session: it makes the gap bigger than any turn
this mock can take.

## The defect: the discriminator was spent as a bound

```rust
const WAITED: u64 = 400;
tokio::time::sleep(Duration::from_millis(WAITED)).await;
// ...
assert!(
    after.iter().all(|at_ms| *at_ms < WAITED),
    "every line under the second header is counted from it: {after:?}",
);
```

One constant does two jobs. As a *sleep* it is a separation between two bases and
it is the right idea. As a *bound* it is a claim that **the second session
produces all of its lines within 400 ms of wall clock** — a websocket handshake,
a prompt, a mock reply and the trace lines under it — which is true on an idle
machine and is not a property of anything this test is about. It failed twice in
one afternoon on a loaded checkout and passed the ten workspace runs after, which
is the signature.

[`the-drafts-floor`](2026-09-21.the-drafts-floor.completed.md) §Still open left it
rather than raising the number, on the grounds that raising a bound written for
somebody else's reason is somebody else's decision. That was right about the
caution and wrong about the fix available: **the number does not want raising, it
wants removing.**

## The proposal: measure the thing the bound was guessing

The reason a wall-clock bound looked necessary is that the test compares a
recorded offset against nothing. It has the other term available and does not
take it. After the turn, the second session has been alive for a knowable number
of milliseconds, on the same clock the recorder uses (`session::now_ms`, which
`serve.rs` subtracts `session_started_at` from to make every `at_ms`):

```rust
let alive = luu::session::now_ms().saturating_sub(started_at);
assert!(after.iter().all(|at_ms| *at_ms <= alive));
```

Under the defect each line reads `alive + gap`, where `gap` is the distance
between the two headers' bases. So the assertion still fails on the code the test
was written against, and it **cannot** fail for being slow: load moves `alive`
and the lines it bounds by the same amount, in the same direction, on the same
clock. The bound stops being a claim about a machine and becomes an arithmetic
identity about two offsets.

`WAITED` keeps its real job under a name that says it: the separation between the
bases, asserted from the file rather than assumed from the sleep —

```rust
assert!(second.saturating_sub(first) >= APART);
```

which is the sentence *the discriminator has room*, and is the only thing the
sleep was ever needed for.

## What it costs

- **A public function used from an integration test.** `session::now_ms` is
  already `pub` in a `pub mod`, so nothing widens. Using the recorder's own clock
  rather than `SystemTime` in the test is the point: two clocks would reintroduce
  a comparison between two machines' ideas of now.
- **A slightly weaker assertion.** `at_ms <= alive` allows a line to be recorded
  later than the test thinks; `at_ms < 400` did not. The lost strength is a claim
  about latency, which this test never set out to make and which nothing else
  reads. What it keeps is the whole of item 23: *counted from the header above
  it*.
- **`alive` is measured where it is tightest**, right after the socket block —
  every `at_ms` is computed when its event is handled (`serve.rs`), so no line
  can be stamped after the last message this test waits for.

## What was rejected

- **Raising 400 to 2000.** Cheapest diff, and it buys time rather than
  correctness: a bound that is wrong in principle is wrong at any value, and the
  next loaded runner finds the new number. It is also the change
  `the-drafts-floor` declined to make, and declining it twice with a better
  option in hand would be a worse record than making it.
- **`tokio::time::pause()` and a virtual clock.** The recorder reads
  `SystemTime`, not tokio's timer, so pausing moves the sleep and not the
  offsets. It would make the sleep free and the assertion meaningless.
- **Dropping the timing assertion and keeping the metadata one.** The bases are
  the half of item 23 that had the bug; the posture half was never wrong. Keeping
  only the easy half is how a test stops covering what it was written for.

## Still open

- **Nothing else in the tree asserts on `at_ms`** — one grep, one call site — so
  this is a fix and not a pattern. If a second one appears, the identity above is
  the shape to copy rather than the constant.

## Appended 2026-09-21, second section: built, and the row was half a row

The proposal above survived unchanged and was not the whole fix. What follows is
what building it found.

### 1. There were two flakes in this test, and the roadmap named one

The bound went in, the test passed, and it passed under load — then failed under
*more* load, on a different assertion:

```
assertion `left == right` failed: two sessions, a third, and a resume:
  [1790000075852, 1790000076739, 1790000076792]
  left: 3   right: 4
```

Three headers where the file should hold four. **The recorder writes on its own
task** — `Recorder::create` spawns it, one `write_all` and one flush per line —
so a line is not in the file the moment the request that produced it returns.
The test reads the recording immediately after the resume's `POST` comes back
and had been assuming the writer had run.

This is the only test in the suite that reads a recording **out from under a
live server**. Every other `read_record` — `store_parity`, `edit_reread_probe` —
reads a file a `luu` process has already exited from, where the writer is
finished by construction. One test, one exposure, and it is the same test the
wall-clock bound was in. Two independent races in one function is what *twice in
one afternoon and not in ten runs since* was actually describing.

### 2. Waiting for headers is not waiting, and the load said so one level down

The first helper polled until the file held *n* headers. Under 48 busy loops on
four cores it produced:

```
the second session recorded nothing
```

The headers had landed and the turn's lines had not. So the helper takes the
caller's own predicate rather than a count — *two headers and a line under the
second* for the first read, *four headers* for the second — and the assertions
stay exact and stay at the call site. **A poll for the wrong condition is a
slower version of not polling**, which is worth writing down because the first
version looked like the fix and passed on an idle machine.

### 3. The numbers, each confirmed against its absence

| | |
| --- | --- |
| **The old bound under load** | 48 busy loops on 4 cores, `at_ms < 400` restored: **6 runs, 6 failures** |
| **Both fixes under the same load** | **6 runs, 6 green**, and 5 more at a third of that load |
| **The bound still catches item 23's defect** | Recorder re-base commented out: `[458, 460, 460, 460, 461, 461, 461, 463] against 44` — exactly one `APART` over, as the identity predicts |
| **The workspace** | `cargo test --workspace`: 515 passed, 0 failed; `cargo fmt --all --check` and `RUSTFLAGS=-Dwarnings cargo clippy --workspace --all-targets` clean |

The third row is the one the argument owed: the new assertion fails on the code
the test was written against, so nothing was traded for the robustness.

### 4. One wrong turn worth recording

The first attempt to reproduce the defect commented out
`*app.session_started_at.lock().await = started_at` in `serve.rs` — and the test
passed. That field is the **live view's** base, not the recorder's; the recorder
carries its own `AtomicU64`, set by `Recorder::session`, which is the half item
23 moved. Two bases with one name between them, and the wrong one is the one a
grep finds first. The doc comment on `Recorder::started_at` already says *the
header above it, not the process* — it is right, and it is not where somebody
looking for "where does a session's clock start" lands.

## Still open, after building it

- **Nothing else reads a recording from under a live server**, so `recording_once`
  has one caller. It is in the test file rather than a helper crate for exactly
  that reason, and the second caller is the one that should move it.
- **The ten-second deadline is a wall clock**, and it is the one place a number
  survives. It bounds *the writer task never ran*, which is a hang rather than a
  slow machine, so it is a different kind of claim from the one this record
  removed — but it is still a number, and a machine slow enough would fail it.
- **The `after` set is everything under the second header to end of file.** It
  happens to be one turn's worth because nothing else runs before the read. A
  future line added between the turn and the read would be silently included.
