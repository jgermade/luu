# The isolation run in the image, and the three things it found

> Check isolation in the published image, and test with a real mail server.
> Both need to happen before a second person uses it.

Row 70 of [`ROADMAP/2026-09-23`](../ROADMAP/2026-09-23/README.md), owed by
[`a-user-a-code-and-a-folder`](2026-11-03.a-user-a-code-and-a-folder.completed.md):
`exposure = "public"` in the release's image, two users, and a *command* in
one user's session trying what is not theirs, held by Landlock and nothing
else. Row 64's two gaps (a cargo home per user, signals) were to be checked
the same afternoon. Both were real, and a third thing was found that nobody
had listed: in the image no `cargo build` could link. All three are fixed
here, and the same run passes on this branch. It is `completed`: the run
was its purpose, and it ran.

## How it was run

**The image.** v0.1.6 was released at 12:50 UTC (row 69). Its image is
public — the manifest answers without a login — but its layers are served from
`pkg-containers.githubusercontent.com`, which this environment's network
policy refuses. So the image was rebuilt here from `deploy/Containerfile.release`'s
final stage ([`Containerfile.run`](runs/2026-11-04.isolation-in-the-image/Containerfile.run)):
the same base, user, `ENV`, volumes and entrypoint, `deploy/luu.toml`, and the
release's own Linux binary, checked against `SHA256SUMS`. Two differences:
ripgrep is copied rather than installed with apt, and there is no kubectl,
which only the `kubernetes` runtime uses (the build container cannot reach
`dl.k8s.io` through this environment's proxy). Nothing here is luu's own build
until the fixes.

**The users and the command.** Two users, `ana` and `bo`, each with a `secret`
in their folder. A user's session does not take `serve --mock-reply` (that
script is the server's own session's), so the provider is a scripted
OpenAI-compatible server on the host
([`fake-model.py`](runs/2026-11-04.isolation-in-the-image/fake-model.py)):
a plan, then one `run_command`, then *Done*. The client logs in with
`luu user code`, opens the socket, approves the plan and says *now*
([`probe.py`](runs/2026-11-04.isolation-in-the-image/probe.py)).

The command is `git`, which the image's policy allows, as `git -c
alias.probe='!…' probe`: git runs the alias with `/bin/sh`, so one call is a
shell held to exactly what the session's command is held to. Any granted
program that runs others (cargo's build scripts, a test binary) reaches the
same place.

**The plan is the widest the policy allows** (`.` and `/state/cargo`, read
and write). On a server with users a user approves their own plans, so the
policy file is the bound, not the plan. The first run used a plan with no
writes, and it narrowed the session's own folder too
([`0-…narrow-plan.txt`](runs/2026-11-04.isolation-in-the-image/0-release-0.1.6-narrow-plan.txt)).
That is right, but it proves less.

## What did not

**1. Signals.** `kill -0 1` succeeded: pid 1 is `luu serve`, so one user's
command could stop the server for everyone, and could signal any other
session's command, all being one uid. Known since
[`a-user-a-code-and-a-folder`](2026-11-03.a-user-a-code-and-a-folder.completed.md)
*Still open*; confirmed.

**2. `/state/cargo` is one folder every user's commands could write *and run
from*.** `read-write` is every right Landlock has, execute included, and
cargo reads `$CARGO_HOME/config.toml` on every invocation. Known as "a cargo
cache one user's build could leave something in for another's"; what it
really is was shown by three runs
([`2-…cargo-shared.txt`](runs/2026-11-04.isolation-in-the-image/2-signals-and-tmpdir-cargo-shared.txt)):
- ana writes `/state/cargo/config.toml`, a `runner = ["/state/cargo/runner"]`
  for the host target, and the runner;
- bo runs `cargo run` on his own project, as any day;
- cargo execs ana's runner *inside bo's sandbox*, which reads bo's folder and
  can write `/state/cargo`; it copies his `secret` there;
- ana reads `bo-secret`.

**3. No `cargo build` linked in the image.** Bo's `cargo run` in 0.1.6 never
reached the runner. `cc` aborted with `Cannot create temporary file in /tmp/:
Permission denied`: a command's environment had no `TMPDIR`, and the policy
grants no `/tmp`. The draft floor writes the system's temporary folder,
which is why nobody saw it; an approved job does not. The image's one
compiler was usable for `cargo check` and nothing that links.

## What changed

**Signals are scoped** (`sandbox/linux.rs`): the ruleset asks for
`Scope::Signal`. From ABI 6 a held command signals its own children and
nothing outside its domain. The crate drops the scope on an older kernel, and
the verdict says `(signals scoped)` only where it held. Abstract unix sockets,
ABI 6's other scope, are not asked for: with the network off seccomp refuses
every socket, and with it on they are the network. A test runs `kill -0`
against a process outside the sandbox and `kill` against the command's own
child. It fails without the scope.

**`[sandbox.env]`** (`sandbox/policy.rs`, `tools/command.rs`): what a
command's environment says over what it inherits. A value that is `.` or
starts with `./` is resolved against the session's folder; anything else is
passed as written. It is set last, carried through a plan's narrowing (a
plan has no words for it), sent to a worker with the rest of the policy, and
listed by `luu tools`.

**`deploy/luu.toml`** sets `TMPDIR = "./.tmp"` and `CARGO_HOME =
"./.tmp/cargo"`, and no longer grants `/state/cargo`. `.tmp` is the scratch
luu already makes at the top of every session's folder, gitignored. So a
compiler's temporary files and cargo's home are each session's own, inside
the `.` the user already has. The startup warning about a path every user can
write is gone, because there is none.

## The same run on this branch

[`3-this-branch.txt`](runs/2026-11-04.isolation-in-the-image/3-this-branch.txt),
the image above with this branch's binary (built in `rust:1-bookworm`, whose
glibc the image has) and policy:

## What it costs

- **A cargo home per session, not per user.** A user's two sessions build
  their own caches. With the network off (the image's default) there is
  nothing to fetch. With it on, each session fetches its crates once.
- **Temporary files land in the session's folder**, under `.tmp`, which is
  ignored by git and is already where a draft writes.
- **A kernel before 6.12 still lets signals out.** The verdict shows it
  (no `(signals scoped)`). Nothing refuses to run there, as nothing refused
  before Landlock had `Truncate`.

## Rejected

- **A cargo home per user, at `<root>/<user>/.cargo`.** It is outside a
  session made in a subfolder, so it needs a grant beyond `.`. Within the
  user's own folder it is harmless, but it is still a second grant for every
  deployment to write down, to save a cache the network-off default never
  fills.
- **`TMPDIR` set by luu itself**, without the policy saying so. It would
  work, and it would be a grant a reader has to infer, which is the one
  thing `SYSTEM_ROOTS` is listed by `luu tools` to avoid. The deployment's
  file says where scratch goes, as it says everything else.
- **Refusing any writable path outside the root in `public`.** That is right
  for `/state/cargo`, and `deploy/luu.toml` no longer has one. But it is a
  deployment's file, and a deployment that shares a read-only toolchain cache
  on purpose should be told, not refused. The startup warning stays.

## Still open

- **The published bytes.** This ran on an image rebuilt from the release's
  Containerfile and binary, not on the layers pulled from `ghcr.io`. That
  needs `pkg-containers.githubusercontent.com` reachable, which the
  environment's settings allow. The next release's image carries the fixes,
  so it is the one worth pulling.
- **`/etc` is readable**: the container's own, as a system root for every
  command. Nothing of a user's is there. Mounted secrets are refused under it
  (`mail::refuse_where_commands_read`).
- **The chart's pod per session** has its own `/tmp` and home. `TMPDIR` now
  points it at the claim's `.tmp` instead, which is the session's own and
  changes nothing about who reaches it. Not run, because there is no cluster.
