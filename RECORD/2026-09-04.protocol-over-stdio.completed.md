# The protocol over stdio

**Status:** a proposal and the code it plans. It is item 7 of
[`ROADMAP/2026-09-01`](../ROADMAP/2026-09-01/README.md), decided in
[`RECORD/2026-09-01.how-a-surface-reaches-the-engine.completed.md`](2026-09-01.how-a-surface-reaches-the-engine.completed.md).

[`how-a-surface-reaches-the-engine`](2026-09-01.how-a-surface-reaches-the-engine.completed.md)
decided that the editor surface (e.g. VSCode extension) talks to `luu` spawned as a
subprocess over standard input/output (`stdio`), rather than attaching to a shared
HTTP/WebSocket port.

## Why stdio

1. **No port, no bearer token, no exposure:**
   A local socket carrying `approve_task` grants filesystem reads, writes, and
   command execution. On loopback it is open to any process on the machine; off
   loopback it requires token gating. stdio has no socket and no port to collide
   when multiple editor windows are open.
2. **One process per window:**
   Each editor window manages its own `luu` child lifecycle. Killing the editor
   window drops standard input and cleans up the engine and any container worker
   tied to it.
3. **Identical message protocol:**
   [`ClientMessage`](../crates/agent-core/src/protocol.rs) and
   [`ServerMessage`](../crates/agent-core/src/protocol.rs) were designed for this
   from day one: line-delimited JSON (NDJSON) over standard streams.

## The interface

```
stdin  <-- ClientMessage (NDJSON)
stdout --> ServerMessage (NDJSON)
stderr --> diagnostic logs and warnings
```

On startup:
The engine sends `ServerMessage::Hello { protocol, backend, model, turn }` immediately.

Input loop:
Reads lines from standard input and maps them to the same task and turn lifecycle
as `luu serve`:
- `Prompt`: enters planning call (if ungated/unplanned) or runs turn (if task is open).
- `ApproveTask`: widens plan within policy file limits, approves task, runs held prompt.
- `RejectTask`: drops held prompt and marks proposal rejected.
- `CloseTask`: folds completed turns into task summary.
- `ReopenTask`: unfolds task turns.
- `Cancel`: aborts active turn in flight.

Output loop:
Broadcast events from the engine serialize as single-line JSON on `stdout`.
Stderr is reserved for human diagnostics and warnings so that stdout remains pure
protocol frames.
