# Connecting a provider

The provider form asks for seven things in a column — name, backend, URL,
model, window, tool calls, key — and offers *Test* beside the model as an
afterthought. Jesús, asking for it to be rebuilt:

> mostrará los campos: name, backend, URL? (se muestra si el backend lo
> requiere), key? […] <botón>Conectar<>
>
> una vez conectado, colapsará la configuración en un resumen […] debajo de
> esto, habiendo recuperado el listado de modelos, dará la posibilidad de
> elegir una ventana de contexto para cada modelo […] un listado de los
> modelos, que funcione como checkbox, para elegir el modelo por defecto,
> permitiendo no elegir ninguno […] si los modelos no soportan tools,
> agruparía primero los que lo soportan, y luego los que no; tendríamos un
> check para desactivar los que no lo soportan; si no se desactivan, se
> mostrará un warning indicando que se usará fenced con esos modelos

It is the order the form should have had: [`probing-a-destination`](2026-10-20.probing-a-destination.completed.md)
argued that the form writes a destination it has never spoken to, and fixed it
with a button. This makes speaking to it the form's first step, and lets
everything after it be filled in from the answer instead of typed.

## What a server can say, checked

Against this machine's own servers on 2026-10-21, not from documentation:

| Server | Window | Tools |
| --- | --- | --- |
| Ollama 0.33, `POST /api/show` | `model_info.<arch>.context_length` — **the training maximum**: 32 768 for `qwen2.5-coder:7b`, 262 144 for `gemma4:26b-mlx` | `capabilities: ["completion", "tools", …]` |
| llama-server, `GET /props` | `default_generation_settings.n_ctx`, the window it was started with (32 768); `/v1/models` adds `meta.n_ctx_train` | `chat_template_caps.supports_tools`, `supports_tool_calls` |
| vLLM, `/v1/models` | `max_model_len` (already read by `window()`) | nothing: it depends on flags the server was started with |
| hosted (MiniMax, OpenAI) | not in `/v1/models` as far as known | nothing |

LM Studio and mlx-serve are unverified: mlx-serve was not running, and no LM
Studio is installed here.

Two consequences, and they shape the proposal more than the screen does:

- **The window is not one thing.** On Ollama luu *chooses* it per request
  (`num_ctx`), so a number per model is a real setting. On llama-server and
  vLLM it is the *server's*, one model and one `n_ctx`, and a larger number in
  the form is a lie found on the first long turn. On a hosted API it is the
  model's maximum, rarely published, and what luu can choose is a **budget**
  under it. And Ollama's `context_length` is the most the model was trained
  for, not what Ollama uses when nobody asks — a form that showed it as *the
  window* would describe a request luu does not make.
- **Tool support has three answers, not two**: yes, no, and *nobody said*.
  vLLM and every hosted API are the third, and grouping them with *no* would
  state something nothing checked.

## The proposal

### The form, in two halves

```
 Name      [ local           ]
 Backend   [ Ollama        ▾ ]
 URL       [ http://127.0.0.1:11434 ]      only where the backend has one
 Key       [ ••••••••        ]             openai only, optional
           [ Connect ]  [ Save without connecting ]
```

**Connect** is the probe of `probing-a-destination`, asked more: the list,
and per model what the server says of its window and of tools. It writes
nothing. On an answer the first half folds into one line and a *Change*
under it:

```
 local · Ollama · 127.0.0.1:11434 · 6 models              [ Change ]
```

**The key** is shown for `openai` always and optional, because a backend kind
cannot say whether a server wants one — llama-server does not, MiniMax does.
A `401` from Connect focuses it, with the server's own message.

**Save without connecting** stays, for the reason the existing route gives: a
server that is off is the ordinary state on a laptop, and a model not pulled
yet is a legitimate thing to write down. It saves the first half and nothing
the second half would have asked.

### The models, once connected

```
 [x] Same window for every model   [ 16384 ]

 Default model — none chosen: the first listed
 Tools ─────────────────────────────────────────
 ( ) qwen2.5-coder:7b        [ 32768 ]  up to 32 768
 (•) qwen2.5-coder:32b       [ 32768 ]  up to 32 768
 Not said ──────────────────────────────────────
 ( ) some-model              [       ]
 No tools ──────────────────────────────────────
 ( ) old-model               [  8192 ]
 [ ] Leave out the models without tools
 ⚠ old-model will use fenced tool calls: luu's own format, in the prompt.
   Measured on qwen2.5-coder:7b, fenced made 7 of 15 calls and native 15.
```

- **The default is a radio that can be cleared**: none chosen means what it
  means today, *the first listed*, through the precedence the picker already
  has (last used with this profile → the profile's → the first listed).
- **The window input is prefilled from the server and does not go past it.**
  On Ollama it is a choice up to the training maximum; on llama-server and
  vLLM it is read and can only be lowered — what is saved is then a budget,
  and the form says so; with nothing said it is empty and optional.
- **Three groups**, *tools*, *not said*, *no tools*, the last only when
  something is in it. The check leaves out the third; the warning names its
  models and the measurement it rests on
  ([`native-tool-calls`](2026-09-30.native-tool-calls.completed.md)).
- **Editing opens folded**, on the saved values, with the models from
  `GET /api/providers/{name}/models` — the request the chat's picker already
  makes. Nothing is asked that a person did not ask for.
- **A provider whose `engine` luu starts** does not connect: its list is this
  machine's models, and the form points to Settings → Engines.

### What `config.toml` gains

**Exceptions, not a catalogue.** Nothing in the file enumerates what a
provider offers, and nothing should — a model pulled tomorrow appears with
the defaults, without an edit:

```toml
[provider.local]
backend = "ollama"
model = "qwen2.5-coder:32b"     # the default; absent = the first listed
context-limit = 16384           # "same window for every model"

[provider.local.models."qwen2.5-coder:7b"]
context-limit = 32768           # only the ones that differ

[provider.local.models."old-model"]
enabled = false                 # left out: not offered by the pickers
tool-calls = "fenced"
```

- `models.<name>.context-limit` wins over the profile's, which wins over
  nothing — the same precedence one level down. *Same window* checked writes
  the profile's and removes every model's.
- `models.<name>.tool-calls` is **written by the form from what the server
  said**: `native` where the model has tools, `fenced` where it has none,
  nothing where nobody said, which falls to the profile's `tool-calls`. The
  decision lives in the file, where a run can resolve it without asking
  anyone; the server is consulted when a person is looking, not when a
  session starts.
- `enabled = false` takes a model out of the chat's picker and the session
  starter. **`-m` still reaches it**: naming a model is choosing it.
- A file without `models` tables means exactly what it means today.

## What it costs

- **A format change**, small and additive: `Profile` gains a map, and the
  loader, the writer and the view carry it. The probe's answer gains a shape.
- **N requests on Ollama**, one `POST /api/show` per model, on a Connect.
  Six here; a machine with fifty pays fifty, so they go out together, under
  the probe's timeout, and a model whose answer does not arrive is *not said*.
- **The resolved tool transport becomes per model**, so `Resolved` reads two
  levels. `--tool-calls` still wins over both, as it wins over the profile
  today.
- **The form is rewritten**, and the smoke spec that drives *Test* with it.

## What was rejected

| | |
| --- | --- |
| Storing the list of models | A catalogue goes stale the day a model is pulled or removed, and it contradicts the picker, whose second column *is* the server's list. |
| Asking the server for capabilities when a session resolves | `Resolved` is built without network — the reason `probing-a-destination` already gave. The form asks; the file remembers. |
| Grouping by *has tools* / *has not* | Puts every hosted model in *has not* on no evidence. |
| An editable window above what llama-server reports | The server's `n_ctx` is a fact, and a larger number is a budget the server cannot honour. |
| Showing Ollama's `context_length` as the window | It is the training maximum; Ollama uses its own default unless luu sends `num_ctx`. It is the input's ceiling, not its value. |
| Connect as the only way to save | Locks out the laptop whose server is off, and the model not pulled yet. |

## Still open

- **What MiniMax's `/v1/models` carries** beyond ids, and whether LM Studio
  and mlx-serve say anything — to be read when the probe is extended, not
  assumed.
- **What an empty window means on Ollama.** Today luu sends no `num_ctx` and
  Ollama picks; the form could show Ollama's own default if the server says
  it anywhere. Not checked.
- **llama-server's `supports_preserve_reasoning`** is the server saying
  whether it wants the thinking back — the open question in
  [`a-call-written-while-thinking`](2026-10-21.a-call-written-while-thinking.completed.md).
  The probe will have it in hand.
- **Disabling a model that is a session's current one**: the session keeps
  it; the pickers stop offering it. Whether the page should say so is not
  decided.
