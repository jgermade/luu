# One site chooses what holds a turn

Row 43 of [`ROADMAP/2026-11-08`](../ROADMAP/2026-11-08/README.md): *the two
sites that choose the floor decide differently*. Left open by
[`what-an-unapproved-turn-may-reach`](2026-09-21.what-an-unapproved-turn-may-reach.completed.md)
§1 and §Still open, after building it. The roadmap's next move was *a test that
tries*.

## The problem

Two functions choose the sandbox a turn runs under, and they had two answers:

```rust
// begin_turn — what the selector reads through, and the authority note
match &session.narrowed {
    Some((_, sandbox)) => sandbox.clone(),
    None => floor_holding(&session, &agency),
}

// start_turn — what the tools run under
match (session.context.live_task(), &session.narrowed) {
    (Some(live), Some((task, sandbox))) if live == *task => sandbox.clone(),
    _ => floor_holding(&session, &agency),
}
```

The record worried about the first one: a narrowing left behind by a job that is
no longer live would hold the selection and not the tools.

## What trying found

**That state is not reachable today.** Every site that ends a job also clears
its narrowing (`close_job`, `close_if_met`), every site that starts or resumes
one rebuilds it (`approve_plan`, `reopen_job`, the resume, a new session), and
a runtime move refuses while an approved job is open. Only the last job can be
open (`Context::reopen_job`), so there is never a second one to leave a
narrowing behind. The divergence is real in the code and has no path to it.

**The two sites agree on something worse.** Both fall back to the floor when
`narrowed` is `None` — including for a live job **that has a plan**. Three sites
can leave it that way:

| Site | How |
| --- | --- |
| `approve_plan` | `plan.narrow` fails (a path gone between the check and the narrowing). Its comment says *"the job runs with nothing granted"*. It ran on the floor |
| `reopen_job` | the same `narrow`, through `.ok()` |
| the resume | the same, through `.ok()?` |

And one window: `approve_plan` released the lock after `Context::approve_plan`
and set `narrowed` only after the fold was published. A prompt in between ran
job *n*'s first turn on the floor.

The floor is the policy file downgraded to reads. On this repository that is
`.` at `read`: the whole tree, for a job a person approved to read
`Cargo.toml`. That is the design doc's *"checking the plan against the policy
and then running with the policy makes the plan a comment"*, at read strength.
The authority stamp made it quieter, not louder: `floor_holding` declines to
call it a draft, so a recording names it `Policy`.

## The proposal

One function, `turn_sandbox`, read by both sites:

| Live job | `narrowed` | Holds the turn |
| --- | --- | --- |
| none | anything | the floor |
| a draft | anything | the floor, stamped with the draft |
| job *n*, with a plan | `(n, s)` | `s` |
| job *n*, with a plan | `None`, or another job's | **nothing**, under `Plan(n)` |

The last row is the change. *Nothing* is `Plan::default().narrow(…, n)`, the
narrowing an empty plan already gets and which `job.rs` pins as *a plan that
declares nothing narrows to nothing*. It fails closed and every refusal says
which job refused, which is what `approve_plan`'s comment already promised.

And `approve_plan` narrows inside the lock it approves under, so the window
closes rather than merely failing closed.

## What it costs

- A job whose plan stopped resolving can do nothing until it is closed and
  replanned. Before, it could read the tree. That is the trade, and the
  `eprintln!` at the approval still names the path that broke it.
- `begin_turn`'s selector, given a stale narrowing, now reads through the floor
  or through nothing instead of through the stale job's plan. Unreachable, as
  above, so free.

## What was rejected

- **Keeping `begin_turn`'s reading and fixing `start_turn` to match.** Trusting
  `narrowed` alone is the one that would go wrong first if a path to a stale
  narrowing ever appears.
- **Falling back to the agency's full sandbox** for a plan that cannot resolve.
  That is the policy file, wider than the floor.
- **Refusing the turn** instead of running it on nothing. It would need a new
  refusal and a page that shows it, for a case a person can already read from
  the denials; *nothing* is what the approval's comment said would happen.

## Still open

- **Why the narrowing failed is in stderr, not on the protocol.** A person sees
  the job's denials and not the path that went missing.
- **`narrowed` still exists beside the context.** It is derivable from the live
  job's plan and the agency, and a field beside the thing it is derived from is
  the shape `Context::current_job`'s doc comment argues against. Deriving it per
  turn costs a `narrow` per turn; not done here.

## What was run

- `an_approved_job_without_its_narrowing_runs_on_nothing` (in `serve.rs`):
  approves a plan for `Cargo.toml`, checks the floor reads it, then holds the
  live job with its own narrowing, with `None`, and with job 1's. The last two
  are denied under `Plan(2)`; closed, the floor reads it again.
- Against its absence: with the last arm of `turn_sandbox` put back to
  `floor_holding`, the test fails at *an approved job never falls to the
  floor*. Restored: green.
- `cargo test --workspace`: **782 passed, 0 failed**.
  `cargo fmt --all --check` and `RUSTFLAGS=-Dwarnings cargo clippy --workspace
  --all-targets`: clean.

Not run: the live-server Playwright specs. Nothing on the page or the wire
changed.
