# Consent is asked when a provider becomes the default

Asked, after the held line came up a second time, for MiniMax:

> *me parece muy lioso, prefiero un checkbox de confirmación cuando se añade
> el proveedor*

and then, before it was committed:

> *espera, en lugar del checkbox, usemos una modal de confirmación cuando se
> convierta en default*

## What it was

[`a-default-is-chosen-and-held`](2026-10-26.a-default-is-chosen-and-held.completed.md)
split the default from the consent. A click chose the default, and the
consent, `remote = true`, was written by **typing the host back** in a line
over the columns, *after* the click had already written that provider as a
held default. The order was what confused: a click, then an objection, then
something to type, and nothing at the moment of the click said why.

## What it is

- **The question comes with the click.** A click on a model of a provider
  that is not this machine and has not said `remote = true` opens a
  confirmation, *Make MiniMaxAA the default*:

  > **MiniMaxAA** sends to **api.minimax.io**, which is not this machine.
  > As luu's default, every run that names no provider — a new session,
  > `luu chat` with no `-p` — sends its prompts there.
  >
  > Cancel · **Make it the default**

  *Make it the default* writes the default, the model and `remote = true` in
  one write, so nothing is ever held by a click. *Cancel* writes nothing.
- **The browser still never decides what *this machine* is.**
  `GET /api/providers/where?backend=&url=` answers `{ host, this_machine }`
  from `provider::is_this_machine`, the loader's own rule, before anything is
  written. A provider on this machine, an engine's included, is made the
  default with no question. A provider that already says `remote = true` is
  too.
- **A default that is already held** — written by hand, or chosen before
  this asked, as AliOAi and MiniMaxAA were — keeps its line over the columns,
  now with *Confirm…*, which opens the same modal.
- **The provider form asks nothing.** It carries `remote` as the file has it.

## Argued against the record it changes

The typed host was chosen so that *the word is produced by a person answering
the machine's objection rather than by a checkbox the program pre-ticked*.
That much holds. The answer is a person's click on *Make it the default*, in a
modal that exists only to ask it and names the host. What is given up is the
proof that the host was *read*: it could not be typed without being read, and
a button can be pressed without reading what is above it. The owner judged
the friction to cost more than that proof bought. The consent is still
explicit, per provider, and given before anything is sent.

What is gained is the moment. Consent is asked when the provider becomes the
thing it is consent for, the default, and never earlier. A remote provider
that is only ever named with `-p`, or chosen for one session, is never asked
anything.

## Rejected

- **A checkbox in the provider form**, *Send to <host> when it is luu's
  default*, unticked. It was built first, on the first ask, and replaced
  before it was committed, on the second. It asks at the wrong moment: when a
  provider is added, most of them will never be the default, and the box is
  one more thing to read on every remote provider.
- **Writing the held default first and asking afterwards**, the shape this
  replaces. A click whose effect is a warning is the confusion that started
  this.
- **No consent at all.** It is the local-first promise this rule keeps, and
  nothing in either ask argued with it.

## Tested

`settings.spec.js`, *a remote provider becomes the default through a
confirmation*:

- a click on `far-1` under a provider at `models.example.invalid` opens
  *Make faraway the default*, naming the host;
- *Cancel* leaves the file without `default = "faraway"`;
- a second click and *Make it the default* write `default = "faraway"` and
  `remote = true`, show no held line, and move the live session there;
- a file written by hand with that default and no `remote` shows the held
  line, its *Confirm…* opens the same modal, and confirming writes the word
  and clears the line.
