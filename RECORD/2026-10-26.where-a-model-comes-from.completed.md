# Where a model comes from, as a badge

Asked:

> *a la derecha del modelo, en lugar de ' (ollama)' pondremos un badge con
> [luu|ollama], [system|ollama], etc. según corresponda*

## What it was

A model on this machine was named `name (source)`, and the source and the
name were one string. The catalog's `label` read `tiny:1b (ollama)` or
`big:27b-mlx (ollama, mlx)`, and the models route wrote `qwen3:8b (ollama)`
for everything an ollama server listed. That one string said the store a
file sat in, but not **whose** it was. A model served by luu's own copy of
ollama read exactly like one from the ollama the machine already had.

## What it is

A badge to the right of the bare name, in segments, the first saying whose
place it is:

| the model | badge |
|---|---|
| listed by luu's own copy of ollama (`binary = "managed"`) | `luu · ollama` |
| listed by any other ollama (one the machine had, or a provider with no engine) | `system · ollama` |
| a file in the machine's ollama store, Hugging Face cache or llama.cpp cache | `system · ollama`, `system · huggingface`, `system · llama.cpp` |
| a file in luu's own models directory | `luu` |
| a format that is not GGUF | one more segment: `system · ollama · mlx` |
| a model a remote API lists | nothing: there is no place on this machine to name |

`luu` is drawn in the accent, as the Engines cards draw `luu:`. The whole
badge is one title (`system · ollama`), for a screen reader and for a
pointer.

- **The server says which.** The catalog's `LocalModel` carries `badge`
  beside `label`. `GET /api/providers/{name}/models` carries `badges` per
  model, and each unavailable model carries its `badge`. For an ollama
  provider, the first segment comes from the engine's binary: `managed` is
  luu's, anything else is the system's. The page draws what it is given, as it
  does with the brand marks.
- **Names lose their suffix wherever a badge stands beside them**: the
  columns (the chat's picker, the new session's dialog, Settings → Models),
  the greyed models an engine cannot load, the engine sheet's *Start* list,
  and the provider form's rows. `label`, `name (source)` in one string, stays
  in the catalog for titles and log lines, where a badge does not fit.
- `components/origin-badge.html`, self-contained, draws nothing with no
  parts.

## Rejected

- **The badge worked out in the page from a reference's prefix.** The
  prefix says the store, not whose ollama is listing it, and not the format.
  Both are the server's to know.
- **`luu · <format>` for luu's own directory.** A GGUF there would read
  `luu · gguf` while the same file anywhere else reads `system · <tool>`.
  `luu` alone says the one thing that differs, and a format that is not GGUF
  is added the same way everywhere.

## Tested

`settings.spec.js`, 23 passed:

- the engine sheet's *Start* list reads `tiny:1b` and `small-Q4_K_M`, with
  badges `system|ollama` and `system|huggingface`;
- the chat's picker under `fake` has the same names, two badges, the first
  titled `system · ollama`;
- the greyed MLX model is `big:27b-mlx` titled `system · ollama · mlx`;
- `fake`'s form rows have the bare names and the same badge.

A screenshot with an ollama engine on `binary = "managed"` drew `luu ·
ollama` in the accent.
