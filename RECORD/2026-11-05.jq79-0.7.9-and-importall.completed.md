# jq79 0.7.9, `importAll`, and a page that says it is loading

## The question

Jesús: *en la v0.7.9 de jq79 he añadido `.importAll` — agrupar varios imports
hace que con http2 vengan en la misma petición, y mejore mucho el rendimiento;
aplícalo en todos los sitios donde se pueda.* And then: *vendría bien una
animación de carga, con el svg del logo.*

## What changed upstream

Read from `src/` in the published 0.7.6 and 0.7.9 tarballs, diffed: two things.

1. **`Component79.importAll(specifiers)`** — `Promise.all` over jq79's own
   `import()`: an `.html` resolves to the component, anything else to the module
   namespace. A relative specifier is resolved against **the page**, not the
   file that calls it, because a library cannot see its caller; a bare one goes
   through the import map.
2. **`C79` is a setup helper**, beside `Component79`, so a setup script can call
   `C79.importAll` without importing the library.

## What luu did with it

- Every setup script with more than one `await import(...)` now has one
  `const [...] = await C79.importAll([...])`. Thirty-four component files, the
  theme's `demo.html`, and `closeSettings` in `lib/store.js` (which imports
  `C79` beside `$reactive`). `app.html` was 38 sequential awaits and is one.
- Every specifier in an `importAll` is an `@web/` one. The relative ones that
  were there (`./provider-form.html`, `./hunks.html`, `./monaco.js`, …) would
  have resolved against `index.html` and not their own directory.
- Left alone: files with a single import (nothing to group — the six theme
  components that import `./scrollable.html`, `users.html`, `card.html`,
  `context-view.html`, `tool-group.html`, `version-control.html`), the lazy
  `./unzip.js` in `lib/workspace.js`, and the snippets in
  `theme/default/usage.js`, which are text shown to a reader and which
  `theme.spec.js` asserts verbatim.
- What `app.html` ran between its imports (the `?add-key=` check, two `$:`
  lines, `openOutside`) needed nothing from the later ones, so it now runs after
  the one `await`.

**The loader** is the logo, inline in `index.html` beside `#app`: the `l` and
then the `uu` drawn by `stroke-dashoffset`, the dot after them, wiped and drawn
again. It fades in after 150 ms so a fast load never flashes it, and is hidden
by CSS alone — `#app:has(> *) + .boot` — because jq79 appends nothing but
comment markers until a held render paints. `prefers-reduced-motion` gets the
logo still.

## Checked

- `web/vendor/jq79.js` and its map are `dist/jq79.js` and `dist/jq79.js.map`
  from `npm pack jq79@0.7.9`, unchanged; the files they replace were 0.7.6's
  byte for byte. `C79.version` reads `0.7.9` in the page.
- Against `luu serve` on the mock: the page paints with no console error, and
  the loader is hidden once it does. With `app.html` held back four seconds the
  loader is on screen, mid-draw.
- **The live suite: 73 passed, 6 failed.** One (`policies.spec.js:327`) passed
  when run again. The other five fail the same way with these changes stashed
  and the binary rebuilt — a terminal in a container, the icon-pack scan, two
  brand/engine tests and a grant on `run_command`, all about this machine
  (macOS, no runtime started) rather than about the page.
- No request was timed. That grouping makes the first paint faster is the
  premise of the change, not something this record measured.
