## The prose, drawn

A reply was drawn in three kinds of part: tool calls (`segments.js`), fenced
blocks (`snippets.js`, coloured by the server), and the text between them, put
on screen as text with `white-space: pre-wrap`. Models write that text in
Markdown, so it read as marks. `web/helpers/markdown.js` draws it: ATX
headings, bullet, numbered and task lists (nested by indent, tight or loose),
quotes, GFM tables with their alignment, rules, `**strong**`/`__strong__`,
`*em*`/`_em_` (not inside `snake_case`), `~~struck~~`, code spans, backslash
escapes, `[links](…)`, `<autolinks>` and bare `https://` addresses.

**Escaped first.** The text is the model's and is never the page's markup: it
is escaped before any element is made, a code span's text is held out of the
emphasis, and a link is made only when its address is `http:`, `https:` or
`mailto:` — a `javascript:` one leaves its label as text. A tag the model
wrote, `<b>raw</b>`, is shown as those characters.

**A line break stays one.** Markdown joins a paragraph's lines; the reply had
always been shown with its breaks, and a model that breaks a line means it, so
a single newline is a `<br>`. A blank line is a paragraph.

**Partial while it streams**: an unpartnered `**` is two asterisks until its
partner arrives; a table is a table once its rule row has. The reply is drawn
again on every token, so the HTML is kept by text — at most 400, then the
cache starts over — and a part that did not change costs a lookup.

### Only what jq79 keeps

The first version wrote `<table>`, `<hr>`, `<del>`, a disabled checkbox, a
`style` for a column's alignment, `start` on an `<ol>` and `target="_blank"`.
On screen the table was simply gone: jq79's `:html` runs every string through
its sanitiser, which keeps `a`, `b`, `i`, `em`, `strong`, `p`, `br`, `ul`, `ol`,
`li`, `blockquote`, `code`, `pre`, `span`, `div`, `h1`–`h6` and `img`, with
`class` on all, `href`/`title` on `a`, `src`/`alt` on `img`, and gives every
`a` `rel="noopener noreferrer"`. The renderer stays inside that rather than
going around it — the sanitiser is a second line behind the escaping, and
`innerHTML` set by hand would be the one place in the page without it. So:

- a table is `div.md-table-box > div.md-table > div.md-row(.md-head) >
  span.md-cell(.md-right|.md-center)`, laid out by `display: table` in
  `app.css`, the box scrolling sideways when the table is wider than the chat;
- a rule is an empty `div.md-hr`, struck text a `span.md-del`;
- a task's box is a `span.md-box(.md-on)`, drawn with a tick;
- a numbered list that starts past 1 — the one that carries on after a code
  block, `2.` on — writes its numbers in `span.md-n` and hides the markers;
- a link has no `target`, so the transcript opens it itself: a click on an
  `a[href]` in the prose is `window.open(href, "_blank", "noopener,noreferrer")`
  and not a navigation, which would have taken the session's page with it.

The rules are in `app.css` under `.reply-md`, global on purpose: what `:html`
puts in is not reached by the transcript's scoped style, the reason the code's
`hl-*` rules are there too. Inline code is a chip on the chat's lighter grey;
headings are a step or two over the text, never a page title.

## The answer a step smaller, the prompt marked

`article.assistant .text` is `.93em` of the prompt's size — 13px against 14 at
the default zoom, scaled with the chat's own zoom since it is in `em`. Code
blocks, tool cards and the thinking keep their own sizes.

A prompt is marked by `| ` before it: `article.user .text::before`, in
`--luu-black`, a new token in `luu.css` beside the chat's inks, `#333a3e`, the
same in both tones because the chat's grey is (`8.5:1` on `#dddddd`). Drawn by
CSS rather than written into the text, so a copy of the prompt is the prompt
and every test that reads it reads what was typed.
