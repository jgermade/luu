## What is answered that was not this morning

**A recording can say what a session forgot.** Re-recording the fixtures
unchanged gives the first direct reading of the two eviction policies — ten small
cuts under `turn`, two deep ones under `block`, and **none at all** in the tasks
run, where the fold kept the history under the limit. That third number was
already claimed in [`tasks-in-code`](2026-08-30.tasks-in-code.completed.md) and rested on a
bucket that *looked* like it had not moved; it is now the absence of a message.

**The outline is not the whole answer at 8K.** This repository's complete outline
is **6 327 tokens — 77% of an 8K window**. At any budget a real run can afford,
most of the repository is not in the map, and path order picks which part. That
was the open question in the Aider record's own appended correction, and the
answer decides the shape of the next commit rather than leaving it to taste. See
[`2026-08-31.the-repo-map.completed.md`](2026-08-31.the-repo-map.completed.md).

**The planning call is a turn that is never remembered**, so a gated session's
turn numbering and its history's contents diverge from the first task onwards.
Known in principle, never visible; the first tombstone over a socket named turn 2
and made it a fact.

## The finding: we are building instruments faster than we run them

This morning's file named one unrun question. Tonight there are three, and they
are the same shape:

| Written | Needs |
| --- | --- |
| The grounded fold probe (2026-08-27) | run twice, answered — the pattern that works |
| **The gate probe** (`c3ec4db`) | a machine with a model **and a person at the gate** |
| **Does the map buy back its 870 tokens a turn?** (`e95ebf5`) | a machine with a model |
| Replication on 14b/32b, folding at 32K, reuse as *seconds* | a machine with a model |

Three commits today, and **every one of them ends in a protocol for a run nobody
has done**. That is not obviously wrong — the fold's question got answered
*because* its protocol was written first, and both new probes are written in that
form on purpose. But the ratio has changed: the instrument is now well ahead of
the readings, and an instrument that is never read is indistinguishable from one
that does not work.

The honest statement of the debt: **the last real-model run in this tree is
`d1b0e81`, the grounded pair rerun.** Everything since — narrowing, the refusal
message, the gate's `source`, the tombstones, the map — has been verified against
the mock, by hand, or by a browser. All three are legitimate ways to check that
code does what it says. None of them can say whether it *helps*.

## Pending, grouped by what blocks it

Each verified against the code today, not against the record that asked for it.

### Blocked on a machine with a model

- **The gate probe.** Fifteen prompts, the four failure modes, the five numbers.
  [`2026-08-31.the-gate-probe.WIP.md`](2026-08-31.the-gate-probe.WIP.md).
- **The map probe.** `grounded.txt` with `--map-tokens 0` against the same script
  with the map on, sampling pinned. The map costs 870 tokens on every turn at
  `--map-tokens 1024`; the question is whether the answers get better by more
  than that costs. Nothing about ranking should be believed before this.
- **14b and 32b**, folding at 32K, and whether prefix reuse becomes *seconds* —
  which needs timings the backend still does not read off the `Done` line.

### Blocked on nothing

- **Ranking the map**, and then the reference graph. `@reference.call` is in the
  same `TAGS_QUERY` the outline already uses; nothing in the tree reads it yet.
  The tension to resolve first is written down: ranking personalizes, and a map
  that changes per turn is not a prefix.
- **Rebuilding a stale map.** Built once per run today, so an agent that edits a
  file carries the outline it had. `mtime` detects it; *when* to pay the prefix
  break is Aider's refresh-mode question.
- **Reading the context window from the backend**, instead of `--context-limit`
  being a flag someone has to set right. `num_ctx` is sent; nothing is read back.
- **Sessions in SQLite.** No sqlite dependency; `serve` still loses the
  conversation on restart. Must be derivable from the event stream.
- **Pruning tool results** out of the history. No `prune` in `context.rs`. Note
  it would be the first *partial* eviction, and the `evicted` message
  deliberately cannot describe one — a tombstone for part of a turn is a message
  nobody has designed.
- **A second grammar for the map**, when there is a second language to ask about.

### Narrowing, what is left of it

- **`network` and `enforcement`.** `Plan` is `steps`, `files`, `writes`,
  `commands`; a task still inherits both from the policy file.
- **Whether `writes` should bound `run_command`.** A child can write whatever the
  task's roots allow, and a plan's `commands` list says nothing about paths.

### Security debts, named and unpaid

- **`openat2(RESOLVE_BENEATH)`** for the in-process tools —
  `sandbox/mod.rs:312` is still a doc comment naming a TOCTOU window.
- **Level 3**, the container, with level-2 restrictions applied inside it.
- **Auth**, if `serve` is ever bound off-loopback.

### Smaller, and each becomes folklore if it survives

- `luu chat --record` still sleeps 50 ms before exiting so the writer can drain
  (`crates/luu/src/lib.rs:1114`).
- `SessionView` still cloned under the mutex on every API read
  (`serve.rs:984`, `:992`).
- The replay still caps inter-message gaps at 400 ms (`ui/store.js:396`) and
  nothing in the UI says so.
- `?from=&limit=` on `/turns` still unimplemented.
- `RejectTask { task }` still carries no reason, so a refused agent cannot
  propose again in the user's light. The gate probe's prompt 10 is where this
  will be felt first.
- **A turn that was never in the window reads like one still in it.**
  `evicted_by: null` covers both, and the planning call is always the first such
  turn. The honest fix is for the view to know which turns the history holds.
- Native function calling and a GBNF grammar, replacing the text parse. The gate
  probe's declaration rate is what would promote this from *smaller* to *next*.
- Sub-tasks and nesting. Still deliberately not now.
- The CLI still has no gate, and whether it should grow one is still undecided.

**Paid since this morning's list:** *eviction as a recorded event* — asked for
three times, with the precondition "nothing — it is small", and it was. *The
first piece of relevance selection*, which had been the one unbuilt part of step
2 since step 2 was written.

## What I would do next, and why

**Run something.** Specifically the gate probe, because it is the one whose
result changes the *order* of everything else: if a 7B cannot produce a parseable
plan, a GBNF grammar stops being a line in the *smaller* list and becomes the
next commit, ahead of ranking. The map probe is second and cheaper — it needs no
person, only the machine — and it is the precondition for believing anything
about ranking.

Ranking the map is the obvious thing to build next and it is the wrong thing to
build next. It would be the fourth instrument in a row, and its baseline is a
number nobody has yet checked against a model.
