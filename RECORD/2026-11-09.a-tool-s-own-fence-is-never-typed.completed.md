# A tool's own fence is never typed

Row 7 of [`ROADMAP/2026-11-08`](../ROADMAP/2026-11-08/README.md): *drift under
a tool's own name: wants `avoid_until_forced` once per tool name*. Left by
[`what-constrain-does`](2026-09-14.what-constrain-does.completed.md) §What is
still open, where two of fifteen probe prompts fenced a call as
`` ```list_dir `` or `` ```run_command `` in both the `off` and `grammar` arms
alike.

## The problem

`--constrain grammar` compiles text that avoids `` ```tool ``, and once the
model types it, forces a well-formed call and the closing fence. A fence under
a tool's own name never contains `` ```tool ``, so it was ordinary prose to the
grammar: the model could write

````
```list_dir
{"path": "src"}
```
````

and `parse_call` would score it `Drifted`, the grammar having done nothing.

## The proposal

**One automaton, not one per name.** The record asked for the construction
*run once per tool name*. Run as written, that is several automata, and a
grammar's prose rule can only be one of them: the text is a single stream of
characters, and each state must know at once how far it is into `` ```tool ``
and into `` ```list_dir `` — which share their first three characters. The
construction that does that is Aho-Corasick: a trie of every pattern, with
failure links, each state's transitions completed through them. For one
pattern it is the KMP automaton this file had, state for state, which is why
the five tests that pin that construction pass unchanged on the new code.

**Two ends.** A pattern's completion is either:

| Pattern | End |
| --- | --- |
| `` ```tool `` | `Forced(call-tail)`: the call and the closing fence, nothing else |
| `` ```<name> `` for each tool | `Forbidden`: the last character is not offered, by a branch or by the catch-all |

Forbidden, as the record said, and not forced toward a call: the drifted shape
is the arguments without the name (`{"path": "src"}`), so forcing a call after
`` ```list_dir `` would mean the grammar inserting a name the model did not
write. Stopping one character short leaves it the correct fence, another word
(`` ```list_dirs ``? no — that has the fence as a prefix, and is refused too;
`` ```lisp ``, yes), or no fence.

**Prose stays prose.** `` ```rust ``, `` ```ru `` and `` ``` tool `` all pass;
`` ```ru `` on its way to `` ```run_command `` that becomes `` ```rus `` is back
at the start state, not stuck.

A tool named with the fence tag as its prefix (`tool_x`) is left out: the
trigger is completed first and forces a call.

## What it costs

More states: one per distinct proper prefix of all the patterns, about sixty
for the standard tools against seven. The grammar is compiled once per session.
Every state's catch-all class grows by the few characters that state lists.

A word that **starts** with a tool's fence is refused with it —
`` ```read_fileish `` cannot be typed. No language fence looks like that.

## What was rejected

- **Several automata, one per name**, as the record put it: above.
- **Forcing a call after a tool's own fence.** Above.
- **Forbidding at `` ``` `` followed by any tool name's first letter.** It
  would refuse `` ```rust `` for `run_command`'s sake.

## Still open

- **The run.** Nothing here was sent to a server. The fifteen prompts of
  `scripts/tasks/tool-call-probe.txt` under `--constrain grammar`, on
  `llama-server`, are what says whether the two drifted prompts now call
  correctly, answer in prose, or find a third fence. Machine 3.
- **Whether `llama-server` takes the larger grammar.** The rules use only the
  constructs the measured grammar already used (literals, classes, rule
  references, alternation); `every_rule_the_grammar_names_is_defined` checks
  the references here, which is the first thing a GBNF parser checks, and not
  the rest.
