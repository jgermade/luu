# A test that clicks Approve

**Status:** a proposal, and the test it plans.

Item 2 of the reordered [`ROADMAP/2026-09-08`](../ROADMAP/2026-09-08/README.md),
argued in [`the-surfaces-first`](2026-09-08.the-surfaces-first.completed.md).

## The problem

Two bugs in two days were found by a person opening the page, and neither by a
test:

- [`a-second-header`](2026-09-07.a-second-header.completed.md) — the page named
  the gate's job field twice, and **no approval from this UI had reached the
  server since the rename**.
- [`the-surfaces-first`](2026-09-08.the-surfaces-first.completed.md) — a plan
  that granted a file could not read it, for three days, on every platform.

Both live in the same gap. CI runs one browser test and it loads the **static
twin** — `site/`, assembled from recordings, with no server behind it. A page
with no server has no socket, no gate and no tool call, so the half of the UI
that *acts* is covered by nothing. The only thing that drives it is
`tests/smoke/gate-probe.mjs`, which needs a model, a running server and a person
watching fifteen prompts go by; it is a probe, and it is scored by reading.

## The proposal

**A second spec in `tests/smoke/`, against a live `luu serve` on the mock.** It
starts the binary itself in `beforeAll` — its own port, its own `LUU_HOME`,
`--no-store` — and drives the page through one whole job with the mouse:

1. the first run opens the configuration modal, and closing it leaves a composer
   that can be typed in;
2. a prompt produces a **gate**, with the objective and the plan the model
   declared;
3. the plan is **amended** in the browser with a file it did not ask for;
4. **Approve**;
5. the turn runs, the tool call appears in the inspector with a verdict, and it
   **reads the file the amendment added**;
6. **close & fold** leaves the job as one folded entry with its summary.

Step 3 is the point of the whole thing, and it is what makes this cheap test
worth more than its size. The mock's tool call reads a path the *plan* never
declared, so the read succeeds only if the amendment a person typed into the
browser reached the server and became part of the job's sandbox. That is
`a-second-header`'s bug, asserted. And the amendment grants a **file**, so the
job's sandbox root is a file — which is `the-surfaces-first`'s bug, asserted, at
the surface where it was found rather than at the unit where it was fixed.

**Three mock replies are the whole fixture**: a plan block, a tool block, an
answer. No model, no network, no fixtures directory, and it runs in the CI job
that already builds the release binary and already installs node and Chromium.

## What it costs

- **A second server in the smoke suite.** The static twin keeps its `webServer`;
  this one is spawned by the spec, because the two want different lifetimes and
  a `webServer` array would start `luu` for the static test as well.
- **The binary is a fixture now.** `npx playwright test` fails without one, with
  a message naming `cargo build --bin luu`. Deliberately not a skip: a skipped
  test is a test that is not there, and this suite exists because things that
  are not there is the failure mode being fixed.
- **It asserts on class names.** `.gate`, `.amend`, `.timeline` — the same ones
  `gate-probe.mjs` already depends on. A restyle that renames them breaks both,
  which is the price of testing a page that has no test ids.

## What was rejected

- **Driving the socket instead of the browser.** `serve_ws.rs` already does that,
  and it is exactly what missed both bugs: the protocol was right in each case
  and the *page* was wrong.
- **Extending `gate-probe.mjs`.** It answers a different question — *does a model
  propose a sane plan* — and it needs a model to answer it. Scoring what a model
  proposes and asserting what a page does should not be the same file.
- **A `data-testid` pass over the page first.** Worth doing and not now: it would
  be a diff over the whole UI, ahead of the test that would tell us the UI still
  works.

## What it found before it passed

**The page could not open a session at all.** The first run of the spec never
reached the gate, and the reason was in the socket frames:

```text
→ {"type":"hello","protocol":5,"format":7}
← {"type":"refused","request":"hello","reason":"version",
   "detail":"this host writes record format 8 and the client reads 7"}
← close
```

`record::FORMAT` went to 8 with rule B ([`prune-behind`](2026-09-08.prune-behind.completed.md),
merged the same day) and `crates/luu/ui/store.js` still declared 7. The version
handshake did exactly what it was designed to do — refuse out loud rather than
misread the next message — and **the whole debug UI had been dead on `main`
since that commit**, on a page whose only visible symptom was the word `closed`
in the corner, because the reconnect loop cleared the refusal off the screen
every few seconds and put it back.

Three things came out of it, and only the first is the bug:

1. `FORMAT = 8` in `store.js`.
2. **`crates/luu/tests/ui_versions.rs`** — two constants in two languages want a
   test that reads both. It is four lines of parsing and it runs in
   `cargo test`, where the person who bumps the Rust constant already is. The
   browser test would have caught this too, and a minute later.
3. **A version refusal stops the reconnect loop.** Retrying cannot fix a
   mismatch, and retrying is what made it invisible.

That is the third bug in three days found by opening the page, and the first one
found by a test — which is the whole argument for this file, arriving before the
file was finished.

## Still open

- **Nothing drives the configuration modal.** The providers table writes
  `config.toml`, and the test only closes the modal the first run opens. Writing
  a profile from the browser and starting a session on it is the next thing this
  file should have covered.
- **Nothing drives a rejection**, a cancel mid-turn, or a reopen. One job, one
  approval, one fold — the path a person takes every time, and the least of what
  could be asserted.
