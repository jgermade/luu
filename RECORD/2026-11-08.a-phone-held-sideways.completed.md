# A phone held sideways is still a phone

**Status:** completed. It was decided and built the same day.

> Qué es lo del móvil?
> Forzaría que se vea siempre en vertical

This answers the question
[`where-the-public-luu-stands`](2026-11-04.where-the-public-luu-stands.completed.md)
left open: what a phone shows when it is held sideways.

## What was true

[`a-phone-is-three-slides`](2026-10-02.a-phone-is-three-slides.completed.md)
decided the layout by width alone: `window.innerWidth < 760`. An iPhone in
portrait is 390 wide, so it got the three slides. Turned sideways, the same
phone is 844 wide and 390 tall, so it got **two desktop columns 390px tall**:
the resize handles, the column switch, and no swipe.

## The decision

The person asked for *always vertical*. A page cannot give exactly that:

- Safari on iOS has no `screen.orientation.lock` at all.
- Chrome on Android has it only in fullscreen, or for an installed app whose
  manifest says `"orientation": "portrait"`, and luu has no manifest.

What a page *can* do is keep the vertical layout whichever way the screen is
turned, and that is what was built. **A phone is a touch screen
(`pointer: coarse`) whose short side is under 760px**, in either orientation.
Width under 760 still counts as before, so a narrow desktop window keeps its
slides.

- An iPhone at 844×390 now gets the slides.
- An iPad (short side 820 or more) stays on columns.
- A desktop window made 390px tall has a fine pointer, and it stays on
  columns.

`app.html`'s `isMobile` decides it, on load and on every resize, so rotating
the phone changes nothing on screen except the proportions. The project
modal's one-column rule (`project.html`) uses the same condition as a media
query.

## Rejected

- **Rotating the page with CSS** (`transform: rotate(90deg)` in landscape).
  Touch coordinates, scroll direction and the keyboard all stay the device's,
  so the page would fight every gesture.
- **A "turn your phone" overlay.** It blocks the page for no gain: the slides
  work in landscape, only shorter.
- **A manifest with `"orientation": "portrait"`.** It is the one real lock, but
  only for an installed app on Android. Installing luu as an app is its own
  question, not asked.

## Checked

- `gate.spec.js`, *a phone held sideways › keeps the slides*: 844×390 with
  touch gives `data-columns="slides"` and no column switch. It fails on the
  previous `app.html` and passes on this one.
- *A short desktop window is not a phone*: 844×390 with a mouse is not slides.
- *On a phone the columns are slides* passes unchanged.

## Still open

- **A landscape slide is 390px tall**, with the chat's two-row foot and the
