# Brand icons for providers and models

> *Me gustan los iconos, ¿sería posible usar los iconos oficiales en los
> proveedores y en los modelos?*

Asked back where they come from, the answer was: *unos pocos SVG en el repo,
que iremos iterando con el uso, y soporte para instalar otros paquetes, p.e.
`@lobehub/icons-static-svg`, como hemos hecho con los iconos del árbol de
ficheros.*

## The problem

A provider in the pickers is a name and a line of text — `claude · anthropic
· native tools` — and a model is its name. The two columns are read by shape
before they are read by word: twelve providers and forty models are a wall of
the same grey. Every one of them has a mark, and the mark is what a person
already recognises.

The tree's icons settled the larger question first, against vendoring: *a
theme is one person's taste, and shipping it makes this repository a
redistributor* (`crate::icons`). A brand mark is different on both counts —
there is one per brand, so there is no taste to tie the page to — and the
same on the second: the marks are their owners' trademarks whatever the
licence of the file that draws them.

## The proposal

**A few marks in the tree, from Simple Icons**, which publishes its SVGs
under CC0: no licence to carry, and one path each, monochrome, on a 24×24
box. They go in `web/brands/`, named by **lobehub's slugs** (`gemini`, not
Simple Icons' `googlegemini`; `mistral`, not `mistralai`), so a lobehub pack
installed later answers the same names. Thirteen to start, the ones a
local-first setup meets: `anthropic`, `claude`, `ollama`, `huggingface`,
`meta`, `qwen`, `gemini`, `google`, `deepseek`, `kimi`, `mistral`,
`lmstudio`, `vllm`. Not MiniMax, whose mark Simple Icons records under a
licence of its own, and not Apple, which does not allow its logo to be used to
name somebody else's thing — so an `mlx` engine has no mark. A `README` beside them says where they came from
and whose marks they are. No OpenAI: Simple Icons does not publish it, and an
OpenAI-compatible URL is far more often a local `llama-server` than OpenAI.

**Drawn as a mask**, `mask-image` over `currentColor`, so a mark takes the ink
of the row it is in — muted, accent on hover, both themes — like every other
icon on the page. A pack's colour variants are drawn the same way, as their
silhouette.

**Which mark is one rule, in the page** (`lib/brands.js`):

- a **provider** by its backend and its URL's host — `ollama` is ollama's,
  `api.anthropic.com` Anthropic's, `api.deepseek.com` DeepSeek's, a MiniMax or
  Moonshot host theirs; a local OpenAI-compatible server has none;
- a **model** by its name — `claude-*` Claude's, `qwen*` Qwen's, `llama*`
  Meta's, `gemma*` Gemma's (Google's where the pack has no Gemma), `gemini*`,
  `mistral*`/`codestral*`/`devstral*`, `deepseek*`, `kimi*`, `glm*`, `gpt-*`
  OpenAI's — after the catalog's `ollama:` / `huggingface:<org>/` prefix.

Nothing found is no mark, never a wrong one.

**And a pack instead of the built-in ones**, named in `config.toml`:

```toml
[ui]
brand-icons = "~/.luu/brand-icons/lobehub"   # a folder of <slug>.svg
```

A pack is a folder of SVGs named by slug, or a folder with an `icons/` folder
of them — lobehub's `@lobehub/icons-static-svg` is the second. It is offered
from where it already is: **imported** into `<state dir>/brand-icons/` (a
folder or a zip, picked or dropped, through the importer the icon themes use,
re-checked component by component), or **installed with npm** into
`web/node_modules`, where Monaco and xterm.js are — `npm install
@lobehub/icons-static-svg` in `web/` is enough for Settings to find it.
Settings → Appearance lists the built-in set and every pack found, and writes
the key. A slug the pack lacks falls back to the built-in mark.

**The id is the security design here too.** The pack is read once into a
slug → file table, a slug is `[a-z0-9][a-z0-9.-]*`, and `/api/brands/icon/{slug}`
serves only slugs in the table, as `image/svg+xml` and nothing else. An SVG
drawn through `mask-image` or `<img>` runs no script.

## What it costs

- About 50 KB of SVG in the tree, and a `README`.
- A key in `[ui]`, four routes, and a module (`crate::brands`) that is mostly
  the tree icons' rules applied to a flat folder.
- `icons::import` splits into the folder checks every import needs and the
  check that the folder is a theme, so a pack is imported by the same code.
- **The same limit as the tree's icons on a guarded server**: the page draws
  them by URL, and `/api/*` wants the bearer token a URL in CSS cannot carry.
  The built-in marks are static files and are not behind it.

## Rejected

- **Vendoring lobehub's set.** 991 files, MIT: a licence to carry and a
  thousand marks nobody asked for. It is the pack to install, not the default.
- **Colour.** The page's icons are ink, and a coloured mark beside grey text
  reads as a badge. A pack's `-color` files are there for a later ask.
- **Guessing from a port** (1234 for LM Studio, 8000 for vLLM). A port is a
  flag anybody passes.

## Still open

- Which marks are missing is a question for use: the built-in set grows by
  copying a file and adding its slug.

## Built, the same day

As proposed, with what the proposal did not know:

- **Two marks fewer.** Simple Icons' disclaimer says its CC0 does not reach
  every mark, and its data records MiniMax's under a licence of its own;
  Apple's guidelines do not allow its logo to name another thing. Thirteen,
  then, and the `README` says why the two are missing.
- **A pack's paths are canonical.** The npm one is found under
  `CARGO_MANIFEST_DIR/../../web/node_modules`, and a path with `..` in it is
  what Settings would have written; and the file may say `~/…` where the
  list says `/home/…`. `Found.path` is canonical, and the view's `chosen` is
  the file's path made the same way, which is what the page compares.
- **`packs` copies what it lists.** Appearance builds the list out of
  `brands.view`, another store's object, and the loop this repository found
  in the context modal came from exactly that; each pack is spread into a
  plain object first.

Tested: `brands::tests` — a slug is a name (`../x`, `.hidden`, `Claude`, `a b`
refused), a flat folder and lobehub's `icons/` layout both load and an empty
one does not, and a pack is found where luu imports it and where npm puts it.
`settings.spec.js`, last in the file: a provider on ollama's backend wears
ollama's mark and its Qwen model Qwen's, from `web/brands/`; a pack laid out
under `brand-icons/mine` is chosen in Appearance, written to `config.toml`,
draws its own Qwen and the page's own Ollama, is served as `image/svg+xml`,
and refuses `..%2Fconfig.toml`, a slug it lacks and an uppercase one; and the
page's own again takes the key away.

## Appended the same day: the engines' own marks

*En Settings > Engines, usemos iconos junto al nombre*, with Ollama's logo
named by its URL in `ollama/ollama` (`docs/ollama-logo.svg`) and llama.cpp's
mark pasted as SVG. Both are in `web/brands/` now — Ollama's in place of
Simple Icons' drawing of it — and each engine's card and each kind in the
installer wears its kind's mark (`engineBrand` in `lib/brands.js`: `llamacpp`,
`ollama`, `mlx`). A third was asked for, an SVG made from mlx-serve's app icon
at `mlxserve.com/appiconb.png`; this session's network policy refused the
host, so there is no MLX mark yet rather than one drawn without the original.
