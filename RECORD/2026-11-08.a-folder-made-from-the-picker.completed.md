# A folder made from the picker

## The problem

The project picker (`web/views/inspector/tree/project.html`) lists the folders
under where `serve` was started and nothing else. A project that does not exist
yet has no row to choose, so starting one meant leaving the page for a terminal,
running `mkdir`, and coming back to a list that had cached the old answer. Asked
for directly: *"en la selección de carpeta del proyecto, hecho de menos un botón
para añadir carpeta"*.

## The proposal

- **`POST /api/folders {path, name}`** beside the `GET` the picker already
  reads. `path` is the parent as `/api/folders` lists it (`""` for the root),
  `name` one name. Answers `{path}` of the folder made.
- **`workspace::make_dir`**: `rename`'s name rule (not empty, not a dot, no
  separator), `create_dir` and never `create_dir_all` — one level, and a parent
  that is not there is `Missing` rather than made — and `AlreadyExists` is
  `Taken`, so asking twice never empties or replaces anything.
- **The sandbox asked is the root's, `read-write` and nothing else**, the
  `get_folders` sandbox with the access raised. Not the session's: the picker
  chooses *which* folder a session gets, so it sits above every session's
  sandbox, as its `GET` already does. `check_path` refuses a `..` or a symlink
  out exactly as it refuses a tool call.
- **Who may is who may rename a file** — `workspace_writable`, now told what is
  being done so its refusal names it: a person at this machine (loopback bind,
  loopback `Host`), or a user on a public server, whose root is their own
  folder (`user_root`). A bearer token off loopback does not buy it, for the
  rename's reason.
- **The page**: `New folder` beside the crumbs opens a field under them; Enter
  or *Create* makes it, ESC or *Cancel* puts the field away (and only the field:
  the picker on a first visit is locked). A refusal is said under the field with
  the field kept. Made, the picker goes into it, so *Use this folder* takes it.
  On another host it is the same `POST`, through `/h/<name>/api/folders`.

## Cost

One route, one function, one field. The refusal text of a rename changed from
*Rename from a browser on the machine itself* to *Do it from a browser on the
machine itself*, with the action named; nothing matched on the old words.

## Rejected

- **Making it in the session's sandbox** (`/api/workspace/*`): the folder a new
  project needs is usually beside the session's folder, not in it, and a
  read-only posture would refuse a write the person is making about *where to
  work*, not *what the model may touch*.
- **`create_dir_all` with a path for a name** (`a/b/c`): a typo becomes three
  folders. One level per click, and the picker is inside the new one after it,
  so a second level is a second click.
- **Allowing it with a bearer token off loopback**: the rename refuses there,
  and a folder made on someone's machine is the same kind of write.

## Evidence

- `workspace::tests::a_folder_is_made_once_and_only_inside` — made at the root
  and under a folder, taken (a folder and a file, neither touched), names that
  are paths, a parent that is not there, `..` as the parent, and a read-only
  sandbox.
- `tests/smoke/workspace.spec.js` *the picker makes a new folder and goes into
  it* — the forced picker on a first visit: taken said under the field, ESC
  closing the field and not the picker, two levels made and gone into, *Use
  this folder*, and the server refusing `..` whatever the page sends.

## Still open

- No delete or rename from the picker. The tree renames inside a session's
  folder; a folder made by mistake here is removed outside luu.
