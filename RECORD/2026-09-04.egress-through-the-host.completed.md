# Narrowing phase 2: Egress through the host

**Status:** a proposal and the code it plans (`WIP`), written on 2026-09-04.
Unblocked by [`network-per-plan`](2026-09-04.network-per-plan.completed.md) and
[`the-container-observed`](2026-09-03.the-container-observed.completed.md).

## The problem

[`network-per-plan`](2026-09-04.network-per-plan.completed.md) made network access
per-job rather than ambient across the entire session: an offline job gets no
network (enforced by seccomp in Linux containers blocking `AF_INET`, `AF_INET6`,
and `AF_PACKET`).

However, when a job *does* require network (`network: true`), the kernel's
primitives are strictly all-or-nothing:
- **seccomp cannot filter by destination:** it cannot dereference user-space
  pointers (like `sockaddr *` in `connect()`).
- **Landlock network rules (ABI v4) only filter by port:** `LANDLOCK_ACCESS_NET_CONNECT_TCP`
  can permit port 443, but cannot distinguish between `crates.io` and an arbitrary
  remote server.
- **Data exfiltration remains possible:** a build script (`build.rs`) or tool
  execution can curl sensitive host or repository data to any external IP.

The layer that can filter destinations is userspace, because it inspects protocols
rather than raw syscalls.

## The proposal

### 1. Host-side Egress Proxy (`EgressProxy`)

A lightweight, built-in HTTP CONNECT proxy in `agent_core::sandbox::proxy`:
- Binds to a local address (e.g. `127.0.0.1:0` ephemeral port).
- Handles HTTP `CONNECT <host>:<port> HTTP/1.1`:
  - Parses target `<host>`.
  - Matches `<host>` against the active egress allowlist (`egress` rules).
  - Wildcard subdomain support: `*.crates.io` matches `index.crates.io` and `static.crates.io`. Exact match: `crates.io`.
  - **If allowed:** opens a TCP connection to the upstream destination, responds
    `HTTP/1.1 200 Connection Established\r\n\r\n`, and tunnels bytes bi-directionally
    using `tokio::io::copy_bidirectional`.
  - **If denied:** responds with `HTTP/1.1 403 Forbidden` and a clear explanatory body:
    `destination <host> is not allowed by the egress policy\n`.
- Handles plain HTTP requests (`GET http://<host>/...`): forwards if allowed, returns 403 if denied.
- Reports connection attempts and denials through events/callbacks so that egress is
  transparent in session records and traces.

### 2. Policy and Plan integration

- **In `SandboxPolicy`:**
  ```rust
  #[serde(default)]
  pub egress: Vec<String>,
  ```
  `[sandbox] egress = ["crates.io", "*.crates.io", "github.com"]` can be declared in
  `luu.toml`. Empty means unrestricted if `network: true`.
- **In `Plan`:**
  ```rust
  #[serde(default)]
  pub egress: Vec<String>,
  ```
  A plan can specify `egress: ["crates.io"]`.
- **In `Plan::narrow`:**
  The job's active egress allowlist is the intersection with the session policy:
  ```rust
  policy.egress = match (session.egress().is_empty(), self.egress.is_empty()) {
      (false, false) => self.egress.iter().filter(|d| session.allows_domain(d)).cloned().collect(),
      (false, true) => session.egress().to_vec(),
      (true, false) => self.egress.clone(),
      (true, true) => Vec::new(),
  };
  ```
- **In `Plan::unmet`:**
  If the plan declares a domain forbidden by `session.egress()`, it is flagged before
  the job runs at the gate.

### 3. Environment Injection

When executing commands in a job where egress proxying is active:
- Standard proxy environment variables are set on the child process (or passed to
  the worker):
  - `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`
  - `http_proxy`, `https_proxy`, `all_proxy`
- Standard build tools (`cargo`, `rustup`, `git`, `curl`, `pip`, `npm`) honor these
  variables automatically and route all HTTPS and HTTP traffic through the CONNECT proxy.

## What it costs

- Zero new external dependencies: implemented with Tokio's native `TcpListener`,
  `TcpStream`, and `tokio::io::copy_bidirectional`.
- CONNECT tunneling requires no TLS certificate generation or MITM CA installation,
  preserving end-to-end encryption integrity.
- Tools that deliberately bypass proxy environment variables cannot reach external
  endpoints in isolated environments.

## What was rejected

- **TLS MITM with generated root CAs:** Decrypting traffic inside the proxy is
  intrusive, risks security flaws, and requires injecting custom trust stores into
  containers and runtimes. CONNECT host matching is sufficient to verify domain destinations.
- **eBPF / transparent redirect:** Requires root privileges on the host and Linux-specific
  kernel hooks not available on macOS or rootless containers.

## Still open

- Docker `--internal` bridge network integration to prevent non-proxy egress entirely
  at the network namespace level.
