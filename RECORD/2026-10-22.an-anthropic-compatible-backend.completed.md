# An Anthropic-compatible backend, with its thinking kept

**Status:** plan, then code. Asked for by Jesús, in two messages:

> De igual modo que damos soporte a proveedores compatibles con la API de
> openai, quiero dar soporte a proveedores compatibles con la API de Anthropic

> Debemos aprovechar que soporta bloques de thinking, interleaved thinking y
> otras funciones avanzadas

The first is a third backend beside `ollama` and `openai`. The second is what
makes it worth more than a second spelling of the same request: the Messages
API (`POST /v1/messages`) is the one API luu speaks that has **reasoning as its
own typed, signed block**, and a tool loop in which the model thinks *between*
calls and is given that thinking back. Everything luu does with reasoning
today — [`a-call-written-while-thinking`](2026-10-21.a-call-written-while-thinking.completed.md)
— is recovering it from a reply that arrived as text.

"Anthropic-compatible" is not a hosted-API feature for the same reason
"OpenAI-compatible" was not ([`an-openai-compatible-backend`](2026-09-01.an-openai-compatible-backend.completed.md)):
Anthropic's own API, MiniMax, DeepSeek, Moonshot (Kimi), Z.ai (GLM), and the
local servers that grew a `/v1/messages` — `llama-server` and Ollama — all
answer the same shape. Their docs give a base URL for `ANTHROPIC_BASE_URL`
(`https://api.minimax.io/anthropic`, `http://localhost:11434`), and that is
what the profile's `url` is: luu appends `/v1/messages`, as the SDKs do.

## What does not transfer from the OpenAI backend, and what does

**The window is still not sendable.** `max_tokens` caps the output, as it does
on chat completions, and there is no field for the window. The caveat, the
`context-limit` in the profile and the check moving to `usage` all carry over.

**`max_tokens` is required.** The one difference that forces a decision. The
OpenAI record left it unsent and named `--reserve` as the number that belongs
there; here a request without it is a 400. `--reserve` is still not the answer
— it is a budget held back (512 by default), and as a hard cap it would cut
every answer and every thinking block at 512 tokens. So the backend sends its
own default, **16 384**, and a profile (or one model) says otherwise with
`max-tokens`. A guess and a key, like an engine's `ready-timeout`: DeepSeek
documents 8 192 as its ceiling, Claude takes 128 000, and a server that
refuses the number says so in its own 400 at the first turn.

**Usage is three numbers, not one.** `input_tokens` excludes what the prompt
cache served: the prompt is `input_tokens + cache_creation_input_tokens +
cache_read_input_tokens`. Reporting `input_tokens` as `prompt_tokens` would
show a cached prompt as a short one — the zero-for-not-reported failure again,
by a different road. The three are summed.

**Sampling.** The API version is `2023-06-01`, the one every compatible server
was written against. `2026-10-21` removes `temperature` outright — a 400 on
every model — and that would make `--temperature` impossible everywhere to make
it right on Claude. Under `2023-06-01` a pinned temperature is sent and the
server decides: Claude 4.7 and later refuse it, the compatible servers honour
it. **There is no `seed` field on this API**, so `--seed` is not sent, and a run
that pinned one is told so before it measures anything — the rule the window
caveat set.

## Thinking, kept

This is the part the second message asked for, and it is the part with a
decision in it.

**In: a thinking block streams up as `<think>…</think>`.** The text everything
above the backend already reads as reasoning — masked before a call is looked
for, drawn folded on the page, stored as the model wrote it. A block with no
text (Claude 4.7+'s default `display: "omitted"`) streams nothing, and is kept
anyway.

**Out: the block goes back signed, or not at all.** The API wants thinking back
in the tool loop — interleaved thinking is the model reading what it thought
before the call it is now reading the result of — and it wants it back
*unchanged*: a block carries a signature, and on Claude 5.x that signature also
binds the conversation before it. A block whose prefix changed is a 400 on
accounts created after 2026-08-31. And luu changes history on purpose: it
evicts turns, folds tasks into summaries, moves a span to its oldest turn
under `--repeat-once`, prunes a turn's spans behind the line. Every one of
those is an edit the check sees.

So the backend **remembers the blocks it streamed, by the exact prefix they
answered**: a hash of the model, the tools, and every message before the reply,
plus the reply's own text. Building a request, an assistant message whose
prefix and text hash to a remembered entry goes back as the blocks the server
sent — thinking, signature, `tool_use` id and all. Any other assistant message
goes back as its text with the thinking cut out, because sending reasoning back
as *text* teaches the model to write `<think>` into its answers.

That is the server's own rule computed on this side, and it has three
properties worth naming:

- **It replays exactly what the check would accept.** A block is replayed only
  if nothing before it changed; and since a change before block *n* is a change
  before every block after it, what is dropped is always a leading run — the
  one removal the chain allows.
- **Inside a turn it always holds**: `run_agent_turn` appends to a copy of the
  selection and never re-selects, so every step of a tool loop finds its
  predecessors. Interleaved thinking works on every turn.
- **Across turns it holds until luu edits**, which is the context manager doing
  its job: after an eviction or a fold the earlier reasoning is not resent, and
  nothing fails.

No beta header, no `block_binding`, no per-host behaviour: compatible servers
that never heard of the check get the same request as Claude does.

**The memory is the process's.** A resumed session, or a restarted `serve`,
replays nothing from before — the store keeps text, and a signature in the
store would be a second copy of the reply that the store's parity rule
(`fold(record) == load(store, id)`) would have to account for. Dropping
reasoning at a boundary is the documented cheap case. Bounded at 64 replies.

## The rest of what the API offers, and what luu takes

| | |
| --- | --- |
| **Native tools by default** | `tool_use` / `tool_result` blocks, through the same pairing `native.rs` does. Interleaved thinking *is* thinking between `tool_use` blocks, so fenced calls would throw away the thing asked for; an `anthropic` profile resolves to `native` unless it says `tool-calls = "fenced"`. No earlier recording exists under this backend, so no default moves under one. |
| **One call per step** | `tool_choice: {type: "auto", disable_parallel_tool_use: true}`. The loop runs one call per step, and a replayed `tool_use` without its `tool_result` is a 400. |
| **Prompt caching** | `cache_control: {type: "ephemeral"}` on the system block (tools render before it, so both are covered) and on the last block of the last message. The stable prefix is already byte-identical by design; on Claude it is only *cached* if it is marked. |
| **`thinking`** | A key on the profile or one model: `"adaptive"` (sent as `{type: "adaptive", display: "summarized"}`, so the page has something to fold), `"off"` (`{type: "disabled"}`), or a number of tokens (`{type: "enabled", budget_tokens: N}`, for Claude 4.5 and earlier and the compatible servers that implement that shape). Absent sends nothing: the server's default. |
| **`effort`** | `output_config.effort`: `low` … `max`. Absent sends nothing. Claude Opus 5.5 defaults to `medium`, which is the reason it is a key. |
| **`Constraint::Schema`** | `output_config.format`, `{type: "json_schema", schema}` — Claude's structured outputs. A compatible server may ignore it, and the caveat says so. |
| **`Constraint::Grammar`** | Nothing to put it in. Not sent, and said. |
| **Models** | `GET /v1/models?limit=1000`. Claude's listing carries `max_input_tokens` — the most the API accepts, which luu budgets under — and the capability tree, whose presence is taken to mean a Claude model, every one of which takes `tools`. A `404` is a server that does not list, not an error. |
| **Stop** | `end_turn`, `stop_sequence`, `tool_use` → `Stop`; `max_tokens`, `model_context_window_exceeded` → `Length`; `refusal`, `pause_turn` and anything new → `Other`, reported as itself. |
| **Key** | `x-api-key`, from the key file, never an `Authorization` header: on Claude a bearer is an OAuth token and a different conversation. |

`thinking`, `effort` and `max-tokens` are refused on a profile of any other
backend. A key that a backend ignores is a key somebody believes is working.

`WindowIs` gains `limit`: the most this API accepts per request. Not
`trained` (Ollama's ceiling under a default that is something else again), not
`served` (one number for every request). The form treats it as a ceiling with
no placeholder, the way it treats `trained` without saying *Ollama's*.

## What was rejected

| | |
| --- | --- |
| The signature in the text, `<think sig="…">` | Every stored reply, every token count, every recording and the page would carry a base64 blob the size of the reasoning, for a value only the backend can use and only while the prefix is unchanged. |
| Replaying only the current turn's blocks | Simpler, and it throws away cross-turn reasoning on the turns where luu edited nothing — which, with the prefix byte-identical by design, is most of them. The hash rule replays the current turn *and* everything the server would still accept. |
| `thinking.block_binding.prefix_mismatch_behavior = "drop_block"` | Claude's own way to survive an edited history, behind a beta header the compatible servers have never heard of. The hash rule never sends a block that needs it. |
| `anthropic-version: 2026-10-21` | Removes `temperature` everywhere — see above — and buys nothing this backend sends. |
| Bearer auth beside `x-api-key` | Claude reads a bearer as OAuth and wants a beta header with it. The compatible servers document the SDK's `api_key`, which is `x-api-key`. |
| `--reserve` as `max_tokens` | It is a budget, not a cap, and its default would end every thinking block at 512 tokens. |
| Server-side compaction, context editing | Both rewrite the history on the server. luu's context manager *is* the thing that decides what history is sent, and measuring it is the project. |

## Cost

One file (`backend/anthropic.rs`), its wire test, a `thinking_spans` split out
of `mask_thinking` so the backend can cut what the mask blanks, `--anthropic-url`
on the three subcommands that take the other two URLs, three optional keys on a
profile and a model entry, one `WindowIs` variant, and the provider form
offering the backend and the three keys. The trait gains `sampling_caveat`,
defaulted to nothing.

## Still open

- **The cache's own numbers.** `cache_read_input_tokens` is the server saying
  how much of the prefix it reused — the measurement `prefix_reuse` computes
  from strings. Carrying it means a field on `Usage`, which the protocol and
  the record share. Summed into `prompt_tokens` for now, so the comparison
  against our own count stays right.
- **Whether the compatible servers honour `cache_control`, `output_config` and
  `disable_parallel_tool_use`**, and whether MiniMax, DeepSeek, Kimi and GLM
  list models at `/v1/models`. Read when a key for each is on this machine, not
  assumed.
- **`llama-server`'s and Ollama's `/v1/messages`** are the default URL and the
  documented one; neither was run against here.
- **Thinking between tool calls on Claude 5.x comes back as progress notes**,
  empty under `omitted` and summarized under `summarized`. `display: "updates"`
  would give the notes without the reasoning, behind a beta header — a choice
  for when somebody has watched both.

## Appended 2026-10-22: built

As planned, with five things the plan did not know:

- **`thinking_spans`** is split out of `mask_thinking`: the mask blanks the
  spans so every offset still indexes the text, and the backend has to *cut*
  them, so both now read the same three shapes from one function.
- **The blank line after `</think>` goes in with whatever follows it**, not
  with the tag. A reply that thinks and then only calls would otherwise carry
  four newlines before the fence — two from the tag and two from `fence`'s own
  separator.
- **`#[serde(flatten)]` does not combine with `deny_unknown_fields`**, and both
  `Profile` and `ModelEntry` rely on refusing a misspelt key. So `thinking`,
  `effort` and `max-tokens` are fields on each, and `MessagesKeys` is only the
  value `resolve` reads them into, a model's over its profile's — and only
  while the backend is still the profile's own, as with its URL.
- **The form writes `tool-calls` only where it differs from the backend's
  default**, which is now per backend: an `anthropic` profile whose models have
  tools writes nothing, and one set to fenced writes `fenced`. A model entry
  keeps the Messages keys the form does not draw, while the backend still reads
  them. The chat's picker says *native tools* from the same rule.
- **The engine wrapper delegates `sampling_caveat`**, as it does
  `constrain_caveat`; without it a profile whose engine luu starts would answer
  for the wrapper's default rather than the backend's.

**Checked**: unit tests for the rendering — the system text on its own, the
cache breakpoint, a step as `tool_use` and `tool_result` merged with the next
prompt, thinking cut from a reply sent as text, and a held reply sent back only
under its own prefix, falling back to text when one byte before it changed; for
the stream's events, the stop reasons and `Thinking`'s three spellings.
`anthropic_wire.rs` drives the socket: headers, the body, the usage summed, no
seed and no window in any field, a budget's beta header, a 401 in the server's
words, the listing's limits, a `404` that lists nothing — and **a two-request
tool loop whose second request carries the first's thinking block, signature
and `tool_use` id**. `provider.rs` tests the precedence, the native default, the
URL flag, the keys left behind under another backend's flag, and every refusal.
`settings.spec.js` connects an Anthropic provider through a stand-in that
refuses any `x-api-key` but one, and checks what the file holds: 14 of 14.

And the binary once, end to end, against a stand-in Messages API on this
machine: `luu chat "what is in AGENTS.md?" --backend anthropic --seed 7
--context-limit 8192` printed `provider: anthropic@127.0.0.1:18765, tool calls
native`, the window note and the seed note, streamed the thinking, ran
`read_file`, and answered `[stop] 4260 prompt / 49 completion` — 900 + 1 200
written to the cache on the first call and 60 + 2 100 on the second, of which
2 100 were read from it. The second request's assistant message was the
thinking block with its signature and `toolu_e2e`, and the `tool_result`
answered that id. No real Claude, MiniMax or local `/v1/messages` was reached:
everything under *Still open* stays open.

Found re-reading the diff, before it was committed: a held reply whose call
the model wrote as **text** — a ```` ```json ```` block the server did not
parse, so no `tool_use` — was treated as a reply that had lost its call, sent
