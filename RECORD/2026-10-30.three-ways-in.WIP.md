# Three ways in: one line, a container, a chart

**Status:** proposal, built in the same change; verified as far as this
machine reaches, which is said at the end.

> luu se puede instalar como binario, docker y helm?
>
> mira las opciones de instalación de https://jgermade.github.io/intergate/

## What there is today

| Way | State |
| --- | --- |
| **A binary** | `curl -fsSL https://jgermade.github.io/luu/setup.sh \| sh`: install, reinstall, uninstall, checked against the release's `SHA256SUMS` ([`an-installer-and-a-landing`](2026-10-23.an-installer-and-a-landing.completed.md)). `curl` only. |
| **A container** | `deploy/Containerfile` and `deploy/compose.yaml` ([`a-public-luu`](2026-10-07.a-public-luu.WIP.md) step 1) — built **from source on the machine that runs it**. No image is published, so there is nothing to `docker run`. |
| **Kubernetes** | Nothing. A chart is `a-public-luu`'s step 4, with several identities behind passkeys. |

intergate offers three tabs on its landing — *One line* (with a curl/wget
switch), *Docker* (a published image, a volume, one `docker run`) and
*Kubernetes* (an OCI chart, `helm install`). The question is whether luu can
offer the same three.

## The proposal

### 1. One line, with curl or wget

`setup.sh` downloads with whichever of `curl` and `wget` the machine has —
curl first — so a minimal Debian, which ships `wget` and not `curl`, runs it
as `wget -qO- …/setup.sh | sh`. The two places it reaches the network are
`fetch` and the `latest` redirect; both get a `wget` arm. The usage text names
the one the person used.

### 2. Two published images, from the release

- **`ghcr.io/jgermade/luu`** — `luu serve` in a container, from
  `deploy/Containerfile.release`: `deploy/Containerfile`'s final stage, with the
  release's Linux binary in place of a `cargo build`, checked against
  `SHA256SUMS` as `Containerfile.release` already checks the worker's.
- **`ghcr.io/jgermade/luu-worker`** — the worker, from `Containerfile.release`
  as it is. Settings → Runtimes builds this same image on every machine today;
  published, an `[image.*]` can name it and pull it instead.

Both for `linux/amd64` and `linux/arm64`, tagged with the version and
`latest`, by a job in `release.yml` after the release exists — the images are
built *from* its files, so they cannot come first. Nothing is compiled twice.

```sh
docker volume create luu-state
docker run -d --name luu --restart unless-stopped \
  -v luu-state:/state -v luu-work:/work -p 7878:7878 ghcr.io/jgermade/luu
docker exec luu cat /state/token
```

### 3. A chart of one identity

`deploy/helm/luu`, published as `oci://ghcr.io/jgermade/charts/luu` by the same
job. **One identity, the token** — `a-public-luu`'s step 1, which is what the
image already is — not its step 4. The chart is the container's shape in
Kubernetes words:

- one replica (a `Deployment` with `Recreate`, since `serve` runs one live
  session and the state volume is `ReadWriteOnce`), the image's user, a
  read-only root, every capability dropped, `/tmp` an `emptyDir`;
- two `PersistentVolumeClaim`s, `/state` and `/work`, or `existingClaim`s;
- a `Service`, and an `Ingress` where `ingress.enabled` — host, class, TLS
  secret, annotations for a cert-manager issuer — with `LUU_ORIGIN` set from
  the host, which is what the entrypoint's `[server]` needs behind a proxy;
- the policy, `deploy/luu.toml`, replaceable from `values.yaml`
  (`policy:`), mounted at `/etc/luu/luu.toml` as the image's comment says.

The token is the entrypoint's, written on first start into the state volume;
`kubectl exec deploy/luu -- cat /state/token` reads it, as `docker exec` does.

intergate's chart is written for Traefik (`IngressRoute`, a TCP entry point
for SSH). luu has no SSH and nothing that is not HTTP, so a plain `Ingress`
works on Traefik, nginx and the rest; nothing here is Traefik's.

### 4. The landing, in three tabs

The install card gets intergate's three tabs: *One line* with a curl/wget
switch, *Docker*, *Kubernetes*. The commands are what §1–3 publish. The page
keeps its rules: no CDN, mobile first, commands that wrap rather than scroll.

## What it costs

- **A second job in every release**: a multi-arch build of two images under
  QEMU, minutes, and `packages: write` on the workflow.
- **The chart is a fourth thing to keep in step** with the image's paths and
  the entrypoint. A lint in `build.yml` holds it to rendering; nothing holds it
  to a cluster.
- **A public image is a public promise**: it carries the version's worker
  protocol, as the worker image already does on every machine that built it.

## Rejected

- **Building the images from source in the release.** The release already
  built the Linux binaries, on the oldest runner for glibc's sake; compiling
  again inside an image is minutes for a binary that differs only in where it
  was made.
- **A Traefik-only chart**, as intergate's. Its reason is SSH on a TCP entry
  point; luu has only HTTP.
- **Several identities in the chart now.** That is `a-public-luu` step 4, and it
  waits on passkeys. A chart that offered `identities:` before luu can tell two
  people apart would be a value that does nothing.
- **Docker Hub.** The release, the pages and the images are all GitHub's; one
  place to trust.

## Still open

- `a-public-luu` step 4 — identities, a pod per identity — reshapes this chart.
- The worker image could become what Settings → Runtimes *pulls* rather than
  builds; today it still builds, and offers the build first.

## Built, the same day

**One line.** `setup.sh` picks `curl`, else `wget` (`pick_getter`), and only
`install` needs one — uninstall downloads nothing. `fetch` and the `latest`
redirect each have a `wget` arm; BusyBox's `wget` has no `--tries`, so it is
tried three times in the script, and the redirect is read from `wget -S
--spider`'s headers, the first `Location` naming a tag. The lines it prints
to run it again say whichever it used.

**Images.** `deploy/Containerfile.release`: the release's Linux binary,
checked against `SHA256SUMS`, under `deploy/Containerfile`'s final stage word
for word — held there by the test that already holds `Containerfile.release`
to `Containerfile`. `release.yml`'s `images` job, after `publish`, builds it
and `Containerfile.release` for amd64 and arm64 and pushes
`ghcr.io/jgermade/luu` and `ghcr.io/jgermade/luu-worker`, `:<version>` and
`:latest`, then packages and pushes the chart.

**The chart**, `deploy/helm/luu`: a `Deployment` of one with `Recreate`, the
image's uid with `fsGroup`, a read-only root, every capability dropped,
`RuntimeDefault` seccomp, `/tmp` an `emptyDir`; two claims kept on uninstall
(`helm.sh/resource-policy: keep`) or `existingClaim`s; a `Service`; an
`Ingress` with `LUU_ORIGIN` from its host; `policy:` as a `ConfigMap` over
`/etc/luu/luu.toml`. `build.yml`'s `chart` job lints and renders it.

**The landing** has three tabs and a curl/wget switch; without the script all
three panels show. The README says the same three.

**Verified**:
- `wget` with no `curl` on `PATH`, under `dash`, against GitHub: found
  `v0.1.5`, installed it, and printed `wget -qO- … | sh -s -- reinstall` as
  the way back. `scripts/setup-check.sh` passes on the `curl` path.
- `deploy/Containerfile.release` built with `LUU_VERSION=0.1.5`, and run as
  the landing says: 401 without the token, 200 with it. Run again under the
  chart's constraints in Docker — read-only root, `/tmp` a tmpfs, every
  capability dropped, uid 10001, `LUU_ORIGIN` set — the same 200. (The build
  in that sandbox needed its proxy's CA handed to `curl` as a build secret,
  in a scratch copy; the file as published has no such line, and GitHub's
  runners need none.)
- The landing at 375 and 1280: each tab shows its own commands, the switch
  swaps `curl` for `wget`, nothing scrolls sideways, the console is empty.

**Not verified**: the chart against a cluster, and even `helm lint` — downloading
Helm was refused in that session as external code, so the lint is CI's first
run of `build.yml`. The `images` job and the OCI push run only in a release.
