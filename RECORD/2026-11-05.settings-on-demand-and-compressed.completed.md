# Settings on demand, parts declared where they are drawn, and gzip

## The question

The two items left open by
[`what-the-first-load-waits-on`](2026-11-05.what-the-first-load-waits-on.completed.md):
*Adelante con la compresión y con Settings bajo demanda.* And: *jq79 permite
definir componentes dentro de componentes, quizá sea útil para los
componentes que sólo se usan dentro de otro componente.*

## What changed

1. **Each section of Settings is asked for when it is mounted.** `settings.html`
   imported all nine at its top, so opening it brought nine sections and their
   forms to draw one. Now the same `later()` as `app.html`'s dialogs, one `$:`
   per section on `mounted(name)`, and the other sections' files once the
   dialog is idle. The two sheets it mounts (`SessionsDialog`, `Project`) go
   through `later()` with the same specifiers `app.html` uses, so both get one
   definition.
2. **`<template name>` for parts only one component draws, and always with
   it.** jq79 reads a top-level `<template name="X">` as a component of the
   file, visible to every other component in it, its scoped styles stopping at
   its own boundary as a file's do:

   ```html
   <!-- sessions.html -->
   <SettingsResend />
   …
   <template name="SettingsResend">
     <script :setup> … </script>
     <div> … </div>
     <style scoped> … </style>
   </template>
   ```

   Merged: `resend.html` and `authority.html` into `sessions.html` (a 2 KB
   wrapper around the two), `context-view.html` into `context-modal.html`.
   Each was one request and one round trip after its parent, every time the
   parent opened.

   **Not merged**: what opens on a click from inside its parent —
   `engine-form.html`, `engine-sheet.html`, `provider-form.html`,
   `host-form.html`. jq79 0.7.11 starts their downloads when the parent
   renders, so they are there before the click; merging them saves a request
   and costs a parent of 50 KB instead of 20. Nor the components in
   `components/` and `theme/`, which are the design system's whatever imports
   them, nor anything `app.html` draws: it is 104 KB already.
3. **`luu serve` gzips the page.** `serve_asset` compresses text from 1 KB up
   when `Accept-Encoding` takes gzip, with `flate2` (new dependency; its
   default backend is pure Rust), once per file content — keyed by the sha256
   rust-embed already computes, so a debug build reading `web/` from disk
   never answers with a stale copy. The gzipped copy has its own `ETag`,
   `"<sha256>-gz"`, and every compressible file says
   `Vary: Accept-Encoding`; a 304 still answers the tag the browser holds.
   Brotli would take about another tenth off and a second dependency; not now.

## Measured

`luu serve` on the mock, release builds. *main* is the page before 0.7.11
(that commit's binary, `vendor/jq79.js` answered with 0.7.9); *no gzip* is
this binary behind a proxy that drops `Accept-Encoding`; *now* is this
change. Chrome's own network emulation — it counts the bytes on the wire, so
it sees compression where a per-request delay does not. Seven loads per arm,
interleaved, after a warm-up; medians. The logo; the folder question; Settings
from the click to its rail; the bytes transferred by 1.5 s after the folder
question.

| Network | Arm | Logo | Folder | Settings | KB |
|---|---|---|---|---|---|
| loopback | main | 186 | 289 | 86 | 946 |
| | no gzip | 178 | 287 | 58 | 812 |
| | now | **166** | **281** | **57** | **310** |
| 40 ms, 10 Mbit/s | main | 940 | 1149 | 224 | 946 |
| | no gzip | 844 | 1145 | 77 | 801 |
| | now | **589** | **848** | **75** | **306** |
| 100 ms, 4 Mbit/s | main | 2158 | 2640 | 494 | 949 |
| | no gzip | 1936 | 2605 | 142 | 801 |
| | now | **1300** | **1844** | **134** | **306** |

- **Gzip is most of the gain once bandwidth is the limit**: 844 → 589 ms at
  10 Mbit/s, 1936 → 1300 at 4. On loopback it is within the noise.
- **Settings opens faster than it ever did**: 57 ms on loopback where the page
  before 0.7.11 took 86, because its first section is one file and its
  imports, not nine.
- No console error in any measured load.

## Checked

- `cargo fmt --all --check`, and `cargo clippy --workspace --all-targets`
  with `-D warnings`: clean.
- `cargo test --workspace`: everything passes, two new tests among them —
  `app.html` gzipped to a client that takes it, unzipped equal to what is
  embedded, a 304 for its own tag, and the plain bytes under the plain tag for
  no `Accept-Encoding`, `identity` and `gzip;q=0`; and what is worth gzipping.
- Static twin 5 of 5; the live suite 78 passed, 1 skipped (the container
  shell: no Docker daemon), none failed — its Settings tests open General,
  Appearance, Models, Engines and both halves of Sessions.

## Still open

- Brotli, and whether a `luu export` site (the static twin, Pages) should
  carry `.gz` copies for hosts that serve them.
- The level after `app.html`'s imports is still a level: what the first paint
  draws imports a few files of its own (`card.html`, `prompt-parts.js`,
  `text-input.html`, `rows.js`). A merge would take `card.html`, but
  `prompt-parts.js` keeps the level there.
