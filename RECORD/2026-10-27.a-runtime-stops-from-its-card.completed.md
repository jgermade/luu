# A runtime stops from its card

> *Creo que le falta un botón de parar, y un check verde. El check lo pondría
> verde si está arrancado, doble si es default.*
>
> And, while it was being built: *el lápiz de edición del proveedor, lo
> pondría justo a la derecha del nombre del proveedor, formando, junto al icono,
> un botón.*

## What it was

A runtime card in Settings → Runtimes could install its runtime and start it,
but not stop it. Its check only meant *make it the default*: the same grey on
a runtime that answered and on one that did not. The default had no check at
all, only its `default` tag.

## What it is

**Stop, where start is.** `runtimes::stop_steps` is the other half of
`start_steps`, by each runtime's own word:

| Runtime | How it stops |
|---|---|
| Docker on a Mac | the app quits (`osascript -e 'quit app "Docker"'`), taking its VM with it |
| Podman on a Mac | `podman machine stop` |
| Colima | `colima stop` |
| Apple's `container` | `container system stop` |

Nerdctl's containerd is a system service, and Docker off a Mac is a daemon run
as root. Neither is started from the page, and neither is stopped from it.

- The card shows ■ while the runtime answers and has a line to stop it
  (`stoppable`).
- The stop is a task like a start: `POST /api/runtimes/{runtime}/stop`. Its
  output stays on the card while it runs, or if it fails.
- **The page never stops the runtime the live session runs its commands on.**
  The route refuses it (409, *move it elsewhere first*), and the button is
  disabled and says why. A session left with nowhere to run its commands is
  not a thing a click should do.

**The check says two things.**

- It is green while the runtime answers.
- On the default it is doubled (`#i-check-double`, a new symbol in the
  sprite). It is a mark, not a button, since there is nothing to click to make
  the default the default.
- On the others it is still the button that makes them the default, green or
  not.

**The provider's head in Settings → Models.** The provider's mark, its name
and a pencil right after the name are one button, which edits the provider.
`ProviderModels` takes `edits` and emits `edit`. The pickers leave it off,
because a session does not edit where it sends. The pencil was a separate
square button at the far right, past the tags.

## Tested

- `settings.spec.js`, Runtimes. A stand-in `colima` that answers its probe and
  its `stop` sits beside the stand-in `nerdctl`.
  - Docker, the default while nothing names another, wears the double check.
  - The answering nerdctl's check is green, and doubled once it is made the
    default.
  - Nerdctl has no Stop.
  - Colima's Stop runs a `stop` task, which ends `done`.
- `runtimes::tests`: no stop for nerdctl, `colima stop` and
  `container system stop` for the other two.
- `settings.spec.js`, Models. Every test that edits a provider opens it by the
  head's button, by its name, `Edit <provider>`.
- `gate.spec.js`: the sprite counts 35 symbols.
