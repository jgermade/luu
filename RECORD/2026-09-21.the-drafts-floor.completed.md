# The draft's floor

Item 22 landed on 2026-09-20 and opened a hole its own record wrote down rather
than closed:

> **A draft turn runs under the session's own policy file, and on this
> repository that file grants `.` at `read-write` plus `cargo`, `rustc`, `git`.
> So an exploratory turn may edit the tree and run the build with nobody having
> approved anything.** Before item 22, the first prompt of a session waited
> behind the gate and this was unreachable.
>
> — [`every-turn-belongs-to-a-job`](2026-09-20.every-turn-belongs-to-a-job.completed.md) §third

The same section named the row this is: *the session's floor narrowed to reads,
so exploration is exploration and the gate is what unlocks the write bit*, and
called it one afternoon. This file is that afternoon.

## The shape, as it stands

`serve` decides what holds a turn in exactly one place:

```rust
// crates/luu/src/serve.rs — the turn's sandbox
let sandbox = {
    let session = app.session.lock().await;
    match (session.context.live_task(), &session.narrowed) {
        (Some(live), Some((task, sandbox))) if live == *task => sandbox.clone(),
        _ => agency.sandbox.clone(),
    }
};
```

`session.narrowed` is `Option<(JobId, Arc<Sandbox>)>` and is written at exactly
one site — the approval, where `Plan::narrow` resolves the approved plan against
the session's sandbox and stamps it `Authority::Plan(job)`. Every other write
sets it to `None`: the job closing, a fresh session, a resume, a reopen of a
draft.

So the fallback arm is *what holds a turn nobody approved*, it is one expression,
and before item 22 it was reachable only by a session with no open job at all —
which, in a served session, never happened, because the gate held the first
prompt. Item 22 made it the normal case.

## The finding: the floor is a change to the fallback, not to the draft

The tempting reading of *give the draft a floor* is that a draft acquires
something — a plan of its own, a sandbox of its own, a field. It does not need
to. `Draft` is already the absence of a narrowing, and the absence of a
narrowing already has a single expression. **Giving exploration a floor is
changing what that one expression falls back to**, and nothing about `Job`,
`JobKind` or the alternation is touched.

This matters for more than tidiness, because a draft's id does not exist when
the sandbox is chosen. `Context::open_draft` is private and runs inside
`push_turn_with_steps` — *a job opens when a turn lands in it* — so on the first
prompt of a session `live_task()` is `None` and there is no draft to hang
anything off. A floor keyed by job id would have to invent one.

## The second finding, found by reading this fallback: a resume widens

`session.narrowed = None` is what the resume route writes, and the jobs come back
from the view with their open state intact. So a session resumed **inside an
approved job** matches the fallback arm and runs under the policy file rather
than under the plan it was approved with.

Today that is a **widening** — the session comes back able to touch more than
the person granted. Under the floor it becomes a **narrowing** — the session
comes back unable to write at all, mid-job. Neither is right, and the second is
worse for being silent in a different direction.

It is item 9's shape one field along: a grant outliving the thing it was granted
under. Item 9 asked what a session was approved *under* and found the posture;
this asks what the live job was approved *with* and finds nothing. It is not
caused by this change and it is made louder by it, which is the argument for
fixing it here rather than filing it.

*(Stated from reading `serve.rs`. The build below owes a test that confirms it,
and this file says so before rather than after.)*

## The proposal

**1. `Authority::Draft`, a unit variant.** `Authority` rides every denial and
crosses the worker IPC so a refusal cannot arrive having lost who refused; a
floor refusal that read as `Policy` would send a person to edit `luu.toml` when
the answer is to approve a plan. It carries no `JobId` for the reason above —
the floor is derived from the session, not from the job — and because the first
prompt of every session would otherwise need an id that does not exist yet.

**2. `Sandbox::read_only(&self) -> Sandbox`, infallible.** Clone the resolved
sandbox, map every root's access to `Read`, stamp `Authority::Draft`. Not
`Plan::narrow`'s route through `SandboxPolicy` and `Sandbox::new`: that
re-canonicalises paths, re-adds the implicit `SYSTEM_ROOTS`, and **can fail** —
and a floor that can fail needs a fallback, whose only safe value is *nothing
granted*, which turns a missing path into a session that cannot read its own
tree. Downgrading in place cannot fail, so the question does not arise.

**3. `Agency::floor`, resolved once beside `Agency::sandbox`**, for the reason
that struct's own doc comment already gives: *two call sites resolving a policy
differently is two sandboxes*.

**4. `serve`'s fallback becomes `agency.floor`.** One expression. Every site
that sets `narrowed = None` starts meaning *the floor* without being edited,
which is the same property that made item 25's counts derived rather than
stored.

**5. The resume re-narrows.** The route rebuilds the live job's plan and narrows
with it, exactly as the reopen path already does four hundred lines above —
which is the fix being *already written*, one branch along, for the job that is
reopened rather than the job that is resumed.

**6. `chat` keeps the policy file.** Not an oversight and not symmetry lost:
`lib.rs` says why in its own words — *`luu chat` has no gate, so it has no
approver either: the policy file is its standing approval and the operator who
ran the command is who that was*. A floor is the gate's shadow; where there is
no gate there is nothing for it to be the shadow of.

## What it costs

**A draft can no longer run the build.** `cargo test` in an exploratory turn
fails when it writes `target/`. That is the intended outcome — building is not
exploring — and it is still a working habit removed from the four days between
item 22 and this file.

**The floor is only as strong as enforcement.** Under `best-effort` there is no
Landlock, so a subprocess started by a draft turn can write anyway. True of
every path grant in this project and not new; written down because the floor is
the first grant whose entire content is a *subtraction*, and a subtraction that
silently does not hold is worth more warning than a grant that does.

**A denial mid-draft costs a turn.** A model that tries to edit and is refused
has spent a round trip finding out. Whether it should be told first is below.

## What is rejected

**Giving the draft a real `Plan`.** Item 22's record named this and declined it
there; it is declined here too, on a second ground. A `Plan` is the object a
person approved — it has a proposer, an approver, a signature and a round. A
plan nobody approved, sitting where the gate panel reads plans, makes the word
mean two things at the one surface built to show exactly one of them. The floor
is a sandbox, not a plan.

**Dropping the commands.** The allowlist is program *names*; what a command may
do is decided by the paths it may touch, and under the floor those are reads. So
the commands need no separate subtraction, and subtracting them anyway would
take `rg` and `ls` — the two things exploration is *for* — in order to restate a
bound the paths already hold. It would also be a second claim, *what may run*,
smuggled into a change whose whole argument is about *what may be written*.

**Dropping network.** Same reason, and the axis is already off by default.

**A `[sandbox] draft = …` knob.** 2026-09-18's answer to a thing nobody can see
was to make it visible, not configurable, and it applies harder here: a floor
that can be turned off is not a floor. If the floor is wrong for a repository,
that repository's `luu.toml` is already the place the grant is written.

## Still open

- **What the model is told.** Item 22 left this open for drafts in general; the
  floor gives it teeth. A draft that does not know it may not write discovers it
  by being refused, and a refusal is a turn. Still unmeasured, still the kind of
  claim this project does not get to make without a run.
- **Whether the gate panel should show the floor.** Item 12's field would like
  it, and today the panel shows what a plan asks for and never what an
  unapproved turn may reach. Its own row.
- **`Authority::Draft` has no job**, so a recording says a refusal came from the
  floor and not which draft was refused. Cheap to add the moment somebody asks
  the question; nobody has.

## Appended 2026-09-21, second section: built, and the four things the argument had wrong or had not seen

The shape above survived. What follows is what building it changed.

### 1. The floor took `/dev/null` with it, and `git` cannot start without that

The first `read_only` downgraded **every** root, and that is wrong in a way the
argument did not see. `SYSTEM_ROOTS` and `NULL_DEVICE` are implicit grants: they
exist so a *subprocess can start*, they are excluded from `check_path`, from
`access_for` and from `to_policy`, and they were never part of what the agent may
reach. There is no write bit in them to take — except that `/dev/null` is granted
**read-write**, deliberately, because `git` calls `sanitize_stdfds()` before
`main` and exits 128 without it. That is
[`git-could-not-open-dev-null`](2026-09-15.git-could-not-open-dev-null.completed.md),
six days old, and the floor walked straight back into it: a draft could run `git`
by the allowlist and `git` could not start.

So the floor downgrades the **explicit** roots only, which is also the sentence
that was true all along: *the floor subtracts what the policy file granted*, not
what the sandbox adds so a child can run at all. The test asserts the null device
survives at `ReadWrite` and that the implicit roots come through untouched —
written after the fact, and it fails on the version that had the bug.

**The calibration note is that §The proposal's own reasoning contained the fix
and did not apply it.** It argued for downgrading in place *because* going
through `Sandbox::new` would "re-add the implicit roots", which is one sentence
away from noticing that the implicit roots are a separate population. Having the
distinction and not using it is a different failure from not having it.

### 2. The second finding was real, and the number is `". (read)"`

Reverting the resume route's re-narrow and running the test: the turn after the
resume reads `src/serve.rs` **allowed**, under rule `". (read)"` — the session's
own grant, not the plan's, on a job whose approved plan names `Cargo.toml` and
nothing else. Stated from reading in §The second finding and now measured. It
predates this change by however long the resume route has looked like that.

### 3. Six `Agency` literals, and making the field private found two of them

The floor is derived in `Agency::new` and the field is **private**, so a struct
literal no longer compiles outside `session.rs`. That was meant as tidiness and
paid immediately: a search found four literals, the compiler found **six** — one
in `serve.rs`'s own test module and one in `tests/stdio.rs`. The struct's doc
comment has said *two call sites resolving a policy differently is two
sandboxes* since it was written; six had accumulated under it. A comment that
has been true and ignored for that long is an argument for a type, not a better
comment.

### 4. Nothing bumps, and it is worth saying which nothing

`Authority` gains a variant and crosses the worker IPC inside `WireSandbox` —
host and worker are the same binary, so that is not a compatibility surface. It
does **not** reach `record::FORMAT` or `protocol::VERSION`: a denial carries the
authority as *formatted text* in `Verdict::rule`, not as the enum. So format 16
and protocol 7 stand, and an older recording reads unchanged. The one visible
change to a reader is the words in a refusal, which is the intended one.

### What was run

`cargo test --workspace` (four consecutive clean runs), `cargo fmt --all
--check`, `RUSTFLAGS=-Dwarnings cargo clippy --workspace --all-targets`, and the
16 Playwright specs of `tests/smoke` against a release `luu serve` — all green.
`scripts/container-check.sh` could **not** be run: the checkout has the Docker
CLI and no daemon. It is in CI and the seam it exercises is one this change
touches only through `WireSandbox::of`, which carries per-root access and the
authority and is covered by `worker_seam.rs`.

Each of the three new behaviours was confirmed against its absence rather than
asserted: reverting the fallback makes the draft write go through, reverting the
resume re-narrow makes the read go through, and downgrading the implicit roots
fails the null-device assertion.

**One of those reverts wrote `broken` over `crates/luu/Cargo.toml`**, because the
first version of the draft test pointed at the checkout the way its sibling does.
A test whose failure mode is a successful write must not be aimed at the
repository; it now writes to a temp path the policy grants and the assertion is
that the path does not exist.

## Still open, after building it

- **The three from §Still open survive**: what the model is told when it is
  drafting (now with teeth — a refusal costs a turn), whether the gate panel
  should show the floor, and whether `Authority::Draft` should name its draft.
- **`a_recording_that_spans_sessions_carries_a_header_for_each` is load-flaky**,
  twice in this afternoon and not since, across ten subsequent workspace runs.
  It asserts that every line under the second header has `at_ms < 400`, where
  400 is also a `sleep` — a wall-clock bound on how long a session takes to
  produce its lines, which a loaded machine can exceed. **Not this change**:
  that test's replies are prose, so no plan exists, so the resume computes
  `None` exactly as the line it replaced did, and no turn in it makes a tool
  call for the floor to answer. Left rather than fixed, because raising the
  bound is a change to somebody else's test written for somebody else's reason.
  It is a row.
- **The floor under `best-effort` is advisory**, per §What it costs. Nothing
  measures how often a session actually runs that way, which is item 25's
  neighbourhood and not this file's.
