# What the first load waits on

## The question

After [`jq79-0.7.11`](2026-11-05.jq79-0.7.11.completed.md) showed the first
load bringing all of Settings: *Ok, dale, la idea es optimizar la carga en
general.*

## What the first load waited on

One load of the static twin under 0.7.11, every request held 100 ms. Each
level waits for the one above it:

```
L0  index.html
L1  the stylesheets, components-once.js, jq79.js, account.js
L2  api/auth/me.json            whoAmI(), once jq79 has run
L3  app.html                    picked by the answer
L4  app.html's 38 imports       one importAll
L5  their imports               jq79 0.7.11 starts these as each file arrives
L6  theirs                      Settings' sections, their forms, …
    → the logo paints after L5; 91 files by the time the page is idle
```

Two things in it are not the page's own shape:

- **L2 and L3 wait on jq79** only because the script that asks for them runs
  after its imports. Neither needs jq79 to be asked for.
- **Half of L4–L6 is never drawn by a first load**: Settings and its nine
  sections, the sessions dialog, the context modal, the permissions dialog,
  the diff modal, the snippet preview, the runtime dialog, the folder picker
  and the terminal panel, and what each of them imports. With 0.7.11 a
  top-level import is a promise to download that file's whole tree.

## What changed

1. **`index.html` preloads `api/auth/me.json` and `app.html`** with
   `<link rel="preload" as="fetch" crossorigin>`. `whoAmI`'s `fetch` and
   jq79's take those responses: one request each, at L1. On the login view
   `app.html` goes unused and Chrome warns about it once ("preloaded using
   link preload but not used"); the page reloads into the app after the
   login. The 401 on `me.json` it also logs there was already logged before.
2. **What the page draws only when asked is asked for when it is asked.**
   `lib/later.js` is `C79.importAll([one])`, kept per file for the visit:

   ```js
   let SettingsModal
   $: if (state.settingsOpen) later(LATER.settings).then(c => { SettingsModal = c })
   ```

   A tag whose variable is `undefined` draws nothing, quietly — jq79 says so
   in `renderNestedComponent` — and the dialog appears when it lands. A `$:`
   is not a top-level import, so the 0.7.11 scanner leaves it alone. In
   `app.html`: the nine above. In `model-picker.html`: `provider-models.html`,
   the menu's list. In `editor.html`: `hunks.html`, a diff's.
3. **Once `app.html` has painted and the browser is idle**
   (`$mounted()`, then `requestIdleCallback`), `app.html` asks for its nine
   files anyway. Without it Settings took 119 ms to open on loopback, where it
   took 88, and 299 at 100 ms a request, where it took 166.

## Measured

Three arms, interleaved, seven loads each after a warm-up, a fresh browser
context per load. *main* is the page before 0.7.11, *0.7.11* the commit that
vendored it, *now* this change. *main* and *0.7.11* differ only in
`vendor/jq79.js`, so both are one server with that file answered from each
version's npm tarball. Every request is held *delay* ms in the browser before
it goes out, all at once — a link that multiplexes. Marks timed in the page
with a `MutationObserver`; medians, in ms. Requests counted when the page is
idle (the static twin) or 1.5 s after the second mark (`luu serve`).

**`luu serve`, mock, release build** — the logo; the folder question a first
visit is asked; Settings, from the click to its rail.

| | now | **173** | **271** | 104 | 76 |
| 40 | main | 442 | 634 | 107 | 74 |

**The static twin**, `python3 -m http.server` — the logo; the recording

| Delay | main | 0.7.11 | now |
|---|---|---|---|
| 0 | 204 / 239 | 257 / 318 | **182 / 212** |

57 requests under main, 91 under 0.7.11, 60 now — nine of them the warm-up,
after the paint.

- **The first paint is two levels shallower** and gains most where a round
  trip costs most: 10 ms on loopback, 280 at 100 ms a request.
- **Settings is where it was on loopback** and ~20 ms later at 40–100 ms:
  the warm-up gets `settings.html` there before the click, not its sections,
  because jq79 reads a file for preloads only when it renders it.
- No console error in any measured load.

## Rejected

- **Listing the children's imports in `app.html`** to flatten L5 into L4.
  It is what a bundler does, and by hand it is a list that rots: a component
  that stops importing a file leaves `app.html` downloading it.
- **Inspectors loaded by which one is chosen.** The chosen one is drawn by the
  first paint, and asking for it after `prefs.js` arrives adds a level to it.
  The two that are not chosen are a few small files.
- **`$importAll`**, for the reason in the 0.7.11 record.

## Still open

- **Compression.** `luu serve` sends every file whole: `app.html` is 104 KB,
  `store.js` 73 KB, `jq79.js` 76 KB. Nothing here for loopback; for a page
  reached over a network it is most of the bytes.
- **Settings' sections** are all imported at its top, so opening it brings
  nine sections to draw one. The same `later()` would make that one.
- HTTP/2 is still modelled, not measured.
