# Naming a provider: where a model lives, written down once

**Status:** a proposal, and the code it plans.

It answers the first *Still open* line of
[`local-first`](2026-09-01.local-first.completed.md) — *whether `luu.toml` grows
provider profiles* — with **no, and a sibling in the state directory instead**.
The reasoning for that half is short and the reasoning for the rest of the file
is not, because a named destination is a weakening of a commitment this project
made in writing six days ago, and the file has to be shaped around that rather
than around convenience.

## The problem, which is four flags

Pointing `luu` at a model that is not the default is this, today, per run:

```sh
luu chat "hola" --backend openai \
  --openai-url https://openrouter.ai/api/v1 \
  --model anthropic/claude-sonnet-4.5 \
  --api-key-file ~/.luu/openrouter.key
```

Four flags, declared three times in
[`lib.rs`](../crates/luu/src/lib.rs) — once each for `chat`, `serve` and
`stdio` — and resolved by `build_backend`, which already grew a `BackendArgs`
struct to stop the two callers drifting apart. Nothing persists any of it.
`local-first` filed the complaint in one sentence and it has not moved since:

> "the user chooses" is not a real freedom if the choice is four flags retyped
> per run.

The six machines in [`machines.md`](../ROADMAP/2026-09-01/machines.md) make it
worse than tedious. Five of them serve through `llama-server` or a hosted
endpoint, so five of them are a different `--openai-url` — and the numbers a run
produces are only comparable when the header says which box answered. A flag
retyped from memory is how the wrong box ends up in the header.

## What the file must not become, stated before what it buys

`local-first` did not only permit remote models, it wrote down what permitting
them obligates. Two of the four are about this file:

> 2. **Remote is named, never a fallback.**
> 3. **Nothing leaves the machine without the destination having been typed.**

A profile is a destination typed **once, weeks ago, and never again**. That is
commitment 3 weakened, and it is the cost of this proposal rather than a detail
of it. `--openai-url https://…` on the command line satisfies the commitment by
construction: typing it *is* the declaration. A line in a file is not typing it.

So the shape of the answer is not "profiles are fine, here is the schema". It
is: **the file has to make a remote destination impossible to configure by
accident, and impossible to use in silence.** Everything below that is
bookkeeping.

## The proposal

### Where it lives: the state directory, and not `luu.toml`

[`the-name-and-the-config-dir`](2026-09-04.the-name-and-the-config-dir.completed.md)
closed with the rule that decides this, and it decides it against the question
`local-first` asked:

> Nothing reads `luu.toml` from the state directory, and nothing should until
> there is a setting that is about the machine rather than the project.

A provider is that setting. `http://192.168.1.40:8080/v1` is a fact about one
LAN; `~/.luu/modelark.key` is a fact about one disk; `qwen2.5-coder:7b` is a
claim that a particular machine has pulled a particular model. None of it
survives a clone, and all of it is the shape the store's doc comment already
sorted: **project policy is committed, machine state is not.**

So `config::dir()/config.toml` — the second thing to land in the directory
after `sessions.db`, which is what that record's other *Still open* line
anticipated. **Not** named `luu.toml`: two files with the same name meaning
different things is the exact drift the rename spent a day removing.

### What a profile is

```toml
# ~/.luu/config.toml — or ~/.config/luu/config.toml. LUU_HOME answers it.

default = "local"

[provider.local]
backend = "ollama"
url = "http://127.0.0.1:11434"
model = "qwen2.5-coder:7b"

[provider.workstation]
backend = "openai"                       # llama-server on the Ryzen box
url = "http://192.168.1.40:8080/v1"
model = "qwen2.5-coder-14b"
context-limit = 16384                    # what the server was started with
remote = true

[provider.modelark]
backend = "openai"
url = "https://ark.ap-southeast.bytepluses.com/api/v3"
model = "deepseek-v3"
key-file = "~/.luu/modelark.key"
remote = true
```

```sh
luu chat "hola"                       # the default profile
luu chat "hola" -p workstation
luu serve -p modelark --select-tokens 2048
```

`context-limit` is in the profile because it is a fact about the server, not
about the run: the OpenAI API has no field for the window, so the number is
whatever `llama-server -c` was given on that box, and a person retyping it per
run will eventually retype it wrong. `--context-limit` still overrides, and the
caveat `build_backend` prints is unchanged.

### The rule: the file must agree with the URL, and disagreement is a load error

`remote = true` is required on any profile whose URL does not resolve to
loopback, and **refused** on one that does. A missing declaration is a load
error — not a warning, and not a prompt.

- **A LAN box counts as remote.** Commitment 3 says *the machine*, not *the
  building*. The Ryzen on the desk is one word in the file, and that word is
  the point: nothing about `192.168.1.40` reads as egress until somebody wrote
  down that it is.
- **`remote = true` on a loopback URL is also an error**, because a file that
  can lie in the safe direction is a file that trains people to write the word
  everywhere and stop reading it.

This is the sandbox's own rule, applied to a different file: *a granted path
that is not there is a load error rather than a rule that silently does
nothing.* Two ways to be wrong, both refused at load, neither of them
discoverable halfway through a run.

And the destination is **printed once per run**, beside the window caveat that
already prints there:

```
provider: modelark → openai@ark.ap-southeast.bytepluses.com (remote)
```

The record header carries the same thing already — `openai@<host>` exists
because "openai" alone cannot tell a 7B on a laptop from a hosted frontier
model — so commitment 4 needs no new machinery, only this line where a person
can still act on it.

### Precedence, which is one sentence

**Flags beat the profile; the profile beats the built-in defaults.** `-p`
names a profile, and `--backend`, `--model`, `--openai-url`, `--api-key-file`,
`--context-limit` override its fields one at a time. A flag that contradicts
the profile wins without complaint, because the printed line shows what was
resolved — an override that is visible does not need to be an argument.

A URL typed as a flag needs no `remote = true`, by the same distinction the
whole file turns on: typing it is the declaration.

### The key file gets the check the auth token already has

`--api-key-file` reads any file that exists and is non-empty. `--auth-token-file`
refuses one that is readable beyond its owner
([`auth.rs:81`](../crates/luu/src/auth.rs#L81)). Same class of secret, one of
them checked; the profile's `key-file` and the flag both go through
`check_mode` after this.

Two things the file will not hold:

- **No `key = "sk-…"`.** A key in a config file is a key in every backup, every
  screen share and every `cat ~/.luu/config.toml` in a bug report. A path is not.
- **No environment variable, including `OPENAI_API_KEY`.** `auth.rs` gives the
  reason and this repository makes it sharper than it was: *an env var is
  inherited by every child this process spawns* — and spawning children is what
  this process does. [`command.rs:143`](../crates/agent-core/src/tools/command.rs#L143)
  sets `HTTP_PROXY` and nothing else; there is no `env_clear` anywhere in the
  tree, so a key in `luu`'s environment is handed to every `cargo`, `git` and
  `rg` the model asks for, inside the sandbox built to bound exactly those. The
  convenience is real and it is refused here on those grounds.

## What it costs

- **A second file in the state directory that can be wrong**, in a directory
  whose whole virtue until now was that its existence was the only thing it
  said. A malformed `config.toml` now fails a run that used to work.
- **The weakening is mitigated, not removed.** A destination typed once is still
  a destination not typed today. The printed line and the two load errors are
  what stands between that and a silent send; neither is as strong as the
  original commitment, and the honest way to hold it is to say so here rather
  than to claim the file restores it.
- **One more flag on three subcommands**, and a resolution step in front of
  `build_backend` that has to be tested for precedence rather than assumed.
- **`default = "modelark"` is a legal thing to write**, and someone will. The
  file makes it deliberate and visible; it does not make it impossible, and it
  should not — the alternative is a tool that argues with its user about their
  own machine.

## What was rejected

| | why |
| --- | --- |
| Provider profiles in `luu.toml` | It is committed with the project. One person's LAN and one person's key paths would arrive in every clone, and a key path in a reviewed file is a footgun with a diff. |
| A fallback chain (`local`, then `modelark` if it is down) | `local-first` rejects it by name, explicitly so that it has to be argued rather than added. This record does not argue for it. |
| Deriving `remote` from the URL alone, with no declaration | It is derivable, and that is the problem: the declaration is not there to inform the program, it is there because a person has to have written it. |
| Three classes (loopback / private / public) instead of two | A word that is read carefully is worth more than a taxonomy that is read once. Two states, one of which is refused unless declared. |
| `OPENAI_API_KEY` and friends | Inherited by every sandboxed child; see above. |
| Auto-discovering a running Ollama or `llama-server` | A destination nobody typed, arriving from a port scan. It is the fallback in a different coat. |
| Switching provider mid-session | The debt `local-first` named — `SessionView.backend` is one `String` set from `Hello` — is not paid by this record, and profiles must not wake it. One provider per session stays true, and the session store's record settles the rest. |

## Still open

- **The UI has no provider picker**, so `serve` resolves once at startup and a
  person in the browser sees the name and cannot change it. That is the same
  hole the window caveat has, and it stays open here deliberately: a picker is
  a switch, and a switch is the schema question above.
- **Per-role providers** — a hosted model for the planning call and a local one
  for the turn, which is one `--model` today for both. `local-first`'s third
  *Still open* (whether a hosted model may be the judge) is the same question
  arriving from the other side, and both want the roles named first.
- **The egress asymmetry is untouched and now nameable.** A plan grants files
  and commands and says nothing about where the tokens go. After this, the
  destination is a *named thing* rather than a URL in an argv, which is what a
  plan would have to declare — progress toward that question, not an answer to
  it.
- Whether the first run should offer to write a `config.toml` the way it offers
  to create the directory. Leaning no: the directory prompt exists because the
  answer cannot be defaulted, and this one can — no file means the built-in
  Ollama default, which is the local-first behaviour anyway.

## 2026-09-07, later — three questions, and what they narrowed

Read back the same day, before any code. Three questions, and all three moved
something. None of them changed where the file lives or what it holds; two
changed how much ceremony it charges, and the third is a consequence of the
precedence rule that is worth writing down before somebody hits it.

### 1. `remote = true` moves to the default profile alone

The question was *what is `remote = true` for*, and the answer above does not
survive it intact. The declaration is not information — the URL already says
whether it is loopback, and the rejection table admits as much: *it is
derivable, and that is the problem.* But commitment 3 says the destination has
to have been **typed**, and

```sh
luu chat "hola" -p modelark
```

**is typing it.** Naming the profile at the moment of use is the declaration;
requiring a second one in the file is charging twice for the same thing. There
is exactly one shape where nothing was typed:

```sh
luu chat "hola"        # default = "modelark"
```

So the rule narrows to that shape: **`remote = true` is required on the profile
`default` names, and refused there when its URL is loopback.** Every other
profile may carry the word or not; `-p` is its declaration. What this keeps is
the case the rule was built for — a `config.toml` that arrived from somewhere
else still fails to load if its default points off the machine — and what it
drops is five lines of ceremony across the five profiles in
[`machines.md`](../ROADMAP/2026-09-01/machines.md) that a person names by hand
every time.

The printed line is unchanged and now has a clearer job: on `-p` it is
confirmation, and on the default it is the *only* signal, which is where it was
always doing the work.

### 2. `-p` and `-m`, and what stays long

The tree has **three** short flags in total — `export -o`
([`lib.rs:62`](../crates/luu/src/lib.rs#L62)), `key new -o`
([`:677`](../crates/luu/src/lib.rs#L677)), `key sign -k`
([`:689`](../crates/luu/src/lib.rs#L689)) — and none of them is on `chat`,
`serve` or `stdio`. `serve` binds with `--bind` rather than `--port`, so `-p`
collides with nothing.

```sh
luu chat "hola" -p workstation -m qwen2.5-coder:14b
```

These two are the ones that were being retyped, so these two get the short
forms and nothing else does. Two that stay long **on purpose**:

- **`--openai-url` and `--api-key-file`.** They are what the profile exists to
  stop retyping. A short form makes the path this record wants to make more
  expensive cheaper instead.
- **`--context-limit`.** `-c` is also `llama-server`'s flag for *the server's
  own window*, and those two numbers are the pair this design already warns can
  disagree with nothing to detect it but `usage.prompt_tokens` afterwards. One
  character meaning both is how the wrong one gets typed.

### 3. What `-m` does not do, which follows from precedence

Flags beat the profile field by field, so `-m` replaces the model and **nothing
else** — not the URL, not the key, not the backend:

```sh
luu chat "hola" -p local -m gpt-4o     # asks Ollama for a model it does not have
```

The answer is the server's 404, not a redirect. That is the precedence rule
working, not an exception to it, and it is written here because `-m` reads like
*pick a model* to everyone who has used one of these tools, while what it means
is *override one field of the destination I already named*. A profile is the
unit that moves; the model is a field inside it.

## 2026-09-07 — what building it decided

Code, in the shape argued above and narrowed by the section before this one.
[`crates/luu/src/provider.rs`](../crates/luu/src/provider.rs) holds the file and
the resolution, [`crates/luu/src/secret.rs`](../crates/luu/src/secret.rs) holds
what both secrets pass through, and `-p`/`-m` are on `chat`, `serve` and
`stdio`. Six things the plan did not know.

**The flags had to stop having defaults.** `#[arg(default_value_t = BackendKind::Mock)]`
erases the difference between *the user said mock* and *the user said nothing* —
and that difference is the entire question a profile answers. So `backend`,
`model`, `ollama_url` and `openai_url` are `Option` now, and the defaults moved
into the resolution, where they can be overridden by a profile before they
apply. The cost is that `--help` no longer prints them, so each doc comment
says its own.

**One enum for the flag and the file.** `BackendKind` moved out of `lib.rs` into
`provider.rs` and grew `Deserialize` beside its `ValueEnum`. Two enums would
have let `--backend openai` and `backend = "openai"` drift into naming
different sets, which is a bug nobody would find until a profile stopped
working.

**The two URL flags collapse into one resolved URL**, and doing it exposed a
case the plan did not consider. `BackendArgs` carried `ollama_url` *and*
`openai_url`, one of which was always ignored; `Resolved` carries the one that
the chosen backend dials. But a profile's URL belongs to *that profile's*
backend — `--backend openai` over `[provider.local]` pointing at Ollama would
otherwise send an OpenAI-shaped request to `/api/chat`. The flag drops the
profile's URL when it switches backend, and
[`switching_backend_by_flag_drops_the_profiles_url`](../crates/luu/src/provider.rs)
is the test that says so.

**Reading the config must not ask the first-run question.**
[`config::dir`](../crates/luu/src/config.rs) asks where the state directory goes
and then *creates* it — right for a session store, wrong for a file that is
absent on most machines. `Config::load` uses the pure `config::resolve` instead
and treats an undecided machine as one with no providers: the same answer,
without a prompt in front of `luu chat "hola"`.

**`deny_unknown_fields`, because the failure is silent otherwise.** A profile
with `backedn = "ollama"` parses fine and does nothing, and the run it produces
is the mock answering as if nothing were wrong. It is now a load error, which is
the same rule the rest of the file follows.

**`check_mode` had to be generalised, not copied.** It lived inside `auth.rs`
with its message hardcoded to the auth token. `secret::read` now does the read,
the trim, the empty check and the mode check for both, and takes the
*consequence* sentence as a parameter — what a leaked token costs is not what a
leaked key costs, and a message that generalised over both would tell a person
neither.

### What the runs show

Against the Ollama on this machine, with `LUU_HOME` pointed at a scratch
directory holding a `config.toml`:

```text
$ luu chat "…"                       # no flags at all
provider: local → ollama@127.0.0.1:11434
[stop] 465 prompt / 34 completion

$ luu chat "…" -p local-v1           # backend openai, against Ollama's own /v1
provider: local-v1 → openai@127.0.0.1:11434
note: the window is the server's: --context-limit 8192 is what this run budgets…
[stop] 465 prompt / 38 completion
```

The window in that note came from the profile's `context-limit`, with no flag on
the command line — which is the field doing the job it was added for.

And the rule, on a file whose default points off the machine:

```text
$ luu chat "hola"
Error: …/config.toml: [provider.hosted] is the default and https://openrouter.ai/api/v1
is not this machine, so every run with no -p sends there. Add `remote = true` to say
so, or name a local profile as the default.

$ luu chat "hola" -p hosted          # the same profile, named
provider: hosted → openai@openrouter.ai (remote)
Error: reading the API key file from /Users/joshua/.luu/openrouter.key
```

Both halves of the narrowing in four lines: refused as a default, allowed when
typed. The second stops at the key because this machine has none, which is the
next thing it would have needed.

`cargo test --workspace` is 349 green, 13 of them this module's;
`cargo clippy --workspace --all-targets` is clean under `-D warnings`.

### Still open, after this one

- **Ollama's backend name is still just `ollama`**, with no host in it
  ([`ollama.rs:126`](../crates/agent-core/src/backend/ollama.rs#L126)), while
  `openai.rs` builds `openai@<host>` because *"openai" alone cannot tell a 7B on
  a laptop from a hosted frontier model*. That argument was about hosted
  endpoints; a provider file makes it true of Ollama too, since two profiles can
  now point at Ollama on two different boxes and every record header would call
  both `ollama`. It is not changed here because the name goes **into recorded
  headers**, and that is a comparability change to argue on its own rather than
  a rename smuggled in beside a config file.
- **The line prints, and nothing reads it back.** A recording carries the
  backend name and the model; it does not carry which *profile* produced them,
  so two runs from `local` and `workstation` that resolve to the same backend
  name are indistinguishable in the record. Cheap to add, and it belongs with
  the header question above rather than before it.
- The UI still has no provider picker, and per-role providers are still one
  `--model` for the planning call and the turn. Both unchanged from the plan.
