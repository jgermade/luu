# A turn asks before its tool limit ends it

> *¿A qué se debe tool_limit?* — *¿El tool_limit aplica a todos los modelos?*
>
> *Lo aplicaría por proveedor y por modelo (teniendo el modelo el del
> proveedor por defecto). También pondría el valor por defecto en Settings >
> General, de modo que si el proveedor no lo define, usaría el general, y si el
> modelo no lo define, usaría el del proveedor. Además, en lugar de
> interrumpir el chat, mostraría una opción para prorrogar otros N tools (o sin
> límite para la sesión). El modo 'Auto' aplicaría tool_limit sin límite.*

## What it was

One number for the whole process: `--max-tool-steps`, 8 unless typed, fixed
when `luu serve` started. Every session, every provider and every model
counted against it.

A turn that reached it ended on `tool_limit`, with the model's last text
standing. That text was an investigation cut short, not an answer. The case
that asked was *audita el proyecto*: eight calls (`list_dir`, `read_file`,
`list_dir`…), then the end, with the model still on its way to reading the
code.

## What it is

**A number per model, per provider, and the file's own.**

- `max-tool-steps` is a key in three places in `config.toml`:
  - in a model's entry, `[provider.x.models."m"]`;
  - in a provider's table;
  - at the top of the file, beside `default`.
- The model's holds over its provider's, and the provider's over the file's.
  Where none says, it is `DEFAULT_MAX_STEPS`, 8.
- `--max-tool-steps`, when it is typed, holds over all three, as a flag does
  over the file field by field. Settings → General says so when it is in
  force.
- `serve` reads the file at the start of each turn (`tool_budget`), so a
  number changed in Settings reaches the next turn without a new session.
- Where Settings writes it:
  - **General** has *Tool calls per turn*, the file's own (`PUT
    /api/tool-steps`). The providers' view carries it, with the default and
    the flag.
  - **A provider's form** has the field on *Connection*, and a column per
    model under *Models*. Each placeholder is the next value up: a model's is
    the provider's, and the provider's is General's.

**The limit is a question, not an end** (protocol 12, `record::FORMAT` 25).

- When the model asks for a call the budget has no room for, the loop asks an
  `Extender` instead of breaking (`agent::Extender`). `serve`'s is
  `Watching`, the same person a held call is put to.
- The question goes out as `limit_reached { turn, step, index, used, more }`.
  The page draws it as a card under the turn's last call, with three answers:
  - **Continue · N more**: another budget's worth for this turn, then
    `limit_extended { budget }`.
  - **No limit this session**: no limit for this turn or the ones after it,
    then `limit_extended { budget: null, session: true }`. The fold keeps it
    (`SessionView::tools_unlimited`), and a resume restores it.
  - **Stop here**: the turn ends on `tool_limit`, as every turn did before.
- It is asked only when the model's reply asks for a call past the budget.
  If the budget runs out at the end of a reply, the model is asked again, and
  if it answers then, nobody is asked anything. With nobody to ask, the old
  rule stands: no further model call once the budget is spent, so as not to
  spend the window on a turn with nothing left to give.
- Cancelled while it waits, the turn ends cancelled. An answer for a call
  that is not waiting is refused (`refused`, `extend_limit`), as a stale
  `answer_call` is.
- Any turn may ask, a job's included. Going on is not an authority a plan
  grants: it costs time and window, and grants nothing the sandbox would not.

**Auto answers *more* itself.** It is the same decision as the gate's: a
person deciding once, not per question. Each time the budget is spent, the
page answers `more`, so a turn in Auto has no limit. Back in Manual, the next
question goes to the person. The server knows nothing of Auto, as with the
gate.

**`luu chat`** has nobody to ask, and ends on the limit as before. It reads
the file's numbers once, at the start, where the flag does not say.
**`luu stdio`** asks as `serve` does: same `App`, same `Watching`.

## Rejected

- **Asking when the budget runs out at the end of a reply.** The next model
  call may be the answer, and the question would interrupt a turn about to
  finish. The question waits until a call past the budget is asked for.
- **Auto as *no limit for the session*.** Switching back to Manual would then
  leave the session unlimited, which nobody chose. *More*, answered each time,
  ends the moment Auto does.
- **The server knowing about Auto.** Auto is the page answering the gate on
  the person's behalf, and the server has never known it. Two kinds of Auto
  would not stay in step.
- **A new refusal value for a stale answer.** `Refusal::Call` already means
  *nothing is waiting where you answered*, and this is that.

## Tested

- `agent::tests`:
  - With an extender, *more* lets the turn go on to its answer and is asked
    once, at the call past the budget. `limit_extended` carries the new budget.
  - *Stop* ends on `tool_limit`, the call unrun. *Session* lifts the budget,
    budget `None`, asked once.
  - A model that answers when the budget runs out is not asked anything.
- `provider::tests`: the model's number over the provider's over the file's;
  `None` where none says; the key written at the top of the file, and gone
  again when cleared; a misspelling refused.
- `serve_ws.rs`, over the socket, with a budget of 4:
  - `limit_reached` with `used` 4, `more` 4, at step 5;
  - an answer for step 99 refused;
  - *more*, then `limit_extended` with budget 8, then `stop`;
  - *session*, then budget `null`;
  - a next turn of six calls that asks nothing.
- `limit.spec.js`, a new spec with its own server (`--max-tool-steps 2`, a
  mock that makes three calls and then answers):
  - the card under the turn, and *Continue · 2 more* reaching the answer;
  - *Stop here* ending on `tool_limit`;
  - Auto answering by itself, so the card never stays;
  - *No limit this session* asked once and never again;
  - Settings → General writing `max-tool-steps = 12`, then removing it, and
    saying the flag holds over it.
- `settings.spec.js`: a model's number and its provider's written from the
  provider form, each placeholder the next value up, and 0 refused.
