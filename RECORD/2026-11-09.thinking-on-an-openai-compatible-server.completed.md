# Thinking on an OpenAI-compatible server

## The problem

Two gaps left open by
[`a-live-session-moves-when-asked`](2026-11-08.a-live-session-moves-when-asked.completed.md)
§Still open, both found switching one session between MiniMax
(Anthropic-compatible) and Alibaba Cloud (OpenAI-compatible), and both asked to
be fixed:

1. **DashScope's thinking was not shown.** Its compatible mode streams a thinking
   model's reasoning in `delta.reasoning_content` with `content: null`. The
   `openai` backend read `content` alone, so the page showed nothing for as long
   as the model thought, then the answer — and the reasoning was in no turn.
2. **Another model's thinking was sent as text.** Moved from MiniMax to Alibaba
   Cloud, MiniMax's earlier answer went up as `<think>pensando en
   MiniMax</think>\n\nRespuesta…`: the `openai` backend sends history as it is.
   The `anthropic` one cuts thinking from every reply it does not replay as the
   blocks it came as; the other way round it was already cut.

## The proposal

**Reasoning streams up as `<think>…</think>`**, the shape the `anthropic`
backend already gives its thinking blocks and everything above both already
masks before it looks for a call and folds in the page. `reasoning_content`
(DeepSeek's name, kept by Alibaba Cloud and vLLM) or `reasoning` (OpenRouter's,
llama-server's); empty strings — the role event's — are nothing. `</think>\n\n`
goes up before the first answer text, or alone at the end of a reply that
thought and then only called a tool or was cut off.

**A reply's thinking goes back only to the destination that wrote it.**
`Written`, per backend: a hash of the model and of everything the stream sent
up, kept for every reply with thinking in it. Building a request, an assistant
message with thinking that is not there goes up as `without_thinking` (moved
from the `anthropic` backend to `backend/mod.rs`, so both cut the same three
shapes). One that is found goes as it came:

- **inside a turn**, every step of a tool loop — interleaved thinking, which
  MiniMax's own OpenAI-compatible API asks to be kept, inline in `content`;
- **across turns**, while the backend lives and luu has not edited the reply.

A backend is built per destination, so a switch starts with nothing
remembered — which is the rule: the thinking of a reply goes only to the model
that wrote it. A reply that was nothing but thinking is dropped and the user
messages either side joined, so a template that requires alternation still
gets it.

## Evidence

Before, the driver of the 11-08 record against its two fakes stored turn 2 as
`'Respuesta de Qwen.'`, and `ali` received MiniMax's answer with its `<think>`.
After:

```
1 '<think>pensando en MiniMax</think>\n\nRespuesta de MiniMax.'
2 '<think>pensando en Qwen</think>\n\nRespuesta de Qwen.'
3 '<think>pensando en MiniMax</think>\n\nRespuesta de MiniMax.'

ali recibe:
    user 'hola, primera pregunta'
    assistant 'Respuesta de MiniMax.'
    user 'segunda pregunta'
```

- `openai::tests::reasoning_in_its_own_field_is_reasoning_by_either_name` —
  both names, the role event's empty fields, both fields on one event.
- `openai::tests::only_the_thinking_this_destination_wrote_goes_back` —
  foreign cut, own kept, plain untouched, all-thinking dropped and the prompts
  joined, a template-opened `<think>` (close tag only) cut.
- `openai_wire::reasoning_comes_up_as_think_and_goes_back_only_where_it_was_written`
  — through `stream()` and a socket, two calls on one backend: the reasoning
  stream as `<think>`, the foreign answer cut in both requests, the backend's
  own kept in the second. The stub now serves several requests in order
  (`stub_each`), one connection each.

## Cost

A `u64` per reply with thinking, 4096 at most per destination. A local
llama.cpp session resumed after a restart sends its earlier answers without
their thinking where it used to send them with it; the Qwen and DeepSeek
templates drop an earlier turn's thinking themselves, so what the model sees
does not change for them.

## Rejected

- **Cutting every earlier turn's thinking, own or not.** Simpler, and it
  breaks interleaved thinking inside a tool loop, which MiniMax's API and the
  `anthropic` backend both keep.
- **Leaving it to each server's template.** A hosted API has no template a
  person can see, and DashScope reads `<think>` in an assistant's content as
  something the assistant said.
- **Remembering by prefix**, as the `anthropic` backend must: a signature binds
  what came before, so it replays only an unchanged prefix. Nothing here is
  signed; whether the text is this destination's own is the whole question.

## Still open

- The `ollama` backend: Ollama's `/api/chat` returns a thinking model's
  reasoning in `message.thinking` when asked to think, and sends history as it
  is. The same two changes would apply; nobody has hit it yet.
- A `finish_reason` and the last text on one event: `parse_event` returns the
  stop and drops the text, which predates this and no server here has been
  seen doing.
