# Sessions that name themselves, and a history to search

Seventy-three sessions on this machine, and every one is called by its id:
`session-1792572711767-43e5`. The history could not say which held what, and
the afternoon this was written Jesús opened three empty ones looking for one
that had eight turns. Hiding the empty ones
([`three-columns-that-each-have-a-footer`](2026-09-16.three-columns-that-each-have-a-footer.completed.md),
appended today) left the rest still named by their ids. Jesús:

> las sesiones no tienen nombre, estaría bien que con el primer prompt, se le
> pregunte al modelo que sugiera uno
>
> preferiría que el botón abra una modal, que muestre el listado y permita
> hacer búsqueda

## The proposal

### A name, asked of the session's own model

When a session's **first turn ends** and the session has no name — its title
is `live` or its id — the server asks the same destination the turn went to
for a title, from the first prompt alone:

```
system  Name the conversation below. Reply with only its title: two to six
        words, in the language it is written in. No quotes, no final period.
user    <the first prompt, up to 2 000 characters>
```

and sets what comes back as the title, the way `PATCH /api/sessions/{id}`
does for the live session: on the view, then checkpointed. What comes back is
cleaned before it is used — thinking cut out by
[`mask_thinking`](2026-10-21.a-call-written-while-thinking.completed.md)'s
rules, quotes and a trailing period stripped, whitespace collapsed, at most
sixty characters — and an empty answer names nothing.

- **After the first turn, not beside it.** A local server with one slot
  would queue one behind the other, and the one the person is waiting for is
  the turn. The name arrives a few seconds after the answer.
- **The session's own model, no other.** A second destination for a title is
  a second place a prompt is sent, which local-first does not get to add on
  its own.
- **Bounded without a field for it.** `CompletionRequest` has no output cap,
  so the call reads its own stream and drops it once it has a line of answer
  or after sixty seconds — dropping the stream is dropping the request.
- **Never over a name somebody gave.** A title that is not `live` and not the
  id is left alone, and so is every session after its first turn.
- **Not on the mock.** It answers from a script, and a naming call would take
  the next scripted reply from the test that wrote it.
- **A knob**, `[sessions] auto-name`, on unless the file says `false` —
  it spends a call per session, and on a hosted API that is money.

**The page learns the name by asking.** When a turn ends in a session still
called by its id, it asks for the session list again, a few times over the
next half minute, until the name is there or it stops. A protocol message
would say it at once and costs a version — `protocol::VERSION` 10, a new
variant every reader of the stream has to know — for a label.

### The history, as a modal

The clock opens a modal rather than a popover: a search field, focused, over
the list. The search matches the title and the id, case- and
accent-insensitive. Each row is the name, how many turns, and when it was
last written to; the current one marked; *×* arming and deleting as it did.
The empty sessions stay out, as in the popover.

## What it costs

- **A model call per session**, on whatever the session sends to. Small —
  a few hundred tokens in, a handful out — but on a thinking model the
  thinking is paid for too, and it is the reason for the sixty seconds.
- **A name the person did not choose.** It can be wrong, and it is renamed
  the way any session is.
- **Up to a few extra `GET /api/sessions`** after a first turn.

## What was rejected

| | |
| --- | --- |
| Naming from the first words of the prompt | No call, no cost, and a title that is half a sentence cut mid-word. It is what a failed call falls back to — nothing — rather than a bad name. |
| Naming while the first turn runs | Contends with the turn on a one-slot server, and the turn is what the person waits on. |
| A cheaper model for titles | A second destination, chosen by the program. |
| A protocol message for the new name | `VERSION` 10 and a variant in every reader of the stream, for a label a list refresh delivers. |

## Still open

- **Sessions named before this** stay named by their id. Naming them is the
  same call over their first prompt, run once over the store; not done here.
- **What a call that fails says.** Nothing, today: no name, no message.

## Appended 2026-10-21: built

As proposed, in three pieces.

- **`serve::name_session`**, last in `start_turn`'s task, after the plan
  check: it returns at every condition the proposal named — not the first
  turn, a name already given, the mock, `auto-name = false`, a config that
  will not load — then sends `NAMING` and the first 2 000 characters of the
  prompt with the turn's own `context_limit`, reads the stream, and drops it
  at the first line outside the thinking that tidies into a title, or at
  sixty seconds. It checks again, after the answer, that the session on
  screen is still the one it asked for and still unnamed, then sets the
  view's title and checkpoints. `tidy_title` strips a `Title:` label — inside
  Markdown bold too, the first test caught that — quotes, a closing period
  and whitespace, skips a label on a line of its own, and cuts at a word
  before sixty characters.
- **The page** asks for the session list again after the first turn ends,
  at 0.5, 2, 5, 10, 18 and 30 seconds, and stops at the name.
- **The history is a modal**, `views/chat/sessions-modal.html`: the search
  focused on opening — `showModal` gives the focus to the close button, so it
  is moved once the dialog is open — matching every word against the name
  and the id with case and accents folded; rows with the name (*Untitled
  session* in italics where there is none), when it was last written, its
  turns, the open one marked; × arming and deleting. The popover, its CSS,
  its two handlers and its rung on the page's ESC ladder are gone.

**Checked against this machine's Ollama**, `qwen2.5-coder:7b` at 8 192: the
first turn of *¿Cómo escribo una función en Rust que invierta una cadena?*
ended at 30 s and the session was *Cómo escribir una función en Rust que
invierta una cadena* at 32 s — in the prompt's language, and longer than the
six words asked for, inside the sixty characters. Unit tests for the tidying
and for what counts as unnamed; `history.spec.js` through the modal,
searching a piece of one id to one row and a word nothing has to *No session
matches*; `gate.spec.js` and `reading.spec.js` moved from the popover to the
modal. The live suite fails only where it failed on `main`, and the icon and
terminal specs that pass when run again.

## Appended 2026-10-23: archived

Asked: *En la modal del listado de sesiones, tendremos: New Session, History y
Archived; las sesiones en History tendrán las opciones de archivar y borrar;
las sesiones en Archived tendrán las opciones de restaurar y borrar; la opción
de borrar debe tener una modal de confirmación*.

**Three tabs.** History's rows carry *Archive* and *Delete* where its × was;
**Archived**, counted on its tab, lists what was put away, newest first, each
row with *Restore* and *Delete*, and says when it was archived. The search is
over whichever of the two is open. An archived row is not opened from there —
restored first. The session on screen offers neither, as it offered no ×.

**Deleting is confirmed**, in a `SubModal` over the dialog rather than by the
two clicks on a × it was: the session's name, *deleted for good… cannot be
undone*, and — for one not archived yet — *Archive* beside *Delete*, the way
to get it out of the way without losing it.

**Archiving is a column, not a move.** `archived_at` in `sessions`, schema 5
(`NULL` for every row from before, which is what they were), set and cleared
by `SessionStore::archive` and `PATCH /api/sessions/{id}` with `archived` —
the route that renames, since both change something beside the fold rather
than the fold. The upsert names its columns and this is not one of them, so a
save never restores what was archived. `SessionSummary.archived_at` is what
the page sorts by. The live session is refused.

**Verified**: `store.rs` — archived, a save does not undo it, restored, and a
missing session says so. `history.spec.js` — a second test archives the other
session, finds it under Archived with the count, restores it, archives it
again, cancels a delete and then confirms one, and the server no longer lists
it. `gate.spec.js` counts 28 sprite symbols and takes the dialog's own head
first, the sheet having one too.
