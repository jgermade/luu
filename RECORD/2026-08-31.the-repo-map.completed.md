# The repository map: the outline first, the graph after

**Status:** plan, then code. Starts step 2's last unbuilt piece — relevance
selection, the project's stated differentiator — and starts it at the *smallest*
end, which is not where [`2026-08-27.aider-repo-map.completed.md`](2026-08-27.aider-repo-map.completed.md)
began but is where its own appended correction ended:

> The cheapest first step is smaller than decision 1 as written here. A
> **per-file outline** — definitions with their signatures, bodies elided, from
> `TAGS_QUERY` alone — needs no graph, no PageRank, no personalization vector and
> no tuned constants […] Aider begins at the graph because it has a large window
> to fill with a whole-repository map; at 8K the outline may be the entire
> answer, and the graph is what happens if it is not.

So this file builds the map and does not rank it. Ranking is the next commit, and
it has to beat what this one records.

## What is being answered, and what is not

**Answered here:** the model is asked about a repository it cannot see. Today the
only way anything from that repository reaches the prompt is `--fragment`, which
is a person naming a path and a line range. A 7B asked *"what does the context
manager do?"* with nothing attached answered about Python's `__enter__` — the
finding that bought the fragment surface in the first place.

**Not answered here:** *which* files matter for the turn in front of us. That is
relevance, it wants the reference graph, and the honest order is to make the map
exist and be measurable before deciding what it should prefer.

## What it is

An outline of the repository, in the prompt:

```
# Repository map — 14 files, tree-sitter

crates/agent-core/src/context.rs
   19  pub enum Counter
   46  pub trait TokenCounter
  127  pub struct Turn
  302  pub fn push_turn
  ...
```

Definitions with the line they start on, bodies elided, extracted with
`tree-sitter` and the `TAGS_QUERY` that every `tree-sitter-*` crate exports as a
`pub const`. There is nothing to vendor and nothing to write:
`tree_sitter_rust::TAGS_QUERY` captures `@definition.*` already.

Rust only, and that is not a placeholder for "we will get to the others" — it is
the language this repository is written in, so it is the language the map can be
*checked* in. A second grammar is a `use` and a line in a match, and it should
arrive when there is a second language to answer questions about.

## Where it goes, and why that is the whole design

**In the cached prefix, under the tool definitions.** Not fused into the user
message the way a fragment is.

That follows directly from decision 2 of the Aider record, which corrected this
project's own ordering rule:

> Order blocks by how often a block is **rewritten**. A block that only grows at
> its end is not rewritten.

A map above the history sits in the reusable prefix and stays there for as long
as it does not change. A map fused into each turn's user message would be paid
for in full on every call and would push the changed bytes to the front of the
prompt. Aider puts its map above the history for this reason; the refresh modes
it grows around it are the same trade seen from the other side.

Within the prefix the order is **system, tools, map** — most stable first. The
system block is a constant, the tool definitions change when the tool set does,
and the map changes when the repository does. Getting that order backwards costs
nothing visible and destroys the reuse the prefix exists for.

## Which files, and in what order

The sandbox's **read roots**, walked, `.rs` files only. Two rules on the walk,
both stated rather than hidden:

- a directory whose name starts with `.` is skipped, and so is one named
  `target`. A build directory is not the repository, and `target/` here holds
  generated `.rs` files that would otherwise outweigh everything real in the map.
  It is a short list and it is a guess; `luu map` prints exactly what the walk
  decided, so the guess is visible rather than inferred from a number that looks
  wrong.
- the walk stops after a bounded number of entries, so a map cannot become an
  unbounded traversal of somebody's home directory because a policy file granted
  one.

Files are outlined **in path order**, which is not relevance and is not pretending
to be. When the budget runs out the map stops on a file boundary and says so in
its own last line:

```
# 9 more files not shown — the map's budget is 1500 tokens
```

A map that silently ends is the same failure as a prompt that was silently
truncated: nobody can account for it afterwards. And path order in a truncated
map has a real bias — `crates/agent-core/` outranks `crates/luu/` for no reason
other than the alphabet. **That bias is the thing ranking has to beat**, and it is
recorded here so the comparison has a baseline that was written down before the
result was known.

## The budget

`--map-tokens N`, and **it is 0 by default: off**.

A map that arrived switched on would change every number in every recording made
so far, quietly, and the first thing anyone would notice is that the old runs
stopped being comparable. Opt-in keeps the baseline intact, which is the whole
reason there is a baseline.

The map is filled to its budget by whole files, counted with the run's own
counter — the same `TokenCounter` everything else is measured with, so the `map`
bucket in the panel is in the same unit as the bars beside it.

## One reading that will be wrong if it is not written down now

**The map inflates prefix reuse, and that is arithmetic, not an improvement.**

Reuse is reported as shared tokens over prompt tokens. Adding a large stable
block to the prefix increases both, and the ratio moves towards 1 no matter what
the map contains — an empty map of 1500 tokens of whitespace would "improve"
reuse. So:

> A reuse percentage from a run with `--map-tokens` set is **not comparable** to
> one from a run without it.

Comparing two map sizes against each other is fine. Comparing map-on against
map-off is measuring the size of the map.

## What it costs

- **Two dependencies**, `tree-sitter` and `tree-sitter-rust`, and they are C
  grammars compiled by a build script. `cargo build` still needs no node; it now
  needs a C compiler, which the Rust toolchain already assumes.
- **A walk and a parse per session.** Bounded by the file cap, and paid once.
- **Staleness.** The map is built once per run. An agent that edits a file then
  carries an outline of the file as it was — the same class of wrongness as any
  cache, and the fix is not free: rebuilding mid-session rewrites a block that
  the entire placement argument above depends on staying still. `mtime` is how
  it would be detected, and *when* to pay for it is Aider's refresh-mode question,
  which needs a measurement rather than an opinion. Not now, named here.

## Rejected

- **Embeddings.** Closed in the Aider record and not reopened: a graph can say
  *why* a file was in the prompt, a cosine distance cannot, and nothing
  measurable has asked for a second copy of the user's code on disk.
- **Starting at PageRank.** It is the right end state and the wrong first commit:
  its constants are Aider's, tuned against a frontier model on a large window,
  and adopting them here would mean measuring a tuning rather than an idea.
- **Ranking by what the task named**, as a cheap stand-in for the graph. It is
  cheap, it is probably better than path order — and it makes the map change per
  task, which moves it out of the stable prefix and quietly reverses the one
  decision this file is most sure of. If ranking is worth a prefix break, that
  should be a measured trade, not a side effect of the first patch.
- **Whole files instead of an outline.** That is `--fragment`, it exists, and the
  window is 8K.
- **A `.gitignore`-aware walk** (the `ignore` crate). More correct, one more
  dependency, and it can wait for a repository where the two rules above give a
  wrong answer.

## How it will be measured

The map is a context strategy, so the rule in `AGENTS.md` applies: numbers from
the same model and the same task set, before and after, and *"fewer tokens" is not
a result on its own*.

What the mock can answer, and what this commit records:

1. **What the map costs.** Tokens for this repository at a given budget, and
   what is left out.
2. **That it does not move.** The rendered prefix is byte-identical across the
   turns of a run — assert it, because the placement argument is worthless if
   the map wobbles.
3. **That the budget is honoured**, and that a truncated map says so.

What only a model can answer, and what this commit does **not** claim:

4. **Does a 7B answer a repository question better with the map than without it?**
   The corpus for that already exists — `scripts/tasks/grounded.txt` is twenty
   prompts about this repository — and the run is the grounded script with
   `--map-tokens 0` against the same script with the map on, sampling pinned,
   same model, same window. The map's own bias makes the interesting question
   sharper: the grounded script asks about `crates/luu/` too, which is the half
   path order truncates first.

## Still open

- **Ranking**, and then the reference graph: edges from `@reference.call`, which
  the same query already captures. The next commit, measured against this one.
- **Rebuilding a stale map**, and what it costs in reuse when it happens.
- **A second language**, when there is a second language to ask about.
- **Whether the map belongs in the prefix at all once it is ranked.** Ranking
  personalizes; personalization moves per turn; the prefix wants stillness. That
  tension is the next real decision, and it is not this one.

## Appended the same day: built, and what the numbers say

### The answer to this file's own open question is no

> at 8K the outline may be the entire answer, and the graph is what happens if
> it is not — [`2026-08-27.aider-repo-map.completed.md`](2026-08-27.aider-repo-map.completed.md)

It is not. This repository's whole outline is **6 327 tokens** (approximate
counter, 29 files, `#[cfg(test)]` modules already excluded). That is **77% of an
8K window**, before the tool definitions (465), the reserve (512), the question
and any history. `luu map` at the budgets a real run could afford:

| `--map-tokens` | files outlined | left out | tokens |
| ---: | ---: | ---: | ---: |
| 512 | 2 | 27 | 430 |
| 1024 | 5 | 24 | 870 |
| 2048 | 10 | 19 | 1 890 |
| 4096 | 18 | 11 | 3 975 |
| 8192 | 29 | 0 | 6 327 |

So at any budget this window can pay, **most of the repository is not in the
map** — and which part survives is decided by the alphabet. `crates/agent-core/`
outlines completely before `crates/luu/` gets a line. The case for ranking is no
longer an argument; it is that table.

### What it costs a run

The grounded script, twenty turns, 8 192-token window, mock backend, one flag
apart:

| run | map | total prompt tokens | peak prompt | mean prefix reuse |
| --- | ---: | ---: | ---: | ---: |
| `--map-tokens 0` | 0 | 30 876 | 2 282 | 93.9% |
| `--map-tokens 1024` | 870 | 48 276 | 3 152 | 96.3% |
| `--map-tokens 2048` | 1 890 | 68 676 | 4 172 | 97.4% |

Two readings, and the second is the trap this file warned about before running
anything:

- **The map is paid on every call.** 870 tokens × 20 turns is +56% on the run's
  total; 1 890 more than doubles it. What it buys back is that those tokens sit
  in the *reused* prefix, so on a backend with a prompt cache they are cheap in
  time and expensive in window. At 8K the window is the scarce one.
- **Reuse went up, and it means nothing.** 93.9% → 97.4% is arithmetic: a larger
  constant block raises shared and total together. A run with the map is not
  comparable on reuse to a run without it, exactly as written above — and the
  numbers now demonstrate it rather than predicting it.

### Two things the code learned by being run

**The test modules were most of the map.** The first `luu map` of this
repository spent its whole 1 024-token budget on three files, and most of those
lines were `async fn a_denied_call_is_reported_to_the_model_rather_than_ending_the_turn`.
A `#[cfg(test)]` module is not the interface a map exists to describe, so it is
skipped — the same budget now reaches five files, and they are code.

**The greedy fill was not monotone, and that is a real bug for a baseline.**
Skipping a file that does not fit and carrying on with the next one packs the
budget better and produces this:

```
--map-tokens 1500  →  13 files
--map-tokens 2048  →  12 files
```

One large outline displaces several small ones, so a *tighter* budget showed
*more* files. A map whose contents do not nest as the budget grows cannot be
compared against itself, and comparing is the whole job. The first file that does
not fit now stops the map, and `a_wider_budget_shows_everything_a_tighter_one_did`
holds it to that.

### Where it stands

Built, tested (11 in `repo_map`, 2 in `context`, 1 in the browser smoke run),
default off, and inspectable with `luu map`. What it has *not* answered is
whether a 7B does better with it — that is the model run this file already
describes, and it now has a number to beat: the map has to buy back the 870
tokens a turn it costs.
