# The container observed: Landlock ABI v8 inside Docker Desktop on a Mac

**Status:** run, measured and completed. It closes the distinction
[`the-worker-and-the-seam`](2026-09-02.the-worker-and-the-seam.completed.md)
§What is built and [`ROADMAP/2026-09-01`](../ROADMAP/2026-09-01/README.md)
kept: *"No container has been started yet. `Containerfile` has never been built
and no tool call has run inside the image it describes."* That is no longer true.

## The run

The image was built from the tree's [`Containerfile`](../Containerfile):

```sh
docker build -t loude-worker:dev -f Containerfile .
```

The build finished in 51.9s on Apple Silicon (Docker Desktop 29.7.2, VM kernel
`6.12.76-linuxkit aarch64`), compiling `luu` in release mode inside Debian
Bookworm and installing `ripgrep`.

Pointing `luu tools` at the container posture:

```sh
cargo run --bin luu -- tools --sandbox luu.container.toml
```

The host launched `docker run -i --rm ... loude-worker:dev luu worker`,
performed the handshake over stdio, and verified the manifest:

```text
sandbox — base /Users/joshua/luu
  read-write /Users/joshua/luu
  execute    /private/etc   (implicit: commands need their interpreter)
  execute    /bin   (implicit: commands need their interpreter)
  execute    /opt   (implicit: commands need their interpreter)
  execute    /sbin   (implicit: commands need their interpreter)
  execute    /usr   (implicit: commands need their interpreter)
  commands   cargo, rustc, rustup, git, rg, ls, cat, sh
  network    allowed
  enforce    kernel
  limits     rlimits (cpu 600s, file 1024M)
  worker     docker (loude-worker:dev) — luu 0.1.0, protocol 1
  on PATH    cargo, rustc, rustup, git, rg, ls, cat, sh
  tools      edit_file, list_dir, read_file, run_command, write_file
```

Zero commands reported `absent`.

## Tool execution and kernel containment, observed

Four tool calls were executed across the pipe, testing each boundary:

### 1. An allowed command executes under full kernel containment

```sh
cargo run --bin luu -- chat "run cargo --version" --sandbox luu.container.toml \
  --mock-delay-ms 0 \
  --mock-reply '```tool
{"name":"run_command","arguments":{"command":"cargo","args":["--version"]}}
```' --mock-reply 'Cargo ran.'
```

Verdict:
```text
  [1] → run_command {"args":["--version"],"command":"cargo"}
  [1] ← ok · commands allows `cargo` · held by landlock ABI v8 + seccomp (ptrace) + rlimits (cpu 600s, file 1024M) · 9 ms
```

**Landlock ABI v8 is active and enforcing in the guest.** On the macOS host,
`run_command` is denied before it starts (*"the kernel cannot hold this child"*,
as measured in [`the-size-sweep`](2026-09-03.the-size-sweep.completed.md) when 14b
attempted it). Inside the container, Level 2 sandboxing is active inside Level 3
isolation.

### 2. An unallowed command is refused in-process

Attempting `python` (which is not in `commands = [...]`):
```text
  [1] → run_command {"args":["-c","print(1)"],"command":"python"}
  [1] ← denied · `python` is not in commands = [cargo, rustc, rustup, git, rg, ls, cat, sh], under the sandbox policy · held by in-process check · 0 ms
```

The check is in-process on the worker side, before any child process is spawned.

### 3. Filesystem isolation holds against directory traversal

Attempting to list `/root` with an allowed executable (`ls`):
```text
  [1] → run_command {"args":["/root"],"command":"ls"}
  [1] ← ls exited with 2 · commands allows `ls` · held by landlock ABI v8 + seccomp (ptrace) + rlimits (cpu 600s, file 1024M) · 2 ms
```

The command was permitted by the allowlist, spawned, and restricted by Landlock
from reading directories outside the granted roots.

### 4. In-process tools route over the worker pipe

```sh
cargo run --bin luu -- chat "read agents" --sandbox luu.container.toml \
  --mock-delay-ms 0 \
  --mock-reply '```tool
{"name":"read_file","arguments":{"path":"AGENTS.md","max_lines":2}}
```' --mock-reply 'Read it.'
```

Verdict:
```text
  [1] → read_file {"max_lines":2,"path":"AGENTS.md"}
  [1] ← ok · /Users/joshua/luu (read-write) · held by in-process check · 2 ms
```

All 5 tools execute inside the container, without touching host filesystem APIs
directly.

## What this changes

- **Level 3 in its development posture is closed in practice**, not only in code.
  The image exists, builds, boots, speaks protocol 1, and enforces Landlock ABI v8.
- **The wall on macOS is breached:** `run_command` with full kernel sandboxing is
  now runnable on macOS development machines via `--sandbox luu.container.toml`.
- **The exit-code rung and gate probe command prompts are unblocked on Mac.**
  Tasks carrying `closes_on` and commands in the gate probe can now run safely.
