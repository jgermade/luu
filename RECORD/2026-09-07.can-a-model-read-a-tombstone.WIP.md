# Can a model read a tombstone, and does it read eleven turns up?

**Status:** a protocol, and the predictions filed before the run. **It has not
been run.** The two rules of `what-leaves-the-history` are both built and both
off, and each is off for two reasons: the first is comparability, and the second
is this file.

Written from a machine that cannot run it — no GPU, four cores, and a network
policy that refuses `ollama.com`. Naming that is why this is a record and not a
result: the instrument is the part that can be built without the box, and
`does-the-model-read-it` is the precedent for filing predictions first and
having them falsified.

## The two questions, which are not the same question

**A — position across the window.** `--repeat-once` renders a span in the
**oldest** turn of the window that carries it, so a turn that selects it again
gets nothing new and must reason from a copy up to eleven turns above its own
message. [`does-the-model-read-it`](2026-09-06.does-the-model-read-it.completed.md)
settled that position inside the *bucket* does not matter — held-but-not-first
answered 13 of 14 against first place's 17 of 19 — and explicitly refused to
lend that answer to this question. This is where it gets asked.

**B — a tombstone instead of the bytes.** `--prune-behind` replaces a fragment
with `// [pruned] path:1-40 — 312 tokens, no longer quoted`. The claim behind it
is that the path is enough, because `read_file` is in the prompt and the model
can fetch what it needs. The claim underneath *that* is that the model will
notice it should.

## The instrument, which exists

`scripts/tasks/grounded.txt`: fifteen questions in three groups of five about
one file each, then **five that attach nothing and ask again about all three**.
That last group has been the fold-fidelity probe since it was written, and it is
the right shape here without modification — under B those earlier turns are
carrying tombstones by the time the last group asks.

The corpus was unrunnable for four days and is not any more; see
[`the corpus rotted twice`](2026-09-07.a-span-is-rendered-once.completed.md).

## The run

Four arms, one flag apart, sampling pinned, against `qwen2.5-coder:7b` — the
model every other measurement in this repository used:

```sh
for arm in "off:" "a:--repeat-once" "b:--prune-behind" "ab:--repeat-once --prune-behind"; do
  luu chat --script scripts/tasks/grounded.txt \
    --backend ollama --model qwen2.5-coder:7b --temperature 0 --seed 1 \
    --tokenizer <qwen2.5-coder-7b/tokenizer.json> \
    --select-tokens 1024 --context-limit 8192 \
    ${arm#*:} --record RECORD/runs/<date>.tombstone/${arm%%:*}.jsonl
done
```

`--tokenizer` is not optional here. Every number in
[`runs/2026-09-07.pruning-behind/`](runs/2026-09-07.pruning-behind/) is
`chars/4`, which is fine for comparing two arms counted the same way and useless
for saying what a window held.

## Scoring

Twenty answers per arm, eighty in total, read by a person. Three marks, and the
third is the one this is for:

1. **Correct** — answers the question from what it was shown.
2. **Wrong** — answers from training, or invents.
3. **Recovered** — under B only: the turn *called `read_file` on the path in a
   tombstone* and then answered. This is the mechanism working as designed
   rather than surviving in spite of itself, and no existing probe counts it.

The last group of five is scored separately from the first fifteen, because they
ask different things: the fifteen are *can it use what is in front of it*, the
five are *what is left*.

## Predictions, filed

1. **A costs nothing measurable.** Arms `off` and `a` score within one answer of
   each other on all twenty. If position inside the bucket does not matter, the
   window is a weaker version of the same claim, and 8 192 tokens is not far
   enough for attention to fall off.
2. **B costs the last group and nothing else.** The fifteen grounded questions
   are asked in the same turn their file is attached, so pruning cannot reach
   them; the last five are asked with nothing attached and against tombstones,
   and that is where B either holds or does not.
3. **`Recovered` is close to zero.** The model will answer from the tombstone's
   path *as a fact about the path* rather than calling `read_file` — the gate
   probe already found a 7B writing a tool result itself instead of waiting for
   one, and this is the same disposition pointed at a different gap.
4. **`ab` scores like `b`.** The two rules touch different halves and their
   costs, if any, do not compound.

If 3 is wrong in the good direction — the model does fetch what a tombstone
names — then B is cheaper than it looks and the cost moves from accuracy to tool
calls, which is a different budget and one nothing here measures.

## What would make each rule default

Not this run alone. **A** wants prediction 1 held on a second corpus that is not
this repository's own docs. **B** wants prediction 2 held *and* the +1.2% token
cost to turn into a saving on a corpus with longer answers, because a fidelity
mechanism that also costs tokens has to be argued per workload rather than
switched on.

## Still open

- **A second model.** Everything here is one 7B. The size sweep exists and could
  be pointed at this, and 14b/32b would say whether a tombstone reads better with
  more capacity — which is the sort of thing that decides a default.
- **No mock arm can stand in.** `--mock-reply` makes every one of these
  questions unanswerable, which is why this file is a protocol and the token
  numbers shipped without it.
