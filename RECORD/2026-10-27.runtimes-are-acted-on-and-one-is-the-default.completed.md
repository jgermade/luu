# Runtimes are acted on, and one is the default

> *En Settings > Runtimes: agrupa las acciones con botones con iconos igual que
> en Engines; añade una opción para marcar un default Runtime.*

## What it was

A runtime's card said what could be done to it in three places and three
styles: an `install` button in the line under the header, a `start it` link at
the end of the error, and a `build` link in an image's row. An engine's card
has had its actions in its header, as icons, since the Engines page was drawn.

And Docker was where every image ran first. `places_for_lists` built the new
session's *Runtime* from `Runtime::CONTAINED[0]` and offered the others after
it: a machine with Podman or Colima and no Docker had its first choice be one
that is not there, every time.

## What it is

**The card's actions are in its header, as icons, like an engine's.** Install
(`#i-download`, where Homebrew can do it with the person's own authority — the
command is still said below, and in the title), start (`#i-play`, where the
runtime says how) and make default (`#i-check`, the ✓ Settings → Models marks
the default with). Make default is offered to an installed runtime only, and
not to the default, which wears a `default` tag in the accent instead. A
build stays in its image's row: it is the image's action, not the runtime's.

**`[runtimes] default` in `config.toml`.** One field, a container runtime.
`Config::default_runtime()` reads it, Docker where the file says none, and
`places_for_lists` declares each image on it — `variants` then offers the
others after it, as before. `PUT /api/runtimes/default` writes it and answers
with the whole Runtimes view, as the section's other writes do; the view
carries `default_runtime`. It refuses `host` and `direct` (422): neither runs
an image. Docker is written as no table, the way `[terminal]` writes its
default.

## Rejected

- **A default that is not installed.** The file would take it, and the next
  session's first choice would be one that is not there — what this was
  written to stop. Offered once the runtime is; a file written by hand still
  may name any.
- **A posture's runtime following the default.** A posture is a policy file,
  and its `[worker] runtime` is the file's to say. The default is for what
  names no runtime: a session made from lists.

## Built, the same day

Tested: `settings.spec.js` — Docker wears the tag while the file names none;
a stand-in `nerdctl` that answers is made the default from its card, the tag
moves, `config.toml` holds `[runtimes] default = "nerdctl"`, and
`/api/postures` offers an image on it first; `host` is refused, and Docker
again is no table. On macOS the install button is the header's icon.

And the open job's menu in the chat's head is named *draft* or *plan*, with
its number in the title; each door says under its name what it does — the
theme's `Menu` takes a `note`, a line under the label, beside the `hint` at
its right.
