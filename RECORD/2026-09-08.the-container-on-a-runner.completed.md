# The container, on a runner

**Status:** a measurement, and the job that will keep making it.

Half of item 5 of the reordered [`ROADMAP/2026-09-08`](../ROADMAP/2026-09-08/README.md).
[`the-container-observed`](2026-09-03.the-container-observed.completed.md) closed
level 3 in practice and left this:

> **No container has been started on Linux.** Every contained run in this
> repository is Docker Desktop on macOS.

That was still true this morning, and the reason given for it was hardware:
machines 4, 5 and 6 are Linux boxes with a hand needed on them. It is the wrong
reason. **A GitHub runner is a Linux box with a Docker daemon**, it is free, and
it is already building this repository on every push.

## What ran

`scripts/container-check.sh`, from the `container` job of `.github/workflows/build.yml`,
on `ubuntu-latest`. It is deliberately a script rather than steps in the YAML:
the same walk has to be takeable by a person with a daemon, and a check that
only exists inside CI is a check nobody can reproduce when it fails.

1. `docker build -t luu-worker:dev -f Containerfile .` — **the first time this
   file has been built anywhere but a Mac.**
2. The handshake and the manifest: `luu tools --sandbox luu.container.toml` says
   `worker docker (luu-worker:dev)`, `enforce kernel`, and **no `absent` line** —
   every command `luu.container.toml` grants exists on the image's `PATH`.
3. A read inside the tree, executed on the far side of the pipe.
4. **The same read on the host**, with both recordings compared field by field:
   `output`, `truncated` and `error` identical. That is the property every probe
   run under this policy depends on, asserted against a real container rather
   than against `direct`.
5. A read of `/etc/passwd` — denied.
6. `run_command`, which is the call level 3 exists for, because on macOS there is
   no Landlock to hold it.

## What it said

```text
[1] ← ok · commands allows `ls` · held by landlock ABI v7 + seccomp (ptrace)
      + rlimits (cpu 600s, file 1024M) · 2 ms

level 3 holds on Linux 6.17.0-1022-azure
```

**Landlock ABI v7**, inside a Docker container, on a stock runner, with the
default seccomp profile — no `--privileged`, no `--security-opt seccomp=unconfined`,
nothing added to the image. The whole ladder held, first attempt, in 2m57s
including the image build.

The number beside the other two the inventory has:

| Where | ABI | How it ran |
| --- | --- | --- |
| Machine 1, macOS | v8 | Docker Desktop's LinuxKit VM — [`the-container-observed`](2026-09-03.the-container-observed.completed.md) |
| Machine 4, native Linux | v10 | No container at all — [`landlock-holds-natively`](2026-09-08.landlock-holds-natively.completed.md) |
| GitHub runner, Linux 6.17 | **v7** | Docker, stock, in CI |

The runner reports the *lowest* of the three, which is worth writing down rather
than explaining away: the ABI a program gets is the kernel's and the runtime's
together, this repository now has three data points and no theory, and the one
that matters for the design is that the lowest of them still holds
`run_command`.

## What it costs

- **Three minutes a push**, most of it the image build. The job needs `test` to
  pass first, so it never runs against a tree that does not compile.
- **The image is rebuilt every time.** No layer cache across runs. That is the
  honest default for a check whose whole point is that the `Containerfile` still
  builds; caching it would make a broken base image invisible until someone
  cleaned the cache.
- **A `.dockerignore` was needed.** `COPY . .` was taking the host's `target/`
  into the build context — a gigabyte of the wrong architecture from a Mac, and
  a slow no-op in CI.

## What was rejected

- **Waiting for a hand on machine 4.** The roadmap called this row *blocked on
  hardware*, which was true of the 14B ceiling and never true of the container:
  what was blocking it was nobody having looked at where Linux boxes already
  are. Machine 4 still answers a question the runner cannot — a GPU and a real
  session with a model in it — and that is the half of item 5 still open.
- **Asserting the ABI number.** It is a fact about the machine, and a test that
  fails when a runner image is upgraded teaches nothing. The script asserts that
  something held the call and prints what; the number belongs here.
- **`--privileged`, or relaxing seccomp, to make it work.** It was not needed,
  and reaching for it before checking would have thrown away the finding that a
  stock runner is enough.

## Still open

- **One worker per process, not per session.** `serve` resolves a single
  `Agency` at startup and every session in it shares that worker, while the
  design says one container per session. Unchanged by this, and it is the
  other half of item 5.
- **The page cannot choose it.** The configuration modal shows the resolved
  sandbox and the worker line inside it, and nothing there can pick a
  container — exactly where the provider was before 2026-09-07.
- **No model has run inside one.** Every contained run, here and on the Mac, is
  the mock. The trigger `luu.container.toml` names for narrowing the network is
  *the first `run_command` inside the container with a model in the loop*, and
  that has still not happened.
- **Nothing measures the seam's cost.** A contained call and a host call answer
  the same bytes; how much slower the contained one is has never been recorded,
  and this job is the obvious place it would come from.
