# What a fold writes down

**Status:** a proposal, and the code it plans.

Item 4 of the reordered [`ROADMAP/2026-09-08`](../ROADMAP/2026-09-08/README.md) —
the compaction log, the last of the four panels
[`luu-design.md`](../luu-design.md) says justify building the debug client at
all, and the only one never built:

> **Compaction log** — when a rolling summary was generated, what it replaced,
> tokens saved.

## The problem, which is not the one item 3 had

Item 3 was a page throwing away data the server already stored. This looked like
the same shape from the roadmap and is not, and the difference is one third of
the sentence above:

| | Where it already is |
| --- | --- |
| **when** a summary was written | `job_closed`, in the stream and in the store |
| **what it replaced** | the job's turns — every turn carries its `job` |
| **tokens saved** | **nowhere** |

`job::Summary` carries `{text, tokens, counted_by}` — what the summary *costs*.
Nothing anywhere carries what the turns it stands in for *cost*, and the saving
is the difference between the two. It cannot be recovered afterwards either:
by the time a reader asks, the window has moved, the counter may have changed
with a resume, and turns that were folded may since have been evicted — the
number was only true at the moment of the close.

A panel that showed the summary's own token count beside nothing would be the
compaction log in name only. So this item wants a line in the record before it
wants a section in the page.

## The proposal

**The fold counts what it replaced, at the close, with the counter that counted
the summary.**

```rust
pub struct Replaced {
    /// Named rather than counted: which turns stopped being sent.
    pub turns: Vec<TurnId>,
    /// What they were worth in the prompt they are no longer in — the same
    /// unit `Summary::tokens` is in, because they are subtracted from it.
    pub tokens: u32,
}

pub struct Summary {
    pub text: String,
    pub tokens: u32,
    pub counted_by: Counter,
    /// Absent in a recording written before format 9.
    pub replaced: Option<Replaced>,
}
```

Three things make it honest rather than merely present:

- **The same counter, the same moment.** `Context::close_job_by` already takes
  the counter and already walks the job's turns to write the summary;
  `tokens_of` is the function the `history` bucket sums, so the number is in the
  unit the bar it will be compared against is in. Two counters subtracted from
  each other is not a saving.
- **`Option`, and the panel says *not recorded*.** A recording from before this
  has no number, and zero is a different claim from silence — the same
  distinction `prompt_sent` and `source` already keep for older streams.
- **It is dropped on a reopen**, with the summary, because a reopened job's
  turns are being sent again and nothing has been saved. That is where
  `summary` and `closed_by` already go, so it is one field joining a group
  rather than a new lifecycle.

**Record format 9, protocol untouched at 5.** Additive to an existing message,
which is the same rule format 7 was taken under (`job_approved` gaining who
approved). The protocol does not move because nothing about *talking* changes: a
client that ignores the field is a client that lacks a panel, not one that
misreads a conversation. `crates/luu/tests/ui_versions.rs` — one commit old —
is what stops the page being left at 8 and refused by the host, which is exactly
how the UI died this morning.

**The panel is then the easy half.** `state.jobs` already carries every closed
job with its summary, from the stream and from the read API both, so the
compaction log is a section in the inspector over data the page has: one row per
fold — the job, the turns it replaced, before → after, and what it saved.

## What it costs

- **A format bump, and the two constants that must move together.** Cheap only
  because the test that pairs them exists; a week ago this would have been the
  fourth UI outage of the day.
- **A count per close.** `tokens_of` over the job's turns, most of them already
  counted and cached by the counter that stored them — the same walk the fold
  makes anyway to write the summary.
- **Old recordings show a gap.** Every fixture in `site/fixtures` predates this,
  so the panel will read *not recorded* for them until CI regenerates them,
  which it does on every push.

## What was rejected

- **Computing the saving in the page.** The turns are in `state.messages` and
  their token counts are not — and even with them, the page would be
  re-implementing `tokens_of`, including the rule that a turn counted by another
  counter is recounted rather than summed. A number that two implementations
  have to agree on is a number that will disagree.
- **A `folded` line of its own.** A new variant of a tagged enum is the one
  change an older reader *chokes* on rather than skips, and the close already
  has a message. Nothing here needs to be said at a moment when a job is not
  closing.
- **Storing `before` and `after` totals of the whole window.** That is a fact
  about the prompt, not about the fold, and the budget already says it every
  turn. The fold's own claim is about the turns it replaced.

## Still open

- **Nothing counts the fold against the eviction.** Both take turns out of the
  prompt; only one keeps a sentence where they were, and no run in this
  repository has put the two side by side on the same corpus.
- **A reopen writes nothing down.** The summary and the numbers are dropped, and
  the fact that a fold was undone leaves no trace but the lifecycle event. If
  the compaction log ever needs to show what was reopened, that is where to look.
- **The saving is not what the prompt saved.** It is what the turns were worth at
  the close; what the *next* prompt actually saved depends on where the floor
  was, and those differ whenever eviction had already taken some of the same
  turns.
