# The tool-call probe, run — roadmap item 4, closed

**Status:** completed the day it was written. Closes the half
[`the-tool-call-probe`](2026-09-14.the-tool-call-probe.completed.md) left open:
*"Running it against a model. Section A's kind of work, on machine 1 or 4 …
the number roadmap item 4 was ordered for."* The harness and the corpus are
unchanged; this is the run.

## The run

Fifteen independent one-shot sessions — no shared history, each line of
[`scripts/tasks/tool-call-probe.txt`](../scripts/tasks/tool-call-probe.txt) its
own `luu chat` — against `qwen2.5-coder:7b` over Ollama, machine 1,
`--context-limit 8192 --temperature 0 --seed 7`: the same destination and the
same settings [`the-7b-does-not-miss-it`](2026-09-14.the-7b-does-not-miss-it.completed.md)
used, for the same reason — a number from machine 1 is worth comparing to the
other numbers from machine 1. Full transcripts, the exact bytes scored, and how
to reproduce the verdicts are in
[`runs/2026-09-14.tool-call-probe/`](runs/2026-09-14.tool-call-probe/README.md).
Scored with the real `agent_core::tools::score_call` — not a hand read and not
a second parser — called from a throwaway example, deleted after use.

## What it says

**A clean call, one in five.** 3 of 15 — a 20% parse rate is the number
roadmap item 4 was ordered for, and it is a worse number than anything else
this project has measured a 7B against: the mock-driven runs measure the
*window's* mechanics and assume a clean call to build a corpus from at all;
this is the first time anything here asked the model itself to produce one on
a real, unscripted grounded question and counted what came back.

**`NoCall` is the largest bucket, and more than half of it is not
refusal — it is confident invention.** Six of the eight: prompt 1 answered
"the second heading in `AGENTS.md` is 'Tools'" — the actual second heading is
`## Where things live` (`AGENTS.md:14`); `Tools` is not a heading in the file
at all, it is the heading of the *system prompt's own tool-definitions
section* the model was given for this run (`<|System|>\nYou are luu, a
concise local coding agent.\n\n# Tools\n…`, visible in `03.jsonl`'s `prompt`
trace line) — the model answered from the preamble it was holding rather than
the file it was asked to read. Prompt 6 answered "edition 2018"; the workspace
is `edition = "2024"` (`Cargo.toml:7`). Prompts 5 and 7 each invented a
plausible-looking directory tree wholesale — neither `RECORD/data/`,
`RECORD/logs/`, `RECORD/config/`, nor `agent-core/src/backend/http.rs`,
`grpc.rs`, `utils.rs` exist. Prompt 10 is the one honest member of the bucket,
declining outright rather than guessing. **The corpus does not score answer
correctness** (`the-tool-call-probe`'s own §What it costs says so), and
nothing above changes that — it is not part of `stats.json`'s verdicts — but a
`NoCall` that is a wrong answer stated as fact is a different failure from a
`NoCall` that is a refusal, and the four-way scorer cannot tell them apart. It
should not have to: that is a second, larger probe, named below.

**Two shapes turned up that the scorer's own four verdicts do not name, both
landing correctly as `NoCall`, for two different reasons.** `the-tool-call-probe`'s
own §Still open called this exactly: *"A shape-based drift detector, if a
second, differently-shaped drift is ever observed. One example is a fence
tag; a second might not be."* Two showed up in one run:

- **Prompts 4 and 14: a `\`\`\`tool` fence — the right tag — around the wrong
  shape.** `{"command":"cargo","args":["fmt","--all","--check"],"cwd":".","timeout_ms":30000}`
  is `run_command`'s own argument object, written directly instead of wrapped
  as `{"name": "run_command", "arguments": {…}}`. `score_call`'s first check
  (`crates/agent-core/src/tools/mod.rs:374`) tries to parse the fenced body as
  a `ToolCall` and fails — there is no `name` field — and its second check
  (`:384`) looks for the fence tagged with a tool's own name, which `tool` is
  not. Both attempts to characterize the block fail, correctly, by the
  algorithm as written, and it falls through to `NoCall` — an attempt with the
  right tag and the wrong contents, scored identically to no attempt at all.
- **Prompt 12: fenced under a third kind of tag.** `\`\`\`json` around
  `{"path": "crates/luu/tests"}` — not `tool`, and not `list_dir`'s own name
  either, a plain language-hint tag of the kind a model reaches for outside
  this format entirely. Same fall-through, same `NoCall`.

Neither is a bug in `score_call`: the function does exactly what
`the-tool-call-probe` specified, and specified it *because* only one drift
shape had ever been observed. This run observed two more. **A fence-tag drift
detector (item 4's original scope) and a wrong-argument-shape detector (what
prompts 4 and 14 are) are different instruments** — the first asks "does the
tag match", the second asks "does a correctly-tagged block's body match the
schema" — and building the second on one example each the way the first was
built on one example is the same warning this file's own §What was rejected
repeats from `the-tool-call-probe`.

## What this does not answer

- **Why.** Nothing here distinguishes a model that does not understand the
  format from one that understood it on the fifteen questions where it
  worked and did not need it — every `Parsed` prompt (8, 11, 13) asked for a
  fact from a specific named file; several `NoCall` prompts (1, 6) asked for
  something a plausible-sounding guess could pass at a glance. That is a
  hypothesis this run's design cannot separate from chance on n=15.
- **A second model, a second run.** One 7B, one seed, one temperature, fifteen
  questions, the same caveat every record here repeats.
- **Whether the two new shapes replicate.** One example each, the same
  standing warning `the-tool-call-probe` gave its own single example.

## What was rejected

- **Re-scoring `NoCall` for answer correctness inside this run.** Named
  above as a real, sharper finding than the four-way scorer surfaces, and
  deliberately left out of `stats.json`: `the-tool-call-probe` scoped this
  probe to shape only, and mixing a correctness read into the same number
  would make the 20%/53% split mean two different things depending on which
  prompt you were looking at.
- **Hand-slicing `NN.txt` to find the first reply's text.** The CLI interleaves
  the model's own text with lines it prints itself (`[1] → …`, `[1] ← …`) and,
  where a tool ran, a second model reply — string-splitting that is exactly
  the "two scanners drift on the same malformed block" problem `fenced`/
  `fenced_span` exists to avoid one layer down. `NN.jsonl`'s `token` /
  `tool_call` event boundary is unambiguous where the printed text is not, so
  extraction reads the events instead — see
  [`runs/2026-09-14.tool-call-probe/README.md`](runs/2026-09-14.tool-call-probe/README.md).
