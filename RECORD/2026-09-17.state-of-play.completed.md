## The shape of the day, in one line

**The housekeeping found the work.** Nothing here began as a plan to change the
gate. It began as *bring the roadmap up to date and fix two records whose suffix
was lying* — and writing the revision is what forced reading item 9's row closely
enough to notice that its sentence was right about the symptom and wrong about
the mechanism. Reading the code to write the record is what turned up the half
nobody had seen: that the **recording** was wrong and not only the gate.

That is the second time in two weeks that a piece of bookkeeping paid for itself.
Item 6 of the last revision — *nothing in the page reads the trace's `pruned`
lines* — was the smallest row in it and found two bugs in the code beside it. The
pattern is not *do more housekeeping*; it is that **the cheapest way to read code
adversarially is to have a reason to read it that is not "find the bug."**

## Found while doing it, none of it by a test written for the purpose

- **The test that pinned the rule could never have caught the bug.**
  `a_session_started_on_a_posture_runs_under_it_and_says_which` asserted exactly
  the sentence the design wrote — resume naming a posture, expect a 409 — against
  a server built with **`store: None`**. Under the change it started answering
  *501, session store is disabled*, because the store check now comes first. With
  no store there is no stored session, with no stored session there is no posture
  to compare, and the 409 it was reading came from a branch that fired before any
  of that. It was green for eight days and it was asserting the half a client
  could see, which is the same shape as the bug it was guarding.

- **The plan was wrong about its own second change, and the error is the
  diagnosis.** The record proposed that the resume endpoint "gains" an optional
  `posture` field. It has had one since 2026-09-08, wired to a blanket refusal.
  So the work was **narrowing a refusal**, not adding a field — and what that says
  about the original defect is the useful part: somebody wrote a check, wrote a
  test for it, and both guarded the door a client could *see* rather than the one
  it could walk through.

- **Roughly a dozen of the thirty-three commits since 2026-09-09 were debug-UI
  work no roadmap row ever asked for.** Good work, properly recorded, and not
  predicted by any plan in this repository. It is in the revision as a section of
  its own rather than left out, because a roadmap that only lists what it got
  right cannot be used to judge how much of this project's work a roadmap
  predicts.

- **A rename's link sweep walks into `target/`.** The move that updates every
  link a renamed record broke —
  `grep -rl … --exclude-dir=.git | xargs sed -i` — rewrote the string inside
  `target/debug/incremental/*.bin`, `deps/*.rmeta` and a test binary, and the next
  build ended in *the compiler unexpectedly panicked*. Nothing in the working tree
  was touched and nothing tracked was at risk; `rm -rf target/debug/incremental`
  cleared it. Worth writing down because this project renames records often enough
  for that sweep to be a standing move, because the damage surfaced two commits
  after the command that caused it, and because the fix is one flag:
  `--exclude-dir=target`.

- **Two dangling links in `RECORD/` are dangling on purpose.**
  [`enforcement-per-job`](2026-09-06.enforcement-per-job.completed.md) points at
  `ROADMAP/2026-09-06/`, a revision written on the branch it was ported from and
  deliberately not imported — it describes a history this tree never had. The
  record says so in its own last section. A link check run naively over `RECORD/`
  reports them as breakage, and the next person to run one should read that
  section before repairing anything. The other eight are the `loude-design.md`
  misspelling that
  [`state-of-play`](2026-09-14.state-of-play.completed.md) named on 2026-09-14
  and left alone, for the reason that has not changed: a link inside a finished
  record is content, and content here is append-only.

## What it cost

- **Four tests, 451 → 455**, and every one of them is a case that had none:
  `same_place` compared from both sides, a resume that moves only the posture, a
  stored posture of `None`, and the first end-to-end test in the tree where a
  posture outlives the session that chose it.
- **One field on `SessionView`**, which is what `luu export` writes and the static
  mirror serves. No format bump — the fact has been on the wire since format 10.
- **Two short store locks where there was one.** The fold decides whether a
  posture needs building and building one can start a container, so an id nobody
  stored has to be a 404 before `posture_for` runs.
- **One extra `GET` per resume from the page**, which answers *say nothing* on any
  failure and therefore behaves exactly as every resume did before it.
- **66 files touched by the rename sweep**, one line each, and no record's content
  changed.
