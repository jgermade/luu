# Engines: installed, started on a model, and uninstalled

The same day as
[`engines-found-used-and-owned`](2026-10-26.engines-found-used-and-owned.completed.md),
from using what it built:

> *Cuando se elige al iniciar una sesión, se carga el motor de inferencia con
> el modelo que se haya elegido, no hace falta elegirlo.*
> *Quitamos 'use →'.*
> *¿Por qué llama_cpp tiene una ruta tan profunda?
> (`/engines/llama/b11236/llama-b11236/llama-server`)*
> *'something already answers on port 8080, and it is not one luu started':
> luu puede buscar puertos libres para evitar este error. ¿Algún rango
> recomendado?*
> *El botón de play podría levantar una SubModal que permita elegir un modelo e
> iniciar un chat en la misma modal.*
> *El botón de desinstalar debería pedir confirmación, borrar el binario (si no
> es del sistema) y luego quitar el motor de inferencia del listado.*
> *La modal de añadir un Engine debe ser más como un instalador, y quitamos el
> modelo. Usa un formulario más ancho con InputContainer.*

## The problem, one ask at a time

**The engine's model is the session's.** `[engine.*] model` is what a
llama.cpp or mlx engine is started on, and `engines::for_run` already replaces
it with the session's model whenever that is a reference into the catalog —
which every model the pickers list for an engine's provider is. The key only
decides the first start, and the form asked for it first, as if it were the
engine's to own.

**`use →` on a card** opens the new session's dialog on one of the engine's
providers. It is the play button's job now (below), and two ways to the same
place on one card is one too many.

**The path is the archive's.** llama.cpp's release unpacks into a folder of its
own, `llama-b11236/`, and luu unpacks the archive as it is into
`engines/llama/b11236/`. `find_in` searches four levels down, so it works; it
reads like a mistake.

**A port is a default, and defaults collide.** 8080 is llama-server's, and
half the machine's other servers'. A table written with no `port` uses the
kind's own, and a second engine of a kind or any other local server on it is
*something already answers on port 8080*.

**Play starts an engine on whatever its table says**, and nothing about a
session. The question a person has at the card is *run this on that model, and
let me talk to it*.

**Uninstall removed the copy and left the table**, which then said *luu's own
llama 11236 is not downloaded yet* on a card nobody wanted any more.

**The form is a settings table**, model and all, under a heading that says
*Add an engine*. Adding one is installing a server: which kind, from where,
where it listens.

## The proposal

- **No Model in the pane or the form.** The key still loads, and an edit keeps
  it as it was: a file that relies on it for a profile with no `model` does not
  break. A new engine is written without one.
- **No `use →`.**
- **An archive with one folder at its top is unpacked without it**, so the
  binary is `luu:/engines/llama/b11236/llama-server`. A copy already on disk
  under the old layout still resolves: `find_in` searches.
- **luu picks the port.** `GET /api/engines/port?kind=` answers the first port
  from the kind's own upward that no table names and nothing on this machine
  listens on — tried with a bind on `127.0.0.1` — within a hundred of it. The
  form starts from that answer and *use* writes it. **The range is the kind's
  default and up**: what each kind's documentation and every port someone
  remembers say, `8080`, `8081`… for llama.cpp, `11234`… for mlx-serve,
  `11434`… for ollama — kept clear of the ephemeral range the OS hands outgoing
  connections (32768 and up on Linux, 49152 on macOS), where a free port now is
  a taken one in a minute. And when one is taken anyway, the start sheet says
  so and offers **move to port N**, which rewrites the table and every provider
  whose URL still says the old one.
- **Play opens a sheet**: the models this engine can load, from the catalog —
  for ollama, ollama's own store — and two ways out. *Start a chat* creates a
  session on the engine's provider and that model, closes Settings, and the
  session's first `ensure` starts the engine on it. *Start engine* starts it
  alone on that model: `POST /api/engines/{name}/start` takes `{ model }` — a
  catalog reference, nothing else from the page — and restarts an engine luu
  runs on another one.
- **Uninstall asks, and then removes the engine.**
  `POST /api/engines/{name}/uninstall`, only for luu's own copy: it stops the
  engine, deletes the copy unless another table runs it, and takes
  `[engine.<name>]` out of the file with the providers that start it (the
  default goes back to the mock if it was one of them). A system binary is
  never deleted, and its card has no uninstall at all. The sheet that asks
  says each of those things before it does them. The route by kind and version
  goes: nothing on the page removes a copy without its engine any more.
- **The form is an installer**, a `SubModal` as the provider form is, wider,
  in `InputContainer`s: the **kind** as three cards, each with what it is and
  whether this machine has a release for it (`installable` on the view, from
  `EngineKind::asset`); **where the binary comes from** — luu's own copy (a
  version, and a variant for llama.cpp), one this machine has, or a path; the
  **name and port**, both filled in; the arguments and the wait under
  *Advanced*. *Install* writes the engine and its provider and, for luu's own
  copy, starts the download and shows it in the form until it is done.

## What it costs

- Two routes (`port`, `{name}/uninstall`), one changed (`start` takes a
  model), one removed (`uninstall` by kind). The protocol and the record
  format do not move: these are page routes.
- A bind per port tried, up to a hundred, on a click.
- The form is rewritten.

## Rejected

- **Choosing the port when the engine starts.** The provider's URL has the
  port in it — *the profile keeps its URL, so the destination a run prints is
  still one line of the file* — and a port chosen per start would make that
  line wrong.
- **A fixed luu range** (39000–39099, say). Nobody looks for llama-server
  there, and a URL somebody types by hand would stop being the one in the docs.
- **Deleting a `path` binary on uninstall.** *Si no es del sistema* — but a
  path somebody typed is somebody's, and luu deletes only what luu put there.

## Built, the same day

As proposed. What the proposal did not say:

- **The start sheet's two buttons are off while the port is somebody
  else's**, not only the chat: an engine started there fails to bind, and a
  chat would talk to the other server. *Move to port N* is the way on.
- **A provider is the chat's only way in**, so an engine no provider names
  starts alone and the sheet says so; with more than one, the sheet asks which.
- **The kind cards say why one is out of reach**: MLX on Linux reads *MLX runs
  on Apple Silicon, and this is linux/x86_64*, and is still chosen when this
  machine already has a `mlx-serve`.

Tested: `engines::tests` — a free port is one no table names and nothing
listens on, and above the one held; an archive's single folder is unpacked
away, and one with a file beside it is not. `settings.spec.js` — the
installer opens on llama.cpp with a name and a free port in and no model, and
refuses a path that is not `llama-server`; play lists the two models llama.cpp
can load and not the MLX one, and starts the engine on one; uninstall asks,
names the copy and the table, and takes the copy, the table and the card; and,
last in the file, a stand-in server on `fake`'s port is named in the sheet,
*move to port N* rewrites the table and the provider's URL, and *Start a chat*
leaves the live session on `fake` and the model chosen.
