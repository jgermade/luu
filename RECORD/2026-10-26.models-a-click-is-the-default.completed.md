## What it was

From the top: the first-run warning (when the server fell back to the mock),
the hero, the mock's own row, the two columns, and *+ provider* under them. A
click on a model opened the new session's dialog on it; *use →* in the
columns' head did the same on the provider's own model. The columns listed
every provider in the file (`every`), the ones whose engine is switched off
included. A provider whose engine luu starts had its form's *Models* tab shut,
with a note sending the person to Settings → Engines.

## What it is

- **The hero first, then the first run**, then the columns, then the mock's
  row. The mock is the fallback, so it reads as the last line, not the first.
- ***+ provider* is in the pane's pinned `.modal-foot`**, the same markup and
  padding as *+ engine* in Engines.
- **A click on a model makes it the default**: `default` names its provider
  and the provider's `model` names it, in one `PUT /api/providers`, through
  the same `makeDefault` as *make default* (which stays in the head, for the
  provider with its own model). *Use its own model*, offered by a provider
  that lists nothing, moves the default and leaves `model` alone. A remote
  default is refused as before and opens the form to have its host typed. The
  columns are `disabled` where the file is not editable, because a click
  writes now.
- ***use →* is gone.** The chat's picker and *New session* are where a
  session starts; a click in Settings meaning both *start* and *default*
  would have been two answers to one gesture. *move it →*, on the line that
  says the live session did not follow the default, stays: it is the only way
  from that sentence to a session that does.
- **Only providers whose engine is enabled are listed.** The `every` prop is
  gone from `provider-models.html`, so Settings lists what the pickers offer
  (`offeredProviders()`, every profile not in `idle`). **This reverses a line
  of
  [`engines-found-used-and-owned`](2026-10-26.engines-found-used-and-owned.completed.md)**,
  which kept those providers in Settings → Models so they could still be
  edited there. The cost is exactly that: a provider whose engine is switched
  off cannot be edited or removed from Models until the engine's switch is on
  again. Uninstalling the engine still removes its providers, from Engines.
- **The providers column steps in .5rem**: the list's padding, each row's
  padding and the gap inside it. **`.models-head` is 3rem tall and ruled off**
  from the models under it, with `.models` losing its top padding so the rule
  meets the box's top edge. Both are the shared component's, so the chat's
  dropup and the new session's dialog changed with Settings.
- **A local provider's form has its *Models* tab.** For a provider whose
  engine luu starts, the form asks `GET /api/providers/{name}/models?facts=1`
  as it does for any edit. For llama.cpp and mlx the answer is the catalog, the
  same list the pickers show: every model on the machine the engine loads, by
  reference, with no facts. So every row is *not said*, and each has its own
  fenced|native. For ollama it is what that ollama lists, with its facts. The
  choice is written as the form writes any exception,
  `[provider.<name>.models."<reference>"] tool-calls`, and only where it
  differs from the profile's. A reference is the name `provider::resolve`
  looks the entry up by, because it is the model a session on that provider
  is on. Rows show it as the pickers do (`tiny:1b (ollama)`) and keep the
  reference in the title. There is still no *Connect*: the URL is the
  engine's, and the engine may not be running.

## Rejected

- **A transport-only list for engine providers.** The tab already has the
  rule for which rows get the choice and how an exception is written; a second
  layout for one kind of provider would be a second copy of it. The window and
  the default come with it, and the default there is the same `model` a click
  in the columns writes.
- **The idle providers greyed out in the columns.** The ask names which ones
  appear, and a greyed row that can be clicked into but whose models start
  nothing is a third state the pickers do not have.
- **The tools group with a choice too.** Native is what that group is for
  ([`connecting-a-provider`](2026-10-21.connecting-a-provider.completed.md),
  2026-10-22), and a catalog's models never land in it, so the ask is met
  without changing that rule.

## Tested

waiting for a host terminal. It fails the same way with this change stashed,

## 2026-10-26 — the mock without its box

Asked: *Quitaría el recuadro blanco del mock built in.*

The mock's row lost its border, its rounded corners, its white ground, and
the accent bar on its left that marked it as the default. It is a line
under the columns now, flush with their edges, as the heading and the
file's path above them are. The *default* tag is the one mark left that
says it is chosen, and it was already there. `settings.spec.js` reads that
tag (`.builtin .tag.default`) and nothing about the box, so it is unchanged.

## 2026-10-26 — superseded in two places

[`a-default-is-chosen-and-held`](2026-10-26.a-default-is-chosen-and-held.completed.md),
the same evening, changed two things this record says:

- the provider's *make default* in the columns' head is **gone**: a click on a
  model is the only way a provider becomes the default;
- a click on a remote provider's model **opens nothing**. The default is
  written *held*, and the host is typed on a line over the columns, not in the
  provider's form. The first *Still open* above, a model the form did not
  carry, went with it.
