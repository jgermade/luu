# jq79 0.7.6

## The question

Jesús, while the landing was being redone: *he actualizado jq79, échale un
ojo* — and then, *ignora lo del tutorial*. jq79 0.7.6 was published on npm on
2026-10-27 at 20:17 UTC; the page ran 0.7.5. The tutorial is jq79's own site
and never reaches the vendored file, so only the library is looked at here.

## What changed upstream

Read from `src/jq79.ts` in the published 0.7.5 and 0.7.6 tarballs, diffed:
two changes, nothing else in `src/`.

1. **A component's source is downloaded once** (`Component79.cache`). `fetch`,
   `fetchAll` and a setup script's `import()` of an `.html` now share one map
   from absolute URL to a promise of the text. Each call still builds its own
   `Component79` from that text, so mounting one never touches another. A
   failed download is dropped and the next request tries again; a hot update
   rewrites the cached text. On by default, with `Component79.cache(false)`
   and `Component79.clearCache()` to turn it off or empty it.
2. **`$mounted()` waits for the children that have not painted.** A nested
   component whose own script held its first render (an `await` before
   `$mounted()`) now counts against its owner, and the owner's `$mounted()`
   resolves once those children have painted, or have been destroyed before
   painting. Upstream's record is `RECORD/2026-10-22.mounted-waits-for-children.md`.

## What it means for luu

- **The cache changes nothing on the first load.** Counted on the static twin
  with Playwright, each version served from its own copy of `site/`: 27
  `.html` files requested, 27 requests, no file twice — under 0.7.5 and under
  0.7.6 alike, two loads each. luu's setup scripts already imported each
  component once per page, so the cache only matters for a component fetched
  again later, and nothing here relied on a second fetch getting fresh text:
  luu does not use jq79's hot reload.
- **Seventeen of luu's component files `await $mounted()`**, the theme's demo
  page among them. The second change can only make one of them wake later,
  never earlier, and only when a child below it holds its render. None of the
  suites saw a difference.

## Checked

- `web/vendor/jq79.js` and its map are `dist/jq79.js` and `dist/jq79.js.map`
  from `npm pack jq79@0.7.6`, unchanged. The file they replace was 0.7.5's,
  byte for byte.
- **The static twin passes 5 of 5**, with `site/` assembled from `web/` and its
  fixtures recorded the way CI does.
- **The live suite passes 76, skips 1, fails none** against a release binary
  built with 0.7.6. The first run had two failures, neither jq79's:
  `limit.spec.js` › *a turn at its tool limit asks, and Auto goes on by
  itself* passed when run again, and `workspace.spec.js` › *the tab shows a
  changed file's diff in a modal* needs xterm.js, which this checkout did not
  have until `npm ci` in `web/`; with it, the test passed alone and then in the
  full run.
- No Rust changed, so `cargo test` was not run for this.
