# What `--constrain` does: the grammar leak closed, the schema arm cannot say no

**Status:** completed the day it was written. Lands roadmap item 5 —
[`a-grammar-for-tool-calls`](2026-09-06.a-grammar-for-tool-calls.WIP.md) — as
code: `Constraint`, `--constrain grammar|schema` on `chat`, and both arms
measured against a real server through the real CLI, not a hand-built
request. Closes the leak
[`the-alternation-that-was-not-one`](2026-09-14.the-alternation-that-was-not-one.completed.md)
found the same day, and builds the second arm that record named but did not
touch.

## What was built

- **`Constraint`** (`crates/agent-core/src/backend/mod.rs`): `Schema(Value)`
  or `Grammar(String)`, carried on `CompletionRequest`. Each backend renders
  what it can into its own field and answers `Backend::constrain_caveat`
  once, before anything is measured — the same rule
  [`OpenAi::window_caveat`](../crates/agent-core/src/backend/openai.rs) set:
  a run that sent a constraint and a run that sent none must not look the
  same afterwards.
  - `OpenAi` renders both (`response_format` for `Schema`, `grammar` for
    `Grammar`) and warns on `Grammar` every time — measured, in
    [`the-bare-grammar-field`](2026-09-14.the-bare-grammar-field.completed.md),
    to work on `llama-server` and be silently dropped by Ollama's own `/v1`,
    same field, same endpoint.
  - `Ollama` renders `Schema` (its own `format` field) and declines
    `Grammar` outright — that API has no GBNF field at all, documented or
    not.
  - `Mock` renders neither and warns on both: it "cannot be exercised with
    `--constrain`" (`the-tool-call-probe`'s own words), and a flag that
    changed nothing silently would be exactly the thing the window caveat
    exists to prevent.
- **`Tools::call_schema`** (`crates/agent-core/src/tools/mod.rs`): a `oneOf`
  over each tool's own `{"name": …, "arguments": …}`, reusing
  `Tool::parameters()` verbatim — no second definition of a tool's shape.
- **The grammar leak, closed** (`crates/agent-core/src/grammar.rs`):
  `Compiler::avoid_until_forced` — a generic KMP substring-avoidance
  automaton, not hand-derived for `` ```tool `` specifically — replaces the
  `root ::= prose | call` that
  [`the-alternation-that-was-not-one`](2026-09-14.the-alternation-that-was-not-one.completed.md)
  proved was a no-op. `prose` no longer contains the fence substring; the
  moment it is typed, the grammar forces a well-formed call and a stop, or
  it is not typed at all. Fully worked by hand against three patterns
  (`"ab"`, `"aab"`, `"abab"`, the last a genuine self-overlap) before
  touching the live server, and every prediction matched the compiler's own
  output byte for byte.
- **`--constrain grammar|schema`** on `luu chat`, threaded through
  `run_agent_turn` so every model call in the turn carries the same
  constraint (not just the first).

## What it measures, through the real CLI this time

Same fifteen prompts, same `qwen2.5-coder:7b`, same standalone
`llama-server`, `--backend openai --openai-url http://127.0.0.1:8090/v1`,
temperature 0, seed 7 — see
[`runs/2026-09-14.constrain/`](runs/2026-09-14.constrain/README.md).

| Arm | Parsed | Drifted | Continued past fence | No call | Never answered |
| --- | ---: | ---: | ---: | ---: | ---: |
| `off` | 3 | 2 | 2 | 8 | 0 |
| `--constrain grammar` | 7 | 2 | **0** | 6 | 0 |
| `--constrain schema` | — | — | — | — | **15 / 15** |

**`--constrain grammar` replicates exactly** what the standalone measurement
found before any of this was wired up: `ContinuedPastFence` eliminated
outright (prompts 3 and 15, previously left running past a clean fence, now
stop exactly at the closing `` ``` ``), and two of the eight `NoCall`
replies (prompts 4 and 14, previously a `` ```tool `` fence around
`run_command`'s flat argument object, missing the `{"name", "arguments"}`
wrapper) now compile to the correct shape. `Drifted` is untouched, exactly
as documented: prompts 2 and 9 fence under the tool's own name
(`` ```list_dir ``, `` ```run_command ``), a different trigger this grammar
was never built to catch.

**One new cost, worth naming plainly: forcing the shape does not mean
forcing the content.** Prompts 4 and 14 both asked to run a real command
(`cargo fmt --all --check`, `cargo clippy --workspace --all-targets`) with
specific flags. Unconstrained, the model wrote the flags into a malformed
call; grammar-constrained, it wrote a *correctly shaped* call —
`{"name": "run_command", "arguments": {"command": "cargo", "cwd": ".",
"timeout_ms": 30000}}` — with the `args` field, the one carrying
`["fmt", "--all", "--check"]`, simply gone. `run_command`'s own schema sorts
`args` before `command` and makes it optional; navigating the grammar's
optional branches is a real decision at each token, and here the model took
the branch that skipped the field it most needed. `score_call` reads this
as `Parsed` — it is, by the only definition this probe has ever used — and
it is also a command that runs `cargo` with no arguments instead of the one
asked for. Shape and content are different claims; this run is the first
place in this project where they visibly point in different directions.

**`--constrain schema` did not answer a single one of the fifteen prompts.**
Every run ended `[tool limit reached]` after exactly 8 calls — `--max-tool-steps`'s
default — having called a tool over and over (prompt 1: `read_file("AGENTS.md")`,
identically, all eight times) and never once produced plain text. This is
not a context-window artifact: the first attempt, against a 4096-token
server, failed at prompt 1 with a genuine `exceeds the available context
size` error by call three; restarted against a 16384-token server (4x), all
fifteen still ran the full eight calls and still never answered. **The
mechanism is exactly what the WIP proposal's own §What it costs named
before any of this was built**: *"a model that cannot say no."* Once the
tool's result comes back as a user message, the model is asked again, still
under the same schema, still with no branch for "here is the answer" — so
it calls again, forever, until something outside the model stops it.

## What this means for item 5

Both bets from the WIP proposal are built and both are measured, and they
land on opposite sides of "worth it":

- **The grammar arm is a real, unambiguous improvement on this probe**, at
  the cost this record names (a correct shape can still drop content the
  malformed version happened to carry) and the one
  [`the-alternation-that-was-not-one`](2026-09-14.the-alternation-that-was-not-one.completed.md)
  already named (drift under a different fence tag is untouched). Still
  off by default, for the same reason every flag in this project is: a run
  made without it should stay comparable to every recording on disk until
  someone decides otherwise.
- **The schema arm, applied to every call in a turn, is not a usable
  default under any measurement this project has made.** It is exactly the
  retry `Tools::call_schema`'s own doc describes — one constrained attempt
  after an unconstrained one drifted, not a policy for the whole turn — and
  nothing here builds that retry loop. Sending it to every call, which is
  what `--constrain schema` does today, is not a smaller version of the
  right idea; it is a different, broken idea that happens to share a flag
  name.

## What was rejected

- **Papering over the schema arm's failure by lowering `--max-tool-steps`
  or special-casing "no branch to answer" in the loop.** The fix that
  belongs here is the retry shape the proposal already named — apply the
  constraint only to a second attempt, never to a call whose result is
  already in hand — not a smaller number of times to fail the same way.
- **Fixing prompts 4 and 14's dropped `args` by hand-ordering the grammar's
  optional branches to match "how a human would fill the form."** That is
  guessing at a second example the way the drift detector's own record
  warned against — one instance, on one model, is not a pattern yet.

## What is still open

- **The retry loop `--constrain schema` was always meant to be**: send an
  unconstrained first attempt, and only on a drifted verdict retry once
  under `Constraint::Schema`. Unbuilt; this record measured what happens
  without it so that whoever builds it can point at exactly what it is
  for.
- **Drift under a tool's-own-name fence** (`` ```list_dir ``,
  `` ```run_command ``), named again here because two of fifteen prompts
  hit it in both the `off` and `grammar` arms identically. Closing it needs
  `avoid_until_forced` run once per tool name, each one forbidden outright
  rather than forced toward a completion — genuinely different from the
  one trigger this record closes, not a bigger version of the same fix.
- **Whether the dropped-`args` cost replicates.** One example, one model,
  one seed — the same caveat every record here repeats, and the one this
  file's own §What it measures does not get to skip either.
- **`serve` and `stdio` have no `--constrain`.** Wired to `chat` only; a
  session started through either surface cannot ask for a constraint yet.
