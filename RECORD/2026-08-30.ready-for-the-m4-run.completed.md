## What landed in PR #6

Five commits, +1507/−29 over 22 files, ported from the two branches that had been
sitting unmerged since 27-Aug (`claude/continuamos-cozerj` and
`claude/agent-web-client-debug-obbg39`). Neither was merged as-is: the first is a
parallel implementation of tasks that conflicts with what PR #5 merged in thirteen
files, and the second's `AGENTS.md` predates the code existing. What came over is
the part of each that was independent.

**A file can be put into a turn.** `--fragment PATH[:START-END]` on `chat`,
repeatable, and `## fragment: <path>` in a script. Read through the sandbox — the
user typed the path, not the model, so this is not the rule about model output
reaching the filesystem but the other one: a path `read_file` would refuse must
not become readable by spelling it in a flag. A denial is an error, never a
warning. Attached to one turn and then gone, because which turns a file belongs
in is what relevance selection exists to decide.

`## fragment:` is deliberately not `## file:`, and the names must stay apart: the
plan's files are what the task may touch, a fragment is text put into the next
prompt. A plan may name a file it never reads; a fragment may ground a turn no
plan names.

This fills the `code` bucket, which had existed since the context manager did and
was zero in every recording ever made.

**Every model call a turn makes is measured, not just the first.**
`TurnEvent::ModelCall` announces every call before it is made;
`TraceMessage::StepCall` measures the ones after the first into the same
`PrefixTracker` chain as the turns; `TurnView.extra_calls` carries them to the
panel. `ServerMessage::from_turn_event` returns `Option` now, which is the
trace/protocol split becoming a type rather than a convention.

**The window is sent.** `CompletionRequest.context_limit` becomes
`options.num_ctx` on the Ollama request. **This was a bug, and it is the finding
of the day**: `ChatRequest` carried `model`, `messages` and `stream` and nothing
else, so the window was never sent and Ollama truncated to its own default in
silence. Any run against a real model on `main` before this commit was measuring
a prompt the model never saw — every bucket, every reuse figure, every usage
count in it a reading of something else, with nothing failing and nothing able to
say so. It was found by reading `ollama.rs` while answering a question about
sampling, not by anything in the system.

The M4 Pro numbers in [`2026-08-27.the-m4-pro-run.completed.md`](2026-08-27.the-m4-pro-run.completed.md)
are unaffected: they were taken on the branch, which did send it. But they were
the only real-model run there has ever been, so in practice nothing was lost —
what was at risk was the *next* one.

**Documentation.** The Ollama setup section, which `main` did not have at all
even though the fold-probe record told a reader to follow it exactly; the commit
convention (keep `Co-Authored-By`, no `Claude-Session:` trailer in a public log);
`2026-08-26.open-after-pr-1.completed.md`, the survey written the day the walking skeleton
merged and left on its branch, landed with an appendix saying which of it four
merges have since answered.

Nothing here was verified by reading. Against the mock: both grounded scripts

## What the M4 has to run

This is the run the whole task boundary is judged by, and it is the only thing in
this file that cannot be done without a machine with a model on it. The protocol
is [`2026-08-27.grounded-fold-probe.completed.md`](2026-08-27.grounded-fold-probe.completed.md) —
**read it first**; this section is the summary, not a substitute.

### The precondition that is not built

**Sampling is not pinned.** The request carries `num_ctx` and nothing else, so
temperature and seed are the server's defaults and the two halves of the
comparison differ by the sampler as well as by the fold. One run each, unpinned,
cannot tell *the summary lost it* from *the sampler wandered*, and that
distinction is the entire finding.

Two ways out, and do not skip both:

1. **Pin it.** `options.temperature = 0` and a fixed `options.seed`, plus two
   flags. `Options` now exists in `ollama.rs`, so it is adding two fields to a
   struct that is already there — perhaps fifteen lines. This is the better probe
   and it is not built.
2. **Run each side twice** and treat only differences that repeat as real. Two
   more runs of the machine, no code, forever.

### The runs

`OLLAMA_KEEP_ALIVE` is read by the *server*, so it must be set before `ollama
serve` starts, not in the shell that runs `luu`. Check `ollama ps` before *and
between* the halves: a reload between them makes the second one cold and turns
the comparison into a measurement of that.

```sh
for script in grounded grounded-tasks; do
  luu chat --script scripts/tasks/$script.txt \
    --backend ollama --model qwen2.5-coder:7b \
    --context-limit 8192 --reserve 512 \
    --tokenizer ~/models/qwen2.5-coder-7b/tokenizer.json \
    --record ~/records/$script.jsonl
done
```

Same model, same window, same tokenizer, same working tree — the fragments are
read from disk at run time, so editing `context.rs` between the halves silently
changes the input.

### What to read

Turns 16–20 of each, the group that attaches nothing and asks the first fifteen
again. In the plain run the three files are still in the window; in the tasks run
they were folded into summaries at turns 5, 10 and 15. A right answer in plain
and a wrong one in tasks, on the same turn, with sampling controlled, is the fold
losing it.

**Turn 18 is the one to trust**: it asks which programs the sandbox policy
allows, and the answer is five literal strings (`cargo`, `rustc`, `git`, `rg`,
`ls`). A model that never saw `luu.toml` has no way to produce `rg` in that list.
Turn 20 is the model's self-report and is not a probe — read it, score nothing by
it.

Also read the `task_closed` summaries in the recording. If turn 18 fails in the
tasks run, the summary for task 3 is where to see why: it will name `luu.toml` as
a file the plan declared and say nothing about what was in it. That is the
deterministic summary working exactly as specified, and the specification being
wrong.

### What to write down

A new dated record with the table from the probe file, the four answers verbatim
from each run, the two token totals, and the verdict. If folding loses answers,

## What is left

### Blocking something else

- **Pin the sampling.** Above. Blocks the probe, and the probe blocks the design
  question the project exists to answer.
- **Nothing in CI exercises the server or the page.** The oldest open item in
  `RECORD/`, first written the day PR #1 merged and still exactly true. Every bug
  found in this repository has been found by running, not reading — including
  today's `num_ctx`, and including the four in the walking-skeleton session. Two
  tests, in this order: an integration test in `luu` that binds an ephemeral
  port, drives one turn over `/ws` and asserts the message sequence and the REST
  answers; and a Playwright smoke test over the static site CI already builds,
  failing on any console error. Neither would have caught `num_ctx` — it needs a
  stub backend asserting the request body, which is a third, smaller test — but
  the next one of that family lands in whichever of the three is missing.

### Structural, and blocked on nothing

- **Narrowing: make the approved plan *be* the `SandboxPolicy` for its task**,
  with the file as its floor. Still the design's own sentence and still not true:
  the plan is checked against the policy and does not narrow it. The earlier
  stock-taking put this ahead of the real-model run, and that ordering is now
  arguable rather than settled — its argument was that a real 7B's first act is
  to propose plans that forget files, which is the workload narrowing has to
  survive. That argument still holds for `serve`, where the model proposes. It
  does not hold for the probe, where the script carries a written plan and no
  model proposes anything. So the two are independent now and the probe does not
  have to wait.
- **Relevance selection.** The one piece of the context manager not built, and
  the question the fragment surface deliberately left open: a fragment is
  attached to one turn because deciding which turns a file belongs in is this
  item's job. `tree-sitter` tags plus a reference graph, not embeddings; see
  [`2026-08-27.aider-repo-map.completed.md`](2026-08-27.aider-repo-map.completed.md).

### Smaller, and each one becomes folklore if it survives

- `luu chat --record` sleeps 50ms before exiting so the writer can drain. A race
  with a delay painted over it; close and await the recorder.
- `SessionView` is cloned under a mutex on every API read.
- The replay caps inter-message gaps at 400ms and nothing in the UI says so.
- `?from=&limit=` on `/turns` is unimplemented, and needs a shape that degrades
  on a static host.
- No `busy` reply: `start_turn` refuses silently when a turn is running, and the
  gate added a second silent refusal beside it. A client cannot tell either from
  a dropped message.

### Not started, and correctly so

Native function calling and a GBNF grammar replacing the text parse; who else may
close a task (exit codes and tests, then the judge in shadow mode);
`openat2(RESOLVE_BENEATH)` for the in-process tools; the container; the VSCode
extension. All unchanged from the earlier stock-taking, which has the reasoning.
