# A call written while thinking

MiniMax answers with its reasoning in the content, `<think>…</think>` and then
the reply, and so do Qwen3 and the 27B that
[`8k-against-96k-on-the-m4-pro`](2026-09-22.8k-against-96k-on-the-m4-pro.completed.md)
caught leaking a bare `</think>` — a template that opens the block in the
prompt, so the reply carries only its end. luu reads all of it as reply.

That is two problems, and one of them is not cosmetic.

## The problem

**A call drafted inside the thinking is executed.** The loop asks
`parse_call` of the step's whole text (`agent.rs`), and `parse_call` takes the
first ```` ```tool ````, ```` ```json ```` or bare `{"name": …}` it finds. A
model that writes *I could run `{"name":"run_command",…}` — no, better to read
the file first* has run the command. Reasoning is where a model tries things
out; it is the one part of the text where a call is least likely to be meant.
The same reader rebuilds the history under the native transport
(`native.rs`, `split_call`), so the drafted call would also be sent back as
the call the model made. And the page draws it as a tool card.

**The page shows the thinking as the answer.** Hundreds of words of
deliberation in the transcript, in the reply's own type, ahead of the reply.

## The proposal

**Thinking is never a call.** One function masks the thinking out of a
step's text before any of the three readers look for a call — `split_call`
(and so `parse_call`), `score_call`, and `segments.js` on the page. Three
shapes count as thinking:

| Text | Thinking |
| --- | --- |
| `<think>a</think>b` | `a` |
| `a</think>b` — no opening tag before it | `a`: the template opened it in the prompt |
| `<think>a` — never closed | `a`, to the end: a call written there is still being thought |

Masked, not removed: the span becomes spaces of the same byte length, so every
offset the readers hand back — where the call starts, what prose came before
it — still indexes the original text. **The text itself is not changed**:
what is stored, resent and shown in the inspector is what the model wrote.

**The page draws thinking as its own part**, folded, under a line that says
*thinking…* while it streams and *thought* once it closed, with the text
behind a click.

## What it costs

- **A model that puts its real call inside `<think>` loses it.** No template
  luu has met does, and the alternative is executing whatever a model
  considers and rejects. A turn that ends with the call only in its thinking
  ends as an answer, and the transcript shows why.
- **A literal `<think>` in a reply about XML** starts a thinking span that the
  model did not mean. The tag is specific enough that this is accepted.

## What was rejected

| | |
| --- | --- |
| Stripping the thinking from the stored text | It changes the history, which is a decision about the window and not about parsing — see *Still open*. And the inspector exists to show what the model sent. |
| Asking MiniMax for `reasoning_split` | Moves its thinking to another field for one provider; Qwen3 and the leaked `</think>` still arrive in the content, so the parser needs the rule anyway. |

## Still open

- **Whether the thinking is resent.** Today it is, as part of the reply.
  MiniMax's own guidance is to keep it in the history; Qwen3's chat templates
  drop it from earlier turns themselves; on a local 8K window it is the most
  expensive text in a turn that nobody reads twice. That is a `[resend]`
  question — a rule beside *do not re-inject* — and it wants measuring before
  a default is chosen.
- **`reasoning_content`.** llama-server, vLLM and DeepSeek send the thinking
  in a field of its own, which `openai.rs` does not read. Nothing is shown
  while it streams — the turn looks stalled — and none of it is kept.
- **`parse_plan`** shares the fence scanner and not this mask: a ```` ```plan ````
  drafted while thinking would still be proposed.

## Appended 2026-10-21: built

As proposed. `tools::mask_thinking` blanks the three shapes byte for byte;
`split_call` looks for the call in the masked text and cuts the prose from the
text as written, so the native history is what it was; `score_call` scores the
masked text. On the page `segments.js` cuts the reply into thinking and
answer by the same three rules, reads only the answer for calls, and hands
back `{ kind: "think", text, open, words }`, which `app.html` draws as a
`<details>`: *thinking…* with the pulsing dot while it is open and streaming,
*thought · N words* after, the text behind the click. An empty block that
closed — `<think></think>`, a model told not to think — draws nothing.

**Checked**, with `tests/smoke/reading.spec.js` › *a call written while
thinking is not run*: the mock thinks `Maybe <read NOT-THIS.md> no.` and then
reads `AGENTS.md`. Three builds, the spec file whole each time — the mock
serves its replies in order, so a filtered run hands this test the wrong one,
which is how the first two comparisons here were void:

| parser | page | result |
| --- | --- | --- |
| before | before | fails: no *thinking…* |
| before | after | fails: **the dropped read ran** — the one card says *failed*, on `NOT-THIS.md` |
| after | after | passes |

Four unit tests beside the parser's own: the dropped call, the template's
bare `</think>`, a block never closed, and the mask keeping every offset.
