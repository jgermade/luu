# Always in this project

Row 52 of [`ROADMAP/2026-11-08`](../ROADMAP/2026-11-08/README.md), put off on
2026-10-22 ([`policies-not-postures`](2026-10-22.policies-not-postures.WIP.md),
*always is for later*) and decided in
[`five-decisions`](2026-11-09.five-decisions.WIP.md) §52: *build it as
recommended*.

## The problem

A person's answer to a held call lasted this call, or the session. Allowing
`npm` in a project meant allowing it again in every new session there — the
*project* row of the 2026-10-22 table, empty.

## What was built

**The answer.** The held card has a third button, *Always in this project*,
beside *Allow* and *Deny*. It is a yes only: a lasting no is the session's,
and a project-wide no is what a list's `deny` already is.

- `ClientMessage::AnswerCall { project: true }`, `Answer::Project`,
  `GrantScope::Project`; `protocol::VERSION` 14, `record::FORMAT` 29 (a step's
  `grant` may now be `project`).
- `Escalation::Granted` carries its scope, so a call let through by what the
  project allows reports `project` and not `session`.

**Where it is written.** luu's own `config.toml`, never the project's tree:

```toml
[project."/home/me/web"]
commands = ["npm"]
writes = ["package-lock.json"]
```

Keyed by the session folder's absolute path — the base of its sandbox — so
allowing `npm` in one folder allows it in no other, and a repository cannot
grant itself anything. `Config::with_project_grant` writes and removes one; a
folder left with nothing is written as no table.

**Where it is read.** `serve::project_grants` when a turn begins, handed to the
`DraftCeiling` (`with_project`). The ceiling asks, in order: a no for the
session → refused; a yes for the session → granted (session); **in the
project → granted (project)**; else asked. So a session's no still refuses what
the project allows, and a list's `deny` is never asked, so a project grant
cannot reach it. Read fresh each turn: a grant taken back holds from the next
turn.

**Where it is seen and taken back.**

- The card: *allowed in this project*, or *… earlier* when nobody was asked;
  *by you, always in this project* in its detail.
- Permissions: *granted for the project*, pointing at Settings.
- Settings → Policies, *Always, by project*: every folder, every grant, each
  with a × (`POST /api/grants/project/remove`, the policies' write rule:
  loopback, or an admin or owner on a server with users).

Not offered where `[approvals] required = true`: nothing is asked in a draft
there, as before (row 53).

## What was rejected

- **Inside the project's tree** (`.luu/…`): a repository could grant itself
  anything, which is what keeping policies out of the working directory was
  decided for on 2026-10-22.
- **A project-wide no**: that is a list's `deny`, which Settings already edits.
- **Copying the grant into the session's answers**: it would be listed and
  taken back per session, and the file would say something else.

## Still open

- **A folder that moves** keeps its grants under the old path; nothing follows
  a renamed project.
- **The new session's dialog** does not show what a folder already allows.
