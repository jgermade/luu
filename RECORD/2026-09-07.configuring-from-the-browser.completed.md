# Configuring from the browser: a modal, and the authority it hands over

**Status:** a proposal, and the code it plans.

It **contradicts a decision recorded this morning** and says so first, which is
the rule. [`naming-a-provider`](2026-09-07.naming-a-provider.completed.md) closed
with the UI hole left open on purpose:

> **The UI has no provider picker**, so `serve` resolves once at startup and a
> person in the browser sees the name and cannot change it. […] it stays open
> here deliberately: **a picker is a switch, and a switch is the schema question
> above.**

That sentence is wrong, and it is wrong by conflation. There are three things in
it and only the last one is the schema question:

| | what it needs | wakes the debt? |
| --- | --- | --- |
| **Editing `config.toml`** — write the file the *next* run reads | a write route and a form | no. Nothing about the running process changes |
| **Choosing at session start** — a new session on another provider | `AppState` holds one `Arc<dyn Backend>` for every session ([`serve.rs:90`](../crates/luu/src/serve.rs#L90)); it would hold more than one | no. `SessionView.backend` is already **per session**, set once from `Hello` |
| **Switching mid-session** | a backend per *turn* in the record, so a protocol version | yes, and it stays rejected |

`local-first` named the debt as *"a session that switched cannot be described by
this shape"* — a session, not a server. A second session on another provider is
exactly what the shape already describes. So the first row is free of it and the
second is a change to `AppState` rather than to the schema, and this record
proposes the first, orders the second, and leaves the third where it was.

## The problem, which is bigger than the missing form

Two facts the browser cannot see today, both of them recorded as holes:

1. **Where this server is sending.** The header shows `state.backend` and
   `state.model` as two tags ([`app.html:101`](../crates/luu/ui/app.html#L101)) —
   and after `naming-a-provider` the name may be `openai@openrouter.ai`, but the
   *profile*, the URL and whether it left the machine are on **stderr**, printed
   once, where nobody in a browser was standing.
2. **The window caveat.** Named as open in
   [`an-openai-compatible-backend`](2026-09-01.an-openai-compatible-backend.completed.md):
   *"`serve` prints it once at startup — where a person who set `--context-limit`
   later in the UI would not see it."* The panel plots our count against the
   server's and the sentence explaining why they can disagree is not on the page.

So the modal's first job is **not** the form. It is to put on the page what the
run already knows and only said to a terminal.

## The proposal

A modal with two sections, opened from the header tags that already name the
backend — the thing you click is the thing it is about.

### Section 1: what this server is running with. Read-only, always.

The resolved provider (profile name, backend, URL, remote or not), the model,
the window and where it came from (a flag, a profile's `context-limit`, or
unknown), the tokenizer or the warning that there is none, `--select-tokens`,
`--map-tokens`, the sandbox's enforcement, and the store. Every one of these is
already resolved at startup and already printed to stderr; none of it is new
information and all of it is currently invisible from the surface a person works
in. Where the OpenAI backend cannot send the window, the caveat is **here**,
beside the number it is about.

This section has no authority attached and no route to write. It reads a new
`GET /api/settings`.

### Section 2: the providers. Editable, on loopback only.

The profiles in `config.toml`, listed; add, edit, remove; and which one is
`default`. Writing goes to `PUT /api/providers`, which rewrites the file through
the same loader that reads it — **the file is parsed and checked before it
replaces anything**, so a write that would not load is refused with the same
error a hand-edited file gets.

Three rules the form does not get to soften:

**The key is a path, never a value.** `naming-a-provider` put it in the design
doc: a key in a config file is a key in every backup. A form field labelled *API
key* that writes what was typed into `config.toml` would undo that in the most
inviting way available. The field takes a path, and the modal shows what the
server can say about it — that it exists, and that its mode is `0600` — which
turns [`secret.rs`](../crates/luu/src/secret.rs)'s check from an error at the
first turn into a state you can see before you run one.

**A remote default is confirmed by typing, not by ticking.** This is the one the
modal could quietly kill. The declaration's whole content is that *a person has
to have written it*; a checkbox pre-filled from the URL is the program writing
it and asking for a click, and the load error would become unreachable code
because the UI would never emit a file that trips it. So: to make a profile
whose URL is off this machine the **default**, the person types its host into a
confirmation field. Typing is the declaration — the same sentence `-p` earns its
exemption with. Every other profile is unaffected, as on the command line.

**Off loopback the section is read-only.** `serve` off loopback is behind a
bearer token, and the token answers *who may reach the port*, never *who
approved* — [`signed-approvals`](2026-09-04.signed-approvals.completed.md)'s
argument, and it applies harder here: approving a job is bounded by that job,
while writing a `default` provider redirects **every future run on this
machine**, outside the gate, after the session ends. That is a larger authority
than the one the design is built around, and it is not one a bearer token should
carry. The section renders with its fields disabled and says why.

### What it does not do

**Nothing in the modal changes the running server.** `serve` resolved its
destination at startup and keeps it. The modal says so in one line, because a
form that looks like it took effect and did not is worse than no form. Choosing
a provider for the *next session* is the natural next item and is ordered, not
built here.

## What it costs

- **A write route into machine state**, which the server has never had. Every
  `/api/*` route today reads; `POST /api/sessions` creates one, and it dies with
  the process. This one outlives it.
- **The file stops being only hand-written.** Comments in a `config.toml` do not
  survive a rewrite through a serializer, and someone will lose one. Mitigated by
  keeping the file small and by the modal being additive to hand-editing rather
  than a replacement for it — but it is a real loss and worth stating before
  somebody discovers it.
- **A modal is a place where settings accumulate.** Section 1 is read-only and
  cheap to extend; the risk is that the next thing to arrive is a flag someone
  wants to make editable, and each of those is a live-reconfiguration question
  wearing a form field.

## What was rejected

| | why |
| --- | --- |
| A provider **picker** in the header that switches the live session | The debt is real for this one: every per-turn number is backend-specific, and a session with two backends under one label produces mixed numbers under a name that says they are comparable |
| A key *value* field, stored anywhere | See above; the design doc already forbids the file, and a server-side keystore is a second secret store to get wrong |
| Editable providers off loopback, behind the token | The token is reachability, not authority. A `default` outlives the session and the gate |
| A checkbox for `remote` | It makes the load-time rule unreachable and turns a declaration into a click |
| Live-reloading `config.toml` on change | The run resolved once and every number it reports assumes that. Reload is the mid-session switch by another name |

## Still open

- **Choosing the provider for a new session.** `AppState` holds one
  `Arc<dyn Backend>`; a session created against another profile needs it to hold
  a map, or to build one per session. No schema change, and the next item.
- Whether `luu.toml`'s `[sandbox]` should be visible in section 1 as *what this
  server resolved* — it is already printed by `agency.describe()`, so it is the
  same kind of already-known-and-unseen the section exists for.
- Nothing versions `config.toml`. A modal that rewrites a file makes the absence
  of a backup more noticeable than a hand-edit does.

## 2026-09-07 — what building it decided

Code, in the shape argued above. `GET /api/settings`, `GET /api/providers` and
`PUT /api/providers` in [`serve.rs`](../crates/luu/src/serve.rs), the write side
in [`provider.rs`](../crates/luu/src/provider.rs), and the modal in
[`app.html`](../crates/luu/ui/app.html). Five things the plan did not know.

**The browser must never classify a URL, and the plan did not say who would.**
It said a person types the host to confirm — and left the page needing to know
*which* host, and whether a URL is off the machine, before it can ask. Written
straight, that is `is_this_machine` reimplemented in JavaScript, and two copies
of that rule drift until the page cheerfully saves a file the next run cannot
load. So the flow inverted: the page sends what it was given, the loader refuses
it, and the refusal carries `{ profile, host }` in a `WriteRefused` body. The
editor then asks for exactly that host and retries with `remote = true`.

The rule lives in one place, and the declaration comes out *better* than the
plan's version: it is typed **against the machine's own objection**, naming the
host the machine says it found, rather than into a field somebody could fill
while thinking about something else.

**`window_from` did not exist and had to.** Section 1 says where the window came
from, and `Resolved` had no answer — the CLI never needed one, because a flag is
a thing you just typed. A page is read by somebody who did not type it, so
`WindowFrom::{Flag, Profile, Unset}` is a new field, and the caveat is a field
beside it rather than a line on stderr.

**`destination()` gives back the whole resolution now.** It returned
`(backend, model, context_limit)` — three of `Resolved`'s fields with the rest
dropped — and the page wants the rest. It returns the `Resolved` instead, with
the model written back through `model_for` so every reader sees the string the
turn will use. `Resolved::mock()` came out of the same change: three test files
were each about to grow the same struct literal.

**The summary is taken before `App` is built, not after.** `budget`, `agency`
and `counter` are moved into the struct, so a `Settings` assembled afterwards
cannot read them. It looks arbitrary in the diff and it is not.

**The refusal and the Save button have to be pinned together.** First attempt
pinned the actions alone; the screenshot showed the message explaining the
button scrolled off below it. A refusal that can be separated from the control
it is about is one somebody clicks past. Both live in one `.modal-foot`, and
this was found by looking at a rendered page rather than by reading the code.

### What the runs show

Against a server on `127.0.0.1:7892` with a scratch `LUU_HOME`, driven in a real
browser:

```text
GET /api/settings   → profile "local", ollama, http://127.0.0.1:11434, remote false,
                      window 8192 from "flag", counter approximate + its warning,
                      the sandbox this run resolved
PUT /api/providers  → 422, and the body names the profile and the host:
                      "[provider.hosted] is the default and https://openrouter.ai/api/v1
                       is not this machine, so every run with no -p sends there."
```

and in the page, making that same profile the default:

```text
confirm disabled before typing:        true
confirm disabled after wrong host:     true      (typed "wrong.example.com")
confirm disabled after right host:     false     (typed "openrouter.ai")
```

after which `config.toml` on disk carries `remote = true` under
`[provider.hosted]`, written by the confirmation and by nothing else. No
`config.toml.new` is left beside it. Console and page errors across both drives:
none.

`cargo test --workspace` is 353 green — `provider` now covers the write
(round-trip, and that a file which would not load replaces nothing), and
`serve_ws` covers the two read routes. `clippy --workspace --all-targets` is
clean under `-D warnings`.

### Still open, after this one

- **Nothing tests `PUT` over HTTP.** A test that exercised it would write a
  `config.toml` on the machine running the tests; pointing it elsewhere means
  `std::env::set_var`, which is `unsafe` in edition 2024 and races every other
  test in the binary. The rule is unit-tested against a scratch path and the
  flow was driven in a browser, and that is the gap: an in-process test of the
  route itself wants `Config` to take its path rather than read the environment.
- **Comments in `config.toml` do not survive a save.** Named as a cost in the
  plan, now true in the tree.
- **The modal reads once, at open.** A file edited by hand while it is open
  shows stale until it is reopened. Deliberate for the settings half — they
  cannot change under a running server — and merely unfinished for the other.
- Choosing the provider for a **new session** is still the next item, and
  `AppState`'s single `Arc<dyn Backend>` is still what stands in front of it.

## 2026-09-07 — the open thread, closed the same day

The last line of *Still open* — **choosing the provider for a new session**,
with `AppState`'s single `Arc<dyn Backend>` named as what stood in front of it —
is built, in
[`the-first-run-has-no-provider`](2026-09-07.the-first-run-has-no-provider.completed.md).

The shape it took is not the one this record guessed. It said the backend would
have to be *"a map, or one per session"*; it is neither. `serve` runs one live
session at a time, so what it needed was **one destination, swapped where a
session begins** — a `Destination` struct holding the backend, the model, the
budget and the counter behind an `RwLock`, replaced in `create_session` before
the new session's header is written. The map was for a shape the server does not
have.

Two of this record's sentences read differently now and are worth marking rather
than leaving to be discovered:

- *"Nothing in the modal changes the running server"* is still true of the
  **server** and no longer of what a person can do from the page: the modal
  writes the file, and a session started from it resolves that file immediately.
  A restart is no longer the way to reach a profile you just wrote.
- The third row of this record's opening table — **switching mid-session** —
  stays rejected, and was re-argued rather than inherited. What changed is that
  a session can now be *resumed* elsewhere, which is a different act: the history
  moves with a `Header` line saying where, instead of a turn being answered under
  a name it was not produced by. See
  [`a-second-header`](2026-09-07.a-second-header.completed.md).

What remains open here is unchanged: comments do not survive a save, the modal
reads once at open, and nothing versions `config.toml`.
