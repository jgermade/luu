# One counting surface

**Status:** WIP — it plans code and the code is not written yet.

It answers the sentence this revision has now written five times in five files,
most recently at the foot of
[`state-of-play`](2026-09-19.state-of-play.completed.md):

> **Nothing counts how often any of this fires** — not the three window rules,
> not the divergence, not item 12's grants, not the `not_granted` refusal.
> Fourth instance of one gap in one revision, and at some point the answer is
> one counting surface rather than a fifth thing that reports per call.

That sentence is now slightly out of date in a way that makes the case rather
than weakening it, and §The prototype exists says how.

## The number was computed with `grep`, and then it was not

[`RECORD/runs/2026-09-19.edit-reread-mock/README.md`](runs/2026-09-19.edit-reread-mock/README.md)
opens on four columns — `diverged` lines, renders, paths, asking — and the run
that produced it got one of them from a pipeline:

```sh
grep '"type":"diverged"' "$SCRATCH/$arm.jsonl" > "$OUT/$arm.diverged.txt" || true
printf '%s: %s diverged line(s)\n' "$arm" "$(wc -l < "$OUT/$arm.diverged.txt")"
```

The other three came out of a person reading the file. *8 of 13* — the number
that reframed item 19's entire trade — was counted by eye.

## The prototype exists, and that is the argument

It did not stay counted by eye for long.
[`a-corpus-that-edits`](2026-09-19.a-corpus-that-edits.completed.md) landed
`record::divergence` the same day, and its doc comment is this record's thesis
written for one finding:

> Beside the format rather than inside the probe: **a tally computed in a test
> is a tally only that test can quote.**

`Divergence` is right about everything except its scope. It draws the
distinction that matters — `renders`, not lines, *because the render is what
was sent to a model* — it counts `asking` once per render on the same
reasoning, and it keeps paths in report order. It is the shape.

So the gap is no longer *nothing counts*. It is that **one finding has a tally
and four do not**, and that the tally lives in `record.rs` over `&[RecordLine]`
where the next four would each need their own. The fifth per-call reporter this
revision kept predicting has arrived as the first per-call *counter*, and the
cheap move — a `prunes()` beside `divergence()`, then an `evictions()` — is the
same failure one abstraction higher. Name the shape once.

## The proposal: derive it from the fold, and absorb the prototype

**`Counts`, computed by `SessionView::counts()`.** The fold already holds every
fact the tally is over — `dropped`, `cited`, `diverged`, `tools[].verdict`,
`jobs[]` — because the live server and `luu export` both build it and have
since the read side existed. A count over it is arithmetic, not a new
observation.

Three things follow, and they are the whole argument:

**It cannot drift from what it counts, because it is what it counts.** A
counter incremented at each site is a second implementation of the finding,
printed beside the finding, and believed over it the day they disagree. This is
`luu export`'s own founding argument — *a static mirror generated by separate
code would drift, and a mirror that drifts is worse than none* — one structure
along.

**No format bump for any of it except §Rule A.** Nothing new is written. A
recording from August counts as well as one from tomorrow, as far as the lines
it carries go; where it carries none, the format number already says whether
that means *nothing happened* or *this reader cannot know*, which is the
distinction formats 11, 12 and 13 were each bumped to preserve.

**One surface, so a sixth finding is a field and not a feature** — which is the
quoted sentence's actual complaint, and the reason `divergence()` is *replaced*
rather than joined. A `Counts` next to a `Divergence` would be the fifth thing
reporting per call with extra steps.

### The substrate moves, and it is a real choice

`divergence()` folds `&[RecordLine]`, deliberately: *so that a caller holding a
stream it recorded itself does not have to write it out to read it back*. That
caller is `edit_reread_probe`, and `SessionView::from_record(&id, &lines)`
serves it just as well — the bridge already exists, because `luu export` is
built on it.

What is given up is not nothing: **a trace line naming a turn the fold never
started is counted by `divergence()` and not by the fold**, which drops it at
`if let Some(view) = self.turn_mut(*turn)`. In every stream this tree writes the
two agree, because both emitters publish `TurnStarted` before any line about
that turn — but that is a property of two call sites, not of the format, and it
is worth a test rather than a sentence. Counting through the fold is also the
more honest reading of the ambiguous case: a finding about a turn no reader of
the session can see is a finding nobody can act on, which is the standard
`Verdict.rule` was written to.

## What it counts

| | from | |
| --- | --- | --- |
| **evictions** | `TurnView::dropped` | renders that cut, turns lost, tokens |
| **prunes** | `TurnView::cited` | renders that moved the line, turns that gave up spans, tokens |
| **divergences** | `TurnView::diverged` | renders, `asking` renders, paths with most bodies, lines — `Divergence`'s own four |
| **repeats** | `TurnView::repeated` | §Rule A, and the only one that needs a new line |
| **tool calls** | `TurnView::tools[].verdict` | allowed and denied, by the rule that decided |
| **refusals** | `SessionView::refusals` | by [`Refusal`] variant, `not_granted` among them |
| **jobs** | `SessionView::jobs` | proposed, approved, rejected, closed, and the paths each approval granted |

`renders` and not `turns` on the window rows, taken from `Divergence` unchanged
and for its reason: the edit-reread corpus's 8 is eight *renders* carrying a
contradiction, of which two were the turn that caused one. A tally that said
"2 divergences" would be counting the wrong noun, and would have agreed with
exactly the assumption that corpus demolished.

## The bill the fold wrote down for itself

`api.rs`, in the fold:

```rust
// Transient feedback to whoever asked, not session state: a refusal is a
// thing the server declined to do, and there is nothing about the session
// afterwards that is different for it.
// It stays out of the view until something wants to count them.
ServerMessage::Refused { .. } => {}
```

**This record is the something.** The comment is not a bug found later; it is a
condition stated in advance by somebody who knew it would come due — the same
class as `resend_rules`' *"is not here because no default has flipped"*, which
[`state-of-play`](2026-09-19.state-of-play.completed.md) calls the argument for
that kind of comment, *and it is cheaper to record than to re-derive*. Second
time in two days that the bill was found already itemised.

The clause that survives is *not session state*, and it is right: a `refusals`
list on `SessionView` does not make refusals into turns. It makes them
countable, which is what the comment reserved the right to do. `#[serde(default)]`,
**no format bump** — the lines have been in the record since format 4 and were
widened by format 7, so this is `posture`'s rule on 2026-09-17 exactly: *no
format bump, the fact has been on the wire since format 10*.

## The one count that needs a new line: rule A's own saving

Rule A has been this project's **default** since yesterday and is the only one
of the three window rules that reports nothing. Rule B writes `pruned`, rule C
sits behind B, and `split_shown` — the whole of rule A — does this:

```rust
let (kept, dropped) = split_shown(&turn.code_context, &mut shown, budget.repeat);
history_tokens += tokens.saturating_sub(fragments_tokens(&dropped, counter));
```

The number is **already computed**, subtracted from a bucket, and dropped on
the floor. Nothing downstream recovers it: a bucket carries the difference, and
a difference is not a measurement of what made it. A run under `--repeat-once`
that collapsed forty spans and one that collapsed none leave the same evidence
— which is, one field along, the identical complaint format 11 was bumped to
fix, where a `--prune-behind` run that pruned nothing was indistinguishable
from a run without the flag.

So: a `repeated` trace line, **format 13 → 14**, shaped like `pruned` because it
is the same kind of fact. Trace and not protocol, on the argument `pruned` and
`diverged` were both taken under and for the third time: every turn is still
asked, answered and in the transcript, and what changed is the prompt.

**What it must not claim**, and this is `Pruned`'s own footnote turned around.
`Pruned.tokens` is *the difference of two windows, not the sum of the spans,
because under `Repeat::Once` a span the pruned turn owned passes to a younger
turn instead of leaving*. Rule A's number is the other one: it **is** the sum of
the fragments this render did not resend, because that is what the subtraction
computes and the only quantity available without rendering twice. It is not
*what the window would have been without rule A* — a span rule A drops from turn
3 is sent by turn 5 instead, which is the same passing-down that forces
`Pruned`'s wording. The field says so in its own doc comment, and a reader who
wants the counterfactual runs the arm, which is what one flag apart is for.

## What is rejected

**Rejected — a counter incremented at each site.** Cheapest to write, and it is
the drift argument above. It also puts state in `Context::select`, the one
function in this system kept a pure function of its inputs, and would make a
count depend on whether a selection was made twice — which `luu select
--explain` does.

**Rejected — `/metrics`, or anything shaped like it.** A counting surface for a
*process* is a different object: it spans sessions, it has no header over it,
and it answers *how is this server doing* rather than *what did this run do*.
Every number this project has published is per run and carries the header that
makes two runs comparable. A process-wide counter has none by construction, and
would be the one number in the tree that cannot say what it was measured under.

**Rejected — counting in each reporter and summing on the page.** Where this
would go by default, because the page is where somebody first wants it. It
fails the twin test: `luu export` writes the static mirror, the mirror would
have no totals, and the numbers this project quotes in records come off
recordings and not off a live socket.

**Not rejected, not taken — item 12's file-versus-directory.** The row asks *how
often a plan grants a file rather than a directory*. A tally over a recording
can count granted paths — per job, reads against writes — and cannot classify
them: `src/` and `src/lib.rs` are two strings, which is a directory is a
question about a disk, the sandbox answers it with `is_dir()` when it resolves a
root at approval, and a fold running on another machine six weeks later has no
business asking. The classification is therefore a field on `job_approved`
written where the answer is known, it is a second thing format 14 could carry,
and it is **not decided here** — settling what the gate writes down from inside
a file about counting is the mistake
[`one-path-two-bodies`](2026-09-19.one-path-two-bodies.WIP.md) §The fix refused
to make about item 20. The surface counts grants as far as the strings go, and
the field is named for what it counts.

## Where it surfaces

- **`luu count <record.jsonl>`** — the family `luu tools`, `luu map` and `luu
  select` are in: print what a thing resolves to, so it can be looked at rather
  than inferred. It is the one that replaces the `grep`.
- **`GET /api/sessions/{id}/counts`**, with `counts.json` beside it, because
  every route on this server answers both spellings.
- **`luu export` writes `sessions/<id>/counts.json`**, so the static twin has it
  and the Pages deploy is not a surface with a hole in it.

The panel is **not** in this record. A number on a page is a layout question and
this is an arithmetic one; the four panels that earn their place were each
argued on their own, and a fifth gets the same treatment or none.

## What it costs

- **A format bump, 13 → 14**, for `repeated`, with the page's `FORMAT` moving in
  lockstep because `ui_versions.rs` is the pair that makes it.
- **A day-old function deleted.** `record::divergence` and `record::Divergence`
  go, their four numbers move into `Counts` unchanged, and `edit_reread_probe`
  asserts the same figures through the new path — which is what makes the
  replacement checkable rather than merely tidy.
- **Nothing on the protocol.** Six is untouched: a client that cannot count is
  not wrong about a conversation.

## Still open

- **A count per session is not a count across sessions**, and *how often does a
  model edit a file it has quoted* is a question about many. This gives the
  per-run number such an answer would be built from; building it is a second
  thing.
- **Item 12 is answered in strings and not in kinds**, above, and the field that
  would close it is named and not written.
- **Nothing counts the spans rule A did *not* collapse**, which is the
  denominator. `repeated` says what was dropped; what share of the window's
  spans that was needs the total, and the total is not in a bucket either.
- **The tally has no opinion.** It says a session carried eight contradicted
  renders and not whether eight is a lot. Nothing else here does either, and the
  reason is item 19's: the corpus was scripted, so every number off it is a fact
  about the corpus. The instrument is again being built ahead of the run that
  gives it meaning — third time this week, which is worth naming as a habit
  rather than rediscovering as a surprise.

## Appended 2026-09-19: built, and the two things it found in its first run

All of it landed as argued, with one change to the plan and two findings the
plan did not have.

**What is in**: `api::Counts` and `SessionView::counts()`; `Tokens`, `Cut`,
`Repeats`, `Divergence`, `RuleCount`, `Calls`, `RefusalCount`, `Jobs`;
`context::Repeated` and `Selection::repeating`; a `repeated` trace line and
`record::FORMAT` 13 → 14 with `store.js` in lockstep; `SessionView::refusals`
with no bump; `luu count <record.jsonl>` with `--json`;
`GET /api/sessions/{id}/counts` and `counts.json`; `sessions/<id>/counts.json`
in an export. `record::divergence` and `record::Divergence` are gone, their four
numbers unchanged inside `Counts`. 499 Rust tests, clippy at `-D warnings`, fmt.

**The change to the plan: a total names every counter that produced part of
it.** `Tokens` was going to be a `u32`. It is a `u32` and a `Vec<Counter>`,
because a session **resumed onto another model** keeps its turns and changes its
counter — which is the whole reason `retarget_header` exists — so a sum over
such a session mixes two measurements. Every per-call report in this tree
already carries the counter that made its number; the first thing that adds them
up is the first thing that could lose it, and losing it silently is the failure
`Counter` was put on `Evicted`, `Pruned` and `Budget` to prevent. One entry is
the ordinary case and two says so out loud.

### It reproduced the hand-counted table, cell for cell

The point of the first run was not to learn anything. `luu count` over
[`edit-reread.txt`](../scripts/tasks/edit-reread.txt), both arms:
8 renders of 13, 2 asking, 8 lines, one path at three bodies; and with
`--select-tokens 1024`, 16 lines over the same 8 renders and the second span
nobody typed. That is
[`2026-09-19.edit-reread-mock`](runs/2026-09-19.edit-reread-mock/README.md)'s
table exactly, through a substrate that moved from `&[RecordLine]` to the fold
on the way. Evidence in
[`runs/2026-09-19.one-counting-surface/`](runs/2026-09-19.one-counting-surface/).

### The first finding: where rule A's saving actually comes from

|  | renders | turns | asking | spans | tokens |
| --- | ---: | ---: | ---: | ---: | ---: |
| fragments only | 7 | 6 | 1 | 7 | 854 |
| `--select-tokens 1024` | 11 | 31 | 5 | 43 | 2 466 |

**Six times the spans off the same thirteen turns**, and nobody typed them: the
selector re-scores the same prompt-relevant file every turn, re-chooses it, and
rule A is what stops each choice going out again. That is
[`a-span-is-rendered-once`](2026-09-07.a-span-is-rendered-once.completed.md)'s
own justification — *9.2% of the code tokens in the precision corpus are a span
some earlier turn already put in the window* — appearing as an arm of a run
rather than as a figure in a record. §Rule A argued this line was owed because
the default reported nothing; the first thing it reported is that the default's
value is mostly a fact about the *selector*, which nothing had said.

### The second: the defect, as two numbers in one session

**`repeated` is 7 where `diverged` is 8**, on the same run. Rule A collapsed
seven spans and could not collapse the eight contradictions, because a
fragment's identity is its path *and* its bytes — so the one case where a span
genuinely needs re-reading is precisely the case the dedup is blind to.
[`one-path-two-bodies`](2026-09-19.one-path-two-bodies.WIP.md) §Why it happens
argues exactly this in three paragraphs; it is now two integers a reader can put
side by side, and the session where the rule fired hardest is the session that
contradicted itself most. Pinned as
`rule_a_collapses_the_spans_it_can_see_and_not_the_ones_that_moved`.

### And one thing the plan got wrong about itself

§The substrate moves said the line naming a turn nobody started is *a property
of two call sites, not of the format*, and gave it a test. Writing the test
turned up that the property is stronger than that: `TurnStarted` goes out before
any line about a turn in both emitters **and** the fold drops what it cannot
place, so the ambiguous case has never existed in a stream this tree wrote. The
test asserts the behaviour rather than the agreement, which is the honest
version — it says what a fold does with an orphan, not that the two tallies
matched on a case neither has met.

## Still open, after building it

The four from §Still open stand unchanged. One more, and it is small: **the
tally is per session and `luu count` takes one file**, while a `--record` file
can now hold several sessions, each under its own header, since
[`a-header-per-session`](2026-09-19.a-header-per-session.completed.md) landed
this morning. `SessionView::from_record`'s *last header wins* means such a file
counts as its last session and says nothing about the others. Named rather than
fixed: what a tally over several sessions *is* — a sum, or a table — is the
same question §Still open's first bullet asks about many runs, and answering it
here would be answering it in the wrong file.
