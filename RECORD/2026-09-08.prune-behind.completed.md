# Prune behind: the conversation survives the cut its quoted code does not

**Status:** a proposal, and the code it plans. Rule B of
[`what-leaves-the-history`](2026-09-06.what-leaves-the-history.completed.md), which
stays `WIP` for exactly this and nothing else. Rule A landed on 2026-09-07 as
[`a-span-is-rendered-once`](2026-09-07.a-span-is-rendered-once.completed.md) and
closed the half that could not touch the prefix; this is the half that can, and
it is where the number is.

## The problem, restated now that A is measured

The proposal's row is still the one to beat: **by turn 20 of the precision run,
~90% of the history block is quoted code**. Rule A took 19.5% off the `code`
bucket of the grounded corpus, and what it took is exactly the part it was
designed for — spans a *later* turn selected again. What is left is the other
kind, and it is most of it:

```text
turn 3   // crates/agent-core/src/context.rs:453-464   312 tokens   ← asked, answered
…
turn 14  the model is being asked about the sandbox; nobody has mentioned
         context.rs for eleven turns, and those 312 tokens are still in the
         prompt at full length, in a turn nothing repeats
```

They stay until the turn is evicted, and eviction is all-or-nothing: the
question and the answer leave with the bytes. That is the trade this record
refuses. **The expensive part of an old turn is its code; the useful part is the
exchange.** A window that has to choose between them is choosing under a
constraint nobody imposed.

## The proposal

### 1. A second ratchet, beside the floor

`Context::pruned`, an index into `turns` and a mirror of
[`Context::floor`](../crates/agent-core/src/context.rs#L342): below it, a turn
renders its spans as citations instead of as text. It only moves forward, for
the reason the floor does — a decision the window took has to outlive the call
that took it, or the prompt oscillates and no prefix survives two calls. Between
two moves the pruned turn's render is byte-identical, which is the whole claim.

### 2. Prune before evicting, and to the same target

When the window no longer fits, the prune line moves first — to the target the
eviction policy has already computed (`available` under `Eviction::Turn`,
`available × low_water` under `Eviction::Block`). Only if pruning every turn in
the window still leaves it over `available` does the floor move at all.

Reusing the policy's target rather than inventing a depth is deliberate: the
depth-versus-frequency trade was argued and measured once already
([`prefix-reuse-and-block-eviction`](2026-08-27.prefix-reuse-and-block-eviction.completed.md)),
and a second constant with its own tuning would be that argument had again,
worse. Under `Block` the prune is deep and rare for the same reason the cut is.

### 3. What replaces the block

`// crates/agent-core/src/context.rs:453-464 — 312 tokens, pruned`, in the
fragment's own comment style and in the fragment's own place in the message.
Not nothing: the model must be able to tell that the file was read, so that
reading it again is a decision rather than a discovery. Not a summary: prose in
a region every later turn is built on is the shape the fold already rejects
([`job.rs:557`](../crates/agent-core/src/job.rs#L557)).

**This is narrower than the proposal asked for.** `what-leaves-the-history` §3
wrote the citation as `[read … — 312 tokens, dropped at turn 31]`, and the turn
number is not in it here. It would need per-span state that a resumed session
cannot carry — see the cost below — and the citation's own position in the
history already says when it happened, to the only precision that matters:
before everything under it.

### 4. The accounting, which is where this gets got wrong quietly

`Turn::tokens` is counted once at push
([`context.rs:523`](../crates/agent-core/src/context.rs#L523)) and read back by
`item_tokens` → `fits_from`. A render that sends less than it counted evicts on
tokens nobody sent, which is the failure this change exists to reduce. So a
pruned turn costs `tokens − fragments + citations`, **subtracted from the stored
count and never recounted** — rule A's rule, for rule A's reason: a turn that
prunes nothing costs exactly what it has always cost, and every recording made
before this reads unchanged.

### 5. A and B compose, and neither needs the other

A pruned turn does not own its spans, because it is not rendering them: under
`Repeat::Once` ownership passes to the oldest turn *above* the prune line that
carries the span. So `--repeat-once` and `--prune-behind` are independent flags
whose combination is defined rather than accidental, and A's measurement stays
comparable to itself.

## What it costs

- **The prefix breaks at the prune, from that turn forward.** The history block
  below the prune line is rewritten once, and then stable. This is the same bet
  `Eviction::Block` made — deep and infrequent beats shallow and every turn —
  and it is a bet, not a corollary: it has to be measured here too.
- **A resumed session has nothing to prune.**
  [`Context::from_view`](../crates/agent-core/src/context.rs#L455) rebuilds
  turns with `code_context: Vec::new()`, because the view does not carry
  fragments. So the win is a live session's, and a measurement taken across a
  resume is measuring something else. That is a hole this record found rather
  than made, and it is filed rather than fixed.
- **The evidence is gone while the turn stays.** A model that wants those lines
  now has to read the file, which costs a tool call the un-pruned prompt did
  not. Whether that trade pays is a question for a model, not for a mock.
- **Tool results are still only capped.** `MAX_OUTPUT_BYTES` caps one result and
  reaches none of the thirty already in the window. The proposal's argument that
  an 8 KiB `cat` and a 1 000-token fragment are the same object to the window is
  untouched here, exactly as it was by rule A.

## What was rejected

- **Pruning by depth** (anything older than N turns loses its code,
  unconditionally). It throws away evidence that fits, which is the one thing
  the window machinery has never done: nothing changes until it must.
- **Pruning the minimum needed, every turn.** That is `Eviction::Turn`'s
  shallow-and-frequent failure rebuilt with a new mechanism, and it would break
  the prefix on every call while saving less than a cut.
- **Pruning youngest-first.** The youngest turns are the ones the model is most
  likely to be reasoning from, and the oldest are the ones a citation costs
  least. Oldest-first is also what makes the ratchet monotone.
- **Dropping the fragment from the stored turn** rather than from the render.
  Rejected in `selection-at-the-gate`, rejected again in
  `what-leaves-the-history`, and rejected a third time here: the bytes on disk
  are what the fold quotes and what a record replays.
- **Summarising the pruned span with the model.** Prose in the write-once
  region.

## Still open

- **Whether a 7B answers worse when a span it saw eleven turns ago became a
  citation.** The same open thread rule A left, one size larger, and the mock
  cannot answer it. It is roadmap item 2 either way, and this makes the run
  worth more: one corpus, three arms (`off`, `--repeat-once`,
  `--repeat-once --prune-behind`).
- **Whether the citation should carry the call that would get it back** — a
  `read_file` line the model can copy rather than a path it has to re-derive.
  Cheap to add, and it changes what the model does with the line, so it is a
  separate arm and not a detail.
- **What a pruned turn does to the fold**, which quotes `shown` verbatim at
  close. The bytes are still in `code_context`, so the fold is unaffected today;
  that this is a *policy* choice rather than a consequence is worth saying once,
  here.
- **Whether the prune line should ever move back.** A fold makes its turns cost
  their summary, so their spans stop costing anything; the ratchet keeps them
  pruned anyway. Nothing is lost by that today and it is the kind of thing that
  is wrong later.

## 2026-09-08, later: what the code and the run said back

Appended rather than edited, as everything in here is. Three things the
proposal above got wrong or did not know, and the numbers it was missing.

### 1. Pruning is not monotone under rule A, and the proposal assumed it was

§3 argued the citation is cheaper than the span "by construction", and guarded
the one case it saw — a span so short that its citation costs more, where the
span stays. That guard is real and it is not the whole of it.

Under [`Repeat::Once`](../crates/agent-core/src/context.rs#L206) a span carried
by three turns is rendered **once**, by the oldest. Prune that turn and the span
does not leave the window: it passes to the next turn that carries it, and a
citation is added where it stood. The window comes out **bigger**. Pruning
oldest-first walks straight into this, because the oldest turn is exactly the
one rule A made the owner.

So `prune_to` takes the shallowest line that fits the target and, where no line
fits, **the line that leaves the window smallest** — which is often the line
already in force. Rule B declines where rule A has already taken the saving, and
that is correct rather than a limitation: there is no second copy left to find.
The run shows it as 9 prunes under `--repeat-once --prune-behind` against 13
under `--prune-behind` alone.

### 2. A recording said nothing about it, which the eviction tombstone record
already ruled out once

`Selection.pruned` existed and reached nobody. A run under the flag and a run
without it produced files that differed only in numbers nobody could attribute —
the same failure `eviction-tombstones` closed for the floor in August, one
mechanism later.

It is now a `pruned` **trace** line: the turns that gave up spans, what the
window saved, and the counter that measured it. Trace and not protocol, and the
line between them is what happened to the *conversation*: an evicted turn is
gone from the window and cannot be answered from again; a pruned one is still
asked, still answered, still in the transcript. What it lost is a fact about the
prompt, and facts about the prompt are what that channel is. `record::FORMAT`
goes to **8** — the number the `imported` bump un-made, free precisely because
nothing ever wrote it — and `protocol::VERSION` stays at 5, because no client
reading the conversation is missing anything.

### 3. The saving is not in tokens, and the table nearly hid it

Twenty turns of the grounded corpus, one flag apart, both policies —
[`runs/2026-09-08.prune-behind/`](runs/2026-09-08.prune-behind/):

| | `off` | `--prune-behind` | `--evict block` | `block --prune-behind` |
| --- | ---: | ---: | ---: | ---: |
| prompt tokens | 124 393 | 124 028 | 100 000 | 101 375 |
| **turns dropped** | 13 | **0** | 16 | **0** |
| prunes | 0 | 13 | 0 | **4** |
| tokens freed by pruning | 0 | 13 732 | 0 | 14 712 |
| mean prefix reuse | 34.1% | 37.6% | 66.5% | **69.8%** |

**−0.3% of prompt tokens, and nothing was evicted.** The freed room is spent
immediately, on keeping the turns the default was dropping — so rule B does not
make the prompt cheaper, it changes what the same prompt is made of. Thirteen
thousand tokens of quoted code left the window and twenty exchanges stayed in
it, where the default kept seven.

**The depth-against-frequency trade is the policy's, and pruning inherits it,
which is what reusing the policy's target was for.** Under `Eviction::Turn` the
line moves 13 times — shallow and frequent, that policy's whole character — and
prefix reuse gains 3.5 points. Under `Eviction::Block` it moves **4** times and
prefix reuse is 69.8% against the 66.5% of the arm that was throwing turns away.
A prune is a rewrite of the history block, and four rewrites that keep the
conversation beat four cuts that do not.

**What this run cannot say** is the thing the proposal already filed as open:
whether a 7B answers worse when a span it saw eleven turns ago is now a line
citing it. The backend is the mock. The corpus, the flags and the machines all
exist now, and it is roadmap item 2 with a third arm.

### Status

`completed`: the code it planned is in the tree with tests, the run it wanted is
on disk, and what is left open is open in the way every record here ends.
`what-leaves-the-history` can stop being `WIP` with it — both its rules are
built, both are measured, and both are off by default.

### One more thread the code left open

**The debug UI does not draw a prune.** `serve` publishes the `pruned` trace
line and the browser ignores it — the panel shows the buckets moving and says
nothing about why. Eviction has both halves (a tombstone in the transcript and
the turn marked), and `SessionView` now carries the same two for pruning
(`cited`, `pruned_by`); the page has not learned to read them. Small, and worth
doing with the tool-result half rather than alone.
