## What landed today (2026-09-03)

Four completed records and two substantive code additions landed in `main`:

1. **The map order probe** ([`the-map-order-probe`](2026-09-03.the-map-order-probe.completed.md)):
   A neutral corpus covering all 38 files of the repository was built and run.
   Path order answered 100% of the questions on files it held; rank order (PageRank)
   answered only 12.5%, generated fabricated Rust, and caused history eviction in
   24 of 38 turns. Path order remains the baseline.
2. **The size sweep** ([`the-size-sweep`](2026-09-03.the-size-sweep.completed.md)):
   The repository map's 0/6 → 6/6 benefit was shown to survive at 14b and 32b on an
   M4 Pro (48 GB). Two critical incidents were recorded:
   - 14b tried to run `run_command` on macOS and was denied by the kernel (*"the
     kernel cannot hold this child"*), demonstrating the need for Level 3.
   - 32b unprompted proposed and executed a write to `agent.rs` in ungated `luu
     chat`, providing direct empirical justification for the gate.
3. **Level 3 container observed live** ([`the-container-observed`](2026-09-03.the-container-observed.completed.md)):
   `loude-worker:dev` was built from `Containerfile` and pointed at with
   `luu.container.toml` on Apple Silicon. Real tool calls ran across the pipe,
   confirming that **Landlock ABI v8 + seccomp + rlimits are active and
   enforcing inside the Docker VM on macOS**. The wall against running subprocesses
   on a Mac is breached.
4. **Colima runtime added to `luu`**:
   `Runtime::Colima` was implemented in `crates/agent-core/src/worker/runtime.rs`.
   It invokes `colima nerdctl -- run ...` to enable running workers without Docker
   Desktop. Unit tests for argv generation and round-trip parsing added.

## What is pending to test and measure

### 1. Run the Gate Probe to completion (Item 4)
Run `luu serve` with a local model and complete the 15 prompts in order:
```sh
cargo run --release --bin luu -- serve \
  --backend ollama --model qwen2.5-coder:7b \
  --context-limit 8192 --reserve 512 \
  --temperature 0 --seed 7 \
  --sandbox luu.container.toml \
  --record records/gate-qwen2.5-coder-7b.jsonl
```
Follow the protocol:
- **Rule:** Approve with the minimum that will run (*approve with the least that will run*).
  Add only what is missing; reject if the plan misunderstands the work.
- **Close the task** after each answer before submitting the next prompt.

#### The 15 prompts in order:

| # | Prompt | What it probes | A plan worth approving names |
|---:|---|---|---|
| 1 | `what does the context manager do?` | Does it plan for a read question | `files: ["crates/agent-core/src/context.rs"]`, no writes |
| 2 | `which programs may a task run here?` | Reading configuration | `files: ["luu.toml"]` |
| 3 | `add a --dry-run flag to luu chat` | First write | `writes: ["crates/luu/src/lib.rs"]` — in `writes`, not `files` |

#### Extract metrics afterwards:

## What is pending to develop

### 1. Narrowing: `network` per plan and egress proxy (Item 6)
Currently `network = true` in `luu.container.toml` opens network access for the
whole session.
- **Code task:** Add `network: bool` to `Plan` (default `false`).
- **Enforcement:** Wire the plan's `network` flag into `WireSandbox` across the IPC
  pipe. In `run_command`, pass `network` to `build_filter(network)` in
  `crates/agent-core/src/sandbox/linux.rs`, so that each child process has network
  access denied unless its approved plan explicitly declared it.
- **Egress:** Build the HTTP CONNECT proxy with a hostname allowlist (`crates.io`)
  for controlled dependency fetching.

### 2. Session Resume in SQLite (Item 2, second half)
Persistent storage in `~/.loude/sessions.db` currently stores and verifies
`SessionView` (the read side).
- **Code task:** Implement the inverse fold: reconstructing an active `Context`
  (the write side) from the stored database view.
- **Questions to settle in a record:**
  - How do folded task summaries restore into context tokens?
  - Does resume preserve the previous active task state or start closed?
  - Parity test: `resume(load(store, id))` produces equivalent prompt tokens to
    the active session before save.

### 3. Protocol over stdio & Multi-session (Item 7)
- Expose the agent protocol over stdin/stdout (`luu stdio`), allowing editors
  (e.g., VSCode extension) to drive `luu` without HTTP or WebSocket ports.
- Support multiple concurrent sessions in `serve`, ensuring each session manages
  its own worker process or container lifecycle.
