# A project is a host and a folder

Asked from the project modal behind the inspector's foot:

> *La modal de cambio de carpeta de proyecto no tiene que definir el Runtime
> ni el modelo.*

## The problem

`RECORD/2026-10-02.a-project-is-a-host-a-folder-and-a-session.completed.md`
made the modal three columns — host, folder, and a session there: the runtime
its commands run on and the model it sends to — with *Open* starting that
session. Since then the sessions dialog grew into the one place a session is
made from (runtime, lists, provider and model, *Start session* and *Continue
here*), and the modal stayed a second, smaller way to do the same: a runtime
picker that knew no lists, a model list of its own, and an *Open* that ended
the session on screen to make another. Changing the folder the panels look at
asked where commands run.

## The proposal

**Host, then folder, and *Use this folder*.** The third column and *Open* go.
Choosing a folder keeps the session on screen; on another host, it loads that
host's page and the session it has, as *Use this folder* already did. A new
session — on this host or once on another — is the sessions dialog's, from the
chat's `+`.

## What it costs

- On another host, a session with a runtime or a model of its own takes two
  steps: the folder here, then the dialog there.

## Rejected

- **Keeping the column and dropping *Open*.** A runtime and a model chosen
  next to a folder and then not used would be choices that do nothing.

## Built, the same day

As proposed: the modal is 52rem and two columns. `gate.spec.js` — the forced
picker has hosts and folders and no runtime, model or *Open*.
