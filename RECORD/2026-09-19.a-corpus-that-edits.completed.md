# A corpus that edits a file and then asks about it again

**Status:** completed — it plans an instrument and the instrument is in the same
commit, with both of its arms run and their evidence in
[`runs/2026-09-19.edit-reread-mock/`](runs/2026-09-19.edit-reread-mock/README.md).
What it does *not* do is answer the question the instrument exists for; that
needs a model, and §Still open says so.

It answers item 24 of [`ROADMAP/2026-09-17`](../ROADMAP/2026-09-17/README.md),
which was opened this morning by
[`one-path-two-bodies`](2026-09-19.one-path-two-bodies.WIP.md) §What is built
and what is not in those words: *the corpus is the real blocker, not the code*.

## The problem

Item 19's fix — newest body wins, older ones become citations — is argued, cheap
and **deliberately not taken**, because it trades a measured quantity (rule A's
+18 points of prefix reuse) for an unmeasured one (how often a window carries a
path whose bytes moved). Nothing in this project could measure the second:

- `grounded.txt` and its twin are twenty questions over a tree nothing edits.
- `steady-state{,-tasks}.txt` attach nothing at all.
- `tool-call-probe-writes.txt` writes and never re-reads: eight one-shot
  prompts, each scored on the call it makes and not on what the next turn sees.
- `one-task.txt`, `long-session.txt`, `map-{order-,}probe.txt` — reads.

**So no corpus here could produce the one case where a span needs re-reading**,
which is why item 19's defect survived every run this project has made, and why
rule A's default flipped on evidence that could not contain it. Item 20 is in
the same position: *fragments across a resume, the reference and not the bytes*
cannot be measured against a session where nothing changes under it either.

## The instrument

[`scripts/tasks/edit-reread.txt`](../scripts/tasks/edit-reread.txt): thirteen
turns that read four files, edit three of them and ask about two of those again,
run against a copy of the committed template in
[`scripts/tasks/edit-reread/`](../scripts/tasks/edit-reread/README.md). Four
files, four jobs, and the two silences matter as much as the noise:

| file | what the corpus does | what it should produce |
| --- | --- | --- |
| `greeting.rs` | read, edited, read, edited, read | the case: one path, three bodies |
| `format.rs` | read twice, never edited | **nothing** — the control |
| `banner.rs` | read once, edited, never re-read | **nothing** — stale and invisible |
| `tally.rs` | read `1-6`, edited, read `1-16` | **nothing** — two paths, one file |

A corpus whose control also fires measures nothing, and the two blind spots are
[`one-path-two-bodies`](2026-09-19.one-path-two-bodies.WIP.md) §Still open's
first and third bullets — named there, reproducible here.

Two arms, one flag apart: the `## fragment:` directives alone, and the same run
with `--select-tokens 1024`. **The second is the one that matters**, because
relevance selection re-reads a span without anybody typing its name, so what it
produces is what a session produces on its own.

## The number, and it is not the shape anyone expected

Both arms are in [`runs/2026-09-19.edit-reread-mock/`](runs/2026-09-19.edit-reread-mock/README.md).
Against the mock, with the edits scripted:

| arm | `diverged` lines | renders | paths | `asking` |
| --- | ---: | ---: | --- | ---: |
| fragments only | 8 | 8 of 13 | `src/greeting.rs:1-10` | 2 |
| `--select-tokens 1024` | 16 | 8 of 13 | that, and `src/greeting.rs:8-10` | 2 |

**Two edits left 8 of 13 prompts contradicting themselves.** The corpus was
built expecting the two turns that re-read the file to be the finding. They are
2 of the 8. The other six are turns 7 to 11 and 13, which attach nothing of that
file and carry the contradiction anyway, because it is *in the history*: turn
1's `code_context` was written when turn 1 closed, and every later prompt
renders it beside turn 6's.

So **a divergence is not an event at the turn that causes it**. It is a state
the window enters and does not leave until eviction takes the stale turn out,
and the frequency item 19's fix waits on is not *how many edits a session makes*
but *what share of its prompts go out after the first one*. That reframes the
trade rather than settling it: rule A's +18 points of prefix reuse are paid on
every turn, and now so is the defect.

`asking` is 2 and not 8, and the gap is exactly what that field was added for:
only turns 6 and 12 disagreed with the disk *as it was when they were sent*.
The other six disagreed with a version of the file that no longer existed
anywhere — which is worse to read and harder to argue is the model's problem.

**The selection arm doubles the lines without moving the renders**: the selector
re-read `src/greeting.rs:8-10`, `greet` itself, a span nobody typed, and it
diverged on the same eight turns. One prompt, one file, two contradicted spans,
and only one of them was somebody's decision.

## What was rejected

**Rejected — a `## project:` directive.** The obvious way to say which tree a
script's paths are relative to, and it would be a line the runner has to ignore:
`luu chat --script` takes its sandbox from where it is started, so a directive
naming a project either does nothing at run time or turns the runner into a file
copier. A directive that means something to a test and nothing to the program is
the *second reader* this repository's own corpus guard warns about, one level
up. What landed instead is a convention that changes only where a path is looked
*up* — a directory beside a script and carrying its name is that script's tree —
so the script is still parsed by `parse_script` like every other one.

**Rejected — a template in `/tmp`, like the last one.**
[`does-the-envelope-collapse-generalize`](2026-09-15.does-the-envelope-collapse-generalize.completed.md)
ran eight write-tool prompts against a scratch project restored from
`/tmp/luu-write-probe-template` before each one. The template was never
committed, so **that run cannot be repeated** — the corpus is in the tree and
the thing it was run against is not. Worth naming rather than quietly not
repeating: it is the same failure as a corpus whose paths rot, one artefact
along.

**Rejected — editing a copy of this repository.** The most realistic corpus
available: an agent editing the code it is reading, which is the case the whole
defect is about. Rejected on rot. A corpus pinned to `context.rs:1-15` is one
rename away from being an error — `task.rs` → `job.rs` did exactly that to five
of twenty prompts in each grounded script, for four days, and it is why
`every_script_names_a_file_that_exists` exists. A corpus that also *edits* those
lines could not be guarded that way at all: the guard checks that a path exists,
not that `"Hello, "` is still in it.

**Rejected — a scratch project in Python, as the 2026-09-15 probe used.**
`agent_core::repo_map` indexes `.rs` and nothing else, so a template in any
other language can be grounded by `## fragment:` and can never be *chosen* by
the selector. That would have left the corpus with only the arm somebody types
by hand, and the run above is the argument against: the selection arm found a
second contradicted span in the same prompt, and it found it without being asked.

## What it cost

**A fixture in this tree is in this tree's own map, and it was measured rather
than assumed.** `walk_sources` skips dot-directories and `target/` and nothing
else, so everything `.rs` under `scripts/` is a candidate for `luu map` and
`luu select` *here*. Running `select_probe`'s 38 questions three ways:

| this repository's tree | all signals, 4096 | graph hop, 4096 | graph hop, 1024 |
| --- | --- | --- | --- |
| without the fixture | 38 held, 1st 17, top-3 31 | 37 held, 1st 11, top-3 24 | 30 held, 1st 11, top-3 24 |
| with it, five files | 38 held, 1st 17, top-3 31 | 37 held, 1st **9**, top-3 **20** | **29** held, 1st **9**, top-3 **20** |
| with it, four files | 38 held, 1st 17, top-3 31 | 37 held, 1st 11, top-3 24 | 30 held, 1st 11, top-3 24 |

Three columns of the six `select_probe` prints; the three left out — *no module
docs* at both budgets and *all signals* at 1024 — held every verdict across all
three trees, and are left out for that reason rather than because they were not
looked at.

The five-file tree had a `src/lib.rs` carrying `pub mod banner;` and three more
like it. **Those four lines are edges**, the graph signal follows them, and they
cost this project's own selector probe two first-place hits and four top-3 hits
at both budgets. Dropping that one file restores every verdict exactly; the four
leaves cost nothing measurable, which is the whole of what the third row says.

Worth writing down twice, because it is the kind of thing that would have landed
silently: `select_probe` asserts *the selector beats path order*, not the
numbers it printed last week, so a fixture that moved them would have passed.
`the_corpus_tree_is_a_fixture_and_not_a_crate` is the guard — no `Cargo.toml`,
no `lib.rs`, no `mod.rs` — and it carries the number in its doc comment so the
next person to want a module root there can see what one costs.

**And a counting surface, which four things have now asked for.**
`agent_core::record::divergence` folds a recording's `diverged` lines into
renders, `asking` renders, distinct paths and their worst body count. It is in
`record.rs` beside the format rather than in the probe that wanted it first,
because a tally computed inside a test is a tally only that test can quote, and
the next thing to want this number is a run against a model.

That is the fourth per-call reporter in one revision — item 12's grants, the
`not_granted` refusal, the three window rules, and now this — and the fourth
time the note *at some point the answer is one counting surface* has been
written. This one at least is over the recording rather than over a call, which
is where such a surface would have to read from anyway.

## Still open

- **The run this exists for has not happened.** The instrument is proved against
  the mock, where the edits are scripted, so 8-of-13 is a fact about the corpus
  and not about a model. What is unmeasured is how often a *model* edits a file
  it has quoted and then asks about it — and that is the number item 19's fix
  turns on. It is Section A work: a machine with a model on it, and the protocol
  is the two commands in the corpus's own header.
- **Whether 8 of 13 generalises at all.** Thirteen turns is a short session with
  a high edit density and no eviction — the window never filled, so no stale
  turn was ever taken out. The share in a long session is bounded by how quickly
  the floor rises past the turn holding the stale bytes, which nothing here
  measures and which the fix's ratchet argument already half depends on.
- **The corpus cannot produce item 20's case.** A resume is a second process
  reading a store; this is one session. Item 20 needed a corpus that edits, and
  it needs this one *plus* a resume in the middle, which is a script directive
  that does not exist.
- **Two of the four files are silent for reasons the detector cannot fix**, and
  the corpus now proves it rather than arguing it. `banner.rs` is the worse of
  the two: stale bytes in every prompt after the edit, nothing to contradict
  them, and no line anywhere. A fix that re-read at render time would catch it
  and a fix that supersedes by comparison never can.
- **Nothing prints the tally.** `agent_core::record::divergence` is a function,
  and the two things that read it are a test and this record. A run against a
  model will want it from a command line or from the panel that already reads
  `pruned`, and choosing which is the same *one counting surface* question that
  item 12's grants, the `not_granted` refusal and the three window rules have
  each asked separately. Deliberately not answered here: this record owes an
  instrument, and a fifth per-thing reporter is what it would be adding.
- **The graph hop moved on five small files**, which is a finding about the
  selector and not about this corpus. Two first-place hits from four `pub mod`
  lines in a file nothing imports is a sensitivity worth a row of its own, and
  it is not this record's to spend.
