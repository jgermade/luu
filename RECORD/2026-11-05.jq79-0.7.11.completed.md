# jq79 0.7.11, and what its preloads bring to the first load

## The question

*Usa jq79 v0.7.11.* The page ran 0.7.9. 0.7.10 and 0.7.11 were both
published on 2026-11-05, at 14:37 and 18:41 UTC.

## What changed upstream

Read from `src/` in the published 0.7.9, 0.7.10 and 0.7.11 tarballs, diffed.

1. **0.7.10: `$importAll([...])`**, a per-instance helper beside `$mounted`:
   `Promise.all` over the script's own `import()`, so a relative specifier
   means the component's file, not the page — the difference from
   `C79.importAll`. jq79's Vite plugin hoists its literal entries.
2. **0.7.11: a preload scanner.** Before a component's scripts first run, jq79
   reads their top level for literal specifiers in statements that always run —
   `import()`, `$importAll`, `C79.importAll`, `C79.fetch`/`fetchAll`, static
   imports — and asks for all of them at once: a `.html` into the component
   cache, anything else as a `<link rel="modulepreload">`. Each component that
   arrives is read the same way, so the scan goes down the tree. A branch, a
   block, a function body or a computed specifier is left to run time. It needs
   the component cache, which is on by default since 0.7.6.

```html
<script :setup>
  // 0.7.9: b.html is asked for when a.html has arrived and this line runs.
  // 0.7.11: both are asked for before the first line, and b.html's own
  // top-level imports as soon as b.html arrives.
  const A = await import("@web/a.html")
  const B = await import("@web/b.html")
</script>
```

## What it means for luu

- **Nothing to change for it to work.** The scanner from 0.7.11's own source,
  run over `web/`: 48 files with imports, 265 specifiers read, and no literal
  `import()` or `importAll([...])` in any `.html` that it leaves to run time.
- **The first load now brings Settings.** `app.html` imports `settings.html`,
  whose top level imports the nine sections; under 0.7.9 those arrived when
  Settings first opened, under 0.7.11 they arrive with the page, and what they
  import with them. Also `context-view.html` (from `context-modal.html`) and
  `host-form.html` (from `project.html`). 31 more files against `luu serve`
  (74 → 105), 34 on the static twin (57 → 91). None of them asked for twice:
  the preloads go through jq79's cache, which fetches through
  `lib/components-once.js`, and that stays.
- **`$importAll` is not adopted.** Every `C79.importAll` here already names
  `@web/` specifiers, which the scanner reads. Rewriting them as `$importAll`
  with relative ones would change the spelling and nothing else.

## Measured

The first load, 0.7.9 against 0.7.11. Playwright 1.63 and its Chromium; a
fresh context per load; each request held *delay* ms in the browser before it
goes out, all of them at once — a link that multiplexes, which loopback
HTTP/1.1 is not. `vendor/jq79.js` is answered from each version's tarball,
every other byte is the same. The marks are timed in the page with a
`MutationObserver`. Medians of seven loads per version, interleaved, after one
warm-up each. Milliseconds.

- **On loopback, where `luu serve` usually runs, 0.7.11 paints 25–50 ms
  later.** The files the first paint does not need are asked for beside the
  ones it does.
- **With latency it starts to pay**, and not much: 30 ms sooner at 100 ms a
  request, on a page about eight round trips deep (849 / 100). `app.html`'s
  38 imports were already one `importAll`, so what the scanner adds is the
  level below, starting when a file arrives rather than when it renders — a
  short gap when the 38 arrive together.
- No console error in any measured load.

## Checked

- `web/vendor/jq79.js` and its map are `dist/jq79.js` and `dist/jq79.js.map`
  from `npm pack jq79@0.7.11`, unchanged; the files they replace were 0.7.9's
  byte for byte. `C79.version` reads `0.7.11` in the page.
- **The static twin passes 5 of 5**, with `site/` assembled from `web/` and
  its fixtures recorded by the release binary, the way CI does.
- **The live suite: 78 passed, 1 skipped, none failed**, against a release
  binary built with 0.7.11 and `npm ci` in `web/`. The skip is
  `terminal.spec.js`'s container shell: no Docker daemon on this machine. Both
  suites ran with the pinned `@playwright/test` 1.56.1 driving the Chromium
  this machine has (build 1243, not the 1194 that version installs), through a
  config in `.tmp/` that only adds the executable's path.
- No Rust changed, so `cargo test` was not run for this.

## Still open

- **Keeping Settings off the first load**: `app.html` could import
  `settings.html` when Settings opens instead of at its top, which takes the
  31 files back out. Not done here — it is a change to how the page loads, and
  on loopback the price is ~25 ms.
- Whether a component that is imported but not drawn should have its own
  imports preloaded is jq79's to decide; the rows above are a case where it
  costs.
- HTTP/2 is still not measured: `luu serve` does not speak it on loopback, and
  the delay above only models a link that multiplexes.
