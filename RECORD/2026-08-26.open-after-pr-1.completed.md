# What is open after PR #1

**Provenance.** Written on `claude/agent-web-client-debug-obbg39` the day PR #1
merged, and left on that branch — it missed the squash by seconds, the same way
its own last bullet says the trailer convention did. Landed here unedited, with a
dated appendix at the bottom saying which of it four later merges answered. Read
the appendix first if you only want what is still true.

**Status:** a survey, written the day the walking skeleton merged. Ordered by
what I would do first, which is not the same as by size, and not the same as
the work order in `loude-design.md` — that one was written before any of this
existed.

## Where things stand

Merged: the workspace, a `Backend` trait over Ollama and a mock, `run_turn` with
cancellation, protocol v1 on three channels (protocol, trace, record), `luu
chat`/`serve`/`export`, the jq79 debug UI with replay, the read API and its
static twin, and CI.

Not merged, because it is not written: any of the context management this
project exists for.

## 1. Nothing exercises the server or the page in CI

The highest-value gap, and the least interesting to write.

Twenty-one tests cover parsers, folds and the turn loop — all of them pure. Zero
cover the WebSocket protocol end to end, the REST handlers, or the page mounting
and streaming. Everything verified in this session was verified by hand, with a
throwaway node client and Playwright, and none of it was committed. A regression
in the router, the protocol or the UI ships green today.

That is not a hypothetical. Every bug found in this session was found by running,
not by reading: the starved backend stream, the `publish` that lost its `await`
and silently stopped sending the trace prompt, the form handler written as two
statements that did nothing, the `:each` binding that never woke. Reviews found
none of them.

Two tests, in this order:

- **An integration test in `luu`** that binds an ephemeral port, drives one turn
  over `/ws`, and asserts the message sequence and the REST answers. Cheap, and
  it covers the layer where three of those four bugs lived.
- **A Playwright smoke test over the static site**, which CI already builds. Load
  it, let a fixture replay, assert the transcript and the budget panel, and fail
  on any console error — the fourth bug announced itself in the console and
  nobody was listening.

## 2. One turn is not a conversation

`start_turn` refuses silently when a turn is already running, sessions do not
accumulate history, and every turn rebuilds the same two messages from scratch.

Everything the project is *for* sits downstream of fixing this. Compaction,
relevance selection and pruning cannot be built — let alone measured — against a
single turn. Neither can the commitment that matters most: the stable prefix has
never once been tested, because there has never been a second call to reuse it.

The silent refusal is its own bug. A client cannot tell it from a dropped
message, which is exactly the failure mode the protocol was shaped to avoid
(`hello` carries the turn in flight for the same reason). It needs a `busy`
reply, or a queue.

## 3. Real tokens, not the backend's receipt

`TraceMessage::Budget` reports `prompt_tokens` and `completion_tokens` as the
backend counted them, in two buckets. That is honest, and it is not a budget —
it is a receipt for a call already made. A budget is a plan: system and tools,
code context, history, and the margin reserved for the answer, measured with the
loaded model's own tokenizer (`tokenizers`) before anything is sent.

Until that exists the panel is truthful and uninformative, which is a worse place
to sit than it looks — it is the shape of a thing that works.

## 4. The prompt diff

Decided and not built: compute it server-side with `similar`, send resolved
spans. It needs #2 first, because with one turn there is no previous prompt to
diff against.

It earns its place ahead of the context manager because it produces the one
number that says whether the stable-prefix discipline is working at all —
how much of the prefix survived into the next call. Building compaction without
it means tuning by feel.

## 5. Then the context manager

Hierarchical compaction, relevance over recency, active pruning of tool results.
Fifth, not first: #1 keeps it from regressing silently, #2 makes it possible at
all, #3 and #4 make it measurable. Starting here without those is how the
differentiator becomes the part nobody can prove works.

## Not started, and correctly so

Tools and GBNF-constrained decoding, the sandbox, container packaging, the VSCode
extension, the `llama-cpp-rs` binding, SQLite persistence.

Two of those have an order that will hurt if it is got wrong:

- **The sandbox goes in with the tools, never after.** A tool that shipped
  unsandboxed has callers, tests and habits built on it, and the policy then
  arrives as a breaking change nobody wants to make. `SandboxPolicy` should be a
  parameter of the first tool, even when it permits everything.
- **`llama-cpp-rs` only once there are numbers.** The HTTP hop is a known cost
  and there is still nothing to weigh it against. The debug UI exists to say what
  the swap bought; swapping before it can is spending the measurement.

## Small, independent, and none of it code

- **Pages is not enabled** for the repository (Settings → Pages → source: GitHub
  Actions). `deploy-pages` fails until someone clicks it.
- **`release.yml` has never run.** The merge validated `build.yml` including the
  `workflow_call` path; the `version` job — a shell bump that pushes a tag — has
  never executed. Run it with `dry-run: true` first.
- **The darwin-arm64 binary compiles and nothing tests it.** That is all that is
  claimed for it.
- **`?from=&limit=` on `/turns` is not implemented.** A static host cannot answer
  query parameters at all, so when it lands it needs a shape that degrades —
  pre-exported pages, most likely, not a truncated array.
- **Most of the exported API tree is served and unread.** The UI reads
  `sessions.json` and nothing else. An endpoint nobody reads is an endpoint
  nobody notices breaking, which is another argument for #1.
- **The AGENTS.md trailer convention missed the squash** by seconds and was
  carried onto this branch by hand. Worth knowing if it ever looks like it
  appeared from nowhere.

## Upstream, in jq79

Unchanged from where the previous file left them, in this order:

1. **The `:each` mutation bug** — assigning a property of an object inside a
   reactive array does not wake the binding. Correctness, with a fifteen-line
   repro in `2026-08-26.walking-skeleton.completed.md`. Worked around here by replacing
   messages rather than mutating them.
2. **A teardown hook.** Avoided rather than solved: the socket lives at module
   scope, owned by the page. That stops working the moment a component owns a
   per-session socket.
3. **Effect batching.** Not blocking — the `requestAnimationFrame` buffer works,
   and migrating later is deleting it.

The promotion rule stands: a gap moves upstream only when it cannot be expressed
in userland, or when the same workaround has appeared twice.

## Debts I would not let get older

Small, and each one is the kind that becomes folklore if it survives a few
months:

- **`luu chat --record` sleeps 50ms before exiting** so the writer task can
  drain. That is a race with a delay painted over it. The recorder should be
  closed and awaited.
- **`SessionView` is cloned on every API read**, under a mutex, for every
  request. Fine at three turns; not fine at a session worth compacting.
- **The replay caps inter-message gaps at 400ms silently.** Reasonable for
  watching, wrong for anything timing-related, and nothing in the UI says it is
  happening.

# 2026-08-30, appended on landing: what four merges since have answered

Nothing above is edited. This says which of it is history and which is still the
work, judged against `main` at the commit this file arrived on.

**Answered.** #2 (one turn is not a conversation) — sessions carry history and
the agent loop runs many turns. #3 (real tokens, not the backend's receipt) —
`Context::select` budgets against the loaded model's tokenizer before the call,
every count carries which counter produced it, and the receipt arrives separately
on `Ended` so the *difference* is the number watched. #4 (the prompt diff) — its
purpose landed as `prefix_reuse`, measured per call rather than rendered as
spans; the diff view itself is still not built and is now a presentation choice
rather than a missing measurement. #5 (the context manager) — history, budget,
per-turn and block eviction, and compaction on task boundaries; relevance
selection is the piece still missing. The sandbox went in *with* the tools, as
this file said it must.

**Still open, unchanged.** #1: no test binds the server and drives a turn over
`/ws`, no test loads the page. Every bug in this file's own list was found by
running, not reading, and that is still the case — the fragment surface and the
per-call trace that landed today were both verified by driving the running
server by hand, because there is nothing in CI that would have. The silent
refusal in `start_turn` is still silent: there is no `busy` reply, and the gate
now adds a second silent refusal beside it (a prompt sent while a task is
pending is ignored).

**Still open, and still small.** `luu chat --record` still sleeps 50ms before
exiting instead of closing and awaiting the recorder. `SessionView` is still
cloned under a mutex on every API read. The replay still caps inter-message gaps
at 400ms and still says nothing about it. `?from=&limit=` on `/turns` is still
unimplemented. The jq79 items are as this file left them.
