luu serve is starting, with its state in a volume that outlives the release.

Online, for people who log in: `luu setup` writes your domain and makes you
the first owner, with a code to log in with; then restart it.

  kubectl exec -it deploy/{{ include "luu.fullname" . }} -n {{ .Release.Namespace }} -- luu setup
  kubectl rollout restart deploy/{{ include "luu.fullname" . }} -n {{ .Release.Namespace }}

Or keep it to whoever holds the token:

The token, written on the first start:

  kubectl exec deploy/{{ include "luu.fullname" . }} -n {{ .Release.Namespace }} -- cat /state/token

{{- if .Values.ingress.enabled }}

Then open {{ include "luu.origin" . }}/?token=<the token>
{{- else }}

Then, with no ingress:

  kubectl port-forward svc/{{ include "luu.fullname" . }} -n {{ .Release.Namespace }} 7878:{{ .Values.service.port }}

and open http://localhost:7878/?token=<the token>
{{- end }}
{{- if include "luu.pods" . }}

Every session runs in a pod of its own (runtime: kubernetes), made through the
ServiceAccount {{ include "luu.fullname" . }}, which may create pods here. Hold
this namespace to Pod Security `restricted` — the worker pods already meet it:

  kubectl label ns {{ .Release.Namespace }} pod-security.kubernetes.io/enforce=restricted
{{- end }}
